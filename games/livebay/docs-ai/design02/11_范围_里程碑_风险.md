# 11 · 范围、里程碑与风险

## 一、MVP 目标

**一句话**：用 1 张场景、6 个房间、3 种资源、3 种故障，验证“没有战斗的舱段生存是否成立”。

### 1.1 MVP 包含

| 项 | 内容 |
| --- | --- |
| 场景 | 断缆 |
| 房间 | 6（走廊、主控、配电、循环、医疗、对接） |
| 资源 | 氧气、电力、压力 |
| 故障 | 泄漏、电气、火 |
| 玩家 | 移动、交互、工具、suit O2 |
| NPC | 1（巡检员） |
| 结局 | 救援 / 撤离 / 死亡 |
| 时长 | 15–20 分钟 |
| 记录 | 班后文本（不跨局） |

### 1.2 MVP 不包含

- 多场景；
- 元进程/程序树；
- 城市状态；
- 多 NPC；
- 难度选择；
- 第一人称；
- 生成式地图；
- 联机/工坊。

## 二、垂直切片

### 2.1 切片 A：系统可读

- 6 房间、3 资源、2 故障；
- 无美术，白盒+文字；
- 目标：玩家能说出“为什么失压/为什么没电”；
- 2 周。

### 2.2 切片 B：生存压力

- 加火/救援窗口/NPC；
- 目标：出现 3 次“不能全做”；
- 2–3 周。

### 2.3 切片 C：叙事/记录

- 广播/日志/班后记录/低报；
- 目标：玩家愿意再试/讨论选择；
- 2 周。

## 三、里程碑

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| M0 | 一页纸/文档 | 方向拍板 |
| M1 | 白盒房间模拟 | 资源守恒、故障可复现 |
| M2 | 20 分钟可玩 | 3 种结局可达 |
| M3 | 可读性/UX | 5 名玩家能说出失败原因 |
| M4 | 内容切片 | 1 场景完整、1 NPC |
| M5 | 决策 | 继续/缩小/停止 |

> 时间只是量级；不要用“做完整个游戏”作为 MVP。

## 四、内容预算

| 内容 | MVP | 正式版候选 |
| --- | --- | --- |
| 场景 | 1 | 3 |
| 房间 | 6 | 9 |
| 事件 | 12–16 | 30+ |
| NPC | 1 | 3 |
| 故障 | 3 | 5 |
| 工具 | 5 | 8 |
| 结局 | 3 | 4–6 |
| 程序 | 0 | 6–8 |

## 五、风险

| 风险 | 概率 | 影响 | 缓解 |
| --- | --- | --- | --- |
| 系统耦合过度，玩家读不懂 | 高 | 高 | 先白盒+检查器；一次只加一层 |
| 没有战斗，压力不足 | 中 | 高 | 用时间/资源/空间三重压力；MVP 验证 |
| 内容成本高 | 中 | 中 | 1 场景/6 房间；事件模板 |
| 与塔防太像/太不像 | 中 | 中 | 明确“无塔无波”；独立项目 |
| 叙事/系统脱节 | 中 | 中 | 事件必须改状态；记录必须来自选择 |
| 死亡挫败 | 中 | 中 | 前兆/重开整班/知识保留 |
| 生存数值难平衡 | 高 | 中 | 先量级后精调；自动测试 |
| 美术/音频拖累 | 中 | 中 | 先程序化/白盒；MVP 不做精细 |

## 六、验证指标

- 首次成功时间 / 首次死亡原因；
- 每局“不能全做”的选择次数（目标 ≥3）；
- 失败后能否说出原因（目标 ≥80%）；
- 撤离/留下比例；
- 重开意愿；
- 是否愿意讨论 NPC/记录选择；
- 系统可读性：5 秒内说出“哪个房间最危险”。

## 七、停止条件

- 玩家在 3 分钟内不知道要做什么；
- 没有战斗就没有压力；
- 每次失败都归因于“运气”；
- 需要靠大量内容/随机事件才能撑 20 分钟；
- 系统复杂度超过 1 场景可控范围；
- 与塔防工程耦合，导致两边都做不好。

## 八、不做的范围

- 不做多人；
- 不做开放世界；
- 不做基地建造；
- 不做战斗；
- 不做装备刷取；
- 不做每日任务/赛季；
- 不做程序生成地图；
- 不做第一人称。

## 九、下一步

1. 人类拍板 [12 待裁决](12_待裁决清单.md) 的 P0；
2. 做 M1 白盒房间模拟（不美术）；
3. 5 人内部测试，验证“无战斗压力”；
4. 再决定是否投入 M2。
