# 06 · 舱段与事件

## 一、内容单位

```text
场景（Scenario）
  └── 舱段（Section）
        └── 房间（Room）
              └── 事件（Event）
                    └── 状态变化（State change）
```

- 场景 = 一张图 + 一套目标 + 一个事件池；
- 房间 = 可进入的空间 + 资源/危险/叙事；
- 事件 = 条件触发/定时触发的系统变化，不是弹窗小说。

## 二、房间模板

| 房间 | 固定内容 | 可变内容 | 作用 |
| --- | --- | --- | --- |
| 中央走廊 | 主通道、门 | 破口/烟/障碍 | 连接/压力传播 |
| 主控室 | 地图、广播、权限 | 门控/电控 | 信息与决策 |
| 配电间 | 电池、配电盘 | 过载/火花 | 电力分配 |
| 循环站 | 过滤器、水泵 | 污染/停转 | 长期生存 |
| 医疗舱 | 药品、床 | 伤员/NPC | 伤情/照护 |
| 居住舱 | 储物、私人物品 | 火/烟/幸存者 | 搜刮/叙事 |
| 断裂段 | 破口、碎片 | 高价值物资 | 高风险 |
| 对接臂 | 救援接口 | 窗口/故障 | 撤离 |

## 三、事件类型

| 类型 | 例子 | 触发 | 玩家应对 |
| --- | --- | --- | --- |
| **环境** | 失压、升温、污染 | 时间/状态 | 封/补/通风 |
| **设备** | 门卡死、泵停、电池过载 | 电/使用 | 修/换/旁路 |
| **结构** | 二次破裂、地板塌 | 压力/火 | 封/绕/放弃 |
| **人** | NPC 受伤/恐慌/被困 | 位置/时间 | 救/安抚/放弃 |
| **制度** | 广播改口、权限收回、救援延迟 | 剧情/时间 | 记录/违令/撤离 |
| **信息** | 日志、录音、错误地图 | 探索 | 更新判断 |

> 事件不是“随机惩罚”，是**系统状态 + 时间**的结果；玩家应能追溯。

## 四、三张场景的事件结构

### 4.1 断缆

| 时间 | 事件 | 目的 |
| --- | --- | --- |
| 0:00 | 到达，主控室半失效 | 信息不足 |
| 2:00 | 第一次失压 | 教封门 |
| 5:00 | NPC 被困 | 教取舍 |
| 8:00 | 配电间过载 | 教断电代价 |
| 12:00 | 二次破裂 | 逼放弃一段 |
| 16:00 | 救援窗口 | 撤离/留下 |
| 19:00 | 班后记录 | 真话/低报 |

### 4.2 低功率夜班

- 主网断，电池只够关键负载；
- 日蚀窗口让太阳能输入下降；
- 玩家在氧气循环/门/通讯/照明之间分配；
- 救援窗口更短，但城市广播更频繁。

### 4.3 封舱

- 火/烟从居住舱开始；
- 门是唯一阻断手段，但会困人；
- 通风可能排烟，也可能助燃；
- 结局取决于封了几段、救了几人、记录怎么写。

## 五、难度

| 难度 | 资源 | 事件频率 | 救援窗口 | 目标 |
| --- | --- | --- | --- | --- |
| 标准 | 基准 | 基准 | 20 min | 撑到救援 |
| 困难 | -20% | +20% | 18 min | 救援+关键修复 |
| 自定义 | 可调 | 可调 | 可调 | 实验 |

> 难度不是“数值乘 1.2”，而是**减少容错/增加耦合**。

## 六、内容预算（第一版）

| 内容 | 数量 |
| --- | --- |
| 场景 | 1（断缆） |
| 房间 | 6 |
| 事件 | 12–16 |
| NPC | 1–2 |
| 故障类型 | 3（泄漏/电气/火） |
| 工具 | 5 |
| 结局 | 4 |
| 单局 | 15–20 分钟 |

> 先做一张场景的完整闭环，再谈第二、第三张。不要一次做三张。

## 七、事件写作规则

1. 事件必须改变**空间/资源/人**中的至少一项；
2. 事件必须有前兆/可读信号；
3. 事件不能靠玩家不知道的隐藏计时秒杀；
4. 同一事件在不同房间/状态下可以有不同后果；
5. 每个事件都要能写进班后记录。

## 八、可重玩性

- 事件池按条件抽取，不是纯随机；
- 房间状态/玩家路线改变事件顺序；
- 玩家知识改变“看到什么”；
- 不靠程序生成地图，靠**组合**。

## 九、待裁决

5. 是否允许玩家选择难度/自定义？
