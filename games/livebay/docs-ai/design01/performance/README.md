# LiveBay · 性能基线

> 运行：`./run.sh perf` · 原始数据：[`bench.json`](bench.json) · 口径：Godot 4.7 headless、只测模拟步进，不含渲染/音频/GPU。

## 一、环境

| 项 | 值 |
| --- | --- |
| 引擎 | Godot 4.7-stable (official) |
| 系统 | macOS · Apple M1 Pro · 8 cores |
| 场景 | `bay01` standard（两座拦截炮 + 供给/补塔/升级） |
| 采样 | 地图预热后 20 次加载 / 9,930 帧 / 每档 120 步 / 18,000 帧长跑 |

## 二、结论

| 指标 | 结果 | 判定 |
| --- | ---: | --- |
| 5 波模拟 p95 | **0.077 ms/step** | 远低于 16.7 ms 帧预算 |
| 2,000 实体 p95 | **6.257 ms/step** | 约为 60 Hz 预算的 37% |
| 5 分钟长跑（18,000 帧） | **187.6 ms wall** | 无异常，约 0.0104 ms/帧 |
| 地图加载 p95 | **≤0.97 ms** | 三图均低于 1 ms |

**当前 headless 基线可以支撑下一步内容扩张；但不能据此宣布“性能已验收”。** 真实渲染、GPU、音频、内存增长与多地图长跑仍待测。

## 四、已知限制

- headless，无渲染/GPU/音频；
- 单地图标准班，未覆盖三图长跑；
- 合成实体不移动、不死亡，只压索敌/遍历；
- 未采样内存峰值、GC/对象分配、磁盘 I/O；
- 不同机器结果会变化，应看同一机器的趋势，而不是绝对数值。

## 五、下一步

1. 加渲染帧时间（GPU/CPU frame）与真机 60/120 Hz；
2. 加内存/对象分配长跑；
3. 三张地图各跑一次标准班长跑；
4. 用 `verify` 之外的性能阈值做回归，阈值建议：
   - 标准班 p95 < 1 ms；
   - 2,000 实体 p95 < 10 ms；
   - 地图加载 p95 < 5 ms；
   - 5 分钟长跑 < 1 s。
