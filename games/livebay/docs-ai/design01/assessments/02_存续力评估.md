# 02 · 存续力评估

> **一句话**：LiveBay 能继续做，是因为它有清楚的方向、可复用的工程与内容管线、低固定成本；但它**没有安全垫**：单点依赖、无收入、无发布、无人类验证、范围仍在扩张。
>
> **结论**：**3.15 / 5（C+，约 63/100）**。不是“项目要死了”，而是“能继续，但不能承受一次大失误”。

## 一、什么是“存续力”

存续力不是“游戏能活多久”或“环保”，而是：

> 项目在**时间、资金、精力、人员变动、平台变化与范围膨胀**中，继续存在并推进的能力。

它关心五个问题：

1. 没有收入时能撑多久？
2. 关键人离开/生病/疲惫时，项目能不能继续？
3. 范围扩大时，能不能砍？
4. 平台/法律/发行变化时，有没有退路？
5. 玩家/社区是否形成反馈回路？

## 四、存续资产

### 4.1 低固定成本

- 无服务器、无在线服务、无日常运营；
- 本地优先、离线可跑；
- 不靠持续更新维持在线人数；
- 失败不会产生永久运营债务。

### 4.2 可复用资产

- 数据管线：numbers → data → MissionPack → 测试；
- 工具：编辑器、沙盘、trace、流程图、verify；
- 文档：49 页 design01 + HUB/GUIDE；
- 工程：模块化、可逆、可回放；
- 内容：6 塔/7 敌/8 波/12 卡/3 合同，可作为下一版本的基础。

### 4.3 范围纪律

v0.2 明确“不新增第四种玩法、不做日常/体力”，这是一次成功的范围控制。

## 五、脆弱点

| 脆弱点 | 后果 | 触发信号 |
| --- | --- | --- |
| 单点依赖 | 关键人停摆，项目停摆 | 连续两周无提交、交接文档没人能独立跑 |
| 无收入/预算 | 无法买时间、美术、音乐、发行 | 只能靠业余时间，且开始砍生活 |
| 无人类验证 | 做了很多“自己觉得对”的内容 | 试玩人数长期 <5，反馈同质 |
| 范围膨胀 | L2/L3 同时开工，主线失焦 | 同时开 3 个以上新系统 |
| 发布未定 | 做完也不知道怎么卖/发 | D14/D17/D18 长期空着 |
| 法律/IP 未审 | 音乐/字体/素材/发行条款返工 | 上线前才检查 |
| 精力耗尽 | 质量与判断力下降 | 连续加班、对试玩失去兴趣 |
| 无社区回路 | 没有真实需求输入 | 没有玩家群/邮件列表/试玩记录 |

## 六、三种存续情景

### 情景 A：低速但持续（推荐）

- 每周固定 2–3 个晚上；
- 每两周一次可玩版本；
- 先人类试玩，再决定 L2；
- 不辞职、不借贷、不承诺日期；
- 目标：12 个月内有一个“可发布候选”。

### 情景 B：冲刺

- 3–6 个月高强度；
- 需要预算/合作/发行支持；
- 风险：burnout、范围膨胀、质量下降；
- 只有在资金与发行确定后才建议。

### 情景 C：停更保资产

- 保留文档、数据、工具与可运行切片；
- 不删除、不散架；
- 未来可重启；
- 这是合法的“存续”，不是失败。

## 七、90 天存续计划

1. **定一个决策日**：D14 平台、D17 更新节奏、D18 语言，最晚 30 天内拍板；
2. **做 10 人试玩**：三图各一轮，记录理解成本/失败归因/再开意愿；
3. **砍范围**：L2/L3 在 L1 验证前不开工；
4. **建交接包**：一页启动、一页发布、一页故障处理；
5. **设停手线**：连续 4 周无法投入，自动进入“停更保资产”，不硬撑；
6. **做一次最小发布演练**：打包、签名、商店页/ itch 页、更新说明；
7. **每月一次“存续复盘”**：时间、钱、精力、范围、外部反馈五项各打 1–5 分。

## 八、存续指标

| 指标 | 目标 |
| --- | --- |
| 每周可投入时间 | 稳定，不靠透支 |
| 试玩人数/月 | ≥5，逐步到 10 |
| 从决策到可玩版本 | ≤2 周 |
| 范围新增 | 每版本 ≤1 个新系统 |
| 交接演练 | 每季度 1 次 |
| 现金流/预算 | 至少 6 个月缓冲，或明确“无收入也接受” |
| 停手线 | 提前写清，不临时决定 |

## 九、结论

LiveBay 的存续力不是“能不能做出来”，而是“**能不能在不毁掉生活的前提下，持续做到可发布**”。
