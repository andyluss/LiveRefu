# 00 · 工程力评估

> **一句话**：LiveBay 已经是一个**工程上可信的垂直切片**：边界清楚、数据单一源、测试与验收齐全、主入口收口；但它还不是生产级项目，性能、发布与人员连续性仍是短板。
>
> **结论**：**3.93 / 5（B+，约 79/100）**，处于 **L2+（垂直切片成熟）**，进入“发布前工程化”阶段。

## 一、评估口径

工程力不是“代码行数少”，而是：

- 能不能**改得动**：边界、模块、入口是否清楚；
- 能不能**验得动**：测试、验收、回放、数据对账；
- 能不能**接得住**：文档、工具、数据源、失败策略；
- 能不能**发得出去**：性能、平台、打包、发布；
- 能不能**交给别人**：交接、可逆、依赖与风险。

本次评分基于当前仓库实际状态，不对外部团队、商业或运营做判断。

## 四、已经成立的部分

### 4.1 边界

```text
main.gd              入口：启动/连线/每帧/绘制（210 行）
game_session        数据/运行时生命周期
game_command        输入/按钮 → Runtime 命令
game_feedback       模拟信号 → 表现
game_ui_presenter   ReadModel → HUD
game_flow_controller 地图/档案/简报/检查单/故障/结算
game_hud            HUD 构建
```

规则在 `core/domain/application`，表现层不直接改 Sim。

### 4.2 数据

- `numbers/*.md` 是唯一数值源；
- `export_numbers.py` 生成 `game/data/*.json`；
- `mission_pack.json` 是 **schema 2 跨地图目录**，按 `map_id` 选包；
- HUB 11 facts、沙盘、trace、测试都做对账；
- `pack-check` / `simulator-check` / `verify` 能发现过期。

### 4.3 验收

```text
./run.sh verify
  = test + expansions + editor + playtest
  + numbers/pack + flow + simulator + briefing
  + headless start + links + R-016
```

当前 **12/12 通过**；测试 95；扩展 34；R-016 60 页。

### 4.4 性能基线

## 五、工程债

| 债务 | 影响 | 优先级 |
| --- | --- | --- |
| 无 GPU/真实音频/内存峰值 | 无法判断真实帧率与设备下限 | 高 |
| 无覆盖率 | 测试数量不等于覆盖质量 | 中 |
| 无远程 CI | 依赖本地 verify 与 pre-commit | 中 |
| Sim 仍编排索敌/移动 | 模块边界未完全收口 | 中 |
| 无发布链 | 平台/打包/签名/更新未定 | 高 |
| 单点依赖 | 关键知识集中在少数人 + AI | 高 |
| 文档/实现同步成本 | 评估与文档可能滞后 | 低 |

## 六、下一步（按优先级）

1. **真实环境性能**：窗口/真机采 GPU、音频、内存峰值；
2. **发布链**：确定 D14 平台、D17 更新节奏、D18 语言，做一次最小打包；
3. **覆盖率**：至少覆盖 Sim 模块与数据加载；
4. **远程 CI**：把 `verify` 接到 GitHub Actions/本地 runner；
5. **交接包**：一页启动、一页发布、一页故障处理；
6. **Sim 再分拆**：索敌/移动/伤害编排从 Sim 抽出。

## 七、结论

工程力已经足够支撑**下一轮内容与试玩**，但不足以支撑**正式发布**。

> 当前最该做的不是继续加架构，而是把“真实性能 + 发布链 + 交接”补齐。
