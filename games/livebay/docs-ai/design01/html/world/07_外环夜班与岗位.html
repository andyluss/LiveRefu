05 · 外环夜班与岗位

塔防不是“战场”，是一班。这一篇给检查单、交接、故障、低报提供日常依据。

一、班次

【参考】外环按三班轮转，夜班是最缺人、最容易被低报的班：

班次 时间意向 状态
日班 06:00–14:00 检查、维护、接待
晚班 14:00–22:00 高峰、货运、演练
夜班 22:00–06:00 最少人、最依赖自动化
  • 交接不是“打卡”，是口头 + 记录 + 现场确认；
  • 夜班通常只有 1 名值班长 + 2–4 名岗位员；
  • 故障多、支援少、广播少，所以夜班故事最多。

二、岗位

岗位 职责 玩法映射
值班长 决定优先级、签字、对外联络 玩家视角/合同
塔位员 建塔、升级、供能分配 塔防操作
巡检员 走段、听异响、复位 故障卡/探索
维护员 修舱、换件、封舱 生存 S2
通讯员 广播、记录、呼叫支援 叙事/低报
医疗员 急救、照护、退役评估 湾民/沉浸

一个人可能兼两个岗位；人少时，玩家必须选择“先做哪件”。

三、一班的结构

班前：签到 → 交接 → 检查单 → 分配
班中：巡检 → 开波/故障 → 处置 → 记录
班后：交接 → 补记 → 签字 → 回家

3.1 班前检查单

【参考】检查单不是形式，是责任转移：

  • 上一班把风险交给你；
  • 你签字，表示“我知道”；
  • 出事时，签字会被翻出来；
  • 所以有人“照签”，有人“复查”，有人“按惯例处理”。

玩法上，检查单的选项应该改变风险/资源/记录，而不是只加一句文本。

3.2 交接

交接包括：

  • 设备状态：哪些塔降级、哪些舱段封了；
  • 人员状态：谁疲劳、谁受伤、谁缺班；
  • 风险：故障趋势、外部碎片、救援计划；
  • 未完成事项：谁答应修但没修。

低报常常发生在交接：上一班不想留下“未完成”，下一班不想接“坏消息”。

3.3 班后记录

  • 事故记录：时间、段、设备、处置、影响；
  • 低报：把“事故”写成“异常”，把“漏过”写成“压力波动”；
  • 补记：事后改记录，是最常见的灰色操作。

四、夜班文化

【参考】

  • 不鼓励英雄主义；“活着交接”比“漂亮战绩”重要；
  • 咖啡/茶/提神片是硬通货；
  • 老值班长有一套“听声音判断故障”的经验；
  • 新人先学“怎么记录”，再学“怎么修”；
  • 夜班的人彼此叫“同班”，比“同事”更亲；
  • 夜班事故的纪念通常很低调：一只杯子、一盏灯、一个不关的工位。

五、与生存玩法的接口

低功率夜班的核心不是“打怪”，而是夜班资源分配：

资源 夜班含义 玩家选择
电力 塔/生命维持/舱门/照明 给塔还是给氧
氧气 舱段循环/储备 封舱还是开舱
舱门 隔离故障/泄漏 放弃哪段
备用电池 应急储备 现在用还是留到救援前
救援 外部接应 撤离还是留下

这些选择都应该能被写进班后记录；结算不是“分数”，是“这一班留下了什么”。

六、与塔防玩法的接口

  • 塔位不是“炮台”，是岗位设备；
  • 升级是“换件/校准”，出售是“拆走/调拨”；
  • 故障停塔是“设备离线”，不是“被击中”；
  • 漏过是“防线失效”，结算要写“哪段、为什么”；
  • 检查单/合同是班次的上层目标。

七、可写的日常细节

  • 夜班食堂只开一个窗口，菜单固定；
  • 巡检要带手电、扳手、记录板；
  • 外环的钟比中环慢 2 分钟（历史遗留，没人修）；
  • 交接室有一块永远擦不干净的故障白板；
  • 新人第一次封舱会手抖；
  • 老值班长会把“别按惯例”挂在嘴边。

八、待裁决

  1. 夜班的具体人数与岗位合并规则；
  2. 检查单签字的责任边界；
  3. 交接是否强制录音；
  4. 夜班补贴/加餐券的具体形式；
  5. 低报是个人行为还是组织行为。
