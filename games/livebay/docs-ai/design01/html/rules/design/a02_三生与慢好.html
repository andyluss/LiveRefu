一句话：每个系统都必须落在「生存 / 生活 / 生产」之一；「慢」是不逼人，「好」是质量与尊严。 形式化：∀s ∈ Systems: layer(s) ∈ {Survival, Life, Production}；SlowGood = Slow ∧ Good。

一、形式化表述

Layers = {Survival, Life, Production}
∀s ∈ Systems: layer(s) ∈ Layers

Slow ⇔ ¬FOMO ∧ ¬dailyEnergy ∧ hasBuffer
Good ⇔ quality > quantity ∧ dignity ∧ transparentRules
SlowGood = Slow ∧ Good

二、通俗解释

「慢好三生」不是一句口号，是三层检查：

  • 生存：空气、水、食物、医疗、安全。不能拿它做交易。
  • 生活：居住、娱乐、教育、社交、心理、养老、尊严。决定人愿不愿意把城当家。
  • 生产：工作、能源、资源、维护、照护劳动。维持前两者的代价。

「慢」不是低效，是不把效率放到人前面：不做每日签到、不做体力、不做限时逼上线、允许发呆。 「好」不是给得多，是给得可靠、有尊严：不卖数值、不抽卡、规则透明、服务有温度。

三、条款

MUST

  1. M1：每个玩法系统必须标明它服务哪一层（生存/生活/生产）。
  2. M2：不得用 FOMO、每日签到、体力、限时数值礼包驱动留存。
  3. M3：不得把生存配额做成付费/随机内容。
  4. M4：玩家离线不应受到惩罚；回归应有“这段时间发生的事”。
  5. M5：内购不得破坏“好”的底线（见 BIZ-A1）。

SHOULD

  1. S1：三种玩法分别对应三层：塔防偏生产，沉浸偏生活，放置偏生活/生产。
  2. S2：每个版本至少有一个“慢”的设计：允许跳过、允许暂停、允许不完美。
  3. S3：每个版本至少有一个“好”的设计：更清楚的规则、更体面的服务、更可靠的手感。

MAY

  1. Y1：可以有“效率优化”，但不能以牺牲照护/尊严为代价。
  2. Y2：可以有“忙碌的一天”，但玩家可以选择不参与。

  system.layer ∈ Layers ∧
  system.fomo = false ∧
  system.offlinePenalty = false ∧
  system.payForPower = false

五、反例

  • 每日登录奖励、连续签到；
  • 体力上限，逼玩家定时上线；
  • 限时卡池/限时礼包；
  • 离线收益归零；
  • “不买就过不去”的关卡。
