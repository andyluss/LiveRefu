一句话：威胁不只来自外面，也来自系统内部；低报事故只埋线索，不替玩家揭晓。 形式化：Threat = External ∪ Internal；LowReport = clue ∧ ¬reveal。

一、形式化表述

Threat = External ∪ Internal
Fault ∈ Internal
Fault.effect = disable(Tower, d) ∧ |targets| ≤ 2
d = 2.5s（v0.1）
LowReport = (clue ≠ ∅) ∧ (reveal = false)
NarrativeAuthority = Human

二、通俗解释

外敌是“碎片、乱流、重壳”；内部威胁是“故障、低报、维护欠账、流程漏洞”。后者更接近这个项目的核心：城不是被一拳打穿的，是被很多“不碍事”磨穿的。

故障的玩法表达要克制：

  • 它不直接扣保障度；
  • 它只让最多 2 座塔离线 2.5 秒；
  • 它从湾口反向来，打乱“只守入口”的布局；
  • 它给玩家一个“要不要为小异常多做一步”的选择。

低报事故不是“反派隐瞒真相”的阴谋剧，而是制度性的轻描淡写：广播说 0 起，记录里有一行“待复查”，玩家可以看见，但游戏不替他下结论。

三、条款

MUST

  1. M1：内部威胁必须与外部威胁有不同的玩法效果，不能只是换皮怪。
  2. M2：故障不得直接扣保障度；它通过停塔间接造成漏过。
  3. M3：故障同时影响塔数 ≤ 2，时长在 v0.1 为 2.5s；提高需人类裁决。
  4. M4：低报事故只能通过记录、广播、NPC 的“按惯例”等线索表达，不得用旁白直接揭晓。
  5. M5：失败结算必须有一份“事故报告”，不能只弹失败。

SHOULD

  1. S1：故障从湾口反向来，迫使玩家在中段留冗余。
  2. S2：广播的“0 起”与记录里的“待复查”形成对照。
  3. S3：玩家可以做“多写一句”的动作；系统提示“超出模板长度”是奖励，不是惩罚。

MAY

  1. Y1：后续可以加“维护欠账”“预算冻结”等内部威胁，但一次只加一种。
  2. Y2：可以让低报在多个班次后才产生后果，但不能永远不兑现。

四、判定与验收

valid(fault) ⇔
  fault.type = internal ∧
  fault.directDamage = 0 ∧
  fault.targets ≤ 2 ∧
  fault.duration ≤ 2.5s

valid(lowReport) ⇔
  clues ≥ 2 ∧
  explicitReveal = false

五、反例

  • 故障直接扣 20 保障度，变成另一个重壳；
  • 故障一次停 7 座塔，玩家只能重开；
  • 旁白直接说“政府在隐瞒事故”；
  • 广播说 0 起，但没有任何可查的记录；
  • 玩家写了备注，系统没有任何反馈。
