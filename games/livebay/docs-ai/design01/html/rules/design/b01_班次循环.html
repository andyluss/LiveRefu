04_塔防玩法 · 06_沉浸体验玩法 · 07_放置养成玩法

一句话：一局就是一个班次：准备 → 波次 → 结算 → 交接；三种玩法都必须落在这个循环里。 形式化：Loop = Prep → Wave → Settle → Handover，Session = one Shift。

一、形式化表述

State = {Prep, Wave, Between, Settle, Handover, Won, Lost}
Loop = Prep → Wave* → Settle → Handover
Session = Shift(profession, goal, record)
∀mode ∈ Modes: ∃shift(mode)

entry(Session) = 接班
exit(Session) = 交班记录

二、通俗解释

玩家每次打开游戏，不是进入一个“关卡菜单”，而是接一个班：

  • 接班：看上一班留下了什么；
  • 准备：布防、读情报、决定先做什么；
  • 执行：塔防的波次、沉浸的对话、采集的窗口；
  • 结算：保障度、漏过、消耗；
  • 交接：写记录，留给下一班。

“班次”是三种玩法的共同骨架。塔防是“扛一波”，沉浸是“值一班”，放置是“你不在时别人替你值班”。

三、条款

MUST

  1. M1：每个可玩模式必须有明确的“接班”和“交班”。
  2. M2：一局必须有结束点与结算，不得无限拖。
  3. M3：结算必须产出至少一条“可被下一班读到”的记录。
  4. M4：失败也必须进入结算（事故报告），不得直接黑屏重开。
  5. M5：波次/对话/离线事件的时间结构必须能被玩家理解（准备多久、进行多久、何时结束）。

SHOULD

  1. S1：塔防一局 5 波，准备 30s + 波间 20s；完整版可扩，但保留结构。
  2. S2：沉浸一局 5–8 分钟，3–5 个选择。
  3. S3：放置的“回归报告”就是交班记录。
  4. S4：三种玩法的记录可以互相引用（同一个人、同一件事）。

MAY

  1. Y1：可以有“加班”“连班”作为特殊模式，但必须明确代价。
  2. Y2：可以有“无交接”的挑战模式，但不能作为主线默认。

五、反例

  • 点开就开打，没有准备与情报；
  • 失败直接弹“重试”，没有事故报告；
  • 沉浸玩法没有结束点，只是无限对话；
  • 放置玩法收菜后没有任何“这段时间发生了什么”。
