规则体系

20 条规则，3 层，4 类 + 根规则。它们不是建议，而是项目在压力下仍然不跑偏的约束：a 层是公理，b 层是结构，c 层是表达。

三层：a / b / c

层级不是重要性排序，而是“改动代价”的排序。越靠底层，越不能随手改。

a · 底层7 条

底层 / 公理

项目为什么存在；改它等于换项目。

b · 中层9 条

中层 / 结构

项目怎么运转；可调，但要评审。

c · 表层4 条

表层 / 表达

项目长什么样、怎么写；可快速调整。

关键依赖

  • ROOT-A0→ROOT-B0人类裁决决定规则如何分层与修订
  • ROOT-B0→ROOT-C0分层规则要求文档可引用、可验收
  • BIZ-A1→DES-A2不卖数值，保护“慢好”
  • DES-C1→TECH-A1数值引用必须落到单一数据源
  • DES-B3→DES-B2故障把“没有完美答案”变成可玩选择
  • ART-A1→ART-B1 / B2 / C1四件套向下展开为空间、维修与色板
  • TECH-A1→TECH-B1 / B2单一数据源让改动可逆、验收可重复

全部规则

按类别分组；每张卡片都可以直接打开。规则正文含形式化、通俗解释、条款、验收与反例。

根 ROOT

3 条
ROOT-A0a · 底层

人类裁决与优先级

AI 可以提方案，但不能替人拍板；人类原始设定高于一切文档与代码。

ROOT-B0b · 中层

规则分层与冲突

规则分三层：a 层是不可轻易改的公理，b 层是结构约束，c 层是表达约束；冲突时 a b c。

ROOT-C0c · 表层

文档与引用契约

文档有统一的元数据、命名与引用方式；生成物从源生成，不手改。

商业 BIZ

3 条
BIZ-A1a · 底层

买断与内购边界

基础游戏买断；内购只卖外观与扩展内容，不卖数值、不抽卡、不订阅。

BIZ-B1b · 中层

切片与范围门槛

先做 10 分钟垂直切片；任何新功能都要先证明它服务这个切片，否则不做。

BIZ-C1c · 表层

对外表达与证据

商店页、预告、截图、访谈里的每个具体承诺，都要能在当前构建里找到证据。

设计 DES

6 条
DES-A1a · 底层

岗位与无名主角

玩家不是天选者，是一个会被排班、轮岗、退休的普通人；每个职业都是「你」。

DES-A2a · 底层

三生与慢好

每个系统都必须落在「生存 / 生活 / 生产」之一；「慢」是不逼人，「好」是质量与尊严。

DES-B1b · 中层

班次循环

一局就是一个班次：准备 → 波次 → 结算 → 交接；三种玩法都必须落在这个循环里。

DES-B2b · 中层

选择必须有代价

有意义的选择至少有两个选项，每个选项都有代价，且不存在“永远正确”的选项。

DES-B3b · 中层

故障与低报

威胁不只来自外面，也来自系统内部；低报事故只埋线索，不替玩家揭晓。

DES-C1c · 表层

数值与场景引用

数值只从 numbers/ 来；文档、UI、场景里出现的数值必须能追溯到表格，不能凭手感写。

艺术 ART

4 条
ART-A1a · 底层

NASApunk 四件套

NASApunk 不是“复古贴纸”，是白盒工程、检查单、模拟界面、机构色四件套。

ART-B1b · 中层

三环三套视觉语法

外环、中环、内环不是三种颜色，是三套“材质 + 光 + 密度 + 声音”的语法。

ART-B2b · 中层

可维修性

每个设备都要让人相信“它能被打开、被修、被替换”；看不见接缝的东西不属于这个世界。

ART-C1c · 表层

色板、字体与比例

颜色是有限的 token，比例是 70/20/10；数据用等宽，标题用无衬线，正文用可读的宋/黑。

技术 TECH

4 条
TECH-A1a · 底层

单一数据源

数值只在 numbers/ 写一次，game/data/.json 是导出物；手改 JSON 无效。

TECH-A2a · 底层

模拟与视图分离

sim.gd 只算规则，不画东西；main.gd 只画东西，不算规则；两者用信号通信。

TECH-B1b · 中层

可逆工程

能改数据就不改结构；每个改动都要能回退，半成品不进主线。

TECH-B2b · 中层

验收与不回归

每次非琐碎改动都要跑对应检查；检查失败不静默绕过。

怎么读

  1. 先看三层：a 层决定什么不能做，b 层决定怎么运转，c 层决定怎么表达。
  2. 再看矩阵：找自己关心的类别与层级，不必从头读 20 条。
  3. 最后看关系：根规则 → 类别规则 → 具体条款；冲突时按 ROOT-B0 判定。
  4. 写文档/代码时：用规则 ID 引用，如 DES-B3，不要只写“按设计规则”。
