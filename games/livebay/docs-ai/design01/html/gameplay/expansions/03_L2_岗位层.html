范围：v0.3 起；在 L1 成立后再做。核心不是「更多塔」，而是「同一座塔长出不同岗位性格」。 一句话：塔座是 ORU 插槽，模块是备件，湾民是岗位，三者都服务于「这一班怎么修、怎么换、怎么扛」。

一、塔座模块化（2 槽）

每座塔有 2 个槽：

槽 作用 例子
核心槽 决定攻击方式/主参数 拦截炮管、脉冲线圈、补给泵
支持槽 改变代价/容错 冷却鳍、电容、旁路继电器、维修臂

规则：

  • 塔的 kind 仍只有 single/aoe/supply；
  • 模块只改「参数 + 一个标签」，不新增一套技能树；
  • 每个槽 1 个模块；换模块只能在准备/波间；
  • 拆下的模块回备件库，不损耗（或 10% 损耗，待试玩）；
  • 模块不随机掉落；通过合同/记录/城市事件获得。

1.1 模块示例

模块 槽 效果 代价
长管 核心 射程 +20% 攻速 -10%
过载电容 支持 攻速 +25% 故障时长 +1s
冷却鳍 支持 故障时长 -1s 造价 +5
旁路继电器 支持 第一次故障免疫 之后故障 +2s
维修臂 支持 每波修复 2 点 输出 -5%

每个模块都应有「不是纯加法」的代价；否则会变成数值堆叠。

1.2 与故障的关系

  • 模块可以被故障「隔离」：只停该模块，不整塔离线（高阶玩法，L2b 再开）；
  • 旁路继电器把「停机」变成「降级」，但增加后续风险；
  • 故障不再只是「停 2.5s」，而是「你装了什么东西，决定它怎么坏」。

二、备件

项 规则
来源 合同完成、记录「如实」、城市事件、拆解
用途 安装/更换模块、维修
上限 软上限，不逼每日刷
不带入 不卖、不抽、不与现实货币挂钩

备件是 L2 的「小资源」，不是第二套主经济；它只影响「这一班能不能换一个模块」。

三、湾民（3 名）

不做抽卡，不做全员养成。第一版只做 3 个有名有岗位的人：

湾民 岗位 特质 效果（小）
阿岚 维修工 手稳 故障停塔 -0.5s
老周 调度 熟流程 检查单复查少花 2s
小满 实习生 学得快 每班首次升级 -5 供能
  • 每个湾民有疲劳/心情，但不死亡、不永久伤病；
  • 分配岗位有 +10% 效率，不匹配 -10%，但可培养；
  • 效果上限小，不能替代塔与操作；
  • 湾民通过剧情/合同加入，不通过抽卡。

四、事故链（3 班合同 → 1 条链）

L2 的「长期对象」不是等级，而是一条 3 班事故链：

第 1 班：发现异响 → 记录
第 2 班：故障升级 → 隔离/旁路
第 3 班：审计/交接 → 选择谁背记录
  • 每班仍是 5 波；
  • 选择改变下一班的 1 个条件（不是永久数值）；
  • 结束后留下 1 个档案条目/1 个模块；
  • 不做多结局树，只做「记录不同」。

五、与 L1 的咬合

L1 产出 L2 用途
低报标记 事故链中触发「审计」班次
复查记录 解锁「旁路继电器」备件
故障处置选择 决定第 3 班是否出现「相邻塔降级」
班次合同完成 获得模块/湾民

L2 不改变 L1 的规则，只把 L1 的记录变成 L2 的内容。

六、数据与工程映射

内容 字段 模块
模块定义 modules[]：id、slot、effects、tags、cost TowerModule 扩展
塔槽 tower.sockets[] TowerModule
备件 parts Economy 扩展
湾民 crew[]：id、role、trait、fatigue ModifierModule
事故链 contracts / records ProcedureModule

架构要求：

  • 模块效果通过 ModifierModule 汇总，不散落在 Tower 的 if；
  • 所有模块可数据关闭；
  • 预览/编辑器能读同一套模块定义。

七、验收

  • 不装模块，标准班仍能过（B/40）；
  • 装模块不出现「唯一最优」；
  • 模块数量 ≤6 个第一版（2 槽 × 3 塔的可用组合不必全填满）；
  • 备件不逼每日刷；
  • 湾民效果不超过一个塔等级的 30%；
  • 故障/记录/模块三者能讲清一个「这一班怎么坏」的故事。

八、L2 不做什么

  • 不做随机掉落/抽卡；
  • 不做三槽以上；
  • 不做人员死亡/永久伤病；
  • 不做独立备件货币的每日产出；
  • 不做新塔/新图（第一版）。
