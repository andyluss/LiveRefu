# 07 · 故障与事故文化

> 故障不是“敌人换皮”，而是**系统老化 + 人的选择**。这一篇给故障卡、检查单、广播、档案提供文化依据。

## 一、故障是什么

【参考】湾民把“故障”分成四类：

| 类型 | 例子 | 处理 |
| --- | --- | --- |
| 设备故障 | 塔离线、传感器漂移、泵卡死 | 复位/换件/旁路 |
| 结构故障 | 舱段裂纹、管线泄漏、门变形 | 封舱/补板/加固 |
| 流程故障 | 交接漏项、签字造假、权限错配 | 复查/上报/追责 |
| 记录故障 | 数字不对、时间对不上、措辞模糊 | 补记/低报/调查 |

> 最后一类最危险：它不直接伤人，但会让所有人误判风险。

## 二、事故等级

【参考】用“段/班/城”三级，而不是简单数字：

| 等级 | 影响 | 记录方式 |
| --- | --- | --- |
| 段级 | 单个舱段/塔位 | 班后补记 |
| 班级 | 一整班/一条防线 | 值班长签字 |
| 城级 | 多环/生命维持 | 议会特别记录 |

- 段级事故最容易被低报；
- 班级事故会被“压缩”成段级；
- 城级事故才会进广播；
- 数字越干净，越可能被处理过。

## 三、低报是怎么发生的

【已裁决 D08】外环事故被系统性低报，只埋线索、不揭开。

【参考】低报不是一个人的阴谋，而是一条“省事链”：

```text
现场：先修，别写
  → 值班长：写“异常”，别写“事故”
  → 档案：归类为“设备波动”
  → 广播：外环事故 0 起
```

### 3.1 低报的常用话术

| 话术 | 真实含义 |
| --- | --- |
| 按惯例处理 | 没按流程，但大家都这样 |
| 已恢复正常 | 暂时压住了，没修根因 |
| 压力波动 | 漏过/停塔/局部失压 |
| 个别设备异常 | 一段防线失效 |
| 无人员伤亡 | 有人受伤但没死，或没记录 |
| 数据待核 | 数字对不上 |

### 3.2 谁会低报

- 想保住班次评级的值班长；
- 怕预算被砍的部门；
- 不想引发恐慌的广播；
- 真的相信“写了也没用”的老员工；
- 被上级暗示“别扩大”的档案员。

> 低报的可怕之处：每个参与者都觉得自己只是“省一点麻烦”。

## 四、故障文化

【参考】

- 故障不是耻辱，**隐瞒故障**才是；
- 但现实中，隐瞒故障的人往往被奖励；
- 老员工会“听声音”判断故障，也会“看数字”判断谁在说谎；
- 新人被教的第一句话是“先保证自己活着”，第二句是“记得写记录”；
- 夜班故障多，所以夜班人更迷信/更有仪式感；
- 故障白板上的擦痕，是城市的历史。

## 五、故障与人的关系

| 故障 | 人的反应 | 玩法接口 |
| --- | --- | --- |
| 塔离线 | 骂一句，复位，继续 | 停塔 2.5s |
| 舱段泄漏 | 先封舱，再救人 | 生存封舱 |
| 传感器漂移 | 不信屏幕，派人去看 | 检查单/巡检 |
| 记录对不上 | 私下问，不公开说 | 档案/低报线索 |
| 故障潮 | 呼叫支援，准备撤离 | 高难波次/生存 |

## 六、仪式与迷信

【参考】

- 交接前敲三下控制台（老习惯，没人记得为什么）；
- 不说“今天很安静”；
- 故障后不庆祝，先补记录；
- 夜班食堂留一个空位给“还没回来的人”；
- 封舱前摸一下门框，表示“我会回来”。

> 这些细节比“设定集”更能让玩家感到这里住过人。

## 七、玩法接口

| 玩法 | 可直接引用 |
| --- | --- |
| 塔防 | 故障反向扩散、停塔、检查单、事故记录 |
| 生存 | 封舱、断氧、低报压力、撤离 |
| 沉浸 | 交接、广播、档案、遗属 |
| 放置 | 设备老化、维修队列、事故链 |
| 叙事 | 低报调查、谁改了数字 |

## 八、待裁决

1. 事故等级的正式名称；
2. 低报是否有“合法”的例外；
3. 广播数字由谁最终审核；
4. 故障是否有超自然解释（建议不要）；
5. 玩家是否能公开揭露低报，代价是什么。
