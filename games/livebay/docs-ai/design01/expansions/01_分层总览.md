# 分层总览：三层怎么咬合

## 一、一张图

```text
L3 城市层（月/版本）
  舱室 · 城市事件 · 职业执照 · 档案
        ↑ 记录/档案/少量备件
L2 岗位层（周）
  塔座模块 · 备件 · 湾民 · 事故链
        ↑ 记录/检查单结果
L1 班次层（分钟）
  检查单 · 故障隔离/旁路 · 事故记录 · 班次合同
        ↑
L0 一班：地图 · 3 塔 · 4 敌 · 5 波
```

关键：**信息向上流动，权力向下克制**。

- 下层产生「记录/档案/备件」，上层用它解锁内容与便利；
- 上层不给下层「必须用的数值门槛」；不用 L2/L3 也能过主线；
- 每层都能单独试玩，避免「必须先玩另一个模式」。

## 二、每层回答一个问题

| 层 | 玩家问题 | 设计回答 | 失败的样子 |
| --- | --- | --- | --- |
| L1 | 这一班怎么过？ | 用检查单、故障处置、记录，让流程有判断 | 弹窗太多，像填表 |
| L2 | 这个岗位怎么变强？ | 用模块、备件、人员，让同一座塔长出不同性格 | 模块太多，像配装游戏 |
| L3 | 你不在时城怎么活？ | 用舱室、事件、档案，让城有连续感 | 收菜日常，逼上线 |

## 三、三层的「硬/软」边界

| 层 | 硬（规则/数据） | 软（表现/文案） |
| --- | --- | --- |
| L1 | 检查单选项、故障时长、记录标记 | 卡片文案、广播、事故报告 |
| L2 | 模块槽位、备件消耗、人员加成上限 | 模块外观、人物语气、安装动画 |
| L3 | 舱室产出上限、事件入口、档案解锁 | 回归报告、城市广播、档案排版 |

> 硬的东西必须可测试、可回放；软的东西可以快速换。

## 四、每层不做什么

### L1 不做

- 不新增塔/敌人/地图；
- 不做随机检查单；
- 不做永久低报惩罚；
- 不做「不选就输」。

### L2 不做

- 不做随机掉落/抽卡；
- 不做三槽以上配装；
- 不做独立备件货币的每日产出；
- 不做人员死亡/永久伤病；
- 不在 L1 未验证前做。

### L3 不做

- 不做全城模拟/政策树；
- 不做每日签到/体力；
- 不做 L3 硬锁主线；
- 不做第二套经济。

## 五、扩展的「最小可行顺序」

```text
1. L1 班次包（N1–N3）        ← 现在
2. L1 班次合同（3 班）        ← 验证记录连续性
3. L2 塔座 2 槽 + 3 模块      ← 验证模块化
4. L2 备件 + 3 湾民           ← 验证轻养成
5. L3 舱室 2 间 + 城市事件 1 个 ← 验证轻城市
6. L3 档案网络               ← 验证跨模式叙事
```

每一步都有「不通过就停」的条件，见 [05](05_版本切片与决策.md)。

## 六、与三玩法的关系

- **塔防**是 L1/L2 的主场；
- **沉浸**是 L1 记录、L2 人物、L3 城市事件的文本来源；
- **放置**是 L3 的舱室与离线报告，不是 L1/L2 的必需资源。

一句话：**塔防负责「这一班」，沉浸负责「这些人」，放置负责「这座城」。**

## 七、判断扩展是否成立

每层做完，只问三个问题：

1. 不玩这一层，原有一班是否仍然完整？
2. 玩这一层，是否多了一个**可解释的选择**，而不是多了一个数字？
3. 这一层是否让「交接班」这个瞬间更成立？

三个都「是」，才进入下一层。
