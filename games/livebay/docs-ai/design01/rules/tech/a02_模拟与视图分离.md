# TECH-A2 · 模拟与视图分离

> **一句话**：`sim.gd` 只算规则，不画东西；`main.gd` 只画东西，不算规则；两者用信号通信。
> **形式化**：`Sim: (State, Input) → State`，`View: State → Render`，`Sim ∩ Draw = ∅`。

## 一、形式化表述

```text
Sim: (State, Input) → State
View: State → Render
Sim ∩ Draw = ∅
View ∩ Rules = ∅
deterministic(Sim, dt) = true

Sim --signal--> View
View --command--> Sim
```

## 二、通俗解释

塔防的规则（敌人移动、塔索敌、伤害、波次、评级）放在一个不依赖窗口的模拟层里；画面（节点、动画、特效、HUD）放在视图层。

好处：

- 可以在无头模式跑测试，几秒验证 5 波；
- 改画面不会改坏数值；
- 同一个模拟可以接不同视图（PC、移动、调试）；
- 回归测试稳定，不靠“看起来对”。

## 三、条款

### MUST

1. **M1**：`sim.gd` 不得引用 `Node2D`、`Control`、`draw_*`、场景树节点或任何渲染 API。
2. **M2**：`main.gd` 不得复制规则（伤害公式、索敌、波次推进、评级）。
3. **M3**：模拟必须可在无窗口环境运行，固定步长可复现。
4. **M4**：视图只读模拟状态，通过信号更新；不得直接改模拟内部字段。
5. **M5**：所有玩法数值从数据加载，不写死在模拟或视图。

### SHOULD

1. **S1**：模拟状态尽量用纯数据（Dictionary/Array），便于快照与测试。
2. **S2**：视图层可以有动画插值，但不得改变模拟结果。
3. **S3**：测试直接驱动 `Sim.step(dt)`，不启动场景。

### MAY

1. **Y1**：可以为调试在视图层显示模拟内部值，但不得写回。
2. **Y2**：可以为演出加“表现时间”，但必须与模拟时间分离。

## 四、判定与验收

```text
valid(sim) ⇔
  no_render_api(sim) ∧
  no_scene_tree(sim) ∧
  deterministic(sim) ∧
  headless_test(sim)
```

检查：

- [ ] `sim.gd` 能否在 `SceneTree` 脚本里跑？
- [ ] 视图层是否复制了伤害/索敌公式？
- [ ] 同一输入序列是否得到同一结果？
- [ ] 动画是否改变了实际命中？

## 五、反例

- 在 `sim.gd` 里 `queue_redraw()`；
- 在 `main.gd` 里重新算“射程内最靠前敌人”；
- 动画播放 0.3 秒，实际伤害在 0.3 秒后才结算；
- 测试需要开窗口才能跑。
