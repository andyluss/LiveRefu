# TECH-A1 · 单一数据源

> **一句话**：数值只在 `numbers/` 写一次，`game/data/*.json` 是导出物；手改 JSON 无效。
> **形式化**：`JSON = Export(N)`，`hand_edit(JSON) ⇒ invalid`，`Check(JSON, N) = true`。

## 一、形式化表述

```text
N = numbers/*.md 的导出表
J = game/data/*.json
J = Export(N)
hand_edit(J) ⇒ invalid
valid(J) ⇔ J = Export(N)

change(N) ⇒ run(export) ∧ run(check) ∧ run(test)
```

## 二、通俗解释

数值只有一个“原文”。Markdown 表格是给人看的原文，JSON 是给游戏读的导出物。两者不一致时，以表格为准。

如果直接在 JSON 里改一个数，下一次导出会覆盖它；更糟的是，文档和游戏会开始各说一套，测试也不知道该信谁。

## 三、条款

### MUST

1. **M1**：数值表格是唯一源；JSON 不得手改。
2. **M2**：`tools/export_numbers.py` 是唯一导出入口；新增数值必须先进表格与 schema。
3. **M3**：每次改数值后跑 `./run.sh numbers-check`，必须返回 0。
4. **M4**：导出脚本必须校验 ID 唯一、引用存在、路径点数量、塔位数量。
5. **M5**：JSON 不得包含表格之外的“隐藏数值”；运行时默认值只能作为缺省，不得覆盖数据。

### SHOULD

1. **S1**：导出文件保持稳定排序与格式，便于 diff。
2. **S2**：在 PR/提交里同时出现“表格改动 + 导出结果”。
3. **S3**：新增字段时先改表格 schema 与 DataLoader 校验。

### MAY

1. **Y1**：临时原型可以硬编码，但不得进入 `game/data/`。
2. **Y2**：可以为导出物加只读标记/说明，但不得改变数据语义。

## 四、判定与验收

```text
consistent ⇔
  export(N) = J ∧
  numbers-check = 0 ∧
  tests = PASS
```

命令：

```bash
python3 tools/export_numbers.py --check
./run.sh test
```

## 五、反例

- 手改 `game/data/towers.json` 把伤害从 10 改成 12；
- 表格加了一座塔，JSON 没导出；
- 代码里写死 `if tower.id == "interceptor": damage = 12`；
- 导出脚本跳过校验，坏数据进运行时。
