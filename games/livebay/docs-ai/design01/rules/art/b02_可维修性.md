# ART-B2 · 可维修性

> **一句话**：每个设备都要让人相信“它能被打开、被修、被替换”；看不见接缝的东西不属于这个世界。
> **形式化**：`Repairable = Seam ∧ Label ∧ Access ∧ Backup`。

## 一、形式化表述

```text
Repairable = Seam ∧ Label ∧ Access ∧ Backup
Seam   = 可见接缝/分模线
Label  = 编号/警示/检修标签
Access = 检修口/面板/梯子
Backup = 冗余回路/备用件/旁路

valid(asset) ⇔ Repairable(asset) = true
```

## 二、通俗解释

NASApunk 的设备不是“魔法盒子”，是**会被修的东西**：

- 有缝：能看到它是几块板拼的；
- 有字：编号、扭矩、警示、上次检修日期；
- 有口：能打开，能伸手进去；
- 有备：坏了有旁路、有备件、有降级运行。

这条规则同时是叙事规则：**能修，才意味着人重要**。如果设备坏了只能换新，人就没有位置。

## 三、条款

### MUST

1. **M1**：所有关键设备必须至少有两项可维修特征（缝/标签/口/备）。
2. **M2**：不得画成完全无缝、无法打开的一体化外壳。
3. **M3**：关键设备必须有编号或检修标签。
4. **M4**：故障场景必须给玩家一个“可操作”的维修动作，而不只是看动画。
5. **M5**：UI 里的设备状态必须能显示“在线/离线/旁路/待修”。

### SHOULD

1. **S1**：用旧胶带、手写标签、替换过的螺丝表达“被修过”。
2. **S2**：重要设备至少有一个备用回路或手动旁路。
3. **S3**：维修动作有声音/灯光/工具反馈。

### MAY

1. **Y1**：可以有“不可修”的一次性件，但必须让玩家感到损失。
2. **Y2**：可以有“修不好的旧设备”，作为叙事道具。

## 四、判定与验收

```text
score(asset) = |{Seam, Label, Access, Backup}|
valid(asset) ⇔ score ≥ 2
```

检查：

- [ ] 这台设备怎么打开？
- [ ] 坏了换哪块？
- [ ] 有没有旁路？
- [ ] 玩家能不能做一个维修动作？

## 五、反例

- 光滑的白色一体机，没有螺丝、没有缝；
- 控制台没有编号，也没有检修口；
- 故障只能看动画，玩家不能操作；
- 设备坏了直接“换新”，没有备件/旁路。
