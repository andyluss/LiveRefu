# ART-C1 · 色板、字体与比例

> **一句话**：颜色是有限的 token，比例是 70/20/10；数据用等宽，标题用无衬线，正文用可读的宋/黑。
> **形式化**：`Palette = Tokens`，`ratio(neutral, structure, accent) = 70:20:10`。

## 一、形式化表述

```text
Palette = {Paper, Cream, Ink, Slate, Teal, Orange, Amber, Sage, Rust}
ratio(neutral, structure, accent) = 70 : 20 : 10
contrast(text, bg) ≥ 4.5 : 1

FontRole = Title → Sans
         | Data  → Mono
         | Body  → Serif/Sans（可读优先）
```

## 二、通俗解释

- **70% 中性**：暖白、米白、纸色——让人待得住；
- **20% 结构**：石墨、深灰、灰绿——设备、边框、文字；
- **10% 强调**：安全橙、琥珀、锈红——只给“需要被看见”的东西。

颜色不是装饰，是层级。橙色多了，警报就不值钱；字体花了，数据就不可信。

## 三、条款

### MUST

1. **M1**：颜色只能从本规则 token 中取；新增颜色需更新本规则。
2. **M2**：橙色/琥珀只用于强调、警报、活动部件，不得大面积铺底。
3. **M3**：正文对比度 ≥ 4.5:1；大字号 ≥ 3:1。
4. **M4**：数据/编号/时间用等宽字体；标题用无衬线；正文不用的装饰字体。
5. **M5**：印刷/截图必须保持浅色可读；不得依赖暗色模式才看得清。

### SHOULD

1. **S1**：每张图/每个页面只保留一个主强调色。
2. **S2**：用留白与线宽分层，不靠更多颜色。
3. **S3**：中文标点用全角；数字与英文用半角。

### MAY

1. **Y1**：可以局部用低饱和噪点/纸纹，但不得影响文字对比度。
2. **Y2**：可以为色盲玩家提供形状/文字冗余，不只靠颜色。

## 四、判定与验收

```text
valid(asset) ⇔
  colors(asset) ⊆ Palette ∧
  ratio ≈ 70/20/10（允许 ±5%） ∧
  contrast ≥ 4.5 ∧
  fontRoles(asset) = true
```

检查：

- [ ] 截图里橙色占比是否超过 10%？
- [ ] 文字在浅色/深色背景都能读吗？
- [ ] 数据是否用等宽？
- [ ] 是否新增了未登记的“高级灰/荧光青”？

## 五、反例

- 整屏青色霓虹 + 橙色标题；
- 用橙色铺满警报面板，导致真正警报不显眼；
- 正文用装饰性手写体；
- 数据用比例字体，数字不对齐；
- 只在暗色模式下可读。
