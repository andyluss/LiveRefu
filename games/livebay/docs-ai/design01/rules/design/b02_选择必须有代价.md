# DES-B2 · 选择必须有代价

> **一句话**：有意义的选择至少有两个选项，每个选项都有代价，且不存在“永远正确”的选项。
> **形式化**：`|Choice| ∈ [2,3]`，`∀o ∈ Choice: cost(o) > 0`，`¬∃o: dominates(o)`。

## 一、形式化表述

```text
Choice = {o₁, …, oₙ}
n ∈ {2, 3}
∀o ∈ Choice: cost(o) > 0
¬∃o ∈ Choice: ∀o' ∈ Choice, utility(o) ≥ utility(o') ∧ cost(o) ≤ cost(o')

Resolution = Choice → Consequence
Consequence = immediate ⊕ delayed
```

## 二、通俗解释

好选择不是“选对的”，而是“选你愿意承担哪一种代价”。

- 按规矩：保护制度，伤害一个人；
- 通融：帮助一个人，累积风险；
- 折中：两边都不满意，但把决定留给下一班。

如果有一个选项“既善良又正确又没代价”，那它不是选择，是按钮。

## 三、条款

### MUST

1. **M1**：关键选择必须有 2–3 个选项，不得只有“接受/拒绝”。
2. **M2**：每个选项至少有一个可见代价（关系、资源、风险、时间、记录）。
3. **M3**：不得存在严格支配选项（某选项全面更优且代价更低）。
4. **M4**：后果必须能被玩家感知：即时反馈或延迟记录，不能“选了等于没选”。
5. **M5**：不得用“隐藏最优解”惩罚玩家；信息可以不全，但不能骗。

### SHOULD

1. **S1**：代价最好落在不同维度：一个伤关系，一个伤资源，一个伤时间。
2. **S2**：允许“没有完美答案”的中间项（如“待复查”）。
3. **S3**：选择后果写进交接记录/湾民档案，跨模式可见。

### MAY

1. **Y1**：可以有“明显更坏”的选项，用于表达角色的道德底线。
2. **Y2**：可以有“暂时看不出后果”的选项，但要在后续兑现。

## 四、判定与验收

```text
valid(choice) ⇔
  n ∈ {2,3} ∧
  ∀o: cost(o) ≠ ∅ ∧
  ¬dominates(any) ∧
  ∃consequence
```

检查：

- [ ] 玩家是否真的犹豫？
- [ ] 每个选项是否都能说出一句“但是……”？
- [ ] 选择后是否留下痕迹？
- [ ] 是否有一个选项明显是“设计师希望我选的”？

## 五、反例

- “救所有人 / 不救”；
- “正确 / 错误”二选一；
- 选完只改一句台词，没有任何状态变化；
- 一个选项给奖励，另一个只给惩罚，没有取舍；
- 用信息差骗玩家选错。
