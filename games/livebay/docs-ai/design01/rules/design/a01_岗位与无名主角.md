# DES-A1 · 岗位与无名主角

> **一句话**：玩家不是天选者，是一个会被排班、轮岗、退休的普通人；每个职业都是「你」。
> **形式化**：`Player = Worker(p)`，`p ∈ Professions`；`name(Player) = ⊥`。

## 一、形式化表述

```text
Player = Worker(p)
p ∈ Professions
name(Player) = ⊥
identity(Player) = {profession, shift, records}
story(Player) = 岗位史，不是英雄史
```

## 二、通俗解释

这个项目的力量来自「普通人视角」。玩家不是来拯救逍遥湾的舰长，而是来值一个班的护理师、护卫兵、采集兵或工程师。

所以：

- 玩家没有固定姓名、固定外貌、固定身世；
- 每个职业都是「你」；
- 情感连接靠「湾民档案 + 交接记录 + 关系」，不靠一段预设的史诗；
- 叙事要往下写：食堂、值班室、交接班，而不是只写议会与阴谋。

## 三、条款

### MUST

1. **M1**：玩家角色不设固定姓名/外观/血统；不得做成“天选者”。
2. **M2**：每个可玩模式必须绑定一个岗位与一个班次。
3. **M3**：职业差异来自岗位流程、设备、风险与叙事，不来自“英雄技能”。
4. **M4**：玩家的成长是“岗位史”（履历、关系、档案），不是“等级碾压”。
5. **M5**：叙事重心在普通劳动，不在王座与预言。

### SHOULD

1. **S1**：用交接记录、排班表、事故报告承载人物关系。
2. **S2**：每个职业至少有一个“只有这个岗位才会遇到”的麻烦。
3. **S3**：让玩家在“照规矩”和“帮一个人”之间犹豫。

### MAY

1. **Y1**：可以有名字的 NPC，但玩家不是他们。
2. **Y2**：可以有“被选拔”的荣光，但必须写清代价。

## 四、判定与验收

```text
valid(mode) ⇔
  mode.profession ≠ ⊥ ∧
  mode.shift ≠ ⊥ ∧
  mode.player.name = ⊥ ∧
  mode.fantasy ≠ “chosen one”
```

检查：

- [ ] 去掉角色名，故事是否仍成立？
- [ ] 这个玩法是否只有这个岗位能做？
- [ ] 玩家的成就感是否来自“把班值好”，而不是“我比别人强”？
- [ ] 是否出现了“只有你能拯救世界”的叙事？

## 五、反例

- 给玩家一个固定名字和宿命，所有职业只是皮肤；
- 玩家是舰长，所有岗位都只是“下令”；
- 等级越高伤害越高，最后变成数值碾压；
- 叙事只写议会阴谋，不写值班室。
