# LiveBay 策划文档集 · design01

## 一、这套文档是什么

这是 LiveBay 的**第一版策划参考集**，按「人类已定的概念 → AI 展开的候选 → 需要人类拍板的问题」三层组织。

它**不是**：
- 不是最终 GDD：没有任何一条 AI 候选自动成为设定；
- 不是工程规格：工程只实现「可逆占位」，见 [12_技术方案](tech/12_技术方案_Godot工程.md)；
- 不是人类原始想法的替代：人类原始想法只在 [`docs-human/概念设定.md`](../../docs-human/概念设定.md)，AI 不改写它。

它**是**：
- 一份把空白处标出来的地图：哪些已定、哪些可选、哪些必须由人决定；
- 截至 2026-11-05，D01–D13、D15、D16 已裁决，P0/P1 已清空；NASApunk 轻量包 N1–N3 已选；E1–E4 已按推荐通过；模块化架构见 [16](tech/16_模块化技术架构_NASApunk.md)，玩法扩展与可插拔架构见 [expansions](expansions/README.md)（已裁决方向）：见 [11](11_待人类裁决清单.md)；
- 一份可以直接拿去拍板的**待裁决清单**：[11_待人类裁决清单](11_待人类裁决清单.md)；
- 一份能让工程先动起来的**最小共识**：把已裁决的方向变成可玩的塔防闭环。

## 二、状态标记（全文通用）

| 标记 | 含义 | 谁能改 |
| --- | --- | --- |
| 【人类已定】 | 来自概念设定，或人类在对话中明确拍板 | 只有人类 |
| 【AI 候选】 | 2–3 个可选方向，附代价；未定 | 人类选，AI 不选 |
| 【AI 建议】 | AI 的倾向与理由；可被推翻，不等于决定 | 人类可采纳/否决 |
| 【待裁决】 | 已登记到 [11](11_待人类裁决清单.md) 的问题 | 人类 |
| 【工程占位】 | 为了让工程能跑而做的临时选择，不是设计定案 | 工程可改 |

> 阅读时请先看标记再看内容。一段没有标记的叙述，默认是**描述性整理**，不是决定。

## 四、AI 的边界（本轮协作约定）

1. **AI 不替人做创意决定**：所有世界观、基调、职业、敌人来源、商业模式，均以候选形式给出；人类不选，就不实现。
2. **AI 不扩写人类原文**：`docs-human/` 只加元数据，不改正文；需要修订时由人类自己改，AI 只在 `docs-ai/` 里提建议。
3. **AI 的工程选择必须可逆**：数据驱动、单一职责、无硬编码剧情；人类改设定时，工程只需改 JSON，不需重写代码。
4. **AI 不伪造证据**：涉及市场、竞品、玩家数据时，标注来源与不确定度；没有数据就写「未知」。
5. **AI 不无限扩张**：每篇文档有明确范围；超出范围的想法进 [11](11_待人类裁决清单.md) 或直接丢弃，不偷偷塞进正文。

## 五、与工程的关系

工程在 [`games/livebay/game/`](../../game/)，当前实现的是「可玩最小闭环」：1 张月牙地图、1 个示例职业、3 种塔、5 波敌人、胜负与结算。它验证的是**手感与结构**，不是设定。按 D02 裁决，首版目标是自然（A）+ 内部（C）双来源，工程已实现 A+C。

工程里的所有内容（职业名、塔名、敌人名、数值）都是【工程占位】，可以在人类拍板后整体替换。替换方式见 [12_技术方案](tech/12_技术方案_Godot工程.md) 的「数据契约」。

1. P0/P1 已清空；D02 的内部故障（C）已落地；
2. 按 D05 的节奏做 **v0.2 护理师**，验证「同引擎换职业」；
