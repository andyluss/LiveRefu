## 一、已定的框架

【人类已定】

- 玩家扮演一个普通人，职业历程大致是：中环普通居民 / 护理师 → 外环卫兵 / 采集兵 → 内环工程师 / 执政官；
- 每种职业都有自己的塔防玩法；
- 工作人员是少数，被选拔，奖励不多，压力大时可退役或轮岗。

## 二、设计原则：一个引擎，多种岗位

【AI 建议】不要把「每个职业」做成「每个新游戏」。更稳的做法是：**同一套塔防引擎，换五件事**。

| 换什么 | 说明 | 例子（护卫兵） |
| --- | --- | --- |
| 防线目标 | 你在保护什么 | 外环第 7 段舱壁 |
| 塔的类型 | 3 种功能位 | 拦截炮 / 脉冲环 / 补给塔 |
| 敌人类型 | 3 种威胁 | 碎片 / 乱流 / 重壳 |
| 资源 | 1 主 + 1 副 | 供能 + 保障度 |
| 失败叙事 | 失败后发生什么 | 舱壁破裂，事故报告 |

这样做的好处：

- 工程只需要一套战斗系统（见 [12](12_技术方案_Godot工程.md)）；
- 每个职业的差异是「数据 + 叙事 + 美术皮」，不是「新代码」；
- 玩家学会一次操作，就能体验多个职业；
- 人类改职业设定时，不需要重写玩法。

## 四、六个职业的展开示例

### 4.1 养生舱护理师（中环，最具项目特色）

- **一班**：巡舱 → 发现异常 → 调配护理站 → 处理突发 → 写交接记录。
- **塔防化**：地图是养生舱的俯视图；「塔」是护理站、缓冲舱、巡检无人机；「敌人」不是怪物，而是**压力波**——沿着舱室蔓延，碰到湾民就降低状态。
- **资源**：「心力」有限，用一次少一次；「保障度」是这一班所有湾民的平均状态。
- **失败**：不是「死人」，而是「有人崩溃，被送进深度恢复」；结算是一份护理报告。
- **核心张力**：你可以把资源集中在一个人身上，也可以平均分配；两种都合理，代价不同。

> 这是最能体现「塔防 = 岗位」的职业，也是最难做的：敌人抽象、反馈不直观。建议作为**第二职业**或**旗舰职业**，不建议作为教学职业。

### 4.2 护卫兵（外环，最稳的教学职业）

- **一班**：接警戒 → 布防 → 拦截 → 修复 → 交接。
- **塔防化**：传统弧形路径；敌人沿外环弧线推进；塔位在弧内侧。
- **资源**：供能（建造/升级）+ 保障度（漏怪扣）。
- **失败**：舱壁破裂，进入事故报告；可以重试。
- **核心张力**：火力覆盖 vs 误伤民用舱段（可选的第二资源）。

> 教学成本最低，玩家一看就懂。缺点是「像别的塔防」，项目特色要靠叙事与美术补。

### 4.3 采集兵（外环，时间压力）

- **一班**：出舱 → 选矿脉 → 布采集臂 → 应对乱流 → 返航。
- **塔防化**：不是「守家」，而是「守采集窗口」；敌人是乱流与时间，不是敌人。
- **资源**：时间（窗口倒计时）+ 氧气。
- **失败**：空手返航，或被迫提前撤离。
- **核心张力**：多采一筐 vs 安全回家。

### 4.4 能源调度员（外环/内环交界，系统玩法）

- **一班**：监控负载 → 切换电路 → 隔离故障 → 恢复供电。
- **塔防化**：电网图，节点是舱段，边是线路；「敌人」是峰值负载与连锁跳闸。
- **资源**：瓦时 + 备用容量。
- **失败**：全城停电，进入应急状态。
- **核心张力**：保核心舱段（医院、养生舱）还是保全城。

### 4.5 工程师（内环，故障链）

- **一班**：接报 → 诊断 → 加固 → 验证 → 交付。
- **塔防化**：系统图，故障像波一样沿连接传播；「塔」是泵、阀、冗余回路。
- **资源**：备件 + 预算。
- **失败**：连锁失效，事故报告。
- **核心张力**：修得快 vs 修得对；临时补丁 vs 彻底更换。

### 4.6 执政官（内环，非传统塔防）

- **一班**：开会 → 听汇报 → 分配预算 → 应对危机 → 广播。
- **塔防化**：地图是「议题/派系/资源」的关系图；「塔」是政策、预算、广播；「敌人」是危机事件与信任流失。
- **资源**：政治资本 + 公信力。
- **失败**：不信任案，提前下台。
- **核心张力**：正确 vs 可接受；短期 vs 长期。

> 这是最冒险的职业：它可能不再是塔防，而是政治模拟。建议作为后期内容，且明确「它是不是塔防」由人类决定。

## 五、成长路径

【AI 候选】每个职业三阶，跨职业可迁移：

| 阶 | 名称 | 玩法变化 | 叙事 |
| --- | --- | --- | --- |
| 1 | 见习 | 教学关，塔种类少，敌人单一 | 刚被选拔 |
| 2 | 正式 | 完整塔种、资源压力、随机事件 | 独立值班 |
| 3 | 带班 | 多目标、手下 NPC、交接责任 | 要为别人的班负责 |

跨职业：

- **转岗**：完成一个职业的「带班」后，可申请转岗；保留部分「湾民档案」加成；
- **退役**：不是失败，转为「顾问」，提供被动加成与剧情；
- **回任**：退役后可回任，但需要重新见习。

> 这套路径的好处是：它把「换工作」变成了玩法循环，而不是重开档。是否采用，建议与 [11](11_待人类裁决清单.md) 的 D04（主角）、D05（第一职业）一起裁决。

## 六、第一职业选谁（D05）

| 候选 | 优点 | 代价 | 适合 |
| --- | --- | --- | --- |
| **A 护卫兵** | 教学成本最低；塔防手感最稳；工程已按此实现 | 项目特色弱；像「又一个塔防」 | 先验证「好不好玩」 |
| **B 护理师** | 最有项目辨识度；最贴合「岗位」主题；情绪强 | 敌人抽象；反馈难做；教学难 | 先验证「主题成不成立」 |
| **C 采集兵** | 时间压力新鲜；外环视觉强 | 不是传统「守家」，玩家可能困惑 | 想要差异化 |
| **D 工程师** | 故障链有策略深度；NASA朋克感强 | 系统复杂，第一版难做 | 想要硬核 |

> 【AI 建议】A 做 v0.1 教学职业，B 做 v0.2 旗舰职业。理由：先用最稳的壳验证手感，再用最有特色的职业验证主题；两者不冲突。
>
> 但这只是建议。如果你认为「第一版就必须是护理师」，工程可以换数据，不需要重写。
