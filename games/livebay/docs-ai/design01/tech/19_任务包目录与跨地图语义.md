# 19 · 任务包目录与跨地图语义

> **一句话**：`mission_pack.json` 是**地图任务包的目录**，不是一张 bay01 的清单。每张地图有自己的 `pack_id`、`map_id`、`version`、`hash`；`default_map` 只是入口提示，不是“所有地图都用这份清单”。

## 一、旧语义的问题

schema 1 的清单只有：

```json
{
  "schema_version": 1,
  "pack_id": "livebay.bay01",
  "hash": "sha256:..."
}
```

它没有 `map_id`，而 `DataLoader.load_mission_pack(base_dir, map_id)` 会把同一个清单无条件挂到 bay02/03 上。结果：

- 地图数据是对的，但 manifest 的 `pack_id`/`hash` 仍是 bay01；
- 跨地图引用看起来“有包”，实际语义不对；
- 测试只覆盖默认 bay01，无法发现错配。

## 二、schema 2：目录结构

```json
{
  "schema_version": 2,
  "catalog_id": "livebay.maps",
  "version": "0.2.0",
  "default_map": "bay01",
  "packs": {
    "bay01": {
      "schema_version": 2,
      "pack_id": "livebay.bay01",
      "map_id": "bay01",
      "version": "0.2.0",
      "hash": "sha256:..."
    },
    "bay02": {
      "schema_version": 2,
      "pack_id": "livebay.bay02",
      "map_id": "bay02",
      "version": "0.2.0",
      "hash": "sha256:..."
    },
    "bay03": {
      "schema_version": 2,
      "pack_id": "livebay.bay03",
      "map_id": "bay03",
      "version": "0.2.0",
      "hash": "sha256:..."
    }
  }
}
```

字段职责：

| 字段 | 职责 |
| --- | --- |
| `schema_version` | 目录结构版本；当前 2 |
| `catalog_id` | 整个地图目录的 id |
| `version` | 目录版本 |
| `default_map` | 首次启动/无参数时的入口地图；不改变其他地图的包 |
| `packs` | 按 `map_id` 索引的包条目 |
| `packs[].pack_id` | 单地图包 id |
| `packs[].map_id` | 必须与键、实际地图一致 |
| `packs[].hash` | 单地图 payload 的内容 hash |
| `packs[].version` | 单地图包版本 |

## 三、Loader 规则

`DataLoader.load_mission_pack(base_dir, map_id)`：

1. 先 `load_game_data` 加载该地图的数据；
2. 读取目录；
3. **按 `map_id` 选择 `packs[map_id]`**；
4. 校验：
   - `packs[map_id].schema_version == 2`；
   - `packs[map_id].map_id == map_id`；
   - `pack_id` 以 `livebay.` 开头；
   - `hash` 以 `sha256:` 开头；
5. 把该条目挂到 `data.pack_manifest`；
6. 额外挂 `data.pack_catalog = {catalog_id, version, default_map}`，便于诊断；
7. 用 `MissionPack.validate()` 再校验地图/波次/阵容/schema/map_id。

失败策略：

- 目录缺当前地图：失败，不静默套 bay01；
- 条目 map_id 不匹配：失败；
- schema 1 旧清单：只允许 bay01，其他地图明确报错；
- 未知 schema：失败。

## 四、默认地图

`default_map` 是**入口提示**，不是全局包：

- `DataLoader.load_mission_pack()` 仍默认 `bay01` 以兼容调用方；
- 调用方切图时必须传 `map_id`；
- HUB/GUIDE/模拟器各自使用对应地图的波次与 manifest；
- `default_map` 只用于“第一次启动看哪张图”和诊断，不参与 pack 选择。

## 五、Hash 的边界

当前 `hash` 是**导出器对单地图 payload 的 canonical JSON hash**：

- Python `export_mission_pack.py` 用 `sort_keys=True` 生成；
- 运行时 `MissionPack.build` 用 `JSON.stringify` 生成，二者不保证字节一致；
- 因此 Loader 校验 hash **格式**与归属，不做运行时内容重算比对；
- 若要做防篡改，应统一 canonical 序列化，或在构建期把 hash 写入并只读校验。

这是已知边界，不是“hash 已完全验证”。

## 六、验收

- `./run.sh pack-check`：目录与三图 payload 一致；
- `./run.sh test`：88 项，包含 bay02/bay03 的 `map_id`/`pack_id` 断言；
- `./run.sh verify`：全量验收；
- 生成：`python3 tools/export_mission_pack.py`。

## 七、不做什么

- 不把三张地图塞进一个“大包”；
- 不让 `default_map` 隐式决定其他地图；
- 不在 Loader 里猜 `map_id`；
- 不在 schema 1 上继续叠字段。
