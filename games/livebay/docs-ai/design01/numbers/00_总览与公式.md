# 数值体系 · 总览与公式

> 这里是 LiveBay v0.1 塔防切片的**数值唯一源**。`game/data/*.json` 由本文档集的表格导出，不要手改 JSON。

## 二、v0.1 目标

- 一局 5 波，含准备/整备约 **5–7 分钟**（1x）；完整版再扩到 8–12 分钟；
- 无塔必败，且在第 2 波内失败；
- 两塔 + 补给 + 一次升级的「标准班」能赢，评级 **B**，保障度约 35–50；
- 四塔以上、合理升级的「熟练班」可到 **A/S**；
- 故障会停塔，但不应让标准班必败；
- 结算评级只依赖保障度，不依赖击杀数，避免刷分。

## 三、单位与取整

| 项 | 约定 |
| --- | --- |
| 坐标 | 屏幕坐标，1280×720，原点左上 |
| 时间 | 秒（s），模拟固定 60 Hz |
| 距离 | 像素（px） |
| 供能 | 整数显示，内部为浮点 |
| 保障度 | 0–100，显示取整，伤害可产生小数 |
| 比例 | 0–1 的小数；文档里 0.7 = 70% |
| 伤害取整 | 不取整；显示时才取整 |
| 退款 | `floor(累计投入 × sell_refund)` |

## 四、核心公式

### 4.1 塔

```text
DPS          = damage × fire_rate
damage(L)    = base_damage × (1 + upgrade_damage_factor × (L - 1))
range(L)     = base_range  × (1 + upgrade_range_factor  × (L - 1))
upgrade_cost = base_cost × upgrade_cost_factor × L
invested(L)  = base_cost + Σ upgrade_cost(1..L-1)
refund       = floor(invested × sell_refund)
```

### 4.2 补给塔

```text
income(L) = base_income × (1 + upgrade_income_factor × (L - 1))
repair(L) = base_repair × (1 + upgrade_repair_factor × (L - 1))
```

补给塔的升级不再是无用升级：每级 +50% 产出与维修。

### 4.3 敌人与覆盖

```text
time_in_range = chord / speed
chord         = 2 × sqrt(range² - offset²)
damage_pass   = DPS × time_in_range
```

`offset` 是塔位到路径的最近距离。当前 7 个塔位都在 76–79 px，覆盖基本等价。

### 4.4 波次预算

```text
wave_hp     = Σ(enemy_hp × count)
wave_reward = Σ(enemy_reward × count)
wave_leak   = Σ(enemy_leak_damage × count)
```

### 4.5 评级

```text
S: integrity ≥ max_integrity × grade_s_ratio (0.9)
A: integrity ≥ max_integrity × grade_a_ratio (0.7)
B: integrity ≥ max_integrity × grade_b_ratio (0.4)
C: integrity > 0
F: 失败
```

## 五、表格与导出

数值表格用 HTML 注释标记：

```markdown
<!-- export: <key> -->
| id | name | ... |
```

导出命令（在 `games/livebay/` 下）：

```bash
python3 tools/export_numbers.py          # 写入 game/data/*.json
python3 tools/export_numbers.py --check  # 只校验表格与 JSON 是否一致
```

导出脚本会校验 ID 唯一、波次引用的敌人存在、路径至少 2 点、塔位至少 1 个。改数值只改表格，然后重跑导出。

## 六、版本约定

- 如果改动影响目标体验，在 [06_难度与评级](06_难度与评级.md) 记录新的实测结果。
