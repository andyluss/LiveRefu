## 一、为什么先读这篇

上一版主线项目的问题是「AI 越做越顺，项目越走越偏」：每个下一步都合理，连起来却离开了最初想做的游戏。根源不是 AI 能力不足，而是**人的意图没有被外化成可执行的边界**。

这套文档用三条规则对抗这种漂移：

1. **所有创意以候选形式出现**，AI 不把「我觉得好」写成「设定如此」；
2. **所有待定问题集中登记**，不散落在正文里，避免「读起来像定了」；
3. **所有工程选择可逆**，人类改主意时不需要重写代码。

## 二、一条创意怎么变成决定

建议用「决策卡」走完五步。每张卡只回答一个问题。

```text
【问题】一句话，必须是可选择的问句。
【选项】A / B / C，各附一句代价。
【AI 建议】选哪个、为什么；必须写明「可被推翻」。
【人的裁决】人类选择一个，或写「再想想」。
【影响】会改动哪些文档、哪些工程数据。
```

流程：

| 步 | 谁做 | 产出 |
| --- | --- | --- |
| 1. 提案 | AI | 在对应文档写候选与代价 |
| 2. 登记 | AI | 在 [11](11_待人类裁决清单.md) 加一行 Dxx |
| 3. 裁决 | 人类 | 在 [11](11_待人类裁决清单.md) 的「裁决记录」写选择与理由 |
| 4. 回写 | AI | 更新正文、删掉落选选项或标注「已否决」、同步工程数据 |
| 5. 复核 | 人类 | 试玩/试读，确认新决定没有破坏原有体验 |

> 关键：**裁决记录只追加，不回删**。将来复盘时，「当时为什么这么选」比「现在是什么」更有价值。

## 四、AI 在什么情况下必须停

出现以下任一情况，AI 不应继续扩写，而应把问题交回人类：

- 需要决定**主题/体验/审美**（例如「这座城市到底好不好」）；
- 需要决定**范围/预算/时间**（例如「做几个职业」）；
- 需要决定**商业模式/平台/发行**；
- 两个候选都自洽，但会导向不同的游戏；
- 现有文档之间出现冲突，且冲突不能靠「以人类原文为准」解决。

停下时，AI 的输出应该是一张决策卡，而不是一篇更长的文档。

## 五、没有裁决时的默认规则

在人类回答之前，AI 可以继续做**不产生创意承诺**的工作：

| 可以做 | 不可以做 |
| --- | --- |
| 工程占位数据、可逆的 UI 骨架 | 写死剧情、角色名、阵营立场 |
| 数值原型与平衡表 | 把某个候选写成「官方设定」 |
| 竞品/资料调研（标注来源） | 编造玩家数据或市场结论 |
| 把问题整理得更清楚 | 用「为了完整性」为由替人选一个 |

工程侧的默认值是「**能跑、能改、能删**」：所有内容走 JSON，职业与关卡是数据，不是代码。

## 六、文档维护规则

1. **一篇文档一个主题**；超过 4000 字就拆，不把世界观、玩法、工程混在一篇。
2. **链接用相对路径**，遵循工作区 [R01](../../../../rules/R01-docs-convention.md) 与 [R03](../../../../rules/R03-link-validation.md)。
3. **日期取系统时间**（东八区），不手写。
4. **裁决后不回删原文**：落选选项保留并标注「已否决（日期）」，保留判断痕迹。
5. **AI 生成的内容必须可识别**：每篇头部有「文档类型 / 来源 / 决策权」元数据。

## 七、这套文档的失败条件

如果出现以下情况，说明这套文档没有起到作用，应停下来重构，而不是继续写：

- 文档越写越多，但人类仍然说不清「这游戏是什么」；
- 每个问题都有「推荐方案」，但没有人真正选过；
- 工程实现了大量内容，但没有一个能被人类试玩判断；
- 人类每次反馈都被 AI 解释成「再加一个系统」。

> 文档的目的是**减少不确定性**，不是**增加产出量**。如果它没有让你更快做决定，它就是失败的。
