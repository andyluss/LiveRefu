- 升级注意：4.x 之间小版本升级可能含 breaking changes，官方提供逐版迁移指南（4.6→4.7、4.7 指南等），量产期不追新、按季评估。

来源：[Godot 官方 Release 博客](https://godotengine.org/blog/release/)、[Godot 4.7 Release 页](https://godotengine.org/releases/4.7/)。

## 三、许可与成本

- **MIT 许可**，引擎本身可自由商用、修改、分发，无版税与授权费（官方 FAQ）。
- 编辑器/运行时导出不需要向引擎方付费；无 Unity 式席位订阅。
- 注意点：遵守引擎与第三方素材各自许可（本项目主美术素材库已按 CC/公有领域收集，与本结论一致）。
- 对 AI 工作室的意义：无授权成本、可读源码、便于团队内做引擎级定制（如图形程序员 A 需要动渲染管线时）。

来源：[Godot FAQ（许可条款）](https://docs.godotengine.org/en/stable/about/faq.html)、[Godot License 页](https://godotengine.org/license/)。

## 四、渲染能力（重点：风格化 / 复古后处理）

### 4.1 三套渲染后端（4.x）

| 后端 | 图形 API | 定位 | 对本项目 |
| --- | --- | --- | --- |
| **Forward+** | Vulkan | 桌面/主机级 3D，光源多、特效全 | 方向 B/C 3D 首选 |
| **Mobile** | Vulkan（移动子集） | 移动/中低端 3D | 未来移动端降级路线 |
| **Compatibility** | OpenGL / WebGL | 2D 与 Web、老硬件兼容 | 方向 A（2D/UI）与 Web 导出可选 |

选哪个渲染器，官方建议按目标平台与 3D 复杂度取舍——[官方文档 Renderers](https://docs.godotengine.org/en/4.4/tutorials/rendering/renderers.html) 有对照。

### 4.2 4.7 与复古视觉直接相关的新能力

1. **HDR 输出支持**（Windows/macOS/iOS/visionOS/Linux Wayland）：自发光屏、霓虹等超亮特效的色域与亮度大幅提升——对"CRT 屏发光、霓虹广告牌、太空星云"这类本作核心意象有直接价值（2D/3D 皆受益）。
2. **3D 最近邻缩放（nearest-neighbor filtering）**：3D 渲染可用最近邻采样做低分辨率像素/低保真风格，性能与双线性相当、不影响 2D——"原子朋克低清风 / PS1 式复古 3D"极契合（官方原文即举例 retro art style）。
3. **`AreaLight3D` 矩形区域光**：真实矩形面光源与柔影，官方示例即"嗡嗡作响的电视屏幕辉光、城市广告牌"——复古场景"屏幕/招牌即光源"的招牌手法可原生实现，无需再靠 emissive+GI 模拟。
4. **DrawableTexture2D**：在纹理上直接绘制的简易 API——可用于"终端内画面、可涂鸦表面"等玩法化表现。
5. Shader 编辑器 **文本 shader 内联实时预览**：图形程序员 A 调 CRT/镀铬/辉光材质时的迭代体验质变。

### 4.3 风格化后处理生态（可参考/引入，需核许可）

- 社区已有现成 CRT 风格后处理（如 `crt_shader_godot`，模拟 CRT 显示）与模块化复古 FX 插件（像素化、抖动 dithering、调色板映射 palette mapping 等）。
- 策略建议：M2 风格切片阶段由**图形程序员 A** 先评估"直接引入社区方案 vs 按主美术方向自研轻量后处理栈"；引入第三方即需过许可与维护性评审，暂不承诺选型。

## 五、2D / UI 能力（方向 A「磁带暖未来」主舞台）

- Godot 2D 是**独立于 3D 的完整 2D 引擎**：像素单位坐标系、2D 光照与阴影、法线贴图、粒子、精灵动画、TileMap 体系完善。
- **UI 系统（Control/Container/Theme）**：可深度主题化与代码自定义——"终端即世界观"（琥珀/绿单色 CRT 面板、扫描线、模拟表盘）的 UI 语言具备原生土壤；4.7 新增 **Control offset transform**（容器内 UI 元素独立位移动画、不破坏布局，官方称利于按钮滑入/缩放动效），对复古"面板弹入、扫描激活"动效友好。
- 字体排印：RichTextLabel 图片随字号自适应等特性已就位；本项目需中文字体回退方案（承接 UI 设计美术 A 的字号规范）。

## 六、3D 能力（方向 B「原子镀铬」/ 方向 C「太空时代」）

- Forward+ 覆盖：SDFGI / VoxelGI / LightmapGI 全局光照、反射、雾效、CSG 建模（4.7 增加 **CSG 自动平滑**）、网格库编辑器（GridMap/MeshLibrary 编辑体验提升）等。
- 风格化 3D（镀铬 PBR 高光、柔光棚拍、轮廓光霓虹）主要靠材质/后处理/光照组合实现——配合 4.2 的 HDR 与面光源利好；**渲染工作量与性能预算归图形程序员 A 承接**（见其 01/02 草案）。
- 规模判断：中低多边形复古场景完全在能力内；高密度动态光源的大场景需按性能预算裁剪。

## 七、脚本语言选择（AI 协作视角）

| 语言 | 优势 | 劣势 | 本工作室倾向 |
| --- | --- | --- | --- |
| **GDScript** | 内置即用；与引擎 API 零摩擦；官方文档/教程/社区示例极多，LLM 语料充足 | 静态分析弱于 C# | **首选**（P0 原型 + 主玩法逻辑） |
| C#/.NET | 类型安全、成熟工具链、大项目组织好 | 需 .NET 版编辑器；导出体积偏大（社区有反馈） | 备选：数值/服务端式模块若复杂再评估 |
| C++/Rust（GDExtension） | 性能极限/自研引擎模块 | 开发慢、绑定成本 | 暂不启用（除图形程序员 A 确需自定义渲染特性时） |

GDScript 与 C# 可在同一项目混用（分场景/脚本），但**初期以 GDScript 单语言为主**，减少心智与构建复杂度。

## 九、风险与注意（主程序视角）

1. **生态规模**：商业资产与专职插件少于 Unity——靠官方 Asset Store（4.7 上线，支持评分/预览放大/后台线程）与开源社区缓解；自研为主、慎引第三方。
2. **版本节奏**：4.x 每 ~4 个月一个大版本；量产期锁定 4.7.x，breaking changes 走官方迁移指南评审后再升。
3. **3D 性能上限**：大场景多光源需图形程序员 A 提前出性能预算（承接其 `02_性能预算与渲染任务清单`）。
4. **中文字体与 UI 高清化**：主题系统灵活但需要 UI 美术 A 定字号/回退规则，防止乱码与低清放大锯齿（工作区 doc 仓库曾有字体兼容乱码教训，见根 README 历史）。
5. **团队熟悉度**：AI 工作室全员对 GDScript 的掌握可通过官方 2D/3D 入门项目快速对齐（官方提供完整示例项目与在线 GDScript 学习）。
