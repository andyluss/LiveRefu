## 一、一句话立场

**M1 需要"两层投入同时落地"：① 磁带频道动效（扫描线+微噪）② 双层光（容器暖光 × 频道色）——二者分属"信号层动效"与"容器层基底"两个不同层，缺一就撑不起"灯下接收机"母意象；M2 三频道滤镜排期为"先磁带建栈、再在共用栈上并行扩展"——磁带于 M1 已定稿，太空/蒸汽波于 M2 各加一个 feature 分支，不做三滤镜并行新工程。**

## 二、M1 渲染投入：要做哪几个 effect、何时切性能

**要做的渲染件（按层）：**

| 渲染件 | 层 | 可关？ | 实现要点 |
| --- | --- | --- | --- |
| 磁带 LUT + 终端边框 + 自发光屏静态纹理 | 基底 | 否 | 频道基底，恒常 |
| 容器层 2D 皮肤（刻度盘/旋钮/网罩/电源灯/天线）+ 暖光径向辉光 | 基底 | 否（暖光常亮属基底） | Way A 分层合成，2D 假辉光，Compatibility 兼容 |
| 中央窗口遮罩（信号层裁剪区） | 结构 | 否 | 隔离"频道色"（信号层窗口区）与"容器暖光"（框架区） |
| 扫描线 + 微噪 | 动效 | 是 | tileable 纹理叠加法（`ColorRect`+`ShaderMaterial`），**不**做屏幕纹理重采样 |
| 暖光呼吸/辉光动态 | 动效 | 是 | 独立子场景，可关（静默可用只关此层，不关暖光常亮） |

**性能切片时机：第一刀就落在 M1 磁带闭环阶段。** 因为 M1 是整个项目里"单频道成本最重"的一点——同时含双层光容器层 + 扫描线 + 微噪，正好用来验证两个工程杠杆：**① 全屏 pass 数量**（合并成单次全屏 pass + 按频道 feature 分支，杜绝多 pass 重复拷贝）；**② tileable 纹理叠加取代屏幕纹理重采样**（扫描线/微噪压到 <0.1 ms）。M1 只做磁带一个频道，对照足、测量干净。正式的"三频道 效果开/关 A/B 报告"放到 M2（呼应 02 草案 §三），但那套杠杆在 M1 已验证。

**预算口径**：单频道后处理 ≈0.5–1.0 ms（双层光加成后 ≈0.6–1.3 ms），仍在 ≤3 ms 预算内、60 FPS 无压力；后台常驻态用"降分辨率 + 降帧 + 暂停粒子"压到可忽略。

## 三、M2 三频道滤镜：先磁带再扩展，非并行；关键决策点

- **推荐"先磁带建栈、再共享扩展"**：磁带（Compatibility/2D）在 M1 已把"单次全屏 pass + 按频道 feature 分支 + 双层光容器遮罩"这套共用框架跑通；太空/蒸汽波在 M2 只在此框架上**加两个 feature 分支**（星雾缓移 / 慢速色偏），共享基底与 pass，不再各起炉灶。三频道滤镜本质是"**一个栈 + 三个 feature 分支**"，不是三个独立工程。
- **不建议并行开发三个滤镜**：并行等于同时维护三套屏幕级采样/三套材质路径，成本倍增，还挤压共享 pass 的合并；且太空/蒸汽波各自的"静默可用静态基底"尚待主美术给视觉样本，并行会被卡住。
- **与主程序的关键决策点——"是否每频道切渲染后端"**：M0 已定"允许每频道切（磁带=Compatibility/2D，太空/蒸汽波=Forward+/3D），M2 前具体定，不阻塞 M1"。我的建议是：
  1. **M1 只用 Compatibility，不涉及切换**；
  2. 真正要切的是 M2——所以**请主程序在 M2 开工前**评估：太空/蒸汽波**是否真需要 Forward+/3D**（3D 景深/真真辉光），还是也可用 **2D/Compatibility** 实现（星雾=UV 滚动+少量粒子、慢色偏=色带映射，两者均为 2D 屏幕/背景级）。
  3. 若能统一 Compatibility/2D → 整包**单后端**、跨频道共用同一 pass 最省；若太空要真 3D/Forward+ → 才引入"每频道切后端"，此时需确认**共用后处理栈是否跨两个后端复用同一 pass**。
  4. **暖光用真 bloom（Forward+ 独占，需 HDR）还是 2D 假辉光（我建议后者，Compatibility 兼容）**——此点直接决定磁带与太空能否统一后端，请主程序一并拍板。

## 四、对其它角色的依赖（M2/材质开工前置）

**主美术（先给，否则我无法收敛 `data/fx_preset.json`）：**
- 容器暖光量化色值/色温：琥珀背光色温、`设备自身暖光` vs `外部台灯` 强度比例、辉光半径。
- 中央窗口区域界定：接收机"中央屏幕/窗口"的尺寸/位置/圆角/遮罩形状——决定信号层裁剪区与容器遮罩边界，影响 `02_` 资源规格与分层命名。
- 三频道动效视觉样本：太空星雾星云色调/密度、蒸汽波慢色偏色带、磁带扫描线密度与微噪强度。
- 静态回退验收基准：「静默可用」各频道静态基准图（GDD §9「静态图 + 音景」）。
- 跨频道同源复用：星雾/慢色偏底图 tileable 是否可共用（影响资产数量与显存）。

**主程序：**
- 执行壳渲染目标（M0 已定 Godot Shader 原生导出）——我按 Godot ShaderLanguage 写，确认无反复。
- **每频道切渲染后端的具体切法**（M2 开工前置，见 §三）：Compatibility vs Forward+ 边界、是否跨后端复用同一 pass、暖光真 bloom vs 2D 假辉光。
- 后台常驻渲染策略：降分辨率/降帧/暂停粒子；全局快捷键唤回是否全量恢复。
- Shader 预编译/预热：切频道前预热，避免切换掉帧（对接加载管线 ≤5 s）。
- 性能档位确认：60/30 FPS 验收 + 后处理总预算 ≤3 ms（我建议认可）。

**UI 设计美术 A：**
- 扫描线/微噪是否覆盖 UI（影响字号/对比度，CRT 磨损文字可读性）。
- 蒸汽波慢色偏是否影响 UI 皮肤可读性与语义色（按钮态/警示色）。
- 各频道"动效关/开"的 UI 层叠约定（对齐 GDD §8.3 计时呈现、§8.8 一句话帮助）。
- 中央窗口遮罩与 UI 骨架的关系（信号层内容区 vs UI 控件占位）。
