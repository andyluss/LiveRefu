**一键验收**：

```bash
cd games/future-debris
./run.sh check       # 7 道闸门（含 16 项玩法行为断言 + 15 项主题断言）
./run.sh theme       # 从 token 编译 Godot 主题并断言生效（15 项）
./run.sh scene       # 场景与视图验收（界面装载 / 几何 / 命中判定 / 取色）
./run.sh shot        # 渲染主界面到 docs/shots/theme_preview.png（并断言渲染底色）
./run.sh s2          # 只跑玩法行为验收
./run.sh sim         # 平衡模拟（--decks 3 --seeds 3）
./run.sh data        # 数据契约校验（--self-test）
./run.sh contrast    # 视觉 token 校验（--self-test）
./run.sh boot        # 只跑工程装载自检
./run.sh run         # 打开占位主界面
./run.sh editor      # 打开 Godot 编辑器

python3 tools/gen_cards.py --target 60   # 卡表量产（幂等；改数值请改 cardgen.seed.json）
```

> 依赖：`godot` 在 PATH（本机为 `/opt/homebrew/bin/godot`，4.7.stable）。无第三方 addon、无联网依赖。

## 四、六道闸门（为什么是这六道）

| # | 闸门 | 拦住什么 | 为什么需要 |
| --- | --- | --- | --- |
| 1 | **文件预算** | 单文件膨胀（core ≤50 / app·view ≤100 代码行） | AI 高产时最典型的失败模式；一年后无法维护 |
| 2 | **数据契约** | 字段缺失、类型错、ID 破规范、ID 重复、枚举外取值、条目数缩水 | 纪元可扩展的前提是**数据表是唯一真相**；契约是数据，不是注释 |
| 3 | **视觉 token** | 对比度不足、层级亮度被压平（颜色达标但分不出主次）、**样张自调色（只能用契约里的色值）** | 对比度是**唯一可纯计算判定**的无障碍维度，该由机器守；**已实测抓出两个真缺陷** |
| 4 | **工程导入** | 脚本解析错误、场景/资源引用失效 | 有些错误只在装载时出现，单元测试看不到 |
| 5 | **无头自检** | 装配接线错误（且**不依赖渲染**，故可在 CI 跑） | 保证"核心逻辑可被机器驱动"，这是后续所有自动化验收的地基 |
| 6 | **玩法行为验收** | 规则被改坏、状态未原子回退、残渣/波次/评级算错、一局不可复跑 | **只断言不变量**（如"必须终止""失败必须完全回退"）；胜负属标定问题，**降级为报告值** |

**两条自我要求**（继承既有教训）：

1. **检查器自己也要被校验**：三个检查器各带 `--self-test` 负向用例（3 + 8 + 6 个）。
2. **反向验证已做过**：数据闸门注入 3 处真实类缺陷被逐条拦下；**对比度闸门实际抓出两个真缺陷**——`--text-faint` 对 `--bg-elev-1` 仅 4.43:1（需 ≥4.5）、`--line-strong` 对 `--bg-elev-2` 仅 2.82:1（需 ≥3，**正是既有项目当年栽过的同一个坑**），修复后才达标；**样张色彩闸门**也已用注入自调灰（`#3C3C3C`）验证会拦。

## 六、硬约束（不要在实现里违反）

1. **核心逻辑不依赖渲染**（否则无法无头验收，AI 也无法高效改玩法）。
2. **数据表是唯一真相**：数值不得硬编码在脚本里；改动必须过数据闸门。
3. **不卖数值、不抽卡**（[`../mainline/docs/04_商业化与收入结构.md`](docs/spec/04_商业化与收入结构.md) 的四条红线）。
4. **第一版必须自洽完整**（Q14 裁决）：纪元包是增量内容，不是补齐手段。
5. **文件预算不放松**：超限时拆分，而不是调高上限。
