# 11 · 内核分层与迁移

> **一句话**：把 `World` 里的时空、主体交互、行为、叙事拆成单向依赖的层；第一阶段只搬家、不改变行为，黄金哈希和事件序列是硬门。

## 一、为什么分层

当前 `world-core` 的 `World` 同时持有：

- tick、时钟、move intent、path、nav、zone bounds
- 实体、背包、门、collider
- schedule、behavior
- flags、quests、dialogue
- rules、ScriptHost、事件队列

`tick_once` 和 `emit` 把命令、移动、日程、任务、脚本副作用串在一个方法里。结果是：

- 空间/交互无法独立测试；
- 新能力只能继续往 `World` 塞字段；
- 事件副作用隐蔽，难以判断一次改动影响了哪一层。

分层不是为了“目录好看”，而是为了三件事：

1. **状态所有权**：每项状态只有一个 owner；
2. **依赖方向**：上层依赖下层，下层不 import 上层；
3. **可验证顺序**：一次 tick 中每层做什么、何时做，写死并有测试。

## 二、层定义

### L0 · 时空物理层

负责：

- 固定 tick、世界时钟、时间缩放
- Zone 边界、Transform、collider
- move intent、path following
- 运动积分、碰撞、阻挡
- 导航网格 A*
- 时空事件：`tick`、`moved`、`blocked`、`zone_activated`

**不知道**：物品、门、任务、对话、日程、规则、脚本。

### L1 · 主体交互层

负责：

- 主体（player/actor/prop/item）的交互语法
- 距离/方向/可交互检查
- 背包、物品转移、拾取
- 门、锁、开关
- 命令：`Interact / Talk / Pickup / OpenDoor / GiveItem`
- 事件：`interacted`、`talked`、`item_acquired`、`door_opened`

**不知道**：任务、旗标、对话文本、日程。

### L2 · 行为/能动层

负责：

- 日程
- NPC 行为选择
- 移动意图/目标
- 可选需求（饥饿、休息、工作）
- 事件：`behavior_changed`、`intent_changed`

**不知道**：任务、对话、社会关系。

### L3 · 叙事/规则层

负责：

- 旗标
- 任务/目标
- 对话图
- 条件/动作
- ScriptHost 事件上下文与脚本命令
- 事件：`flag_changed`、`quest_started`、`quest_completed`、`dialogue_started`

**不直接写** L0/L1 状态；只发命令或调用端口。

### L4 · 社会/关系层（预留）

- 阵营、声望、关系、契约、交易、所有权
- 持久关系图；低频更新
- 通过命令影响 L1/L3

### L5 · 世界演化层（预留）

- 天气、昼夜、经济、生态、人口、补给
- 固定粗粒度 tick 或离屏推进
- 只通过命令/端口改世界

### 非内核平面

- **表现/投影层**：2D/3D、动画、音频、UI；只读 Snapshot/事件。
- **内容/工具平面**：JSON/TS DSL、schema、校验、编辑器；加载期提供定义。
- **Session/玩法模式**：波次、比分、胜负；不进入持久世界内核。

## 三、依赖与 tick

```text
L3 Narrative
   ↓ ports / commands
L2 Agency
   ↓
L1 Subject
   ↓
L0 Spacetime
   ↓
Substrate: EntityId / RNG / serialization / tick

Presentation ── read-only ──▶ Snapshot + Event
Content ── load-time definitions ──▶ Core
```

目标 tick 顺序：

```text
1. CommandRouter
2. L0.step: motion / path / collision / bounds
3. L1.resolve: interaction / inventory / doors
4. L2.update: schedule / behavior / intent
5. L3.observe: flags / quests / dialogue / scripts
6. commit: event_seq / hash
```

**兼容期例外**：Phase 1–4 不重排现有 `tick_once` 语义，只把实现搬到对应层；事件副作用仍保持当前时机。显式 pipeline 只在黄金哈希门通过后引入。

## 四、状态与兼容性

### 4.1 冻结契约

- `Snapshot` 字段顺序
- `state_hash`：港湾 `0x3606a221e9990561`
- 600 tick 事件序列（19 个事件）
- `SaveEnvelope` v1
- C ABI / `world-ffi`
- 现有 14 个内容包行为

### 4.2 内部结构

```text
World (门面 / ABI / tick 调度)
└── CoreState
    ├── Spacetime
    ├── Subjects
    ├── Agency
    ├── Narrative
    └── Systems (预留)
```

`World` 保留现有公开方法；`world-ffi` 不需要知道内部拆层。

### 4.3 快照策略

- `Snapshot` 先作为 v1 兼容 façade。
- 内部层状态不直接改旧 JSON 字段顺序。
- 新层字段只在新的 profile/存档版本启用；现有包不序列化新字段。
- 第一阶段不改 `world-pack` schema。

## 七、风险

| 风险 | 对策 |
| --- | --- |
| 重排 tick 导致哈希变化 | 先搬家不改语义 |
| Snapshot 字段变化 | v1 façade + 黄金门 |
| L3 直接写 L1 | 只允许命令/端口 + import 检查 |
| 过度抽象拖慢 5k | 静态分发、避免每事件分配 |
| 空层 | 每层有独立测试和真实状态 |
| 3D 先行动 | 分层验收后再做旗舰场景 |
