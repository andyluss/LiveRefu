# 08 · 两小时教程：做出「港湾值班室」

> **目标**：一个没写过 Godot/Unity 的人，用 **Web 编辑器 + 预览** 做出一个可玩房间：
> 1 个 NPC、1 段对话、1 个任务、1 扇需要钥匙卡的门，并保存/重载/跑测试。

> **现状**：教程里的功能都已实现；**真实作者计时试用还没做**。所以这里说的是「目标 2 小时」，
> 不是已证实的平均值。遇到工具卡住，把它当工具缺陷记录，而不是「作者再学学」。

## 一、准备（5 分钟）

```bash
cd games/world
npm install                 # 只装 TypeScript（类型检查用）
./worldc editor --port 8788
# 打开 http://127.0.0.1:8788/
```

编辑器打开的是 `data/demo.harbor` 的 **JSON 包**。右上角「打开预览」可以先看成品。

> 两条作者路线二选一：
> - **编辑器路线**：改 JSON 包，适合本教程的拖拽/表单/对话图。
> - **TS 路线**：改 `src/content/demo.harbor/*.ts`，`npm run dev` 编译；两条路线最终编译成同一规范包。
> 不要同时改两边，否则会分叉。

## 二、区域与摆放（15 分钟）

1. 左侧 Canvas 是 `zone.harbor` 的俯视图；网格 2m。
2. 右侧「实体」列出 3 个 placement：值班员、气闸、钥匙卡。
3. 点击「值班员」，拖动到 `(4, -2)` 附近；松手后用「保存摆放」。
4. 点击「气闸」，拖到 `(0, 6)`；「钥匙卡」拖到 `(2, 2)`。
5. 改 X/Z/Yaw 输入框也可以；Shift + 拖动是 0.1m 微调。
6. 拖动气闸后点「烘焙导航」；预览里点击空地，玩家会绕开气闸走 A* 路径。
7. 想看得更沉浸，打开 `demo3d.html`：同一份状态，第三人称/轨道相机；气闸、对话、雨海灯塔都会同步。

**检查**：右侧「摆放」的数字与你想的一致；「已保存」出现。

## 三、角色与日程（15 分钟）

1. 选中值班员；「字段」表单里改 Name 文案、Health、Speed。
2. `Dialogue` 填 `dlg.keeper.intro`，`Schedule` 填 `schedule.keeper`。
3. 点「保存定义」（写 `world/actors/keeper.actor.json`）。
4. 日程在 `schedules/keeper.schedule.json`：06–14 work、14–22 wander、22–06 sleep。
   预览右下角事件里能看到 `schedule_changed`。

> 日程只改变 NPC 的 `behavior` 状态；M1 还没有 NPC 寻路移动。

## 四、物品与门（20 分钟）

1. 选中钥匙卡：`Stack` = 1，Name 用 `loc:item.keycard.name`。
2. 选中气闸：`Locked by` = `item.keycard`，`Verbs` = `interact`。
3. 「保存定义」两次。
4. 预览里点击钥匙卡（或按 `F`）拾取；再到门前按 `E`。

**检查**：背包出现「钥匙卡 ×1」；没有钥匙卡时门提示「气闸锁着」，有钥匙卡时门变绿、显示「已开」。

## 五、规则（20 分钟）

1. 右侧「规则 JSON」选择 `airlock.rule`。
2. 确认结构：

```json
{
  "id": "rule.airlock",
  "on": "interact",
  "target": "demo.airlock",
  "when": [{ "kind": "has_item", "item": "item.keycard" }],
  "then": [
    { "kind": "open_door" },
    { "kind": "play_sound", "id": "sfx.airlock.open" },
    { "kind": "set_flag", "flag": "flag.airlock.open", "value": true },
    { "kind": "emit", "event": "airlock.opened" }
  ],
  "else": [{ "kind": "toast", "text": "loc:airlock.locked" }]
}
```

3. 改 `else` 的文案 key，或加一条 `emit`；「保存规则」。
4. 回到预览验证；看事件日志。

> 规则是「事件 → 条件 → 动作」。作者不需要写引擎节点；`open_door` 会同时改视觉与碰撞。

## 六、对话图（20 分钟）

1. 右侧「对话」选择 `keeper.dlg`。
2. 画布上是节点/边：`greet → shift / end`，`shift → end`。
3. 点击 `greet`，改 text；在选项编辑区每行写 `文案 => 节点`。
4. 「新增节点」会建 `node.N`；「删除节点」不能删 `start`。
5. 「保存对话」。

**检查**：预览里和值班员对话（`T`），选项文案与节点跳转正确。

## 七、任务（15 分钟）

1. 打开 `quests/first_shift.quest.json`（可先用文本编辑器或后续 schema 表单）。
2. 目标：`talk → demo.keeper`、`flag → flag.airlock.open = true`；奖励：`flag.quest.first_shift.done = true`。
3. 预览里完成「说话 + 开门」，任务显示「已完成」。

## 八、测试与构建（15 分钟）

```bash
cd games/world
./worldc bake nav --pack data/demo.harbor
./worldc content-test --pack data/demo.harbor
./worldc test --pack data/demo.harbor \
  --trace data/demo.harbor/tests/m0.trace.json
```

或在编辑器点「构建并试玩」：保存 → `worldc validate/hash` → `worldc build` → 预览自动刷新。

**检查**：

- 6 条内容测试 PASS；
- 600 tick 哈希 `0xc840fe2090a0a085`；
- 预览「回放 M0 trace」显示 PASS。

## 九、你做出了什么

- 1 个区域、1 个 NPC（带日程）、1 扇需要钥匙卡的门、1 个物品、1 段对话、1 个任务；
- 规则、文案、测试都在内容包里，**没有一行引擎代码**；
- 同一内容包可以换宿主（Headless / C ABI / wasm）跑出同一局。

## 十、常见问题

| 现象 | 先看 |
| --- | --- |
| 保存后构建失败 | 编辑器日志里的错误码；服务器会回滚非法保存 |
| 门开了但视觉没变 | 规则里是否有 `open_door`；预览是否刷新 |
| 任务不完成 | `content-test` 的目标 key 是否与规则 flag 一致 |
| 预览 404 | 是否先运行 `./web/build.sh` 或 `./worldc editor` |
| 改 TS 没生效 | 用 `npm run dev`，或在编辑器里从 JSON 包构建 |
