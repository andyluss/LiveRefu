# 03 · 引擎适配与替换

> **一句话**：内核从不调用引擎；适配器只做五件事——收输入、装资产、同步视图、放声音、存字节。
> 五件事都有契约测试；换引擎时，换的是这五件事的实现，不是世界。

## 一、契约总览

```text
┌──────────────────────────── 适配器进程/线程 ────────────────────────────┐
│                                                                        │
│  引擎回调 ──▶ 适配器收集 InputFrame ──▶ world_input()                    │
│  引擎帧   ──▶ 适配器调用 world_tick(frame_dt)                            │
│           ──▶ world_poll_events()  ──▶ 视图/音频/UI/镜头               │
│           ──▶ world_copy_transforms() ──▶ 插值/渲染                     │
│           ──▶ world_save()/world_load_save() ──▶ 平台存储               │
│                                                                        │
│  适配器负责：资产加载、节点池、动画状态机、音频总线、平台文件、坐标转换    │
│  内核负责：世界状态、时间、规则、空间、随机、存档内容、事件顺序            │
└────────────────────────────────────────────────────────────────────────┘
```

**唯一方向**：适配器 → 内核。内核没有回调、没有函数指针、没有引擎句柄。
这条约束换来：任何语言都能接；线程模型简单；崩溃边界清晰；测试可以用假适配器。

## 二、适配器职责矩阵

| 职责 | 适配器 | 内核 | 备注 |
| --- | --- | --- | --- |
| 设备输入轮询 | ✅ | ❌ | 适配器把原始输入变成 `InputFrame` |
| 输入映射/动作 | 部分 | ✅ | 内容定义动作；适配器只报原始键值 |
| 资产加载/卸载 | ✅ | ❌ | 内核只给逻辑资产 ID |
| 节点/视图创建销毁 | ✅ | ❌ | 内核给 `ViewSpec` |
| 变换插值 | ✅ | ❌ | 内核给当前 tick 边界快照；上一 tick 由适配器缓存 |
| 动画状态机 | ✅（表现） | 部分（逻辑状态） | 逻辑状态由内核给；混合/过渡在适配器 |
| 音频播放/混音 | ✅ | ❌ | 内核给音频事件 |
| UI 控件/布局 | ✅ | 部分（UI 模型） | 内核给只读模型 |
| 平台文件/云存档 | ✅ | ❌ | 内核给字节 |
| 世界状态/规则/空间 | ❌ | ✅ | 适配器不得持有玩法状态 |
| 存档序列化 | ❌ | ✅ | 适配器只落盘 |
| 坐标转换 | ✅ | ❌ | 内核用统一坐标 |
| 日志/崩溃上报 | 部分 | ✅（结构化） | 适配器转发 |

**红线**：适配器里出现 `damage`、`quest`、`inventory`、`cooldown`、`wave` 这类玩法词，就是设计错误。
CI 用依赖图 + 关键词扫描做最低限度的拦截，代码评审负责剩下的。

## 三、C ABI

### 3.1 版本握手

```c
#define WORLD_ABI_VERSION 1

typedef struct WorldHandle WorldHandle;

typedef struct {
    uint32_t abi_version;      // 调用方编译时的 ABI 版本
    uint32_t struct_size;      // 结构体大小，便于向后兼容
    const char* user_data_dir; // 平台可写目录
    const char* locale;        // BCP 47，如 zh-CN
    uint32_t flags;            // 调试/严格模式等
} WorldConfig;

WorldHandle* world_create(const WorldConfig* config);
void world_destroy(WorldHandle* world);
```

- `abi_version` 打包为 `(major << 16) | minor`；**主版本必须相等**，且**调用方 minor ≤ 内核 minor**（新内核可跑旧适配器）。
- 主版本不等或调用方 minor 更高 → 返回 `NULL`，原因用 `world_last_error(NULL)` 读取（线程局部）。
- 结构体带 `struct_size`；**同一主版本内**新增字段只能追加，旧调用方传小结构也合法。
- 次版本只允许追加函数/字段；删除/改语义必须升主版本。

### 3.2 函数面

| 函数 | 返回 | 作用 | 频率 |
| --- | --- | --- | --- |
| `world_load_pack(w, bytes, len)` | `WorldStatus` | 加载内容包 | 启动/切换 |
| `world_tick(w, frame_dt_us, &ticks)` | `WorldStatus` | 推进固定 tick | 每渲染帧 |
| `world_input(w, bytes, len)` | `WorldStatus` | 提交输入 | 每帧/事件 |
| `world_submit_physics(w, bytes, len)` | `WorldStatus` | `engine_physics` 模式提交物理结果 | 每 tick（仅该模式） |
| `world_poll_events(w, out, cap, &len)` | `WorldStatus` | 取表现事件 | 每帧 |
| `world_copy_transforms(w, out, cap)` | `size_t` | 取可见实体变换（POD 数组） | 每帧 |
| `world_snapshot(w, out, cap, &len)` | `WorldStatus` | 取完整只读快照（调试/UI） | 按需 |
| `world_command(w, bytes, len, out, cap, &out_len)` | `WorldStatus` | 提交命令并取回结果 | 事件 |
| `world_activate_zone(w, zone_id)` | `WorldStatus` | 请求激活区域（逻辑状态） | 切换区域 |
| `world_deactivate_zone(w, zone_id)` | `WorldStatus` | 请求休眠/卸载区域 | 切换区域 |
| `world_zone_assets(w, zone_id, out, cap, &len)` | `WorldStatus` | 取该区域需要的逻辑资产 ID | 激活前后 |
| `world_zone_status(w, zone_id)` | `ZoneStatus` | 查询区域状态 | 切换区域 |
| `world_set_zone_visible(w, zone_id, visible)` | `WorldStatus` | 区域表现可见性（资产就绪后） | 切换区域 |
| `world_save(w, out, cap, &len)` | `WorldStatus` | 序列化存档 | 按需 |
| `world_load_save(w, bytes, len)` | `WorldStatus` | 读档 | 启动/读档 |
| `world_replay_export(w, out, cap, &len)` | `WorldStatus` | 导出回放字节 | 按需 |
| `world_replay_load(w, bytes, len)` | `WorldStatus` | 载入回放并校验头部 | 回放 |
| `world_state_hash(w)` | `uint64_t` | 状态哈希；`0` 表示错误 | 对账 |
| `world_suspend(w, suspended)` | `WorldStatus` | 暂停/恢复世界时钟 | 按需 |
| `world_set_timescale(w, scale)` | `WorldStatus` | 倍速（只改每秒 tick 数，不改 `dt`） | 设置 |
| `world_last_error(w)` | `const char*` | 最近错误文本；`w` 可为 `NULL` | 出错时 |

**返回值约定**：

- `WorldStatus` 函数用返回码表达成功/失败；需要变长输出时带 `&len`，缓冲不足返回 `1` 且写出所需长度。
- `world_copy_transforms` 返回**需要的数量**：`out=NULL` 或 `cap` 不足时不写、返回所需数量；调用方扩容重试。
- `world_state_hash` 返回 `0` 表示错误（合法哈希强制非 0），详细原因用 `world_last_error`。
- `ZoneStatus` 是枚举：`0 Unloaded`、`1 Dormant`、`2 Activating`、`3 Active`、`4 Faulted`。

```c
typedef struct {
    uint32_t index;
    uint32_t generation;
    float    position[3];
    float    rotation[4];   // x, y, z, w
    float    scale[3];
    uint32_t flags;         // bit0: teleport，bit1: visible
} WorldTransformPod;

size_t world_copy_transforms(WorldHandle* w, WorldTransformPod* out, size_t cap);
```

**为什么给变换开快路径**：60 Hz × 数千实体的位置更新如果每次都走通用序列化，会在 FFI 与编码上浪费大量时间。
变换是 POD，直接按数组拷贝，零解析、零分配。

### 3.3 内存与所有权

| 规则 | 说明 |
| --- | --- |
| 调用方分配缓冲区 | 内核不返回 Rust 分配的数组指针 |
| 两段式取数据 | 先传 `out=NULL, cap=0` 拿所需长度，再分配重试 |
| 句柄唯一 | `WorldHandle` 由 `world_create` 创建，`world_destroy` 释放 |
| 错误字符串 | `world_last_error` 返回的指针在下一次调用前有效；调用方需立即拷贝 |
| 不跨分配器 | 不允许调用方释放内核内存，反之亦然 |
| 输入字节只读一次 | `world_load_pack`/`world_load_save` 的字节只在调用期间有效；内核不保留指针 |
| panic 不跨界 | 每个 `extern "C"` 函数用 `catch_unwind` 包住，转成错误码 |

### 3.4 错误码

| 码 | 含义 | 适配器行为 |
| --- | --- | --- |
| `0` | 成功 | —— |
| `1` | 缓冲区不足 | 扩容重试 |
| `2` | 参数非法 | 记录并中止本帧 |
| `3` | 内容包错误 | 显示加载错误，不进入游戏 |
| `4` | 存档错误 | 提示用户，保留旧存档 |
| `5` | 内核 panic | 上报黑匣子，安全退出 |
| `6` | 版本不匹配 | 提示升级/回退 |
| `7` | 非法状态（未加载包/世界已关闭） | 记录并中止本帧 |
| `8` | 不支持（平台/模式未实现） | 显式禁用对应功能 |

### 3.5 线程

- `WorldHandle` **只在创建它的线程**调用；ABI 不做内部加锁。
- 适配器可以在后台线程加载资产/解码音频；**回到主线程**再调用内核。
- 没有回调，所以不需要 `MonoPInvokeCallback`/GDExtension callable 之类的跨语言函数指针。
- 适配器销毁顺序：停止输入 → `world_destroy` → 释放视图/资产。

### 3.6 多语言接入

「未来可衔接其它语言」不是一句口号，而是四个明确的扩展点：

| 扩展点 | 支持的语言 | 机制 | 何时做 |
| --- | --- | --- | --- |
| **宿主/适配器** | C、C++、C#、Rust、Zig、Go（cgo）、TS/WASM | 版本化 C ABI；每个语言一个薄绑定 | 按目标引擎排期 |
| **脚本宿主** | TS（首发）、Lua、C#、WASM | Rust `ScriptHost` trait；脚本只能命令/查询 | TS 之后按需求 |
| **内容产出** | 任意 | JSON Schema + 规范化包；任何工具都能写包 | 编辑器/外部工具需要时 |
| **绑定生成** | Rust → C/C#/TS/GDScript | 从 schema/IDL 生成，禁止手写两份 | M2 起逐步补齐 |

约束：

- **C ABI 是唯一稳定边界**；各语言的 SDK 只是薄绑定，不在各自语言里重新实现运行时。
- **`world-abi` 只暴露 C ABI 声明与 POD**，不 re-export `world-core` 的类型；Rust 适配器也必须经过它。
- **schema 里不出现 Rust/引擎类型**；只有 POD、字符串、数组、枚举。
- **脚本宿主可换，语义不变**：命令/查询/事件是跨语言的共同词汇；换 Lua 不会改变内容规则的含义。
- **不承诺所有语言同时支持**：先 TS + C ABI，再按真实需求加 C#/Lua/WASM。

## 四、Wire format

内核与适配器之间的字节流（输入、命令、事件、快照）由 schema 定义，编码是可替换的实现细节。

| 阶段 | 编码 | 理由 |
| --- | --- | --- |
| v0 | **JSON**（确定性字段顺序） | 可读、跨语言零成本、调试快；性能不是 M0 的瓶颈 |
| M2 起 | **CBOR**（RFC 8949） | 体积小、确定性编码、各语言库成熟 |
| 快路径 | `WorldTransformPod` 数组 | 变换高频，直接 POD |

**不把编码写进内容契约**：内容包/存档有自己的版本化格式；wire 编码只影响适配器与内核之间的传输。
切换编码时，适配器与内核一起升级，内容包不变。

### 4.1 输入帧

```json
{
  "tick_hint": 12345,
  "actions": [
    { "action": "move", "x": 0.0, "y": 1.0 },
    { "action": "interact", "pressed": true }
  ]
}
```

- 适配器只报「原始动作/轴值」；动作到游戏语义的映射在内容层（`input.map`）。
- 输入带 `tick_hint` 便于回放对齐；内核以自己收到的顺序为准。
- 同一帧内多个设备事件按适配器时间戳排序，再按事件序号兜底。

### 4.2 事件流

```json
{
  "seq": 9042,
  "tick": 12345,
  "kind": "entity.spawn",
  "source": {
    "runtime": { "index": 17, "generation": 3 },
    "content_id": "demo.keeper",
    "persistent_id": "zone.harbor/npc/keeper"
  },
  "payload": {
    "content_id": "demo.keeper",
    "view": "view.actor.humanoid",
    "transform": { "p": [4, 0, -2], "r": [0, 1, 0, 0], "s": [1, 1, 1] }
  }
}
```

- 事件按 `seq` 严格递增；适配器必须**按序**处理，不能乱序应用。
- **内核不丢事件**：单帧事件超过缓冲上限时返回所需长度且**不推进游标**，适配器扩容后重试。
- 适配器在**应用**时可以跳过已被后续变换覆盖的中间更新（表现层合并），但这是适配器的优化，不是内核的丢弃；
  逻辑事件（伤害、任务、物品）不得合并。

### 4.3 schema 即 IDL

多语言接入的前提不是「多写几个 SDK」，而是**一份 schema 生成多语言类型**：

| 文件 | 内容 | 消费者 |
| --- | --- | --- |
| `schema/content.schema.json` | 内容定义（actor/prop/quest/dialogue…） | `worldc`、编辑器、TS 类型、C# 编辑器 |
| `schema/wire.schema.json` | 输入/命令/事件/快照的线格式 | 内核、适配器绑定 |
| `schema/abi.json` | 函数签名、错误码、ABI 版本 | 生成 `world.h` / `world.ts` / `World.cs`；CTS |

规则：

- **单一来源**：Rust 类型与 TS/C# 类型都从 schema 生成或校验；CI 比对生成结果，禁止手写两份。
- **只放 POD/字符串/数组/枚举**：schema 里不出现 Rust 生命周期、trait、引擎类型。
- **版本化**：wire schema 带版本；新增字段可选，删除字段走主版本 + 迁移。
- **生成物可读**：生成的 `.d.ts`/`.cs` 提交或按需生成，但必须能从 schema 复算。

命令/事件是**带标签的联合体**，不是任意 JSON：

```json
{ "op": "command.give_item", "actor": 17, "item": "item.keycard", "count": 1 }
{ "op": "event.door_opened", "door": { "runtime": 42, "content_id": "demo.airlock" } }
```

- `op` 是 schema 里的稳定字符串；未知 `op` 返回 `2`（参数非法），不猜测、不忽略。
- 每个 `op` 的 payload 有生成类型（Rust enum / TS discriminated union / C struct + tag）。
- `world_load_pack` 的字节由调用方持有，**只在调用期间有效**；内核解析/复制后不保留指针。

## 五、表现同步

### 5.1 视图注册表

```text
内核 EntityId ──spawn──▶ 适配器创建/复用 ViewHandle
              ──update──▶ 设置变换/动画参数
              ──despawn──▶ 回收/销毁
```

- 适配器维护 `EntityId -> ViewHandle`；内核不知道 Handle 的存在。
- `ViewSpec` 只给逻辑信息：`view` 类型、资产 ID、初始变换、可选变体。
- 同一 `ContentId` 的多个实例共享资产；状态各自独立。
- 视图创建可以异步（资产未就绪时先挂占位）；事件缓冲到就绪后再应用。

### 5.2 插值

```text
tick N-1 变换 ─┐
               ├─▶ 适配器按 alpha 插值 ──▶ 渲染
tick N   变换 ─┘
alpha = accumulator / dt
```

- `flags.teleport` 为真时跳过插值，直接吸附。
- 旋转用最短弧插值；缩放线性插值。
- 内核不提供「上一 tick 变换」的通用快照；适配器自己缓存上一帧的 POD 数组。

### 5.3 可见性与流式

| 概念 | 谁决定 | 说明 |
| --- | --- | --- |
| 区域激活 | 内容/会话 | 进入区域时请求加载 |
| 区域可见 | 适配器 | 资产就绪后 `world_set_zone_visible` |
| 实体可见 | 内核 | 只对可见区域的实体发表现事件 |
| 视锥剔除 | 适配器 | 内核不做摄像机剔除 |
| 休眠区 | 内核 | 粗粒度模拟，不发表现事件 |

**区域加载握手**（避免「加载时间」污染确定性）：

1. 适配器调用 `world_activate_zone(zone_id)`：内核**立即**完成逻辑激活并返回，不等待资产。
2. 适配器调用 `world_zone_assets(zone_id)` 拿到逻辑资产 ID，开始异步加载。
3. 资产就绪后，适配器调用 `world_set_zone_visible(zone_id, true)`；内核开始发该区域的表现事件。

内核**不读资产加载耗时**，也不因加载慢而暂停世界时钟；需要「加载画面」时，由适配器/会话层决定，
不能改变 tick 与状态哈希。

但「在哪个 tick 激活」本身会影响休眠区的模拟频率，所以：

- `world_activate_zone` 在**录制模式**下必须作为带 tick 的宿主事件写入输入/命令日志；
  回放时按日志里的 tick 重放，而不是按「资产什么时候加载完」重放。
- `world_set_zone_visible` 只影响表现事件，不影响模拟频率，**不记录**。
- 如果做不到这一点，跨宿主一致性就只在「区域固定激活」的测试包里成立，不能推广到真实游戏。

### 5.4 一次性表现

| 事件 | 适配器动作 | 注意 |
| --- | --- | --- |
| `effect.play` | 粒子/贴花/镜头震动 | 不阻塞逻辑；失败可忽略 |
| `audio.play` | 播放音效/音乐 | 同一帧多次播放按序 |
| `animation.trigger` | 触发动画通知 | 只影响表现，不回写逻辑 |
| `ui.patch` | 更新 HUD/面板 | 模型是只读的 |
| `camera.shake` | 镜头效果 | 不影响世界状态 |

### 5.5 UI 的边界（v0 的已知限制）

UI 是「换引擎」最容易被低估的部分。v0 的边界必须说清楚：

| 层 | 谁负责 | 换引擎时 |
| --- | --- | --- |
| UI 数据模型（血量、任务、背包、对话文本） | 内核/套件 | 不变 |
| 声明式布局（HUD 位置、对话框、背包网格） | 内容包（`ui/*.json`） | 不变 |
| 控件实现（按钮、滚动、动画、输入焦点） | 适配器 | 要重写 |
| 复杂自定义 UI（小地图、特殊面板、过场） | 适配器/游戏代码 | 要重写 |

- v0 只承诺：**简单 HUD、对话、背包、任务列表**可以用声明式布局，在多个宿主上表现一致（外观可不同）。
- v0 **不承诺**：任意复杂 UI 都能零成本换引擎。这需要一套跨引擎 UI 工具包，是独立的大工程。
- 如果 UI 是某款游戏的核心差异化（例如复杂建造面板），建议先在目标引擎做，等 UI 层成熟再迁移。

> 这条限制会写进适配器 CTS 与 swap-check 报告：**逻辑状态一致**是硬指标，UI 外观一致不是。

## 六、输入与回放

- 适配器把设备输入采集为 `InputFrame`；内核记录到回放日志。
- 回放时，适配器不读设备，改从回放日志喂 `InputFrame`；其余路径完全一样。
- **`tick_hint` 只是提示**：内核以「输入到达时正在执行的 tick」为准，不按提示回填历史。
  因此跨宿主一致只承诺**逐 tick 输入轨迹**，不承诺「真实墙钟下的同一次点击落在同一个 tick」。
- 回放文件存的是**已量化到 tick 的输入轨迹**；不存原始设备时间戳。
- 输入映射（动作、轴、死区）在内容层定义；适配器只报原始键值/轴值，避免「换引擎后手感变了」。
- 平台差异（键位、手柄布局）由适配器的输入配置处理，不属于玩法。
- 内容层只声明**语义动作 + 默认绑定**（如 `interact` 默认 E/手柄南键）；适配器提供平台设备配置，
  玩家设置可覆盖。作者不需要知道引擎的 Input Action 资源。

```json
{
  "actions": {
    "move":     { "axes": ["wasd", "left_stick"], "deadzone": 0.2 },
    "interact": { "keyboard": ["E"], "gamepad": ["south"] },
    "cancel":   { "keyboard": ["Esc"], "gamepad": ["east"] }
  }
}
```

## 七、资产管线

### 7.1 逻辑资产 ID

内容只引用逻辑 ID，不引用路径：

```json
{
  "mesh.keeper": {
    "role": "mesh",
    "source": "art/keeper.glb",
    "variants": { "lod1": "art/keeper_lod1.glb" }
  },
  "anim.keeper.idle": {
    "role": "animation",
    "source": "art/keeper.glb#Idle"
  },
  "sfx.airlock.open": {
    "role": "sfx",
    "source": "audio/airlock_open.ogg"
  }
}
```

| 角色 | 用途 | 适配器处理 |
| --- | --- | --- |
| `mesh` | 静态/骨骼网格 | 导入、LOD、材质映射 |
| `skeleton` | 骨骼 | 导入 |
| `animation` | 动画片段 | 导入、重定向 |
| `texture` | 贴图 | 压缩、色彩空间 |
| `material` | 材质参数 | 映射到引擎材质 |
| `sfx` / `music` | 音频 | 解码、总线 |
| `ui` | 图标/字体 | 导入 |

### 7.2 每引擎导入配方

导入配方属于**适配器**，不属于内容：

```text
adapters/
├── godot/import.json
├── unity/import.json
├── unreal/import.json
└── web/import.json
```

```json
{
  "mesh": { "importer": "gltf", "scale": 1.0, "generate_lods": true },
  "texture": { "compression": "bc7", "srgb": true },
  "audio": { "format": "ogg", "quality": 0.7 }
}
```

内容作者不需要知道 BC7 还是 ASTC；适配器/平台配置决定。

### 7.3 资产校验

- 每个被引用的逻辑 ID 必须在 `assets.index.json` 中存在；
- 每个 source 文件必须存在且格式受支持；
- 每个角色必须有当前平台可用的变体或回退；
- 禁止内容里出现 `res://`、`Assets/`、`.prefab`、`.uasset` 等引擎路径。

## 八、各引擎适配器

> 版本号为写作时的参考；实际以 M2 的验证矩阵为准。适配器是**可替换件**，不是内核的一部分。

### 8.1 Godot（首个生产适配器）

| 项 | 方案 |
| --- | --- |
| 接入方式 | GDExtension（`godot-rust/gdext`），Rust `cdylib`；**通过 `world-abi` 的 C ABI 调内核，不直接依赖 `world-core`** |
| 驱动 | 一个 `WorldNode`（`Node`）在 `_process` 里 `world_tick` |
| 视图 | `Node3D`/`Node2D` 池；大批量静态物可用 `MultiMesh` |
| 资产 | `ResourceLoader` 加载 glTF/纹理/音频；按逻辑 ID 映射 |
| 输入 | `Input` 单例；映射到 `InputFrame` |
| 音频 | `AudioStreamPlayer`/总线 |
| 存储 | `user://` |
| 坐标 | 内核与 Godot 同为右手 +Y 上 -Z 前，3D 基本零转换；2D 做轴映射 |
| 版本 | gdext 最低 Godot 4.2；运行时 ≥ API 版本（[兼容性说明](https://godot-rust.github.io/book/toolchain/compatibility.html)） |
| 打包 | 桌面可动态链接；移动/主机可静态链接内核，但**仍走 C ABI 头文件**，不直接 `use world_core` |
| 预估 | 基础适配器 1,200–2,000 行（不含资产导入配方） |

**风险**：gdext API 仍在演进，升级 Godot 可能带来编译/行为变化；用固定 Godot 版本 + 适配器 CI 矩阵缓解。
**为什么先做它**：当前主线是 Godot；它是「真实游戏能不能跑」的最短验证路径。

### 8.2 Unity（第二个生产适配器，M3 之后）

| 项 | 方案 |
| --- | --- |
| 接入方式 | C# `MonoBehaviour` + `DllImport` 调原生库；每平台放对应 `.dll`/`.so`/`.dylib`/`.a` |
| 视图 | `GameObject` 池 + `Transform`；静态用 `Graphics.DrawMeshInstanced` |
| 资产 | Addressables 或 `Resources`；逻辑 ID → AssetReference |
| 输入 | Input System（新） |
| 音频 | `AudioSource` |
| 存储 | `Application.persistentDataPath` |
| 坐标 | Unity 左手 +Y 上 +Z 前；位置 z 取反，旋转 `q=(x,y,z,w) → (-x,-y,z,w)`（轴角镜像，不是取共轭） |
| 注意 | IL2CPP 下避免跨边界回调（本设计无回调）；iOS 需静态链接 |
| 预估 | 1,500–2,000 行 C# + 平台打包配置 |

**风险**：IL2CPP/AOT、iOS 静态链接、平台原生库签名；这些是工程问题，不是架构问题。

### 8.3 Unreal（按需）

| 项 | 方案 |
| --- | --- |
| 接入方式 | C++ 模块 + 第三方库（`Build.cs`）；静态链接或动态加载 |
| 驱动 | `UWorldSubsystem` 或自定义 `AActor` |
| 视图 | `UStaticMeshComponent`/`USkeletalMeshComponent` 池 |
| 资产 | `UAssetManager`/软对象路径；逻辑 ID → 资产路径表 |
| 输入 | Enhanced Input |
| 音频 | `UGameplayStatics` |
| 存储 | `SaveGame` |
| 坐标 | Unreal +X 前、+Z 上、厘米；位置 ×100，轴重排 |
| 预估 | 2,000–4,000 行 C++ + 打包配置 |

**判断**：Unreal 的接入成本最高；只有在明确要上 Unreal 项目时才做。不要为了「架构完整」先写它。
它的代码量**刻意超出** 2,000 行基础预算（UE 模块/打包/资产系统更重），这是例外而不是标准。

### 8.4 Web（预览 + Web 发布）

| 项 | 方案 |
| --- | --- |
| 接入方式 | 内核编译为 `wasm32-unknown-unknown`；`wasm-bindgen` 暴露 ABI |
| 视图 | Three.js / WebGL2 / WebGPU（TS） |
| 资产 | `fetch` + 浏览器缓存；glTF 用 `GLTFLoader` |
| 输入 | DOM 键鼠/触屏/手柄 API |
| 音频 | WebAudio |
| 存储 | IndexedDB / OPFS |
| 脚本 | QuickJS 编进 WASM（`rquickjs` 0.14+ 支持 wasm32-unknown-unknown） |
| 坐标 | Three.js 与内核同为右手 +Y 上 -Z 前，基本零转换 |
| 预估 | 1,000–2,000 行 TS/JS + 构建配置 |

**为什么 Web 是第二宿主**：它同时服务「作者预览」与「换引擎证明」，且不需要安装引擎。
**风险**：WASM 体积、内存、移动浏览器性能；用按需加载、资源压缩、对象池缓解。

### 8.5 Bevy（内部工具/测试宿主）

| 项 | 方案 |
| --- | --- |
| 接入方式 | 直接依赖 `world-core`，无 FFI |
| 用途 | 无头测试、工具、未来 Rust 原生游戏 |
| 视图 | `bevy_render`（可选） |
| 优点 | 零 FFI、可调试、可跑 CI |
| 注意 | 不要把 `bevy_ecs` 的类型泄漏到内核公共 API |

### 8.6 Headless（CI/服务器）

| 项 | 方案 |
| --- | --- |
| 接入方式 | 直接链接 `world-core`；`NullHost` |
| 用途 | 黄金回放、性能基准、内容测试、服务器逻辑 |
| 输出 | 状态哈希、事件日志、性能计数 |
| 特点 | 没有渲染/音频/窗口；最快、最稳定 |

**Headless 是第一宿主**：如果内容在无引擎环境下跑不起来，说明内核仍然依赖引擎。

## 九、适配器契约测试（CTS）

所有适配器必须通过同一套测试。CTS 是「可替换」的机器保证，不是文档承诺。

| 组 | 测什么 | 通过标准 |
| --- | --- | --- |
| L 生命周期 | create/load/tick/destroy、重复 destroy、重复 load | 无崩溃、错误码正确、无泄漏 |
| T 时间 | 固定 tick、追帧上限、暂停、倍速 | tick 数与哈希符合预期 |
| I 输入 | 动作映射、多设备、回放输入 | 同输入同结果 |
| E 事件 | 顺序、完整性、缓冲扩容 | 无丢事件、无乱序 |
| V 视图 | spawn/update/despawn、插值、teleport、池化 | 视图与实体一一对应，无悬垂 |
| Z 区域 | 激活/休眠/可见性、流式加载 | 休眠区不发表现事件 |
| A 资产 | 缺失资产、异步加载、卸载、回退 | 占位 + 错误事件，不崩溃 |
| S 存档 | 往返、损坏、版本不匹配、迁移 | 往返哈希一致；损坏明确报错 |
| X 错误 | 非法包、panic 隔离、错误文本 | 不崩溃；错误可读 |
| D 确定性 | 600 tick 黄金回放 | 哈希与事件序列一致 |

### 9.1 CTS 怎么跑

```bash
worldc cts --adapter godot --pack cts.minimal --ticks 600
worldc cts --adapter web   --pack cts.minimal --ticks 600
worldc cts --adapter headless --pack cts.minimal --ticks 600
```

- `cts.minimal` 是专门用于契约测试的小包，覆盖所有事件/组件/区域/存档路径。
- 每个测试输出 `pass/fail/skip` 与诊断；CI 汇总为矩阵。
- 适配器可以 `skip` 平台不支持的能力（如主机上的文件对话框），但必须在清单里声明并计入报告；
  **L/T/E/S/D 五个核心组不可 `skip`**。

### 9.2 反作弊：适配器不能「作弊」

- CTS 会对比**内核状态哈希**，不是截图；适配器无法用「画得像」蒙混。
- 适配器不得直接修改 `WorldTransformPod` 以外的世界状态；变换数组是只读快照。
- 适配器不得缓存并自行推进逻辑 tick；tick 只由 `world_tick` 驱动。

## 十、替换演练（Swap Drill）

### 10.1 目标

同一内容包、同一输入轨迹，在两个宿主上跑出**同一局**：

```bash
worldc swap-check \
  --pack demo.harbor \
  --hosts headless,godot,web \
  --ticks 600 \
  --trace tests/traces/first_shift.trace \
  --report out/swap-report.json
```

### 10.2 输出

```text
host       ticks  final_hash          events  first_divergence  result
headless   600    0x9f3a...c21e       1,842   -                 PASS
godot      600    0x9f3a...c21e       1,842   -                 PASS
web        600    0x9f3a...c21e       1,842   -                 PASS
```

### 10.3 验收

| 项 | 标准 |
| --- | --- |
| 状态哈希 | 所有宿主一致（`arcade` 模式） |
| 事件序列 | 类型、顺序、载荷一致（表现事件可允许适配器差异，但逻辑事件必须一致） |
| 变换 | 可见实体位置/旋转误差 ≤ 1e-4 |
| 存档 | 任一宿主存档，另一宿主可读（同 schema/版本） |
| 渲染 | 截图可不同（美术/后处理），但「同一实体在同一位置」 |
| 性能 | 各宿主达到各自预算（不要求相同） |

### 10.4 失败定位

1. 先比 `final_hash`，不一致则二分 `keyframes` 找首个分歧 tick；
2. 在分歧 tick 对比命令日志、事件序列、组件快照；
3. 常见原因：坐标转换、输入映射、资产缺失导致的占位实体、适配器偷偷改了逻辑状态。

## 十一、降级与失败模式

| 情况 | 行为 | 用户可见 |
| --- | --- | --- |
| 资产缺失 | 占位 + `AssetMissing` | 紫色方块/静音，不崩溃 |
| 音频设备缺失 | 静音，事件照常 | 设置里提示 |
| 存档目录不可写 | 内存存档 + 告警 | 提示「本次无法保存」 |
| 平台不支持某能力 | 适配器声明 + 降级 | 功能禁用，不伪装可用 |
| 适配器崩溃 | 进程分离时内核不受影响；同进程则整体崩溃 | 崩溃上报 + 黑匣子 |
| 版本不匹配 | 拒绝加载，给升级路径 | 明确错误页 |

**原则**：降级必须是**显式的、可观测的**；不要「悄悄降级」，否则作者会以为功能坏了。

## 十二、性能预算

| 指标 | 目标 | 测量 |
| --- | --- | --- |
| 内核 tick P95 | ≤ 2 ms @ 5,000 活跃实体（桌面） | `worldc bench` |
| FFI 每帧开销 | ≤ 50 µs（tick + events + transforms 合计） | 微基准 |
| 变换快路径 | 1,000 可见实体 ≤ 0.2 ms 拷贝 | 微基准 |
| 事件吞吐 | ≥ 10,000 事件/秒不丢 | 压测 |
| 脚本预算 | 软 1 ms / 硬 4 ms 每 tick | 运行时统计 |
| 适配器基础代码 | ≤ 2,000 行（不含资产配方/平台打包；Unreal 例外，见 §8.3） | `tokei`/CI |
| 热重载 | ≤ 2 s（1,000 定义的小包） | `worldc dev` 计时 |
| 存档 | 10 MB 世界 ≤ 100 ms 序列化 | 基准 |

> 这些是**目标值**，M0 先测基线，M2 再按真实游戏调整。不要在没有基准的情况下承诺数字。
> 其中 **50 µs FFI 只适用于 M2+ 的 CBOR/POD 路径**；M0 的 JSON 调试模式不承诺该指标，
> 只记录基线。若 M0 就要求 50 µs，等于提前把编码优化塞进架构验证，得不偿失。

## 十三、安全

| 威胁 | 缓解 |
| --- | --- |
| 恶意 mod 读文件/联网 | 脚本默认无文件/网络能力；能力清单显式授予 |
| 恶意 mod 耗尽 CPU | 脚本预算 + 中断 + 处理器禁用 |
| 恶意 mod 耗尽内存 | QuickJS 内存上限 + 包大小上限 |
| 恶意资产 | 格式白名单、尺寸上限、解码在沙箱/子进程（可选） |
| 存档篡改 | checksum + 可选签名；不把 checksum 当安全边界 |
| 引擎脚本注入 | 内容包不允许携带 GDScript/C#/蓝图；只有数据 + TS（沙箱） |
| 供应链 | 包哈希、来源记录、未来签名；依赖锁定 |

**边界**：v0 的 mod 安全目标是「防手滑与低烈度恶意」，不是「对抗专业攻击者」。真要开放 UGC 平台，
需要 WASM 沙箱 + 进程隔离 + 审计，那是后续阶段。

## 十四、版本矩阵

| 组件 | 版本策略 | 兼容承诺 |
| --- | --- | --- |
| `world-abi` | 主版本 = 破坏性；次版本 = 追加 | ABI 1.x 的适配器可被 1.y 内核加载（y ≥ x） |
| `world-core` | SemVer | 主版本跟随 ABI |
| 内容 schema | 整数 | 不兼容 → 主版本 + 迁移 |
| 适配器 | 跟内核主版本 | 每个适配器声明支持的 ABI 范围 |
| 引擎 | 适配器声明 | Godot 4.2+；Unity/Unreal 版本在 M2/M3 冻结 |

**升级顺序**：内核 → 适配器 → 内容包。内容包永远最后动；能用迁移解决就不改内容。

## 十五、适配器开发清单

新引擎适配器从零到 CTS 通过，按这个清单做：

- [ ] 选定接入方式（原生扩展 / P/Invoke / WASM / 直接链接）
- [ ] 打通 `world_create` → `world_load_pack` → `world_tick` → `world_destroy`
- [ ] 输入采集 → `InputFrame`（至少移动 + 交互）
- [ ] 资产索引解析 + 最小资产加载（一个 mesh + 一个音效）
- [ ] 视图池 + spawn/update/despawn
- [ ] 变换 POD 拷贝 + 插值
- [ ] 事件轮询 + 音频/特效最小映射
- [ ] 区域激活/可见性
- [ ] 存档落盘/读回
- [ ] 坐标转换 + 单位换算
- [ ] 错误处理（版本/包/存档/panic）
