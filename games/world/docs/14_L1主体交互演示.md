# 14 · L1 主体交互室

> **一句话**：只加载 `core + interaction + inventory`，证明拾取、背包、门锁、距离门槛与交互事件不依赖 L2–L5。

入口：

```text
http://127.0.0.1:8787/web/subject.html
```

## 一、内容包

`data/demo.subject/`：

```text
kits: ["core", "interaction", "inventory"]
interaction_range: 6.0
```

内容只有：

- player
- keycard item（`item.subject.keycard`）
- door prop（`locked_by: item.subject.keycard`）
- console prop（`verbs: ["inspect"]`）
- Zone + nav + loc

没有：

- actors / schedules
- rules / quests / dialogue / scripts
- social / systems

## 二、L1 能力

- 拾取：`Pickup` → inventory + `item_acquired` + `entity_despawned`
- 门锁：`Interact` → `locked_by` 检查 → `door_opened`
- 背包：物品堆叠与查询
- 距离门槛：可选 `WorldDef.interaction_range`；旧包省略时保持不限距
- 事件：`interact` / `toast` / `door_opened` / `command_rejected`

## 三、页面

- 显示玩家、钥匙卡、门、控制台、6m 交互圈；
- 右侧操作按钮直接发 `Pickup / Interact`，距离不足时由内核拒绝并显示 `command_rejected`；
- HUD 显示 inventory、door open/locked、距离、tick；
- Independence Check 显示 L2–L5 为空。

## 四、验证

```bash
cd games/world
./web/build.sh
node web/test_l1.cjs
```

断言：

- kits 含 core / interaction / inventory
- actors / rules / quests / dialogue / schedules / scripts 为空
- social / systems 为空
- 远距离开门被拒绝
- 拾取钥匙卡进入背包
- 走到门前后开门成功
- L2–L5 仍为空

## 五、L1 改进

本轮补了可选的 `WorldDef.interaction_range`：

- 旧内容包省略 → `INFINITY`，行为/哈希不变；
- 新内容包可设置 6m 等范围；
- `Interact / Talk / Pickup` 在超距时返回命令错误，不写半状态。

这使“靠近才能交互”成为内核规则，而不是 UI 假装限制。

## 六、边界

L1 仍不做：

- 面向/视野遮挡；
- 交互动画/占用锁；
- 复杂物品容器；
- 对话/任务（属于 L3）。

L2–L5 的内容在包中完全缺失，页面仍能完成拾取与开门，因此 L1 不依赖其上多层。
