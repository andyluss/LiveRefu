# 19 · 分层适配与游戏类型

> **一句话**：RefuWorld 严格说是 **L0–L5 六层**；如果把 L0 视为底座、L1–L5 视为五个玩法层，就是常说的“核心五层”。层不是题材分类，而是**持久状态与核心循环的分类**。

## 一、先厘清：六层，不是五个题材

| 层 | 状态所有权 | 当前实现关键词 |
| --- | --- | --- |
| **L0 时空** | tick、时钟、Zone、Transform、collider、move intent、path、nav | 固定 60Hz、A*、碰撞、边界、动态障碍局部重建 |
| **L1 主体交互** | 背包、物品、门锁、距离门槛、交互事件 | Pickup、Interact、Talk、Door、`interaction_range` |
| **L2 行为/能动** | schedule、behavior、NPC 目标 | 时间窗 → behavior → target → L0 路径 |
| **L3 叙事/规则** | flags、quests、dialogue、rules、script | 分支选择、任务目标、规则动作、ScriptHost |
| **L4 社会/关系** | factions、relationships、reputation | 派系 trust、关系 trust/affinity、社会动作 |
| **L5 世界系统** | weather、solar/wind、battery、water、load、policy | 天气、微电网、水、AI 负载、策略、低量警告 |

关键区分：

- **L0–L5 是内核层**：持有持久状态、可存档、可哈希；
- **表现层**：2D/3D、音频、UI，只读 Snapshot/事件；
- **内容/工具层**：JSON/TS DSL、编辑器、schema；
- **Session/玩法模式**：波次、比分、胜负、战斗结算，不进入持久世界内核。

因此“某层适合什么游戏”，更准确的说法是：

> 这个游戏的**核心循环**是否主要由这一层拥有的状态驱动？

## 二、依赖关系的真实形状

文档的原则是“上层依赖下层”，但实际最小依赖不是一条简单直线：

```text
L0 Spacetime
├── L1 Subject ── L3 Narrative
│                 └── L4 Social
├── L2 Agency
└── L5 Systems
```

- **L5** 只需要 L0：天气/能源/水不依赖主体、行为、叙事或社会；
- **L2** 只需要 L0 的时空与导航；
- **L3** 需要 L1 的 Talk/Interact 作为入口，但不强制 L2；
- **L4** 需要 L1 的 Talk/社会动作入口；
- **L1** 需要 L0；
- **L2/L3/L4/L5 之间没有硬依赖**。

这带来一个很重要的产品判断：

> **可以只启用需要的上层，不必为了一个锁钥玩法引入任务、社会和世界系统。**

## 三、每层适合什么游戏

### L0 · 时空：移动、寻路、碰撞本身是玩法

**适合：**

- 俯视/等距移动原型；
- 寻路、碰撞、空间解谜；
- 潜行、塔防、RTS 单位移动的底座；
- 引擎适配器联调、路径可视化、基准测试。

**适合的游戏类型：**

- 空间解谜；
- 潜行巡逻的移动层；
- 塔防/单位移动；
- 俯视动作的移动与碰撞底座。

**不适合：**

- 平台跳跃：没有重力、跳跃、斜坡；
- 竞速：没有车辆物理；
- 格斗：没有战斗与判定层；
- 可破坏场景：没有刚体/破碎；
- 高保真 VR 物理。

L0 单独通常不是完整游戏，因为没有目标、物品和故事。它适合做“世界的物理事实”，不适合做“玩家的目的”。

### L1 · 主体交互：锁、钥匙、物品与距离

**适合：**

- 密室逃脱；
- 钥匙卡门禁；
- 点击式解谜；
- 轻量盗窃/潜入；
- 物件调查；
- 小型冒险的交互层。

**最小组合：L0 + L1。**

L1 最适合的核心循环是：

```text
移动 → 靠近 → 拾取 → 背包 → 满足门锁 → 开门
```

**不适合：**

- 完整容器/合成/建造；
- 面向/视野遮挡；
- 交互动画/占用锁；
- 复杂物品转移与所有权；
- 需要对话/任务驱动的叙事（属于 L3）。

### L2 · 行为/能动：日程、巡逻与生活节奏

**适合：**

- NPC 作息；
- 警卫巡逻；
- 生活模拟的日常；
- 殖民地居民的基础活动；
- 沉浸式模拟的“人形时刻表”。

**最小组合：L0 + L2。**

L2 当前最准确的关键词不是“AI”，而是：

> **日程驱动的行为编排**

**不适合：**

- 需求/效用驱动的殖民地 AI；
- 记忆、长期计划、群体决策；
- 大规模人群避让；
- 战斗 AI；
- 完整开放世界 NPC。

当前的局部避让/重试是运动层修正，不是完整认知 AI。

### L3 · 叙事/规则：作者写的后果

**适合：**

- 叙事冒险；
- RPG 任务；
- 侦探/悬疑；
- 沉浸式模拟脚本；
- 互动小说/短篇分支；
- 教学/演练场景。

**最小组合：L0 + L1 + L3。**

L3 的强项：

- flags/quests；
- 分支对话；
- 条件规则；
- ScriptHost 延迟命令；
- “玩家做了 A，世界记住并改变 B”。

**不适合：**

- 超长多结局对话树；
- 需要对话历史/回滚的视觉小说；
- 依赖复杂社交状态的对话条件（L4）；
- 依赖天气/经济的叙事（L5）；
- 完整战斗/经济系统。

当前对话是**无状态推进**，node 由客户端携带；做短对话和任务很好，做大型对话树需要先补会话状态。

### L4 · 社会/关系：派系、声望与关系数值

**适合：**

- 派系政治；
- CRPG 声望/阵营；
- 生活模拟关系；
- 殖民地内部矛盾；
- 社交沙盒；
- “同一件事，不同派系反应不同”的内容。

**最小组合：L0 + L1 + L4。**

当前 L4 的核心是**持久社会状态**：

```text
faction trust / relationship trust+affinity / reputation
```

**不适合：**

- 派系外交/条约；
- 群体决策/投票；
- 契约、交易、所有权；
- 大规模社会网络演化；
- 只靠 L4 做完整“社交游戏”。

L4 目前是关系数值层，不是完整政治模拟器。

### L5 · 世界系统：资源约束下的世界演化

**适合：**

- 生存基地；
- 农场/生态模拟；
- 微电网/能源管理；
- 城市/殖民地资源底盘；
- 带天气压力的经营；
- “环境在玩家不操作时也变化”的游戏。

**最小组合：L0 + L5。**

当前 L5 是一条确定性资源模型：

```text
weather → solar/wind → load → battery
water → policy drain / rain
AI → load
policy → load / water
```

**适合的游戏类型：**

- 资源经营；
- 生存；
- 农场/生态；
- 城市管理；
- 控制室/仪表盘式玩法。

**不适合：**

- 高保真能源市场；
- 复杂生态演化；
- 故障链/电网级联；
- 人口/经济/社会联动；
- 把 L5 当完整玩法。

L5 是“世界预算”，不是“玩家目标”；它需要 L1/L3 提供动词和目标。

## 四、按游戏类型选最小栈

| 游戏类型 | 推荐栈 | 主要理由 |
| --- | --- | --- |
| 空间解谜 / 寻路原型 | **L0** | 空间与路径就是核心 |
| 密室逃脱 / 钥匙卡门禁 | **L0 + L1** | 移动、拾取、门锁闭环 |
| 点击式解谜 / 调查 | **L0 + L1 + L3** | 物件交互 + 线索/任务/对话 |
| 俯视潜行 / 巡逻 | **L0 + L1 + L2**，可选 L3 | L2 日程，L1 门锁，L3 目标 |
| 叙事冒险 / 小型 RPG | **L0 + L1 + L3** | 移动、交互、任务、对话齐备 |
| 派系政治 / 社交 RPG | **L0 + L1 + L3 + L4** | 叙事 + 声望/关系/派系 |
| 生活模拟 / 殖民地日常 | **L0 + L1 + L2**，可选 L5 | L2 日程，L1 物品，L5 资源压力 |
| 农场 / 基地 / 生存 | **L0 + L1 + L5**，可选 L2/L3/L4 | L5 资源/天气是核心 |
| 城市/生态管理 | **L0 + L5**，再加 L2/L4 | L5 世界系统是核心，L2/L4 是居民与派系内容 |
| 系统化沉浸式模拟 | **L0–L5 全栈** | 层间交叉反馈才是卖点 |
| 纯视觉小说 | **L3 为主** | 但当前无状态对话/无历史，长分支需先补 L3 |

## 五、不建议使用这套内核的游戏

### 1. 物理驱动游戏

平台跳跃、赛车、格斗、可破坏场景、VR 物理：

- L0 只有 AABB/圆碰撞与简单运动；
- 没有重力、跳跃、关节、刚体、连续碰撞；
- 这些应该放在引擎物理或独立物理层，而不是硬塞进 L0。

### 2. 强实时战斗 / MMO / 完整 RTS

- 内核没有独立战斗层；
- 伤害、命中、波次、比分属于 Session/玩法模式；
- 当前 60Hz 确定性适合“世界层”，不适合作为完整战斗引擎。

### 3. 大世界人群 AI / 完整经济

- L2 是日程行为，不是群体 AI；
- L4 没有派系外交/群体决策；
- L5 是演示级资源模型，不是经济/生态模拟器。

### 4. 超长分支视觉小说

- L3 对话无状态；
- 没有历史、回滚、存档点内对话会话；
- 短篇分支可以，长篇需要先补 L3 对话会话。

### 5. 完整建造/合成沙盒

- L1 没有容器/合成/建造；
- L0 没有体素/地形编辑；
- 这类玩法需要新的主体层能力或独立玩法层。

## 六、当前实现成熟度

这张表用于避免把“架构愿景”误当“已实现能力”：

| 层 | 成熟度 | 已实现 | 仍需补 |
| --- | --- | --- | --- |
| L0 | **稳定底座** | tick、Zone、A*、碰撞、路径、动态 nav | 重力/跳跃/连续碰撞/斜坡 |
| L1 | **可用基础** | 拾取、背包、门锁、距离门槛 | 容器、合成、面向/视野、占用锁 |
| L2 | **日程原型** | schedule → behavior → target → path、局部避让/重试 | 需求、效用、记忆、群体协同 |
| L3 | **较强** | flags、quests、dialogue choice、rules、ScriptHost | 对话会话/历史、分支任务图 |
| L4 | **基础关系** | factions、relationships、reputation、社会动作 | 外交、契约、交易、群体决策 |
| L5 | **演示级系统** | 天气、能源、水、AI 负载、策略、警告 | 季节、故障链、市场、生态、反向反馈 |

## 七、选层方法：四个问题

做新游戏时，按顺序问：

1. **玩家是否直接改变空间？**  
   是 → L0 必须有。

2. **玩家是否通过物品/门/距离改变世界？**  
   是 → 加 L1。

3. **NPC 是否需要按时间/日程行动？**  
   是 → 加 L2。

4. **世界是否需要作者写的目标、对话、规则？**  
   是 → 加 L3。

5. **是否需要持久的派系/关系/声望？**  
   是 → 加 L4。

6. **是否需要天气/能源/水/AI 负载等世界预算？**  
   是 → 加 L5。

每加一层，再问：

> **这层是否拥有新的持久状态？**

如果没有，只是表现或临时玩法，就不该进内核：

- 动画、镜头、音频 → 表现层；
- 波次、比分、胜负 → Session；
- 关卡脚本 → 内容/规则；
- 平衡数值 → 内容/系统配置。

## 八、架构判断

### 强项

- **确定性**：固定 tick、状态哈希、回放、存档；
- **跨引擎**：C ABI / wasm / Godot / headless；
- **层可裁剪**：锁钥游戏不必带任务、社会、能源；
- **内容驱动**：同一套规则换内容与表现；
- **可验证**：每层有独立 Demo 与测试。

### 弱项

- 物理能力有限；
- 没有战斗/经济/群体 AI 等垂直玩法层；
- L4/L5 仍是原型级；
- 对话/任务图还不是完整叙事工具；
- 内容作者需要理解“层”和“状态所有权”。

### 最适合的定位

> **叙事 + 系统的小中型游戏**，尤其是：
>
> - 俯视/等距叙事冒险；
> - 带派系与声望的 CRPG/沉浸式模拟-lite；
> - 农场/基地/殖民地/城市经营；
> - 需要跨引擎、跨表现、可回放的“世界层”项目。

## 九、后续研究问题

1. **L0 物理升级**：是否为平台跳跃加入重力/跳跃/斜坡？还是保持“逻辑空间”并交给独立物理层？
2. **Session/战斗层**：战斗、波次、比分如何与持久世界分离？
3. **L2 认知升级**：需求/效用/记忆/群体规划怎样保持确定性？
4. **L3 对话会话**：对话历史、回滚、多结局图是否进入 Snapshot？
5. **L4 政治层**：派系外交、契约、交易、所有权如何建模？
6. **L5 世界演化**：天气/能源/水如何反向影响 L1–L4，而不破坏层边界？
7. **跨层反馈**：哪些反馈是事件，哪些是命令，哪些是只读快照？
8. **内容成本**：分层内容如何避免作者同时理解六层？
9. **性能**：L2/L4/L5 同时开启时的 5k/多 Zone 预算。
10. **验证方法**：如何用“最小栈 Demo + 层边界测试”持续证明可裁剪性？

---

**结论**：L0–L5 不是“六种游戏类型”，而是**六种持久状态与核心循环**。最适合这套内核的，不是物理或强战斗游戏，而是**叙事、交互、行为、社会与资源系统可以按需组合的小中型世界游戏**。
