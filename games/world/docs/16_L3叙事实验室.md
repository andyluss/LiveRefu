# 16 · L3 叙事实验室

> **一句话**：只加载 L3 的叙事能力，展示“对话分支 → 规则 → 任务 → flags → ScriptHost 延迟命令”，不依赖 L4/L5。

入口：

```text
http://127.0.0.1:8787/web/narrative.html
```

## 一、内容包

`data/demo.narrative/`：

```json
"kits": ["core", "interaction", "inventory", "quest", "dialogue", "script"]
```

内容：

- 档案员 + 分支对话（信任 / 怀疑）
- 记忆碎片 item
- 记忆终端 prop + interact 规则
- `quest.narrative`：talk / acquire / flag 三个目标
- `scripts/narrative.js`：监听 `narrative.terminal_opened`，`ctx.after(2, ...)` 设置脚本 flag

没有：

- schedules（L2）
- social / systems（L4/L5）

## 二、L3 能力链

```text
Talk
  → dialogue_started（带 choices）
  → ChooseDialogue(dialogue, node, choice)
  → dialogue_node / dialogue_ended

Interact terminal
  → Rule: set_flag + toast + emit
  → Quest objective flag
  → ScriptHost onEvent
  → ctx.after(2, commands)
  → flag.narrative.script
```

## 三、本轮补齐

### ChooseDialogue

之前只有 `dialogue_started`，没有推进对话分支的命令。本轮新增：

```json
{"op":"choose_dialogue","dialogue":"dialogue.narrative","node":"intro","choice":0}
```

- 无状态：由客户端携带当前 dialogue/node；
- 服务端校验 dialogue、node、choice；
- 发出 `dialogue_node`；
- 到达 end 节点时发 `dialogue_ended`；
- 可被 trace / content-test / C ABI 命令复用。

同时补充：

- `TraceCommand::ChooseDialogue`
- `PreviewWorld.choose_dialogue`
- runner 的命令标签

## 四、页面

- 画布：档案员、记忆终端、记忆碎片、玩家、交互距离圈；
- 对话气泡：选项按钮直接发 `choose_dialogue`；
- 右侧任务目标：talk / acquire / flag 自动打勾；
- flags 列表与脚本状态；
- 事件日志；
- 独立性检查：L2 `0 schedules`，L4/L5 `absent`。

## 五、验证

```bash
cd games/world
./web/build.sh
node web/test_l3.cjs
```

断言：

- 对话启动并返回两个 choice；
- 选择分支后收到 `dialogue_node` / `dialogue_ended`；
- 拾取碎片、靠近终端、交互规则生效；
- `flag.narrative.terminal`；
- `ctx.after` 两 tick 后 `flag.narrative.script`；
- 任务 completed；
- L4/L5 为空。

## 六、边界

L3 仍不做：

- 对话持久会话（当前由客户端携带 node）；
- 对话历史/回滚；
- 任务分支图/多结局状态机；
- 社会关系带来的对话条件（L4）；
- 世界系统影响叙事（L5）。

L3 依赖 L0/L1 的时空、距离与交互，但不依赖 L2 日程或 L4/L5。
