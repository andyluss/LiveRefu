## 一、评估结论

环境已具备：

- Godot **4.7.stable** 可执行；
- `godot` crate **0.5.6**，提供 `api-4-7`；
- C ABI `world.h` 已有 create/load/tick/command/events/transform/hash/save；
- 现有 Godot 项目（LiveBay 等）可作为后续场景宿主，但 M2 先建独立最小工程。

M2 的关键风险不是 Rust 调 Godot，而是**适配器边界**：不能让 Godot 变成第二权威，也不能让适配器依赖 `world-core`。第一切片先锁定这条边界。

## 三、结构

```text
Godot 4.7 GDScript
      │  WorldNode (GDExtension, godot 0.5.6)
      ▼
godot-extension/  ──只 use──►  world-abi
                                  │ link-world-ffi
                                  ▼
                               world-ffi（C ABI 实现）
                                  ▼
                               world-core（内核）
```

- `godot-extension/src/lib.rs` 不出现 `world_core` / `world_pack` / 玩法规则；
- `world-abi` 只含 C ABI 类型与 `extern "C"` 声明；
- `world-ffi` 是 C ABI 的实现，不是适配器可直接调用的 Rust API。

## 四、复跑

```bash
cd games/world
./godot/test.sh
```

`test.sh` 还会跑 `test/m2_budget.mjs`：适配器行数/边界、pack 体积、CI+GPU 帧预算。`build.sh` 会：

1. 构建 `godot-extension` 的 cdylib；
2. 复制依赖库到 `godot/bin/`；
3. 构建港湾 `pack.data`；
4. 写 `.godot/extension_list.cfg`（避免 Linux headless `--import` 崩溃）；
5. `test.sh` 在 headless 中跑 600 tick 与 save/load。

手动 3D 视图：

```bash
cd games/world
godot --path godot
```

`play.tscn` 是默认场景：WASD 移动、相机跟随；`test.sh` 仍显式跑 `main.tscn` 的哈希/存档对账。
前提：Godot 4.7 在 `PATH`（或 `GODOT_BIN`），Rust stable；macOS/Linux 使用动态库；Windows 需补 `.dll` 打包。
