> 日期：2026-11-04 ｜ 状态：**当前主线** ｜ 项目：`games/livebay/` ｜ 阶段：可玩垂直切片（v0.1）+ NASApunk 轻量包设计

> 一句话：**《逍遥湾》/ LiveBay 是当前主线游戏项目；主线资源、裁决与验收都以它为准。**

## 一、为什么是 LiveBay

LiveBay 是工作区里目前唯一同时具备以下四项的项目：

1. **可玩闭环**：1 张月牙弧地图、7 个塔位、3 种塔、4 种敌人、5 波，能完整走完建造 → 波次 → 结算 → 重试；
2. **可验证工程**：37 项无头断言、数据加载校验、启动检查、数值导出校验，且能无窗口跑；
3. **可持续内容管线**：`numbers/` 表格 → `game/data/` 导出；美术 SVG 程序化；小说/艺术/规则文档已成形；
4. **清楚的创作边界**：D01–D16 已裁决，NASApunk 轻量包 N1–N3 已选，P2/E1–E4 有明确待裁决项。

它不是“最大的项目”，而是**当前最适合承担主线的那一个**。

## 四、当前优先级

### P0 · 把已选的轻量包做出来

按 [14](../../livebay/docs-ai/design01/14_塔防NASApunk深化.md) 实现：

1. 检查单：第 4/5 波前，照签 / 复查 / 照惯例；
2. 第 5 波降级故障：隔离 / 旁路；
3. 事故记录：如实 / 按惯例 / 待复查。

每一步先跑标准班回归：不使用新机制仍应 B / 40。

### P1 · 真人试玩与 v0.2 护理师

- 先做一轮 10–15 人外部试玩，观察“是否理解故障/检查单/记录”；
- 通过后再做护理师 v0.2，验证「同引擎换职业」，不先扩地图/塔。

### P2 · 编辑器只先做 Phase 0

E1–E4 未裁决前，不写编辑器 UI。若选推荐路线，先做 Python bridge / live reload / 校验，不先做视口编辑。

## 五、非目标

- 不新增职业/地图/模式来“撑主线”；
- 不把未来残片、Refu 001 的内容自动并入 LiveBay；
- 不用编辑器替代玩法验证；
- 不因为“主线”就扩成完整游戏；先守住 v0.1 闭环与 v0.2 护理师。

## 六、主线完成的判据

当前阶段（v0.1 → v0.2）的 Done：

```text
1. 轻量包实现并通过回归；
2. 外部试玩能解释“为什么输/为什么赢”；
3. 护理师 v0.2 能用同一套引擎跑通一班；
4. numbers / rules / tests / HTML 四类验收保持全绿；
5. 有一份可公开展示的 3–5 分钟实机。
```
