# 07 · 移动端与界面

> 卡面：用途＝小屏适配与触控规则 ｜ 依赖：[02](02_卡片规则系统.md) ｜ 状态：v0.1 · 2026-09-14

## 一、屏幕与方向

- 首发**竖屏**为主、横屏可选 **【待定：主程序评估后定】**；
- 战场区占屏约 60%，卡牌区占 40%：手牌与卡组一屏可见，减少界面跳转；
- 关键信息三层：卡面（3 个数字 + 1 关键词）→ 长按详情 → 二级说明页。

## 二、手势约定（单手可完成）

| 手势 | 行为 |
| --- | --- |
| 拖拽 | 从手牌拖到槽位＝放置；拖到已有卡＝替换 |
| 长按 | 读取完整卡面（暂停战场） |
| 双击 | 升级 / 触发变体 |
| 上滑 | 回收（返还部分能量） |
| 双指缩放 | 缩放战场（不改变棋盘逻辑） |

禁止依赖三指以上手势与精确小目标；主要触控目标不小于 9mm。

## 三、会话节奏（D5）

- 碎片关 3–5 分钟：一次通勤可打完 2–3 关，随时可退（自动存档）；
- 周常长局：建议在 Wi-Fi/充电场景提示，可在局内保存退出；
- 推送与召回：每日一个"卡片任务"，不做体力惩罚。

## 四、性能与可用性

- 目标机型：中低端安卓与旧款 iPhone；波次单位数设上限（由规则卡控制）；
- 离线可玩 PvE；异步 PvP 需要网络；
- 字号、对比度适配户外光照；色盲友好的卡类色标 + 图标双编码。

## 五、卡片式 UI 的一致性

界面上一切可交互对象都呈现为"卡"：关卡、波次预告、商店外观、成就，均为可拖、可读、可收藏的卡——UI 的卡片化是规则卡片化的自然结果，而非装饰（见 [02](02_卡片规则系统.md)）。
