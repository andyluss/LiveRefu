Delivery pipeline

从文档到可玩，只有一条管线

策划文档是唯一真相，游戏数据是派生物；任何一边改动，脚本都应该立刻发现不一致。

01 / SOURCE
策划卷33 篇设计文档：卡表、数值、地图、故事、美术。
02 / EXTRACT
数据表cards / enemies / maps / waves / challenges / rules / levels。
03 / VERIFY
逐字段对账verify_data.py 把 JSON 拉回文档表格，发现漂移。
04 / ENGINE
Godot 工程core 纯逻辑 → view 只画 → app 界面 → autoload 门面。
05 / GATE
无头验收19 条用例 + 难度模拟器九项 --verify-*。

可复现

所有地图几何、卡表数值、波次预算都能追回源文档；不靠“我记得当时是这样”。

可无头运行

core 不依赖渲染，因此整局可以在 CI 里跑完；截屏、录像、自动玩家共用同一套逻辑。

可回归

改一张卡或一条数值，run.sh check 会同时撞数据对账与玩法断言。

Architecture

四层，不让界面污染规则

core/纯逻辑：战斗域对象、路径、卡组、41 个子系统；不依赖渲染。
data/ · autoload/装载 / 校验 / 查询 / 存档；GameData、AppState、UiFont 作为门面。
view/只画：六个 painter、卡牌控件、色板与控件工厂。
app/界面控制：菜单、关卡、卡组、图鉴、战斗面板与弹窗。

配套约束：核心脚本 ≤50 代码行、界面脚本 ≤100；文件预算由脚本强制，避免“一个大文件长成整个游戏”。
