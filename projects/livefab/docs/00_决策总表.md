## 一、这份方案在回答什么

用户的要求是：

> LiveFab 是一个**将要开始的独立项目**，定位为「**前店后厂、贴近用户**」的在线工作室，
> 综合负责一整个光谱性质的管理——**从前台的运营展示管理、用户沟通管理，到后台的项目开发管理，
> 再到需要分级权限的信息管理**。**现在 LiveFab 还不自研，先考虑整合一些开源项目，
> 到成熟应用后再考虑定制和自研。**

所以本方案要回答的核心问题是：**这一整个光谱，用哪些开源件拼、怎么拼、先拼哪一段。**

## 三、依赖关系（哪些必须先答）

- **L2 是总开关**：选"一站式平台"还是"门户 + 联邦"，后面每个选型都不一样。
- **L3 必须先于 L5/L6/L7**：不先立身份，每接一个系统就多一套账号，**整合的价值会归零**。
- **L4 依赖 L3**：权限模型建在身份之上。
- **L10 依赖 L2/L3/L5/L6**：不定前四个，M1 范围无法冻结。
- ~~L1~~ ✅ 已裁决。

> **已解锁**：L2 已定 → L4–L7 的选型有了框架；L3 已定 → 可以开始立身份。

> **L5b 的由来**：核查 GitHub 指标时意外发现 **Ghost**（MIT、55k stars、自带会员/订阅/Newsletter）。它可能把 A 段从「三件套」简化为「两件」——**但与 L2 的薄门户理念有张力**，因为 Ghost 自带一张前端皮。所以这是一个**真实的取舍**，值得单独裁，而不是由我替你决定。

## 四、本方案刻意不回答的

- **具体域名、服务器采购、备案**——等你定了 L8 再说；
- **财务/合同/人事系统**——你说的"整个光谱"里若含这些，请补一句，我另出一份（当前按"运营展示 / 用户沟通 / 研发管理 / 信息权限"四段理解）；
- **自研定制**——你已明确"到成熟应用后再考虑"，本方案不自研业务功能。
