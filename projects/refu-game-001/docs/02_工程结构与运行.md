## 二、四层结构（为什么这么切）

```
输入/界面  app/*.gd          ← 只做布局、输入、弹窗
   ↓ 读状态 / 调 API
表现       view/*.gd         ← 只画，不改战斗状态
   ↓ 读 Battle
逻辑       core/*.gd         ← 纯逻辑，可在无头环境被脚本驱动
   ↓ 查数据
数据       autoload/game_data.gd + data/*.json
```

这样切的两个直接好处：

1. **可验收**：`core/battle.gd` 不依赖任何场景/贴图，`headless_sim` 能在没有渲染的服务器上跑完整局（[验收与测试](05_验收与测试.md)）；
2. **可换表现**：将来把程序化绘制的塔换成 sprite 图集，只动 `view/battle_view.gd`。

## 三、核心文件地图

重构后共 **128 个 .gd**（每个核心文件 ≤50 代码行、界面 ≤100，由 `./run.sh lint` 强制）。
完整的"想改 X → 去哪个文件"对照表在 **[07 代码地图](07_代码地图.md)**；这里只列最关键的入口：

| 文件 | 职责 | 关键点 |
| --- | --- | --- |
| `scripts/core/battle.gd` | 一局战斗的域对象（生命周期 + 命令） | `_init / start / tick` + `place_card / cast_card / sell_tower / pick_draw / rating`；状态在 `battle/battle_state.gd`，查询门面在 `battle/battle_api.gd` |
| `scripts/core/battle/` | 战斗子系统（41 个文件，按"状态与门面 / 装配与循环 / 流程 / 交战 / 卡片规则 / 查询反馈"六组划分） | 每个文件一个职责，例：`battle_stats.gd` 属性管线、`battle_effects.gd` 钩子解释器、`battle_enemies.gd` 敌人行为 |
| `scripts/core/{tower,enemy,blocker}_state.gd` + `*_unit.gd` | 单位的"状态 / 行为"分离 | 字段搬到 State 基类后，`tw.hp`、`e.distance` 这类字段直达写法一处不用改 |
| `scripts/autoload/game_data.gd`、`app_state.gd` | 数据与全局状态门面 | 只持有 + 转发；实现在 `scripts/data/` 的八个静态类里 |
| `scripts/view/battle/battle_*_painter.gd` | 战场绘制（六个 painter） | 底板路径 / 塔位路障 / 塔 / 敌人 / 弹道伤害场 / 幽灵飘字；只读 `battle_paint_ctx.gd` |
| `scripts/app/battle_screen.gd` + `app/battle/` | 战斗界面装配与面板 | HUD / 手牌 / 波次条 / 底栏 / 输入路由 / 五个弹窗 / 布局与时钟 |
| `scripts/tools/sim/`、`auto_*.gd`、`demo/`、`shot/` | 验收、自动玩家、录像、截图 | 19 条用例、自动玩家启发式、演示时间轴、截图存盘 |

> **文件预算**：核心逻辑 ≤50 代码行、界面 ≤100 代码行（注释与空行不计，物理行兜底）。
> 约定与拆分手法见 [06_文件预算与拆分约定](06_文件预算与拆分约定.md)；超预算会让 `./run.sh check` 直接 FAIL。

## 四、战斗主循环

```
build(15s) ──→ wave ──清空──→ draw(三选一，暂停) ──→ breath(5s) ──→ wave … ──→ won / lost
   ↑ 布防期可放卡              ↑ 能量 +5、on_wave_end 钩子        ↑ 波间也可补卡
```

一个 `tick(1/30)` 内的顺序（顺序本身有语义，别随意调）：

1. 回复能量（`BattleEnergy.regen`：`energy_rate × 挑战卡倍率`，上限 99）；
2. 推进持续修复（`BattleEffectHeal.tick`）；
3. 出兵（`BattleSpawn.tick`）→ 更新"场"（`BattleFields.update`：地形/残留减速/伤害场）；
4. **重算全部塔的最终属性**（`BattleStats.recompute` → `BattleStatsSources` + `BattleStatsAura` 采集八类来源）；
5. 塔选靶并开火（`BattleTowers.update` → `BattleTargeting` / `BattleTowerFire`；不可对空的塔跳过飞行单位）；
6. 弹道飞行与命中结算（`BattleProjectiles.update` → `BattleDamage.apply_hit`：伤害 → `on_hit` → 击杀 → `on_kill` 与返还）；
7. 敌人（`BattleEnemies.update`：先看有没有阻挡单位 → 有则停下交战；没有则边走边打紧邻工事塔并前进；抵达基地则扣血）；
8. 收尾（`BattleCleanup.run`：清理死亡对象、重算人口）+ 羁绊检查（`BattleBonds.check`）。

## 五、怎么跑

```bash
cd projects/refu-game-001/game

./run.sh run       # 开一局
./run.sh editor    # Godot 编辑器
./run.sh check     # 无头验收：先跑文件预算检查，再自动 --import 注册 class_name，最后跑 19 条用例
./run.sh lint      # 只跑文件预算检查（每个 .gd 的代码行是否超预算）
./run.sh import    # 只重新扫描/导入资源
./run.sh shot --scene=res://scenes/battle/battle.tscn --out=/tmp/x.png --autoplay=120 --speed=8
./run.sh demo       # 跑一遍"完整流程演示"（时间轴由 demo_director.gd 驱动）
```

`run.sh` 做了一件容易被忽略但很重要的事：**把 `HOME` 指向工作区内的 `.godot-home/`**。
Godot 会往 `~/Library/Application Support/Godot` 写日志/存档/着色器缓存；指过去之后
既不在真实用户目录留垃圾，也让沙箱与 CI 不需要额外权限。

`run.sh shot` 支持的关键参数：

| 参数 | 作用 |
| --- | --- |
| `--scene=` | 要截的场景（任意 `res://...tscn`） |
| `--out=` | 输出 PNG 绝对路径 |
| `--autoplay=N` | 先用 `AutoPlayer` 自动打 N 秒（游戏内秒）再截图，否则截到的是空战场 |
| `--speed=N` | 自动打时的倍速（1×/2×/4×/8×…） |
| `--frames=` / `--wait=` | 截图前多等几帧 / 几秒（等布局稳定） |

> macOS 的 `screencapture` 需要"屏幕录制"权限，命令行里通常拿不到；
> 本工程的截图走**引擎内 `get_viewport().get_texture()`**，不依赖系统权限，也无头环境外可无人值守。

## 六、性能与已知限制

- 单场规模：塔 ≤ 20、敌人同时 ≤ 20、弹道 ≤ 60，30Hz 逻辑帧，帧内开销可忽略；实测 8× 倍速无掉帧；
- 战场用 `_draw()` 逐帧重绘（无节点树开销），地图底图是一张 1200×809 的 PNG；
- 已知限制：无音效；无粒子；塔/敌用几何体绘制；环形路径（MAP-AST-01）已支持几何但 M1 未使用；
- 退出时会报 `ObjectDB instances were leaked at exit`——RefCounted 之间的循环引用（`Battle` ↔ 单位字典），
  只在进程退出时出现，不影响游戏内内存增长；M2 若做长局存档会改成弱引用。
