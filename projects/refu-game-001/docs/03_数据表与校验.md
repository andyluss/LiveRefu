# 03 · 数据表与校验

> 卡面：用途＝"策划文档 → 游戏数据"的单向管线与对账机制 ｜ 依赖：[`doc/refu-game-001/`](../../../doc/refu-game-001/README.md) ｜ 状态：v1.0 · 2026-09-16
> 原则：**策划文档是唯一真相，游戏数据是派生物**。任何一方改动，都由脚本立刻发现不一致。

## 一、管线总览

```
doc/refu-game-001/                     projects/refu-game-001/
  美术/全量出图/卡面|地图|单位/*.png  ──sync_assets.py──→  game/assets/**/*.png
  美术/全量出图/地图/*.svg           ──extract_map_data.py─→ game/data/maps.json
  14/15/16 卡表 + 数值/01–05 文档    ──（人工录入 + verify_data.py 对账）─→ game/data/*.json
```

三条脚本各管一段，全部**幂等**，可随时重跑：

| 脚本 | 方向 | 幂等策略 |
| --- | --- | --- |
| `tools/sync_assets.py` | 美术出图 → 工程资源 | 按 SHA256 比对，内容不同才覆盖；`--check` 只校验不写 |
| `tools/extract_map_data.py` | 地图卡 SVG → `maps.json` | 每次从 SVG 重新解析并整体覆盖；`--check` 校验一致 |
| `tools/verify_data.py` | 策划文档 ↔ `game/data/*.json` | 解析文档表格逐字段比对，输出 PASS/FAIL/WARN |

## 三、交叉校验（`tools/verify_data.py`）

```
$ cd projects/refu-game-001 && python3 tools/verify_data.py
✅ 卡表.铁砧 12 卡：12 张逐字段比对
✅ 羁绊.三条：火力网 / 加固阵列 / 后勤链
✅ 敌人.6 原型：生命/攻击/攻速/移速/护甲/威胁值 逐字段比对
✅ 波次.WAV-ANV-A：6 波构成 + 威胁值，合计 B=158（= B_ref）
✅ 挑战卡.5 张 + 双流白名单：等级/难度分/掉落/评级 逐字段比对；6 图双入口标志与白名单一致
⚠️  地图.MAP-AST-01.standard：出图画了 8 个标准位，19 号卡表写 10 个；M1 未使用该图，已记录待美术/策划对齐
✅ 地图.6 张：塔位数量 / 入口数 / 双入口标志 逐字段比对
✅ 规则卡.RUL-BASE + 能量曲线：基地生命 20 / 起始能量 10 / +1·s⁻¹ / 上限 99 / 波间 +5

数据校验：PASS（通过 7 项，失败 0 项，已知偏差 1 项）
```

- **FAIL**：JSON 与文档数值不一致 → 必须改 JSON（或按策划裁决改文档）；
- **WARN**：登记在 `KNOWN_ART_DEVIATIONS` 里的**已知偏差**（当前只有 MAP-AST-01 塔位数），
  每次校验都会提醒，但不会挡住构建——这是"发现问题但不擅自替策划做决定"的处理方式。

## 四、卡的数据结构（对齐 doc 02 的三层九字段）

```jsonc
{
  "id": "ANV-T01", "name": "模块炮塔", "cost": 20, "keyword": "弹药",
  "icon": "res://assets/cards/ANV-T01_模块炮塔.png",
  "effect_line": "伤害 12 / 攻速 1.0/s / 射程中",
  "face_stats": [["伤害","12"],["攻速","1.0"],["射程","中"]],   // 卡面层：小屏只显示这 3 个数字
  "type": "tower", "slot": "standard", "tags": ["弹药"],        // 规则层
  "stats": { "damage": 12, "attack_speed": 1.0, "range": 3.0,
             "splash": 0.0, "pierce": 0, "targets_air": true, "max_hp": 0 },
  "hooks": { "on_kill": [{"op": "energy", "value": 1}] },        // 事件钩子
  "faction": "ANV", "sub_faction": null, "flavor": "…",          // 叙事层（可整块替换）
  "source": "14 号卡表 / 数值 01"
}
```

### 钩子/效果 DSL（`cards.json` 的 `_hook_ops` 有完整清单）

| op | 语义 | 铁砧用例 |
| --- | --- | --- |
| `energy` | 立刻获得能量 | T01 `on_kill` +1 |
| `stat_buff` | 给某范围的塔加百分比（可带 `cap`/`max_stacks`） | T02 `on_hit` 攻速 +2%/次、上限 +10% |
| `pierce_bonus` | 穿透数 +N（上限） | T03 `on_kill` 穿透 +1、上限 5 |
| `heal` | 修复（即时 / 每秒 / 按最大生命百分比） | M01 修复 8/s 持续 6s；羁绊"后勤链"5% |
| `shield` | 护盾 | S02 护盾 80 / 10s |
| `aura` | 常驻光环（被动） | M02 同标签塔攻速 +10% |
| `slow_field` | 减速场（被动或残留） | T04 −30%；M03 到期残留 −20%/3s |
| `global_buff` | 全场限时增益 | S01 全场攻速 +40% / 6s |
| `add_tag` | 为塔附加标签（可带选项） | X03 附加「弹药」或「工事」 |
| `trigger` | 链式触发另一个钩子事件 | X03 `on_attach` 触发一次 `on_deploy` |
| `damage_field` / `summon` / `corrosion` / `resonance` | 伤害场 / 召唤 / 腐蚀 / 共鸣计数 | 涌潮与星辉用（M1 已实现解释器，未放数据） |

**数值块独立**（doc 02 五律之四）：改任何一张卡只改它自己的 `stats`/`hooks`，不影响其他卡；
所有属性修正都在 `battle.gd::_recompute_tower_stats()` 里按来源叠加，删掉任一来源不会让别的来源算错（remove-safe）。

## 五、改数据的标准流程

1. 先改策划文档（或确认以文档为准）；
2. 改 `game/data/*.json`；
3. `python3 tools/verify_data.py` → 必须 PASS（WARN 允许，但要看一眼）；
4. `game/run.sh check` → 19 项验收必须 PASS；
5. 数值有实质变化时，把实测结论写进 [调参与实测发现](04_调参与实测发现.md) 并记账到 `CHANGELOG.md`。

> 改美术出图后：`python3 tools/sync_assets.py`；改地图布局（SVG）后：`python3 tools/extract_map_data.py --write`。
