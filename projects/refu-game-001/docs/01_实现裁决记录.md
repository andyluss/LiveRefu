# 01 · 实现裁决记录

> 卡面：用途＝记录"策划文档没说清 / 两处冲突"时我在实现里拍的板 ｜ 依赖：[`doc/refu-game-001/`](../../../doc/refu-game-001/README.md) ｜ 状态：v1.0 · 2026-09-16
> 规则：**能照文档就照文档**；文档未定的，在这里显式裁决并写清理由与代价，**不擅自改策划文档**。
> 每条都给"若要翻案改哪里"，方便策划一句话推翻。

## A1 数值口径：严格执行 + 未定项集中收口

- **裁决**：卡/敌人/波次/挑战卡/规则卡数值**一律照 `doc/refu-game-001/`**，由 `tools/verify_data.py` 逐字段对账；
  文档未定的参数（起手张数、人口上限、布防期、装甲/减速公式、评级权重、地形影响半径…）集中在
  `game/data/balance.json` 与 `game/data/rules.json`，并在条目里写明来源或"文档未定"。
- **理由**：用户决策 D2 选择"严格照文档数值，派生数据集中在可调配置"；这样改数值不用动代码，也不会污染策划卷。
- **代价**：文档未定项在 M1 里带我的默认值，可能与后续策划结论不一致。
- **翻案**：改 `game/data/balance.json` / `rules.json` 对应字段即可，无需改代码。

## A2 输入手势：点选 + 点放为主，拖拽为辅

- **裁决**：点一下手牌＝**选中**该卡（战场高亮可放位置，底部给出提示）；再点战场＝放置；再点同一张＝取消。
  同时支持"按住手牌拖到战场松手"的拖拽放置（doc 07 手势表口径）。长按手牌＝打开完整卡面。
- **理由**：doc 07 要求"单指可玩、禁止精确小目标"。纯拖拽在真实触屏上容易误放；
  "点选—点放"两段式反馈更明确，且**可被自动测试稳定复现**（自动截图与验收都依赖它）。
- **代价**：与 doc 07 手势表"拖拽＝放置"的字面表述不完全一致（保留为等价路径）。
- **翻案**：`game/scripts/app/battle_screen.gd` 的 `_on_card_pressed` / `_on_field_input` / `_input`。

## A3 羁绊计数口径：按"本局上过场的卡"的不同卡号计数

- **裁决**：羁绊条件是**已上过场的卡**（放置过塔/单位、或施放过技能）中，含某标签的**不同卡号**数量达到阈值。
- **理由**：doc 14 的"后勤链＝2 张「维修」"里，铁砧只有 `ANV-M01`（支援）与 `ANV-S02`（技能）带「维修」标签。
  若按"场上存活"计数，S02 是一次性技能卡，施放即消失 → 该羁绊**永远不可达**；按卡号计数可达成，
  且避免"带 3 张同名 T01 就白嫖火力网"。
- **代价**：羁绊一旦达成就不会因卡离场而消失（本局内持续）。
- **翻案**：`battle.gd` 的 `_check_bonds`（`played_cards` 改为"场上存活"即可切换口径）。

## A4 支援单位的"在场时长"用独立字段 `lifetime`

- **裁决**：`stats.duration` 在支援卡上表示**效果窗口**（如 ANV-M01"修复 8/s、持续 6s"），
  **不是单位寿命**；单位寿命用新增字段 `stats.lifetime`（缺省 0＝常驻）。
  `ANV-M01`/`ANV-M02` 常驻，`ANV-M03`（路径阻挡）`lifetime = 15`（对应文本"存在 15s"）。
- **理由**：把两者混为一谈时，M01 会在 6 秒后离场 → 它永远触发不了自己的 `on_wave_end` 钩子，
  后勤链羁绊也不可达（实测：自动玩家把能量全砸在反复重买 M01 上，见 [04](04_调参与实测发现.md) F1）。
- **代价**：`lifetime` 是引擎新增字段（策划文档没有），已在 `cards.json` 的 `_schema.stats_ext` 里登记。
- **翻案**：改 `cards.json` 的 `stats.lifetime`。

## A5 敌人打谁：挡路的会被拦，紧邻的工事塔会被"边走边打"

- **裁决**：
  1. **路径阻挡单位**（`ANV-M03`，`block = 2`）会拦住敌人：敌人停下与其交战，直到它被摧毁或到期（超出阻挡数则绕过）；
  2. **有生命的塔**（工事塔 `ANV-T04`，400 生命）不会拦路，但敌人**路过时顺手打它**（攻击距离 ≈ 0.85 格）；
  3. **支援位**距路径约 1.4–1.5 格，敌人打不到 → 支援单位安全。
- **理由**：doc 04 只说"敌人沿路径推进，抵达基地扣血"，没说塔会不会被打。
  若塔完全不挨打，`ANV-T04` 的 400 生命、`ANV-S02` 的修复/护盾、`ANV-M01` 的维修就全成了死数值。
  采用"工事挨打但不拦路"后，这几张卡都有实际意义，且不会让 18 费的工事变成一堵无敌墙。
- **代价**：工事塔寿命有限（实测约 2–3 波被打爆），"永久减速场"需要重复投入。
- **翻案**：`battle.gd` 的 `_adjacent_fort` 与 `balance.json` 的 `combat.enemy_attack_range`。

## A6 修饰卡：拖到塔上＝挂在该塔；拖到地图修饰位＝全域修饰

- **裁决**：修饰卡拖到**已放置的塔**上→挂在它身上；拖到**地图的修饰位**（琥珀圆点）→作为"全域修饰"，
  作用于场上符合同标签条件的塔。
- **理由**：`ANV-X02`「伤害 +25%」、`ANV-X03`「为**本塔**额外附加 1 个标签」两处文本明确指向"某座塔"，
  说明修饰卡是挂在塔上的；而 `ANV-X01`「同标签塔 +15% 攻速」又指向多塔。
  两种挂载都支持后，三条卡面文本各自自洽，地图上唯一那个"修饰位"也不再是废格。
- **代价**：一副 20 张卡组里有 4–5 张修饰卡，而 MAP-ANV-01 只有 1 个修饰位 → 绝大多数修饰必须挂塔。
- **翻案**：`battle.gd` 的 `_place_modifier` / `_best_modifier_host`。**这条建议策划明确一次口径。**

## A7 起手张数 = 6（文档未定，由实测标定）

- **裁决**：`RUL-BASE.hand_size = 6`（布防期起手 6 张），之后每波结束三选一再加 1 张。
- **理由**：doc 05 只写了"每波结束获得 1 调度点，三选一抽牌"，**没写起手几张**。
  用自动玩家实测扫参：起手 5 张→漏怪 9、评级 B；起手 **6 张→漏怪 1、评级 S**；7 张以上与 6 张同结果（能量成为瓶颈）。
  取 6 张刚好落在 doc 21"第 1 章应 90%+ 稳过"的目标带内。
- **代价**：属于我的标定值，若策划另有起手张数设计，需重跑标定。
- **翻案**：`game/data/rules.json` 的 `hand_size`。

## A9 游戏内显示名

- **裁决**：标题用「**节点防线**」（与小说《节点之海》同宇宙的占位命名）。
- **理由**：策划卷没有给游戏命名（doc 03 明确"命名细节属 v0.1 可改"）。
- **翻案**：`game/scripts/app/main_menu.gd` 与 `game/project.godot` 的 `config/name`。

## A10 中文字体不在仓库里放二进制

- **裁决**：运行时从系统路径加载中文字体（macOS 的 `Hiragino Sans GB` / `STHeiti` / `PingFang`，
  Linux 的 Noto CJK），设为 `ThemeDB` 全局回退字体；找不到时退化为引擎默认字体并告警。
- **理由**：Godot 默认字体没有汉字（界面会全是方框）；把字体二进制放进仓库有授权与体积问题。
- **代价**：换台机器若没有候选字体，中文会变方框——`game/assets/fonts/` 已列为候选路径，
  放入 `NotoSansSC-Regular.otf` 即可（README 有说明）。
- **翻案**：`game/scripts/autoload/ui_font.gd` 的 `CANDIDATES`。
