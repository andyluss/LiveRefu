## 一、一句话立场

**技术排期方向可行但偏紧，M1「单频道（磁带暖未来）闭环」范围合理**——它精确对应 GDD 出口标准（专注 25min 不被打断、混音台可用、可收藏 1 卡），是验证"陪伴手感"的最小充分集；但前提是 M1 启动第一周就**锁定"渲染器选择 + 配置表 schema"两件事**，否则返工与阻塞风险最高。人手侧：闭环本体单人约 3–4 周、双人约 2–2.5 周；若要维持 GDD 的 2–3 周，必须砍掉托盘/滤镜去风险项。

> ⚠️ 文档一致性提醒：`01_tech-stack-draft.md` 与 `02_milestone-plan.md` 仍是"引擎未定、待立项方向确认"的 M0 前状态，且以"方向 A/B/C 游戏"为语境。**M0 已通过并锁定 Godot 4.7.x 桌面导出、产品为氛围陪伴应用（非游戏）**，本次意见按此基准出，正文另立。

## 二、M1 技术排期（单频道闭环）

### 2.1 任务拆解与粗估（人日，1 人日 ≈ 1 全工日）

| # | 任务 | 内容 | 估(人日) |
| --- | --- | --- | --- |
| 1 | 工程引导 | Godot 4.7.x 工程初始化、project.godot、目录结构、配置加载管线(JSON→Resource)、GDScript 规范/CI 钩子 | 2–3 |
| 2 | 配置表 schema 落地 | content_card(含版权字段)/channel/timer/mixer_track/collectible 五张表 + schema 校验 + CI 闸门 | 1–2 |
| 3 | 频道装载 | 单频道(磁带) 配置装载：视觉皮肤(色调LUT/背景)+音景+内容池，按"可插拔 bundle"抽象 | 2–3 |
| 4 | 氛围播放 | 音景循环起播、音量/预置；影音卡 M1 用静态占位替代 | 1–2 |
| 5 | 番茄计时 | 番茄 25+5、频道皮肤化呈现、结束轻提示(音色+可关闭)、时段小结数据 | 3–4 |
| 6 | 混音台 1.0 | 3–4 轨底噪混合、轨道音量、预置读取 | 2–3 |
| 7 | 收藏 1 卡 | 单卡收藏、图鉴条目记录；进度统计 M1 最小版 | 1–2 |
| 8 | 频道滤镜(最小) | 磁带 扫描线/微噪 2D 后处理，可关闭（GDD 静默可用要求） | 2–3 |
| 9 | App 壳(去风险) | 单实例 + 托盘/迷你窗 + 1 个全局快捷键 的 native 可行性 spike | 2–3 |
| 10 | 三态 UI 骨架 | 漫游/专注/设置·图鉴 三态切换骨架(占位 UI) | 3–4 |
| 11 | 集成与自测 | 闭环串通、退出标准自测、macOS/Windows 打包 | 2–3 |

**合计 ≈ 23–31 人日**。去重并行（UI 骨架 与 逻辑层并行、App 壳 spike 与核心循环并行）后：

- **核心闭环（#1–7、10、11；不含滤镜与 App 壳）≈ 15–20 人日 ≈ 2–3 周单人** —— 对齐 GDD 出口标准；
- **全套 M1（含滤镜 #8、App 壳去风险 #9）≈ 3–4 周单人 / 2–2.5 周双人**。

> 结论：不建议 M1 单人压到 2 周；若人力单薄，把 #8 #9 下移为"去风险尾插"，不做进出口标准。

### 2.2 是否含系统级集成（托盘/快捷键）——建议拆到哪

**建议：M1 只做"托盘 + 迷你窗 + 单全局快捷键"的**`app shell`**去风险项，明确不做系统级勿扰集成。**

- **拆到 M1（低优先）：** 单实例守卫、关闭窗口→隐藏为托盘/迷你窗、1 个全局快捷键(如显示/隐藏或起停计时)。它是"桌面常驻是陪伴形态前提"的最小验证，且是 GDD 风险表里唯一的"高/高"平台项，**越早去风险越省返工**。
- **后置到 M2/M3：** 系统级勿扰集成（静默通知）、后台常驻自启、多快捷键映射、Linux 兼容 — GDD 风险表对此的缓解口径即"首期先做托盘+迷你窗+本地快捷键，系统级勿扰后置"。
- **拆到 M2：** 把它从"验证"升级为"产品规格"（托盘菜单项、迷你窗计时显示等）。

> ⚠️ 平台关键风险：**Godot 4 无内置原生系统托盘图标与系统级全局快捷键 API**，二者通常需插件/GDExtension，且 macOS/Windows 行为差异大（打包/签名/权限）。故 #9 必须是独立 spike，先行确认可行性再决定是否进 M1 主体。

## 三、对其它角色的依赖 / 请求（不阻塞 M1 的优先级排序）

> 一切【待定】项均为 M1 的**前置依赖**，标注责任人。

### 阻塞项（M1 启动前必须定，否则卡进度）

- **【待定】渲染器选择**（图形程序员 A + 主程序）：主载体为 2D/UI + 内容播放、弱 3D —— 我**倾向 Compatibility（OpenGL/WebGL）**（低功耗、支持 Web 降级、2D/UI 完整）；但若图形程序员 A 想要 Forward+ 的 HDR/辉光/屏幕发光做更强复古表现，需在 M1 前做一次"双渲染器 2D 后处理对照切片"然后**锁定**。※ 此项同时决定 project.godot 与 #8 滤镜管线，绝不能拖过 M1 第一周。
- **【待定】配置表 schema**（数值策划 A + 主策划）：五张表的**字段定义** —— content_card 必须含**强制版权字段**（来源/版权类型/授权状态，GDD §12·3）与稀有度；channel/timer/mixer_track/collectible 的键与枚举。※ schema 一旦冻结就跑 CI 校验，防返工（GDD 风险表"配置表结构返工 高/中"）。
- **【待定】版权字段 taxonomy**（主策划）：版权类型的取值域（公版/CC0/自产 的默认入池口径，CC BY/BY-SA 需复核标记）——是 schema 里版权字段的枚举前提。※ M1 哪怕只收藏 1 卡，也要先把"字段 + schema 校验 + CI"工程闸门立起来，否则内容管线一铺就漏。

### 建议项（M1 内尽早给，不必开工前全齐）

- **三态界面 + 频道皮肤骨架 + 专注计时器视觉提案**（UI 设计美术 A）：M1 只需"占位 UI 骨架"，但**三态切换与"频道即皮肤"的共用骨架结构**要早定，避免 M2 重构。含**中文字体回退规则 + 字号规范 + 数字等宽规范**（防乱码，工作区有历史教训；见 `03_godot-engine-research.md` §九·4）。
- **频道滤镜实现路径**（图形程序员 A）：社区 CRT shader vs 自研轻量 2D 后处理 —— 需随渲染器一起出**性能预算**，并保证滤镜默认可关闭。
- **音景 3–4 轨 + 提示音 1 套**（音频/美术）：M1 可用程序化/占位，但最少要能起播验证氛围；磁带频道的"暖"基调优先。
- **首频道色调 LUT + 资源规格**（主美术）：M1 可用占位美术，但**色调 LUT/材质方向**需早给，用来确认"灯下接收机"母意象是否成立（这决定 M1 到底证没证到氛围手感）。

## 四、风险与把关

### M1 不该进什么（守门清单）

- 系统级勿扰集成、后台自启常驻、多快捷键（后置）；
- 多频道（M2 才做三频道风格切片）；
- 影音卡真实播放/采集（用静态/占位替，专注闭环）；
- 正式美术/音频资产（灰盒+占位，风格 M2 定）；
- 呼吸器、今日信号、解锁/成长/成就（GDD §4 全为 P1）；
- 登录/云端/账号、Steam 打包与签名、Web 导出、移动端、手柄、C#/.NET 混写（保持 GDScript 单一语言）。

### 最大风险（按"发生概率×影响"排序）与对策

| 风险 | 概率/影响 | 对策 |
| --- | --- | --- |
| **Godot 托盘/系统级快捷键原生缺口，且 macOS/Windows 差异大** | 高/高 | M1 独立 spike(#9)先行验证；若不顺，降级为"关窗→隐藏迷你窗 + 应用内快捷键"，系统级热键后置；平台差异登记 ADR |
| **渲染器选型拖到中段导致返工** | 高/中 | M1 第一周锁定；默认 Compatibility；图形程序员 A 双渲染器对照切片后拍板 |
| **配置表返工** | 高/中 | 第一周冻结 schema（含版权字段）+ CI 校验，样例填充后即冻结 |
| **氛围手感不成立（流派原创性风险）** | 中/高 | M1 本身就是验证它——用最小闭环 + 可调参数尽最早试玩；**不要在 M1 提前投入滤镜/美术**，M1 值的是"闭不闭环"而非"漂不漂亮" |
| 复古滤镜性能超标 | 中/中 | 图形程序员 A 出 2D 后处理预算；滤镜可关闭（GDD 静默可用） |

> 合规把关：**版权是工程闸门，不是范围蔓延**。M1 "只收藏 1 卡"也要把"强制版权字段 + schema 校验 + CI"立起来——这是 GDD §12·3 的已定项，属 M1 流程内必做。

## 五、M2（三频道风格切片）程序侧短评

M2 目标 = 磁带/太空/蒸汽波三频道各达风格定稿，**美术/图形权重高**；程序侧任务为：① 频道化架构泛化（从单频道→多频道可插拔 bundle）、② 滤镜栈定型（扫描线/星雾/慢色偏）、③ 2D 后处理性能预算落地、④ 内容池批量装载。

- 前置依赖：M1 的 #3 必须按"**频道 = 可插拔 bundle**"抽象，否则 M2 需重构频道化架构。
- 可并行性：图形程序员 A 的风格切片（太空/蒸汽波滤镜）可与 M1 后端并行，但需 M1 先定渲染器。
- 排期建议：M2 需主美术风格锚点 + 图形程序 A 滤镜评估齐备后启动，预计 2–3 周（与 `02_milestone-plan.md` 的 1–2 周并行略松，因含多频道化）。
