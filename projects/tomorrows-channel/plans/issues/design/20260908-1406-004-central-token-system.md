# 问题：中央 Token/色板系统未一次定稿（M2 前需锁定）

> 状态：**open**（未解，待主美术 + UI 美术 A 一次定稿）
> 发现：2026-09-08 14:06 · 发现人：主策划 / UI 设计美术 A
> 类型：design · 优先级：**高**（同时阻塞 M1 轻量皮肤与 M2 三频道管线）

## 现象 / 问题描述

M1 目前以"磁带频道轻量 Token 皮肤"落地（[`05_m1-ui-skeleton.md`](../../../docs/ui-artist-a/05_m1-ui-skeleton.md) §八 ①），但**跨频道的中央 Token/色板系统尚未一次定稿**（色板/频道 LUT/材质/字体角色/动效档位，含图形侧"容器暖光×频道色"分层）。M2 三频道皮肤设计为"只挂 Token、绝不各自重画"（[`00-project-plan.md`](../../00-project-plan.md) §三 M2）。

主美术基线 v0.1 已给色值/材质/暖光边界（`05_m1-tape-baseline` §4.2 已对齐），但**装饰字体方向**（磁带=终端等宽）与 **P4（sRGB vs 广色域）** 仍需主美术落定；UI 侧需把"容器暖光×频道色"分层下**自身归属层**一并定清。

## 影响 / 卡点

- 若 Token/色板系统在中段才定稿，M1 轻量皮肤与 M2 三频道管线可能返工（换肤依赖 Token 结构）；
- `game/README.md` §4.2 换肤机制为 M1 已落地骨架，需确认 Token 结构与 M2 复用。

## 尝试 / 参考

- UI A Token 语义角色登记（`05_m1-ui-skeleton.md` §4.2 表格，`color.glow`/`color.scanline` 为 UI 侧渲染边界预留，仍标【待定】）；
- 主美术 `05_m1-tape-baseline.md` §六 P4、`game/README.md` §4.2；
- 开发计划 M2："一次定稿中央 Token/色板系统（色板/频道 LUT/材质/字体角色/动效档位，含分层）"。

## 解决方向 / 需求

- **主美术 + UI 美术 A** 在 M2 前一次定稿中央 Token/色板系统（含装饰字体方向、容器暖光×频道色分层）；
- 定稿后各频道皮肤只挂 Token，不改骨架；主程序据此确认换肤机制（technical-007）与皮肤资源命名。
