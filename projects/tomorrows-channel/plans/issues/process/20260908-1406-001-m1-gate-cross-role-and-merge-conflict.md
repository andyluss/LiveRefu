# 问题：M1 出口缺口跨角色串行 + game/data 并行修改冲突风险

> 状态：**open**（未解，需主持人排期协调；并行修改冲突正在发生）
> 发现：2026-09-08 14:06 · 发现人：主持人（主策划）
> 类型：process · 优先级：**中**（协调性，不阻塞单项开发）

## 现象 / 问题描述

M1 出口缺口（[`game/README.md`](../../../game/README.md) §6.5 "还差什么"）大多**依赖多角色串行/并行**，且相互牵动：

| 缺口 | 责任人 |
| --- | --- |
| 收藏 1 卡（出口标准 #4） | 主程序（内容池收纳）+ 数值策划 A（数据）+ 主策划（版权 taxonomy） |
| 双光实机渲染在编辑器验证 | 图形程序员 A |
| 真实氛围音景 / AudioBus | 主程序（bus 布局）+ 音频/主美术（音景资源） |
| 番茄结束轻提示 + 一次极简泛光 | 主程序（泛光）+ 音频 |
| 频道路由表（M2 扩充 schema） | 主程序 + 数值策划 A |
| 中文字体回退 & 数字等宽资产 | UI 设计美术 A |

同时，**`game/`、`data/` 下正被别的子代理修改（收藏逻辑/卡池开发中）**，与上述跨角色依赖并存 → 存在**并行修改 git 冲突 / 覆盖**风险；机制上靠"各角色只改自己文档、不动他角色文件 + 主持人汇总"约定，但执行中仍需排期防撞。

## 影响 / 卡点

- 出口缺口若无人协调，可能串行拉长 M1；夹带修改（如内容池 schema、频道路由）易与正在开发的卡池/收藏逻辑冲突；
- 需要明确的"谁先谁后 / 谁能并行"矩阵，避免返工与文件冲突。

## 尝试 / 参考

- 各角色以【待定】登记、不改他人文档（主程序 `01_` 约束、图形 A `05_` 语义、开发计划）；lead-artist `04_` §4 登记后续待办不落笔；
- 开发计划 §四 跨角色依赖矩阵（责任人 + 时点）。

## 解决方向 / 需求

- **主持人 / 主程序**：对 M1 出口缺口给出"谁能并行、谁依赖谁"排期；明确 `game/`、`data/` 的**修改权属与合并策略**（谁负责收纳、谁负责数据），避免与进行中的卡池/收藏逻辑撞车；
- 建议按"数据→程序→验收"顺序，版权/音景/字体/双光验证拆分并行。
