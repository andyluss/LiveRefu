## 一、技术主线（M0 已锁定，非再选型）

| 项 | 结论 | 说明 |
| --- | --- | --- |
| **引擎** | **Godot 4.7.x 桌面导出**（锁定） | MIT 许可、可商用零版税；2D/UI 独立完整；4.7 复古风格渲染特性集中（HDR 输出 / 最近邻缩放 / 面光源 / 文本 shader 内联预览）。详见 `03_` §三/§四。 |
| **产品类型** | **氛围陪伴应用**（Ambient Companion），**非传统游戏** | 核心价值是"频道即世界观"的**视觉 + 音景氛围**（低频低打扰），渲染/UI/后处理重、表单与逻辑轻；无传统游戏升级/战斗循环。 |
| **脚本语言** | **GDScript 单一语言**（M1） | 内置即用、与引擎 API 零摩擦、官方文档与 LLM 语料足；M1 不引入 C#/.NET 混写。仅"系统集成 bridge"如确需可走 GDExtension（见 §六）。 |
| **渲染器** | **倾向 Compatibility（OpenGL/WebGL）**，未拍板 | 2D/UI 为主、弱 3D、低功耗、支持 Web 降级。**最终以 M1 第一周"双渲染器 2D 后处理对照切片"拍板**（图形 A 出切片 → 主程序确认），此决定 project.godot 与频道滤镜管线。 |
| **平台** | **桌面双端（macOS + Windows）为主线** | Godot 原生导出双端；Web 导出为次期降级演示；移动/主机不计入首期（`04_` §1.1）。 |

> **一句话**：技术选型 = **Godot 4.7.x 桌面导出 + 薄原生系统桥（托盘/全局快捷键）**；原型范围 = **单磁带频道闭环**。渲染放大氛围价值，是"放大器"而非"本体"，故 M1 用轻量后处理、不追求全栈。

## 二、为何是 Godot（选型判据收敛后，非多方向对比）

> v0.1 曾以"候选方案对比 + 待立项定稿"立论；M0 已锁定方向，此节改为**对既选引擎的判据回填**，并留待 M1 第一周收敛的唯一剩余选型（渲染器）。

| 判据（按优先级） | 本项目权重 | Godot 4.7.x 满足度 |
| --- | --- | --- |
| P0 氛围视觉/UI 表现力 | 陪伴形态核心 | 2D 独立引擎 + 深度可定制 UI（Control/Container/Theme）+ 自发光/面光源/HDR + 复古后处理生态成熟（`03_` §五） |
| P0 原型迭代速度 | AI 工作室并行 | GDScript 轻量、编辑器内置运行、官方示例/教程多，LLM 辅助编码语料足 |
| P1 跨平台与降级弹性 | 桌面主线 + Web 降级 | 原生导出 macOS/Windows/Linux + Web（HTML5）降级（`03_` §八） |
| P1 后台常驻与低功耗 | 陪伴应用刚需 | `OS.low_processor_usage_mode` + 动态降刷新可用于"最小化后仍后台跑计时+氛围"（`04_` §1.3） |
| P2 长期可维护 / 无自研 | 拒绝过度自研 | 开源 MIT、可读源码、官方 Asset Store（4.7 已上线）缓解生态；自研仅限系统集成 bridge |
| P2 合规与成本 | 无授权负担 | MIT 免费无版税，契合素材 CC/公有领域收集口径（`03_` §三） |

**唯一待收敛选型**：渲染器（Compatibility vs Forward+）——【待定】图形程序员 A（见 §三、§七）。

## 三、渲染器决策（M1 第一周必须拍板）

- **默认**：Compatibility（OpenGL/WebGL）。理由：主载体为 2D/UI + 内容播放、弱 3D；低功耗利于常驻；支持 Web 降级。
- **能翻案的情况**：若图形程序员 A 判断需 Forward+ 的 HDR/辉光/屏幕发光（`AreaLight3D` 面光源）做更强"终端/屏幕即光源"表现，且 2D 后处理对照切片显示优势明显，则可改选 Forward+；代价是功耗与工期。
- **决策方式**：M1 第一周由图形 A 出**双渲染器 2D 后处理对照切片**（`05_m1-render-slice`），主程序据此锁定 project.godot 的渲染后端与滤镜管线。
- **约束**：无论选哪个，频道滤镜**默认可关闭**（GDD 静默可用），避免耗电/性能失控；M1 只做磁带轻量后处理（扫描线/暗角/微噪）。

## 四、目录结构与工程规范（对齐 M1）

### 4.1 Godot 工程目录（`game/`）

```
game/                        # Godot 工程根（import 后即为项目根）
├── project.godot            # 工程配置：渲染器、主场景、autoload 注册、显示设置
├── scenes/                  # .tscn 场景 / 预制体（按系统分子目录）
│   ├── app/                 # App 壳 / 空场景（单实例、窗口、生命周期、后台常驻）
│   ├── channel/             # 频道装载与展示（磁带皮肤 + 音景 + 内容池轮播）
│   ├── timer/               # 番茄计时器 UI（皮肤化呈现）
│   ├── mixer/               # 混音台（3–4 轨音量滑杆）
│   └── ui/                  # 三态 UI 骨架（漫游 / 专注 / 设置·图鉴）
├── scripts/                 # 逻辑脚本（GDScript，按系统分子目录）
│   └── autoload/            # 单例：event_bus / config_loader / focus_state_machine 等
├── shaders/                 # 材质 / shader（滤镜双光层栈：扫描线 / 微噪 / 暗角）
├── data/                    # 工程加载用配置表副本（权威源在 ../data/，见 §4.2）
└── addons/                  # 第三方插件（系统集成 bridge / 托盘 / 全局快捷键，经评审后引入）
```

**约定**：`game/` 即 Godot 工程根（`project.godot` 直接位于 `game/` 下），不再嵌套 `project/` 层；系统级新增目录映射到 `scenes/` 顶层子目录。资源源文件在 [`../../assets/`](../../assets/)（最终导出），`art/` 为可编辑源文件——三者分层见项目 README。

### 4.2 数据驱动（配置表 / 内容池）

- **一切内容走配置表**（数值、频道、内容卡、计时参数、混音轨），代码零硬编码、禁止魔法数；字段 `snake_case`，带单位与上限说明。
- **权威源**：表在 [`../../data/tables/`](../../data/tables/)，schema 在 [`../../data/schema/`](../../data/schema/)，由数值策划 A 维护（`data/README.md` 约定）；`game/data/` 只放**工程加载用**的副本/派生。
- **加载管线**：JSON → Resource（Godot `.tres`/自建 Resource 类），非运行时硬编码。
- **M1 五张表**（字段定义见 §五）：`content_card`（含强制版权字段 + 稀有度）、`channel`、`timer`、`mixer_track`、`collectible`。
- **每加一条内容 = 新增一条数据、零代码改动**；配 schema 校验脚本，不合规即 CI 阻断。

### 4.3 工程规范（M1 落地的硬性约定）

| 项 | 约定 |
| --- | --- |
| 语言与风格 | 中文注释 + 英文标识符；统一 GDScript 格式化/lint 配置（引入 `gdformat`/gdlint 工具链或用官方风格指南）。 |
| 表现与逻辑分层 | 逻辑层不直接依赖渲染/UI；UI 通过**事件总线**订阅逻辑层状态。 |
| UI 框架隔离 | UI 层经 `addons/` 之外的独立脚本层订阅状态，便于换肤与复用。 |
| 分支与提交流 | `main` 始终可运行（资源完整、自测通过）；特性分支 `feat/系统名`；提交信息遵循 workspace 约定。 |
| 自测与说明 | 每项改动自测并附一句说明；破坏性改动必须同步更新对应文档。 |
| 合规闸门 | 内容卡**强制版权字段** + schema 校验 + CI 脚本，作为"防漏发"工程闸门（法律判定责任在主策划）。 |
| 渲染与性能 | 滤镜可关闭 + 单测性能数据；M1 目标桌面 60 FPS 不闪。 |

## 五、M1 数据驱动与配置表（对齐数值策划 A）

> M1 第一周必须冻结三件事之一：**配置表 schema**。以下为字段契约的主程序侧需求，字段最终以数值策划 A schema 为准（`data/schema/meta.schema.json` 未出，标【待定】）。

| 表 | 主程序侧要求 | 责任人 |
| --- | --- | --- |
| `content_card` | 内容卡（图文/引言）；**强制版权字段**（source / license / license_url / status）+ 稀有度；字段契约（如 id、type、title、body、art、duration、collect_frag） | 数值策划 A（insert 字段契约）/ 主程序补内容池 schema 收纳 |
| `channel` | 单频道（磁带）：id、name、皮服 LUT/背景、音景轨引用、启动配置 | 主程序内容池 schema 收纳 |
| `timer` | 番茄 25+5、范围 5–120、信号碎片初值 | 数值策划 A / 主程序 |
| `mixer_track` | 3–4 轨（嗡鸣/磁带底噪/雨…）：id、name、默认音量、bus | 主程序内容池 schema 收纳 |
| `collectible` | 收藏条目：卡 id → 本地图鉴条目，最小 1 条 | 主程序 |

> **版权 taxonomy**【待定】主策划（版权类型取值域：公版/CC0/自产默认入池，CC BY/BY-SA 需复核标记）——是 `content_card.license` 字段的枚举前提；M1 哪怕只收藏 1 卡也要先立"字段 + schema 校验 + CI"闸门，防内容管线一铺就漏。

## 六、M1 工程范围与守门清单

**M1 = 单频道（磁带暖未来）闭环**：工程引导 / 配置表 schema / 频道装载（可插拔 bundle）/ 氛围播放 / 番茄计时 / 混音台 1 版 / 收藏 1 卡 / 三态 UI 骨架 / 集成自测。

**M1 做（去风险项）**：App 壳 spike = 单实例 + 托盘/迷你窗 + 1 个全局快捷键（作为独立验证切片先行，`04_` §1.3 薄原生桥评估）。

**M1 明确不做（守门清单，前后端一致）**：系统级勿扰集成、后台自启常驻、多快捷键（后置 M2/M3）；多频道（M2 三频道风格切片）；影音卡真实播放/采集（用静态/占位替代）；正式美术/音频资产（灰盒+占位）；呼吸器、今日信号、解锁/成长/成就；登录/云端/账号、Steam 签名、Web 导出、移动端、手柄；C#/.NET 混写（保持 GDScript 单一语言）。
