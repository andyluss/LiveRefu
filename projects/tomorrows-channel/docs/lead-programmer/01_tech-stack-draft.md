## 一、选型判据（按优先级）

| 优先级 | 判据 | 说明 |
| --- | --- | --- |
| P0 | 原型迭代速度 | 立项初期以最快验证核心循环为准 |
| P0 | 团队熟悉度 | 当前为 AI 工作室，需选 LLM 辅助编码生态成熟的栈 |
| P1 | 风格化渲染能力 | 复古未来题材依赖后处理/风格化（CRT 扫描线、镀铬、辉光） |
| P1 | 跨平台弹性 | PC 起步、移动/Web 可降级 |
| P2 | 长期可维护性 | 中型项目规模，拒绝过度自研 |

## 二、候选方案

| 方案 | 优点 | 缺点 | 适配方向 |
| --- | --- | --- | --- |
| Godot 4（GDScript/C#） | 轻量、开源、2D/3D 皆可 | 生态小于 Unity | 方向 A 2D/UI 重 |
| Unity（URP/HDRP） | 渲染与 UI 生态成熟 | 授权条款、版本碎片化 | 方向 B/C |
| Web 技术栈（TS + 自研/库） | 天然适配复古 UI 氛围 | 3D 重负载吃力 | 方向 A 的网页呈现 |

## 三、暂定架构原则（与引擎无关）

1. **数据驱动**：所有内容（数值、关卡、文案）走配置表（JSON/CSV），代码零硬编码。
2. **表现与逻辑分层**：玩法逻辑层不直接依赖渲染/UI 表现，便于复用与测试。
3. **UI 框架隔离**：UI 层通过事件总线订阅逻辑层状态——复古未来题材的"终端/面板"式 UI 将高度自定义。
4. **资源规范先行**：美术资源命名、尺寸、导入设置按主美术规范执行。

## 四、代码与工程规范（简版）

- 语言与风格：中文注释 + 英文标识符；统一 lint/format 配置。
- 目录结构（以 Godot 为例，待定稿）：
  ```
  project/
  ├─ scenes/   # 场景与预制体（按系统分子目录）
  ├─ scripts/  # 逻辑脚本
  ├─ assets/   # 美术/音频原始资源
  ├─ data/     # 配置表（数值策划 A 维护）
  └─ addons/   # 第三方插件
  ```
- 分支与提交流：`main` 始终可运行；特性分支命名 `feat/系统名`。
- 每项 PR 需自测并附一句说明；破坏性改动必须更新对应 GDD 章节编号。
