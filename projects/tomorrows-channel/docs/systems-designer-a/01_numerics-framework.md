# 数值框架与表结构草案（草案 v0.1）

> 数值策划 A · 2026-09-06 · 状态：待立项方向与 GDD 数值目标定稿
> 本文先立数值工作的"骨架方法"，具体曲线与数值到方向定稿后落表。适配主策划 [01_立项概念草案](../lead-designer/01_concept-draft.md) 的三个候选。

## 一、数值工作总流程

1. 从 GDD 提取 **体验目标**（例：前 10 分钟获得 3 次成长反馈）；
2. 拆成 **数值系统清单**：成长 / 经济 / 战斗（或解谜节奏）/ 随机与保底；
3. 为每个系统建表 → 初值 → 模拟验算 → 调参 → 冻结；
4. 每次调参留记录（原因/旧值/新值/影响）。

## 二、候选方向的数值重心

| 方向 | 数值重心 | 说明 |
| --- | --- | --- |
| A 磁带暖未来（冒险解谜） | 解谜节奏、叙事解锁曲线 | 数值轻，重节奏与"发现"间隔 |
| B 原子镀铬（建造经营） | 经济流转、产出/消耗比 | 数值重，重平衡与循环 |
| C 太空时代（动作冒险） | 成长曲线、难度曲线 | 数值中，重曲线平滑度 |

## 三、通用表结构骨架（数据驱动）

| 表名 | 关键字段（待细化） | 消费方 |
| --- | --- | --- |
| `meta` 全局参数 | 版本、货币位、时间缩放 | 程序全局 |
| `progression` 成长表 | 等级、所需经验、解锁 | UI/主策划 |
| `economy` 经济表 | 资源项、产出、消耗、来源 | 玩法逻辑 |
| `difficulty` 难度表 | 阶段、强度系数、区间 | 玩法逻辑 |
| `probability` 随机表 | 物品、权重、保底 | 玩法逻辑 |

## 四、平衡验算约定

1. 每个系统写 **模拟脚本**（由主程序提供数据驱动底座后执行）；
2. 验算输出必须是 **曲线/数值区间**，而非单点；
3. 关键节奏点（如经济破产点、难度峰值）必须显式列出；
4. 目标受众宽容度：以"普通玩家中位体验"为校准对象。

## 五、开放问题

- 【待定】立项方向（A/B/C）→ 决定数值轻重；
- 【待定】货币/经济是否需要多资源类型；
- 【待定】是否需要抽卡/概率型商业化内容（影响 `probability` 表设计）。
