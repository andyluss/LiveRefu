## 二、三态界面设计提案

GDD §8 要求「漫游态 / 专注态 / 设置与图鉴态」，且**切换不打断专注**。我的理解：这三态不是三个独立应用，而是**同一套骨架上的三种「信息密度档位」**，靠「降噪 + 焦点转移」而不是「换场景」来区分。

### 2.1 三态总体结构（同一频道内）

| 态 | 核心任务 | 界面主导 | 信息密度 | 对专注的打扰 |
| --- | --- | --- | --- | --- |
| **漫游态** | 看内容、收藏、选频道 | 内容低打扰轮播 + 频道皮肤 | 中 | 无（默认） |
| **专注态** | 完成一段专注 | 计时 + 降噪氛围 | 低 | 无（降噪后更低） |
| **设置与图鉴态** | 配置、查收藏 | 面板/列表容器 | 高（临时） | 有意进入才显示 |

### 2.2 各态的「界面语言」

**漫游态（频道内容低打扰轮播）**
- 母意象：**一台点着灯的旧接收机**。界面即「对着频道窗口」，内容以卡片流/轮播缓缓流过，不做强信息层级。
- 顶部只留**频道名 + 信号强度（进度）+ 迷你计时角标 + 收藏/设置入口**，全部可折叠成一条极细的「接收机表带」。
- 卡片自带「降噪」策略：非聚焦卡片降降低亮度/动效，焦点卡片才满亮——用「视觉焦点」而非「滚动压力」引导漫游。
- 关键：漫游态是「可久处」的，任何弹窗/强调都要让位给「氛围先于信息」。

**专注态（计时 + 降噪氛围）**
- 进入瞬间，内容池自动进入**降噪模式**（GDD 附录 A 术语）：非必要元素（收藏按钮、导航、卡片轮播）隐藏或淡出，只保留**频道皮肤 + 计时器 + （可选的）频道氛围文字/引言**。
- 界面主力从「内容浏览」让位给「时间流过」：用频道自己的语言呈现时间（见 §4）。
- 视觉上专注态是一块**更安静的画布**——动态层降到最低，保证「静默可用」（见 §6 图形程序员 A 确认项）。

**设置与图鉴态**
- 独立于频道氛围的「工程台」容器，用**全局统一的面板组件**承载（滑杆/开关/下拉/列表），不做频道皮肤化——它属于「系统的器物」而非「某条时间线的器物」。
- 图鉴（未来档案库）走「卷-频道」归档，容器统一、条目以频道色区分，避免每频道一套图鉴皮肤。

### 2.3 切换逻辑：永不打断专注

关键设计是**三种「不打断」机制**：

1. **冷切换（无焦点剥夺）**：三态切换一律不抢占焦点、不弹模态遮罩、不抢键盘/鼠标焦点。设置与图鉴态进入时若正处专注，计时器暂停于顶栏角标继续走表，**布局只在地面以下增厚，不盖住计时**。
2. **热切换（专注态内直达）**：专注中调「设置」只变更「桌面以下」的配置，禁止弹出盖住计时器的设置模态；要用设置必须先把专注态「拆解」（或提供「随时可用但不盖住」的侧滑）。
3. **状态持久化为「可出可回」**：任何态都可通过频道选择器/托盘/全局快捷键**无损回退**，专属专注期间最小化到托盘/迷你窗时，计时不中断（对齐 GDD §8 第 5 项与 §10 平台风险）。

> **给主程序的一句话**：三态本质是**三套图层可见度 + 一套焦点策略**，不是三套窗口。实现请按「图层可见度开关 + 焦点不劫持」来做，别做三个独立场景（我会在组件清单里对应标注）。

### 2.4 三态与三频道皮肤的关系

- 三态是**架构**（骨架），频道皮肤是**外观**（Token 集合），二者正交：**同一套骨架跑三种信息密度，三套频道皮肤任意套在这套骨架之上**。
- 换频道的动作只在**漫游态**发生；专注态中断切换频道时，**正在计的番茄保留但以「频道切换确认」轻提示**，允许用户「换频道继续此段」，避免强打断强确认（对齐「陪伴不施压」纪律）。
- 频道皮肤的差异只体现在**材质/色板/装饰/字体倾向**（§3），不动三态结构；因此三态在任意频道下行为一致、学习成本低。

## 三、频道皮肤骨架：共用交互骨架 + 频道主题令牌（Token）皮肤化

GDD §8 第 2 项「频道即皮肤、共用同一套交互骨架」与 §9「频道区分度靠色调 LUT + 材质语言 + 动态元素，而非重绘 UI 骨架」——这两条我完全同意，且这是**控制内容管线的关键**。落地思路如下。

### 3.1 结构：骨架（Globals）⇄ 皮肤（Theme）

```
共用交互骨架（跨频道不变，一次实现）
  ├─ 布局/栅格/容器结构
  ├─ 组件：面板、按钮(3态)、开关、滑杆、进度条、图标(线性/填充)、弹窗、Toast
  ├─ 字体排印阶梯（字号/行高/中英回退/等宽数字）——可读性底线，跨频道统一
  ├─ 九宫格/切片逻辑、Hit area、焦点态、键盘导航
  ├─ 图标 language（线性-填充两级）——形状统一，仅着色可频道化
  └─ 交互反馈逻辑（悬停/按下/禁用）——行为统一，仅曲线可频道化

频道主题令牌 Theme Token（每频道一套值，填入骨架）
  ├─ 色板: bg / surface / primary / accent / glow / text / scanline
  ├─ 材质/纹理: 面板材质、边框语言、切角圆角、光照意象
  ├─ 装饰层: 扫描线 / 星雾 / 慢色偏（动态，可关闭）
  ├─ 装饰字体倾向: 标题/引言用（正文不随频道变动）
  └─ 动效基调曲线: 缓动、呼吸、微噪强度（须保证关闭后频道仍成立）
```

### 3.2 三类「元素」的归属：统一 vs 随频道

| 元素 | 全局统一（骨架） | 随频道变（Token） | 理由 |
| --- | --- | --- | --- |
| 布局/容器/栅格 | ✅ 统一 | — | 骨架一致，学习成本低 |
| 组件形状/九宫格切片/3 态 | ✅ 统一 | — | 一次实现，避免每频道重绘 |
| 字体排印阶梯（字号/行高/中英回退） | ✅ 统一（可读性底线） | — | 可读性不随频道打折 |
| 等宽数字（tabular figures） | ✅ 统一 | — | 对齐数值策划 A 字段，防跳动 |
| icon 形状（线性/填充） | ✅ 统一 | — | 语言一致 |
| 色板（bg/surface/primary/accent/glow） | — | ✅ 每频道一套 | **频道区分度的主战场** |
| 材质/纹理/边框语言/切角 | — | ✅ 每频道一套 | 频道「器物感」的来源 |
| 装饰层（扫描线/星雾/慢色偏） | — | ✅ 每频道一套 | 靠后处理叠加（§6 确认强度上限） |
| 装饰字体（标题/引言） | — | ✅ 每频道倾向 | 见 §5，仅装饰字 |
| 动效基调曲线 | — | ✅ 每频道一套 | 自动化：磁带=扫描线微噪、太空=星雾缓移、蒸汽波=慢速色偏 |

**关键纪律：随频道变的只允许是「Token 值」，不允许改「骨架结构」。** 若某频道需要新结构（新的容器），那属于**新增骨架能力**，须经骨架层评审，而不是该频道自带皮肤→否则会退化成每频道一套 UI。

### 3.3 三首期频道的皮肤 Token 初判（供主美术批准）

| Token 类 | 磁带暖未来（默认专注） | 太空时代（深度工作） | 蒸汽波黄昏（放松/漫游） |
| --- | --- | --- | --- |
| 主/背景 | 低饱和暖米底 + 屏幕自发光 | 深空紫蓝底 | 粉紫渐变 / mallsoft 灰粉 |
| 强调色 | 终端绿/琥珀单色 | 星云紫 + 霓虹对比 | 品红 + 青色霓虹 |
| 材质/边框 | 塑料米色、CRT 体积感、按键面板分件 | Googie 悬挑线条、星云描边、飞碟剪影 | 录像带噪点、窗户像素、旧网格 |
| 装饰层 | 扫描线 + 微噪（可关） | 星雾缓移（可关） | 慢速色偏（可关） |
| 装饰字体倾向 | 等宽/终端感 | 海报衬线/宽字距 | 圆体/柔和几何 |
| 光意象 | 自发光屏为主（案头灯） | 轮廓光（明日世界夜景） | 霓虹招牌 + 商场灯箱 |

> 以上仅为**方向性初判**（对齐主美术 01_ 各方向的色/光基调），具体色值待主美术批准后落 Token 表。三频道对应主美术素材库三目录的意象。

### 3.4 为什么这样做能省内容管线

- **组件只做一遍**：任何频道复用同一套按钮/面板/开关切片，只是填不同 Token。
- **新增频道 = 新增一套 Token + 一套材质/纹理 + 一套装饰层**，不动骨架、不动组件、不动排印。这与 GDD §6「每频道 1 套皮肤」的规模预估一致，且大幅摊薄「重绘整套 UI」的成本。
- **「静默可用」达标**：只要装饰层可关闭（每频道提供「关动态」开关），关闭后频道靠**静态图 + 音景**仍成立（GDD §9 第 3 项），骨架层天然支持。

## 四、专注计时器视觉提案

GDD §8 第 3 项与 §1 卖点 2「时间到了用频道自己的方式轻轻提醒」——计时的重点是**别抢戏**。我提两种形态 + 一种克制结束提醒。

### 4.1 默认形态：不显眼（顶栏/角标）

- 默认出现在**接收机表带**上，是一条细小的**频道色进度胶囊/角标**：当前时段剩余时间 + （可选）进度光条。
- **用频道皮肤呈现**（核心卖点）：磁带频道里它可能是**一台转动的磁带倒计时盘**、太空频道是**一弧星雾填充的轨道片段**、蒸汽波频道是**一抹慢速色偏的进度带**——但只做「器物式」点缀，不喧宾夺主。
- 数字用**等宽数字**（对齐 §7.5 决策），避免倒计时跳动引发焦虑。
- 提供「隐藏计时」开关：完全不显示计时，只靠**结束提醒**（见 §4.3）在时间到时报时——真正「隐形番茄钟」。

### 4.2 沉浸大计时（用户显式切换）

- 需要聚焦/自控的时段，用户主动切成**全屏大计时**：频道皮肤化的**大表盘/大字**居中，氛围文字/引言留白，动态层降到最低。
- 仍然**不弹窗、不遮其他必要信息**；沉浸态下可一键「还原为角标」。
- **克制是重点**：大计时不是「游戏化倒计时」，不做秒表滴答、不做夸张转场、不做红色紧迫色调。它仍是「器物」，只是把时间放大成可注视的陪伴物。
- 该形态同样遵守「静默可用」：计时本身不依赖任何动态层，关闭装饰层后依然成立。

### 4.3 结束提醒：克制设计

- **声音第一、视觉第二、绝不打断**：
  - **声音**：每频道 1 套「频道音色」轻提示（GDD §6 提示音），用**频道自己的方式**报时——磁带=卡带弹出声+微噪渐弱、太空=远处信号滴答、蒸汽波=音调慢放渐弱。短暂、可关、可调音量。
  - **视觉**：仅在计时器处做一盏「轻轻呼吸」的泛光或一次极简淡入提示，**不用全屏遮罩、不用强弹窗**。
- **可关闭**：音/视两种提示各自提供独立开关，且提供「静默到段」选项（到段只记录、不提醒，依赖用户手动看角标）。
- **报时后的去向**（对齐 GDD §3.2）：一段结束时给出**轻提示 + 进入休息/漫游的子氛围**，并提供「时段小结」入口；不强制打断当前内容。

> **给图形程序员 A 的协调**：结束提醒的「轻轻泛光」是**频道装饰层的一部分**，须服从「关闭动态后频道仍成立」的静默可用纪律，故其动画强度需与后处理栈一致（§6）。

## 五、字体与可读性：「UI 是世界观器物」的边界

「UI 是世界观里的器物」（我 01_ 卷一节 1）——装饰性、终感字体很能塑造「器物感」，但**在中文下这是最大的翻车点**。我的结论：**装饰字只做「皮」，可读性走「回退体系」，二者显式分离。**

### 5.1 复古终端字体在中文下的三重风险

1. **缺 CJK 字形 → 豆腐块/乱码**：多数复古终端等宽字体（如 VT323、IBM 风格字体）只覆盖拉丁/数字，**不含 CJK**。直接用它排中文正文，必然出现豆腐块或由系统强行回退造成的中英错位。
2. **小字号 CJK 抗锯齿差**：终端像素字体在正文小字号下笔划发糊/断裂，加上扫描线后更糟——这正是「扫描线下中文可读性」陷阱（我 01_ 卷二候选 A 行）。
3. **字体嵌入/回退方案不可假设**：不同 OS（macOS/Windows）与不同渲染器对「系统字回退」的解析不一致，不能假设「系统里有某款中文终端字」。

### 5.2 引用：合订本字体兼容教训（本工作区真实事故）

我 01_ 卷三标注的「历史教训：合订本字体兼容性问题曾致乱码」——指工作区合订本 `doc/retro-futurism/合订本/` 的实践：

- 合订本 **v1** 正文汉字用**苹方（PingFang SC）子集字体**，结果**在个别查看器里乱码**；
- **v2** 改为**单一 TTF（Arial Unicode）显式嵌入（257 页）**才解决，并在 README 注明「两版字体度量不同、页码各自对应、勿跨版使用」；且仍提醒「若 v2 仍乱码请提供查看器与截图以便定位」。

**对我们的教训**：字体问题**必须显式验证、显式声明回退**，绝不能假设某款系统字在目标环境（macOS/Windows 双端）都可用；且「不同字体度量不同」会牵动排版，改动字体须成套验证。

### 5.3 我的排印落地规则（写入本角色规范 v0.2 建议）

| 用途 | 字体策略 | 原则 |
| --- | --- | --- |
| **中文正文 / 卡片文案** | 系统中文回退（macOS `PingFang SC`、Windows `Microsoft YaHei`），**不用终端等宽字** | 可读性优先，跨端一致 |
| **数字（时长/进度/收藏数）** | **等宽数字（tabular figures）** + 等宽回退 | 对齐数值策划 A 字段规范，防跳动 |
| **频道标题 / 引言 / 装饰字** | 各频道复古装饰字体（可用终端/海报圆体），**仅用于标题与引言，不做正文** | 装饰字只做「皮」，承载器物感 |
| **中英混排** | 中西文分别回退，避免西文字体缺字 | 我 01_ 卷二节 3 |

> **给主美术 / 主程序的协调**：装饰字库（频道标题/引言用）需**单列版权与回退**（我 02_ 卷三：字体资源单列版权与回退字体），且**必须显式验证双端 macOS/Windows 渲染**，否则按合订本 v1 的教训处理——宁可系统字回退，不冒乱码风险。
