## 二、为什么是这套（对照用户指定）

用户指定 **Web + Bun + Vue + Nuxt**，因此主线无需论证。真正要论证的是**在主线内的三个分叉**：

### 2.1 内容引擎：Nuxt Content vs 独立文档站

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| **Nuxt Content 3**（推荐） | 同一应用内同时满足博客与 Wiki；SQL 后端；**内置全文检索**；`queryCollectionNavigation` 自动出导航树 | 深度定制需读源码；中文分词受 SQLite FTS5 限制 |
| VitePress / Docusaurus / Starlight | 文档体验开箱即用 | **多一个站点、多一套构建**，博客/画廊/论坛要另起；两处主题难统一 |
| 纯 Markdown + 自研解析 | 完全可控 | 重复造轮子（检索、导航、MDC、代码高亮全部自己做） |

**结论**：本项目要求 **Wiki + 博客 + 画廊 + 论坛在同一个站内统一主题**，因此选 **Nuxt Content**。独立文档站方案会把"统一视觉"这个核心诉求拆散。

**已核验的 Nuxt Content 3 API**（用于 [03](03_信息架构与内容模型.md) 的设计）：
[`queryCollection`](https://content.nuxt.com/docs/utils/query-collection)、
[`queryCollectionNavigation`](https://content.nuxt.com/docs/utils/query-collection-navigation)、
[`queryCollectionItemSurroundings`](https://content.nuxt.com/docs/utils/query-collection-item-surroundings)（上下篇）、
[`queryCollectionSearchSections`](https://content.nuxt.com/docs/utils/query-collection-search-sections)、
[`useSearchCollection`](https://content.nuxt.com/docs/utils/use-search-collection)（全文检索）。

### 2.2 组件库：Nuxt UI + Tailwind vs 纯 Tailwind

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| **Tailwind 4 为主 + Nuxt UI 按需取用**（推荐） | 视觉完全自定义（复古未来主题不吃标准设计系统）；Nuxt UI 只在需要**无障碍正确**的组件（Modal/Dropdown/Tooltip）时引入 | 两套并存需自律，避免样式冲突 |
| 纯 Tailwind | 最干净、产物体积最小 | 弹窗/下拉/焦点陷阱要自己写，无障碍易出坑 |
| 全套 Nuxt UI | 开发最快 | 设计语言强，"复古未来"会被拉回通用风格 |

**结论**：**主题优先**，所以主角是 Tailwind + 自研组件；Nuxt UI 作为**无障碍兜底**按需引入。

## 三、Bun 与 Nuxt 的兼容性（本项目最大风险）

### 3.1 现状：官方支持

Bun 官方指南明确：**"Bun supports Nuxt with no extra configuration"**，并提供 `bun create nuxt@latest` 路径 —— 见 [Build an app with Nuxt and Bun](https://bun.sh/guides/ecosystem/nuxt)。

因此**包管理用 Bun 无争议**。真正的不确定性在**运行时**与**原生模块**：

### 3.2 M0 实测结论（✅ 已验证，含三条真实约束）

M0 实测把上一节的三个"待验证点"全部验完，**结论是：Bun 可用，但有一个必须遵守的铁律。**

| # | 验证点 | 实测结果 |
| --- | --- | --- |
| V1 | `bun install` / `bun run build` 是否正常 | ✅ **通过**。`bun install` 801 包 26s；`bun run build` 成功，产物 27.7 MB（gzip 10.6 MB） |
| V2 | 原生模块 `sharp` | ✅ **通过**。构建日志：`sharp binaries have been included in your build for darwin-arm64` |
| V3 | SQLite 连接器 | ✅ **通过且无需选型**：Bun 下 Nuxt Content 直接用内置 `bun:sqlite`，**不必装 better-sqlite3** |

#### 铁律：构建与运行必须用同一运行时（本项目 = Bun）

实测踩到三个坑，**根因是同一个**——`bun install` 的扁平布局 + 包的运行时条件导出 + Nitro 的文件追踪三者叠加：

| # | 现象 | 根因 | 处理 |
| --- | --- | --- | --- |
| P1 | `node .output/server/index.mjs` 报 `ERR_UNSUPPORTED_ESM_URL_SCHEME: Received protocol 'bun:'` | Bun 下构建时 Nuxt 选用 Bun 运行时预设，产物含 `import { Database } from 'bun:sqlite'`；`@nuxt/content` 依据 `process.versions.bun` 选 SQLite 连接器 | **用 `bun start` 运行**（`package.json` 已如此定义） |
| P2 | `bun .output/server/index.mjs` 报 `Cannot find package 'srvx'` | `srvx` 的 `exports` 按运行时条件导出多个适配器；Nitro 用 @vercel/nft 只复制了构建条件命中的 `node.mjs`，而 Bun 运行时命中 `bun` 条件去要 `dist/adapters/bun.mjs`——该文件不在产物里 | 新增 [`tools/check-build.ts`](../tools/check-build.ts)：构建后按 `exports` 清单校验并补齐（**当前补 14 个文件**），已接入 `bun run build` |
| P3 | Node 下重跑构建，产物仍含 `bun:sqlite` | 与 P1 同源：连接器由**构建时**的运行时决定，不由运行时环境变量决定 | 统一构建/运行运行时即可自洽，无需额外配置 |

> **运维含义（对 D6 的影响）**：部署脚本必须是 `bun run build` → `bun start`，**不能**是
> `bun run build` → `node .output/server/index.mjs`。已在项目 README §四「运行方式」写明。

> **调参路径（若日后必须用 Node 运行）**：需让构建也在 Node 下进行（清掉 `.nuxt`/`.output` 缓存后
> `node node_modules/nuxt/bin/nuxt.mjs build`），此时 `@nuxt/content` 会改用 `better-sqlite3`
> （需额外安装），且需自行处理 P2 的 `srvx` 条件导出问题。**这是一条未经完整验证的退路**，仅在
> 被迫换运行时时才应尝试。

### 3.3 风险对冲原则

> **统一用 Bun（构建 + 运行），并在构建后校验产物。**

具体：
1. `package.json` 的 `build` 已串上产物校验脚本，**构建产物不完整会直接失败**，不留给运行时；
2. 全站脚本用 Bun 跑（`bun run tools/*.ts`），避免"脚本能跑但产物不能跑"的错觉；
3. 数据层仍经 Drizzle 抽象，**不直接散落 `bun:sqlite` 调用**——为将来可能的迁移留门。

## 四、视觉与多媒体实现要点

| 需求 | 方案 |
| --- | --- |
| 图片响应式/WebP | `@nuxt/image` 2.1.0（IPX 自托管，或接 Cloudflare/R2 provider） |
| 画廊灯箱 | **PhotoSwipe 5**：原生手势、键盘、无障碍、零依赖；Vue 侧做薄封装 |
| 视频 | 原生 `<video>` + `poster`（演示录像 92 秒 MP4）；不引入播放器框架，需要字幕/多清晰度再议 |
| 图片墙布局 | CSS `columns` 或 Grid + `aspect-ratio`，**避免引入 masonry 库** |
| CRT 质感 | 纯 CSS（`repeating-linear-gradient` 扫描线 + `radial-gradient` 暗角 + `mix-blend-mode`），**不用 WebGL**，保证首屏性能 |
| 动效 | `motion-v` 2.4.4 做进场/悬浮；**全站尊重 `prefers-reduced-motion`** |
| 中文字体 | **运行时加载系统 CJK 字体**（沿用 [`refu-game-001`](../../refu-game-001/README.md) 既有做法），仓库不塞字体二进制；如需固定字重再考虑子集化 |

> **不引入**：Three.js / WebGL 背景（除非后续要做可交互的"七纪时间轴"3D 版，M4 再议）。理由：首屏性能与可访问性优先于炫技。

## 五、论坛数据层的技术选项

若走 [D4](00_决策记录.md) 路径 C（站内自建），技术组合：

| 项 | 推荐 | 理由 |
| --- | --- | --- |
| ORM | **Drizzle ORM 0.45.3** | 对 SQLite/Postgres 都支持，**对 Bun 有官方指南**（[Drizzle with Bun](https://bun.sh/guides/ecosystem/drizzle)），类型推导好，迁移可版本化 |
| 不选 Prisma | — | **v8 仍在 RC**，且引擎二进制在 Bun 下有额外风险 |
| 会话 | `nuxt-auth-utils` 0.5.30 | Nitro 原生集成，Cookie 会话开箱即用；或用 **Better Auth 1.7.6**（功能更全，见 [D7](00_决策记录.md)） |
| 密码 | argon2 / bcrypt | Bun 文档提供 [`Bun.password`](https://bun.sh/docs/api/hashing)（内置 argon2id/bcrypt），**零依赖** |
| 反垃圾 | 频率限制 + 最小发帖间隔 + 蜜罐 | 首版不做验证码/第三方风控 |
| 实时更新 | **后置** | Nitro 支持 WebSocket（`crossws`）；但首版用轮询/手动刷新即可，避免过早复杂化 |

## 六、版本锁定与升级策略

1. **锁定精确版本**：`package.json` 用精确版本号（非 `^`），配合 `bun.lock`，保证构建可复现；
2. **升级节奏**：仅在小版本安全更新时升；**大版本升级单独立项**（Nuxt 4→5 这类要单独评估）；
3. **预发布禁入**：`nitro`/`h3`/`prisma` 等 RC/Beta 不作为直接依赖写入；
4. **记录**：任何版本变更写入项目 [`CHANGELOG.md`](../CHANGELOG.md)。
