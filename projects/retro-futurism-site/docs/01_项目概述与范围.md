# 01 · 项目概述与范围

> 卡面：用途＝这个站是什么、给谁看、做到哪 ｜ 依赖：[项目 README](../README.md)、[`doc/retro-futurism/`](../../../doc/retro-futurism/README.md) 论文集 ｜ 状态：**草案 v0.1 · 待决策** · 2026-09-27

## 一、一句话定义

**把工作区已有的 14 万字复古未来主义知识库，做成一个"可读、可逛、可讨论"的公开站点**——Wiki 承载知识体系，博客承载编辑部写作，多媒体画廊承载视觉素材，论坛承载读者讨论。

## 二、出发点：工作区已有资产盘点

本项目**不是从零开始的内容站**，它的内容是现成的。立项前先盘清家底：

| 资产 | 位置 | 规模 | 对本项目的用途 |
| --- | --- | --- | --- |
| 《复古未来主义论文集》 | [`doc/retro-futurism/`](../../../doc/retro-futurism/README.md) | 主卷 00—20 共 21 篇 + 7 个附录卷，**91 个 md，约 14.1 万汉字** | **Wiki 主干**（按七纪分期天然成树） |
| 朋克五卷 | [`doc/punks/`](../../../doc/punks/README.md) | atompunk / biopunk / cyberpunk / dieselpunk / steampunk，**53 个 md** | **Wiki 分卷**（每卷 00—08 同构，可做统一版式） |
| 合订本 | `doc/retro-futurism/合订本/`、`doc/punks/合订本/` | HTML + PDF | 站点「下载」区 / 电子书页 |
| 卡牌游戏策划卷 | [`doc/refu-game-001/`](../../../doc/refu-game-001/README.md) | 26 篇 + 可视化 + 美术设定两案 + 40 章小说 | 站点「关联项目」专区（未来可选） |
| 视觉素材 | `doc/refu-game-001/美术/` | **99 PNG / 80 SVG / 47 PDF** | **多媒体画廊**首批内容 |
| 可运行游戏 | [`projects/refu-game-001/`](../../refu-game-001/README.md) | Godot 4.7 工程 + 92 秒演示录像 | 站点「作品」页引流 |

**关键结论**：内容量（265 个 md、约 170 万字符）已经远超一个个人站的启动门槛，**本项目的瓶颈不是"写什么"，而是"怎么组织、怎么检索、怎么让它能持续更新"**。这直接决定了后面的技术选型偏重 **内容管线** 而非 CMS 后台。

## 三、目标读者

| 读者 | 来干什么 | 站点要满足 |
| --- | --- | --- |
| 复古未来爱好者（泛读者） | 逛画廊、看视觉、被吸引 | 首屏视觉冲击、瀑布流画廊、免登录可读 |
| 深度读者 / 研究者 | 通读论文、按线索跳转 | Wiki 目录树、双向链接、全文搜索、引用出处 |
| 编辑部 / 作者（我们自己） | 写新文章、改旧文、发素材 | Markdown 写作 + git 版本管理 + 预览 |
| 社区用户 | 提问、讨论、补充考据 | 论坛（账号、发帖、回复、通知） |

> **设计取向**：**读优先，写其次**。绝大多数访客只读不写；论坛是附加，不是主体。因此 Wiki/博客/画廊的性能与阅读体验优先于论坛功能深度。

## 四、范围边界

### 4.1 首版（M1）做

1. **Wiki**：论文集 + 朋克五卷结构化上线，含侧边导航、面包屑、目录锚点、上下篇、全文搜索；
2. **博客**：Markdown 写作、列表/详情、标签、RSS、发布时间线；
3. **多媒体画廊**：图片墙 + 灯箱 + 视频播放，首批接入 `doc/refu-game-001/美术/` 素材；
4. **论坛**：轻量社区（账号、板块、主题、回复）——**形态待决策 D4**；
5. **站内搜索**：跨 Wiki/博客/画廊统一检索；
6. **视觉**：复古未来主义主题皮肤（CRT 扫描线、镀铬、原子时代配色）。

### 4.2 首版明确不做

- 用户上传大文件 / 视频转码（画廊素材由编辑部提供，开放 UGC 上传后置）；
- 复杂社交（私信、关注流、动态时间线）；
- 商业化（广告、付费墙、订阅）；
- 多语言（仅简体中文，`@nuxtjs/i18n` 预留但首版不接）；
- 原生 App / 小程序。

### 4.3 待决策项（见 [00 决策记录](00_决策记录.md)）

项目命名、论坛形态、存储方案、部署形态、视觉基调、是否迁移现有 md 为唯一信源。

## 六、与工作区其它项目的关系

- **内容源**：[`doc/`](../../../doc/) 是**唯一内容权威**，站点是它的**呈现层**。站点不产生新知识，只组织与展示；
- **不重复**：`doc/refu-game-001/` 是策划卷、[`projects/refu-game-001/`](../../refu-game-001/README.md) 是游戏实现，本项目是**网站**，三者共用「复古未来」母题但产物不同；
- **可复用**：三个项目共享同一套视觉语言（见 [02 技术选型](02_技术栈与选型.md) 的视觉约定段），未来可抽公共设计 token。
