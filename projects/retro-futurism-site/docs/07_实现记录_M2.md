### 2.1 需要你在 GitHub 侧做的四步

代码已就绪，**上线只差这四步**（页面在未配置时会直接把这份说明显示给访问者）：

1. 建一个**公开** GitHub 仓库（或用一个已有的）；
2. 该仓库 Settings → General → Features，勾选 **Discussions**；
3. 到 [giscus.app](https://giscus.app) 把 **giscus App** 安装到该仓库；
4. 在 giscus.app 填仓库名并选一个 Discussion 分类（建议新建 `Announcements`），
   它会给出 `data-repo-id` 与 `data-category-id`；把四个值配成环境变量：

```bash
NUXT_PUBLIC_GISCUS_REPO=owner/repo
NUXT_PUBLIC_GISCUS_REPO_ID=R_kgDOxxxx
NUXT_PUBLIC_GISCUS_CATEGORY=Announcements
NUXT_PUBLIC_GISCUS_CATEGORY_ID=DIC_kwDOxxxx
```

### 2.2 一个刻意设计：未配置时降级而非报错

组件在四个值不全时渲染**配置说明**而不是空白或抛错。理由：站点在未接入讨论区时
应当**依然完整可用**，并且把"还差什么"直接告诉维护者，而不是留一个永远空白的框。

## 三、切换条件（什么时候进第二阶段）

任一满足即值得评估自建论坛（已写入 `/forum` 页面，避免"什么时候该换"变成模糊问题）：

1. **月新增主题 > 50**；
2. **出现需要分区 / 置顶 / 版主管理的真实需求**；
3. **Giscus 的外观或数据归属成为明确障碍**——特别包含**境内可达性**这一条（见 §五）。

进入第二阶段所需的表结构与存储方案已按 [D5](00_决策记录.md) 的 **Bundle A** 定好
（见 [04 §一](04_数据存储与同步方案.md) 与 [03 §3.4](03_信息架构与内容模型.md)），**不浪费这次选型**。

## 四、验收结果（实测）

`tools/verify-giscus.ts`，真浏览器（CDP）：

```
✓ 未配置时降级    显示配置说明，未注入脚本
✓ 配置后注入      term=forum:general mapping=specific lang=zh-CN
✓ 博客讨论区      term=blog:/blog/2026-09-27-why-this-site
```

> **本脚本能证明与不能证明的边界（重要）**：
> ✅ 能证明：未配置时优雅降级；配置后**脚本被注入且参数正确**。
> ❌ **不能证明**：真实 GitHub 仓库与 Discussions 的端到端可用性——
> 本脚本用**占位** `repoId`/`categoryId` 走通注入路径，**未**验证真实讨论能加载与发言。

## 五、已知风险（需你确认）

**Giscus 依赖 GitHub，境内网络可达性存疑。**
若你的读者主要在中国大陆，第一阶段的价值会大打折扣，**应直接考虑第二阶段的站内自建论坛**。
这一条在 `/forum` 页面上也向读者如实标注了。

## 六、M2 踩到的坑

### 6.1 挂载点 id 用 `Math.random()` → 脚本静默不注入

**症状**：页面看起来完全正常——挂载点 `<div class="comments__mount">` 在、
未配置的降级说明也不出现（说明走的是"已配置"分支），但讨论区**永远空白**。
没有任何报错，构建与类型检查全过。

**根因**：最初用 `Math.random().toString(36)` 生成挂载点 id：

```ts
const containerId = `giscus-${Math.random().toString(36).slice(2, 9)}`   // ❌
```

**SSR 渲染出的 id 与客户端 hydration 时算出的 id 不同**（随机数两次不一样），
于是 `onMounted` 里的 `document.getElementById(containerId)` 返回 `null`，
脚本注入被 `if (!el) return` 静默跳过。

**修正**：改用 Nuxt 提供的 `useId()`（SSR/CSR 一致的稳定 id）：

```ts
const containerId = `giscus-${useId()}`   // ✅
```

**教训**：**任何同时用于 SSR 输出与客户端查询的标识符都不能是随机的。**
这类 bug 的可怕处在于"页面没坏、只是功能没生效"——**只有真正在浏览器里查 DOM 才能发现**，
这也是为什么 `verify-giscus.ts` 必须用 CDP 而不是 curl（curl 只能看到挂载点存在）。
