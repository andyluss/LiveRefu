## 一、为什么值得做

工作区已经有**现成的内容家底**，缺的只是一个"门面"：

| 已有资产 | 规模 |
| --- | --- |
| [《复古未来主义论文集》](../../doc/retro-futurism/README.md) | 主卷 00—20 共 21 篇 + 7 个附录卷，**91 个 md / 约 14.1 万汉字** |
| [朋克五卷](../../doc/punks/README.md) | atompunk / biopunk / cyberpunk / dieselpunk / steampunk，**53 个 md** |
| 视觉素材 | **99 PNG / 80 SVG / 47 PDF** |
| 关联项目 | [Refu Game 001](../../projects/refu-game-001/README.md)（可运行游戏 + 演示录像） |

**265 个 md、约 170 万字符**的内容量早已越过个人站门槛——瓶颈不是"写什么"，而是"怎么组织、怎么检索、怎么持续更新"。

## 二、技术栈（一句话）

**Bun 1.4 + Nuxt 4 + Vue 3.5 + Nuxt Content + TypeScript**，视觉用 **Nuxt UI 4 + Tailwind CSS 4**。
版本锁定、选型理由与风险见 [02 技术栈与选型](docs/02_技术栈与选型.md)。

## 三、五个关键设计判断

1. **`doc/` 是唯一内容权威**，站点是呈现层——不复制、不改写正文；
2. **写「内容适配层」而非手工改 doc/**：源文档**无 frontmatter**（用的是 `> 关键词：` 引用块）、**交叉引用是纯文本**（`（见 16 末日篇）`），必须靠转换脚本生成规范元数据 + 可点击链接；
3. **读优先，写其次**：Wiki/博客/画廊的性能优先于论坛功能深度；
4. **「七纪时间轴」做成全局导航**：画廊按年代筛选与 Wiki 按纪读史共用一个心智模型——这是本站的记忆点；
5. **论坛与内容分家**：文件式内容（Nuxt Content）与关系型社区数据（数据库）**分别选型**，不强行统一。
