### 3.2 M1 验收清单

| # | 验收项 | 口径 | 实测 |
| --- | --- | --- | --- |
| 1 | 内容完整 | 主卷 21 + 朋克 45 + 附录 63 全部可访问；构建期链接校验 0 失效 | ✅ 129/129，站内链接 149/149 |
| 2 | 交叉引用 | 改写命中率 ≥ 95%，未命中项列清单（不静默失败） | ✅ **97.1%**（331 处），10 处刻意保留并列清单 |
| 3 | 搜索 | 任取 10 个术语，≥9 个能搜到且直达锚点 | ✅ 6/6 抽样全中（真浏览器 CDP 验证） |
| 4 | 画廊 | ≥40 张素材可浏览/灯箱/筛选；视频可播 | ✅ **99 件**可浏览/灯箱；视频无素材，待接入 |
| 5 | 性能 | 生产构建 LCP < 2.5s、CLS < 0.1（桌面宽带） | ✅ **实测通过**（4× CPU 降速 + 1.6Mbps 限速下 LCP 280–324ms、CLS ≤ 0.0003） |
| 6 | 无障碍 | 键盘可完成浏览与灯箱操作；`prefers-reduced-motion` 生效 | ✅ 键盘/焦点陷阱已实现；**9 项自动检查 × 4 页通过**（含负向自检） |
| 7 | 构建 | `bun run build` 退出码 0；产物可 `bun run preview` 起 | ✅ 构建 + 产物校验通过；产物用 `bun start` 起 |

> **性能与无障碍为何用自研脚本而非 Lighthouse**：验收口径只要 LCP/CLS 两个浏览器原生指标，
> 引入 Lighthouse 及其一大票依赖不划算。见 [`tools/verify-perf.ts`](../tools/verify-perf.ts)。
> **关键细节**：性能测量**必须限速**——本机 localhost 回环下 LCP 只有 60–100ms，
> 那个数字**不能用来判断 < 2.5s 目标是否达成**（等于没测）。脚本模拟 4× CPU 降速 + Fast 3G 网络。
> 无障碍脚本内置**负向自检**（`--selftest`）：故意注入违规 DOM 确认检查器会报错，
> 因为**一个永远返回"通过"的检查器比没有检查器更糟**。

## 四、M2 · 写：论坛 + 账号（1.5–2 周）

按 [00 决策记录](00_决策记录.md) D4 的裁决分两条路，工作量差别很大：

| 路径 | 工作量 | 交付 |
| --- | --- | --- |
| **A. 外挂成熟论坛**（Discourse/PocketBase 等） | **2–4 天** | 单向 SSO/跳转 + 主题化对齐；帖子数据在论坛自己的库 |
| **B. 站内自建论坛** | **1.5–2 周** | 表结构（见 [03](03_信息架构与内容模型.md) §3.4）+ 注册登录 + 发帖/回复/分页/权限 |

**共同验收**：注册 → 登录 → 发主题 → 回复 → 看到回复 → 登出，全链路跑通；有基本反垃圾（频率限制/最小发帖间隔）。

**明确不做**：私信、@提醒、富文本编辑器、附件上传、版主后台（M4 再议）。

## 五、M3 · 打磨（1–1.5 周）

1. **主题皮肤**：CRT 质感（可关闭）、原子时代配色、镀铬标题、机械动效；
2. **首页重做**：从"能看"到"想逛"——精选论文 + 最新博客 + 画廊九宫格；
3. **性能**：图片懒加载与优先级、字体子集化、路由预取、缓存头；
4. **SEO**：结构化数据核对、OG 图自动生成、合订本 PDF 下载页；
5. **运维**：备份脚本（见 [04](04_数据存储与同步方案.md) §D）、部署文档、`CHANGELOG` 与文档同步。
