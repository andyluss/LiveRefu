## 一、两层结构（整个美术体系只有这两层）

| 层 | 可变性 | 内容 | 谁负责 |
| --- | --- | --- | --- |
| **语法层**（本文档） | **永不变** | 色板语义、字号层级、间距、圆角、描边、动效曲线、图标语言、**卡面信息位置** | 工程 + 设计共同守 |
| **风格卡**（每纪元一张） | 每纪元替换 | 色板取值、材质、光源逻辑、装饰母题、图像处理、字体族 | 美术 |

> **一句话规则**：**纪元改变外观，不改变理解方式。** 玩家学一次语法，之后每换一个纪元都在享受新风格，而不是重新学一遍界面。

## 二、色彩 token（语义优先，值可被风格卡覆盖）

**为什么用语义名而不是颜色名**：`--power` 在原子纪是薄荷青，在磁带纪元可能是荧光绿——**语义不变，色相可变**。脚本与 SVG 里只允许引用语义名。

### 2.1 基底与文字

| token | 值（原子纪元风格卡 v1） | 用途 | 约束 |
| --- | --- | --- | --- |
| `--bg-base` | `#10161C` | 页面底 | 全站最暗 |
| `--bg-elev-1` | `#18212B` | 面板 | 必须亮于 `--bg-base` |
| `--bg-elev-2` | `#212E3A` | 卡片底 / 浮起面 | 必须亮于 `--bg-elev-1` |
| `--text` | `#F3EDE1` | 主文字（奶油白，出自原子纪的"奶油白打底"） | 对三种背景 ≥ 4.5:1 |
| `--text-dim` | `#A9A395` | 次级文字 | 对三种背景 ≥ 4.5:1 |
| `--text-faint` | `#9E9889` | 弱文字（脚注/标签） | 对三种背景 ≥ 4.5:1；**它同时是文字可访问性下限，不得再暗** |
| `--line` | `#2A3742` | **装饰**分隔线（1px） | 不受 3:1 约束（刻意保留低对比度以免界面变吵） |
| `--line-strong` | `#6F7B89` | **交互控件**边框 | 对三种背景 ≥ 3:1（WCAG 1.4.11），**不得用 `--line` 代替** |

### 2.2 语义色（游戏语言直接映射到颜色）

| token | 值 | 含义 | 为什么是这个色 |
| --- | --- | --- | --- |
| `--power` | `#4FD1C5` | **电力**（本回合能做的事） | 薄荷青——契合原子纪"薄荷绿打底"的洁净语义 |
| `--residue` | `#FF6B35` | **残渣**（留在地图上的代价） | 放射橙——契合"高饱和放射色"的警示语义 |
| `--accent` | `#E4572E` | 主强调（**同时只允许用于一个焦点**） | 放射红橙；与 `--residue` 同族但更沉稳，避免两个橙色打架 |
| `--focus` | `#8AB4F8` | **焦点环 / 键盘导航可见性** | 与 `--accent`、`--power`、`--residue` **都不同色相**，确保焦点指示不会被误读成语义色；对三种背景 ≥6.5:1 |
| `--warn` | `#FFC857` | 警示（危险阈值，如降级区即将吞掉塔位） | 黄——介于"正常"与"危险"之间 |
| `--ok` | `#7BD389` | 正常 / 洁净 | 绿——与 `--power` 的青区分开，避免语义混淆 |

> **`--power` 与 `--ok` 必须可区分**：青（#4FD1C5）与绿（#7BD389）在色相上很近，因此规定——**两者永不在同一控件内作为唯一区分手段**，必须同时有图标或文字标签（这也是无障碍要求）。
>
> **为什么 `--focus` 单列**（来自视觉实现者的实测反馈）：焦点环若借用 `--accent`，就会与"单一焦点强调色"的规则打架；若借用 `--power`，则焦点会被误读为"电力状态"。焦点指示是**可用性基础设施**，不能复用语义色。

### 2.3 材质与表面（由**风格卡**填写值，语义名固定）

材质隐喻会产生明暗变体（镀铬渐变、塑料半透明、压暗表面）。**若不给它们语义名，每个执行者都会各自调灰**——所以这里给名字，值仍属风格卡。

| token | 值（原子纪元 v1） | 用途 | 约束 |
| --- | --- | --- | --- |
| `--surface-sunken` | `#0B1116` | 凹槽 / 输入框底 / 压暗区 | 必须**暗于** `--bg-base` |
| `--material-mid` | `#39485A` | 镀铬/金属渐变的中调 | 供材质渐变使用；**不得**用作控件边框（那是 `--line-strong` 的职责） |
| `--material-hi` | `#F3EDE1` | 材质高光 | 与 `--text` 同族，避免引入新色相 |
| `--material-shadow` | `#10161C` | 材质暗部 / 投影 | 与 `--bg-base` 同值，可随风格卡改变 |

## 三、文字层级（字号 / 行高 / 字重）

字体族：`ui-monospace, "IBM Plex Mono", Menlo, monospace`——**技术档案感**是复古未来的核心语气（仪表、清单、公告）。

| 层级 | 字号 | 行高 | 字重 | 用途 |
| --- | --- | --- | --- | --- |
| `title-1` | 28px | 1.25 | 700 | 页面主标题、纪元名 |
| `title-2` | 20px | 1.3 | 600 | 面板标题、卡名 |
| `body` | 15px | 1.6 | 400 | 正文、卡牌说明 |
| `caption` | 13px | 1.5 | 500 | 标签、数值单位、脚注 |
| `number-lg` | 32px | 1.0 | 700 | 卡面费用、结算数字（**数字必须等宽**，避免跳动） |

**一条待复核项（S3 截图验收发现）**：`body` = 15px 对**中文**偏小（中文常见正文下限约 16px）。
当前保留 15px 的理由是"技术档案感 + 与 5 级阶梯的整体比例"，**但这是可被推翻的**：
若人工验收（5 人评审）认为正文读起来吃力，把 `body` 提到 16px、`caption` 提到 14px 即可——
改这一处会同时触发 `docs/04` 与 `tokens.json` 的对账闸门，不会漏改。

**规则**：字号只有这 5 级，不新增；`number-lg` 必须用 `font-variant-numeric: tabular-nums` 或等宽字体保证数字不抖动。

### 3.1 唯一的例外：**评审标注级**（不属于产品界面）

评审图（如 [`style-samples/`](style-samples/)）需要 8–10px 的灰色注释（十六进制值、分区说明）。**这类文字不属于五级阶梯，也不得出现在产品界面里。**

- 规则：评审图里的标注文字必须**加显式前缀**（本项目用 `【评审标注】`），并在 SVG 的 XML 注释里声明其不属于字号阶梯；
- 产品界面**禁止**小于 `caption`（13px）的正文级文字。若胶囊标签、卡号、角标确实需要更小字号，**必须先改本节**（新增一级）而不是就地写 9px——否则字号阶梯会被逐次侵蚀。

## 四、间距 / 圆角 / 描边（尺度只有这些）

| 项 | 值 | 说明 |
| --- | --- | --- |
| 间距 | **4 / 8 / 12 / 16 / 24 / 32** | 4 的倍数；不允许出现 5、7、10 这类值 |
| 圆角 | **4px（小控件）/ 8px（面板、卡框）** | 不得使用大圆角；圆润感来自**形状与材质**，不来自超大圆角 |
| 描边 | **1.5px** | 全部控件与卡框统一；禁用 1px 交互边框（易与 `--line` 混淆） |
| 阴影 | 仅 `0 2px 8px rgba(0,0,0,.35)` | 只用于浮起面（弹窗、拖拽中的卡）；不做多层阴影 |

## 五、动效（时长与曲线是语法的一部分）

| token | 值 | 用途 |
| --- | --- | --- |
| `dur-fast` | 120ms | 悬停、按下、开关 |
| `dur-base` | 220ms | 面板展开、卡牌入槽 |
| `dur-slow` | 420ms | 场景切换、纪元切换 |
| `ease-standard` | `cubic-bezier(.2,0,.2,1)` | 默认 |
| `ease-emphasis` | `cubic-bezier(.2,0,0,1)` | 结算、评级揭示 |

**约束**：所有动效必须响应"减少动态效果"（Godot 侧读系统设置 / 提供显式开关）；扫描线等持续纹理必须可关闭（避免眩晕与耗电）。
**焦点可见性**：键盘/手柄导航必须有可见焦点环，用 `--focus`，**描边 2px + 1px 偏移**；不得用 `--accent`（与"单一焦点强调"规则打架）或 `--power`（会被误读为电力状态）代替。

## 六、图标语言

- **几何化、单色填充、1.5px 描边**，画布 24×24，光学对齐；
- 每个图标必须有可读的文字标签或 tooltip——**图标不得是可访问性的唯一载体**；
- 图标集合与语义名一一对应（如 `icon.residue`），纪元可换画风但**不得改语义**。

## 七、卡面信息位置规范（**最硬的一条**）

线框见 [`style-samples/03_卡面_原子纪元.svg`](style-samples/03_卡面_原子纪元.svg)。**位置固定，纪元只改材质与颜色**：

```
┌──────────────────────────────┐
│ 卡名（title-2）        费用 │  ← 顶栏 64
├──────────────────────────────┤
│                              │
│        插画区（300）         │
│                              │
├──────────────────────────────┤
│ 关键词标签（胶囊形，44）     │
├──────────────────────────────┤
│ 电力 │ 残渣 │ 战力           │  ← 数值块 90（三格等宽）
├──────────────────────────────┤
│ 说明文本（body，120）        │
├──────────────────────────────┤
│ 阵营                卡号     │  ← 底栏 48
└──────────────────────────────┘
```

**为什么把它写进契约**：卡牌游戏的**可读性全靠位置**。玩家不该在每个新纪元里重新找"这张卡要几点费用"。

**卡面尺寸与余量（定死，避免实现者自行决定）**：设计尺寸 **520×720**；六段合计 **666**（64+300+44+90+120+48）；**余量 54px = 上外边距 26 + 下外边距 28**（视觉上略偏下，让卡底更稳）。若纪元需要更高的卡，**保持六段顺序与相对比例**，只放大插画区。

**窗口背景（S3 落地时补的一条）**：Godot 没有"全局背景色"设置，必须由场景里的根面板提供。
因此约定：工程主题里注册一个 `RootBackground` 面板类型，其 `panel` 样式固定资产为 **`--bg-base`**；
**每个场景的根必须是一个 `PanelContainer`，并通过 `add_theme_stylebox_override("panel", …)` 显式套用它**。

> ⚠️ **不要用 `theme_type_variation`**（S3 实测教训）：主题里 `RootBackground` 的取值经断言确认是对的，
> 但设了 `theme_type_variation` 的节点**渲染时仍走 `PanelContainer` 的默认样式**——静默回落、无任何报错，
> 只有读像素才发现。因此本工程规定：**背景底色一律用显式样式覆盖**，不依赖变体解析。
> 这条也是"PNG 也是闸门"这条做法的来历：`./run.sh shot` 会在写文件前断言渲染底色等于契约值。
理由：若不约定，每个场景各写一个 `ColorRect` 就会各自取色，`--bg-base` 名存实亡（这一条是截图验收时发现的）。

**控件底色取值（S3 截图验收补的一条）**：按钮/输入框等交互控件的常态底色用 **`--bg-elev-2`**、悬停用 **`--material-mid`**。
理由：`--bg-elev-1` 对 `--bg-base` 的亮度比只有 **1.90**，放在根背景上**几乎看不出有底色**（按钮会像一段纯文字）；
而 `--bg-elev-2` 达到 **3.35**，`--material-mid` 更进一步且与原子纪的"镀铬"材质语言一致。
**这条是看截图才发现的**——数值断言当时全绿。

**关键材质 token 的分工（避免一身二职）**：`--line-strong` **只用于控件边框**；镀铬/金属渐变的中调必须用 `--material-mid`。理由是：材质要长期稳定，而边框色会随无障碍审计调整——两者绑在一起会导致"改边框顺手破坏材质"。

**费用数字的颜色**：**不设专属色**。费用用 `--text` + `--line-strong` 圆环表示；因为 `--power` / `--residue` 已被双资源语义占用，给费用另配一色会让玩家误以为它是第三种资源。

## 八、风格卡接口（每纪元必须填满的槽位）

一个纪元只要替换下面 8 项，就算换了一套风格——**其余一律不动**：

| # | 槽位 | 原子纪元 v1 |
| --- | --- | --- |
| 1 | **色板取值**（覆盖语义 token 的值） | 铸造蓝黑基底 + 奶油白/薄荷绿文字 + 放射橙强调 |
| 2 | **材质隐喻** | 镀铬 + 搪瓷 + 塑料 |
| 3 | **光源逻辑** | 上方洁净白光；长而柔的镀铬反射带（近白→中灰→冷蓝灰） |
| 4 | **装饰母题** | 原子图案：星爆纹 / 电子轨道 / 放射线 / 太阳形（角落与底纹，不压信息） |
| 5 | **图像处理** | 扫描线（每 4px、透明度 ≈0.04）+ 极轻噪点 |
| 6 | **字体族** | 本纪元沿用语法层等宽字体（纪元可换，但字号层级不变） |
| 7 | **UI 外壳** | 仪表盘 + 指示灯 + 胶囊按钮（"按钮生活"的具象化） |
| 8 | **音频语气** | 示波器音调 + 广播旁白 |

## 九、反模式（明确禁止，写下来是为了将来不必重新讨论）

| 反模式 | 为什么禁止 |
| --- | --- |
| 用"复古未来"四个字解释风格 | 它是二十种互相冲突的风格，不是风格 |
| 纪元之间只换颜色 | 玩家会读成换皮 DLC，复购率为 0 |
| 在本纪元里混搭别的纪元的装饰 | 这是拼贴，不是风格卡；只允许在特定模式（未来残片/远征）里出现 |
| 改卡面信息位置 | 破坏可训练性——玩家每次都得重新找信息 |
| 引入 token 之外的新色相 | 一致性崩塌的开始；需要新语义时先改契约 |
| 依赖超大圆角做"复古感" | 圆润感来自形状与材质，不是圆角半径 |
| 把 `--line` 用在交互控件上 | 对比度不足（1.4.11），既有项目已在此栽过一次 |

## 十、验证方式（机器守，不靠肉眼）

`./run.sh contrast`（[`tools/check_contrast.py`](../tools/check_contrast.py)）逐项计算并断言：

1. **WCAG 2.1 对比度**：全部文字 token × 三种背景 ≥ **4.5:1**；`--line-strong` 与语义色（含 `--focus`）× 三种背景 ≥ **3:1**；
2. **层级亮度顺序**：`--bg-base < --bg-elev-1 < --bg-elev-2`；`--text-faint < --text-dim < --text`；`--line < --line-strong`——**只查对比度会漏掉"颜色达标但与相邻层级挤在一起、用户分不出主次"这种退化**；
3. **样张色彩不能越界**：扫描 `docs/style-samples/*.svg`，其中出现的**每一个十六进制色值都必须能追溯到本文档的某个 token**。
   为什么需要这一条（来自视觉实现者的如实反馈）：**"提示词说四级、契约说五级"这种不一致会让执行者只能自编值**；颜色上更隐蔽——自调一个"看起来差不多"的灰，肉眼发现不了，但十张样张之后就会出现十种灰；
4. **检查器自检**：内置负向用例（故意给不达标的组合、被压平的层级、越界的样张色值，断言会报错）。
   一条实测教训：自检**第一版是假通过**——三条负向用例确实都报错了，但报的是**另一条无关错误**。所以负向用例必须断言**错误类型**，不能只断言"有错"。

> 立场（继承既有教训）：**检查器本身也要被校验**；并且**不为了让审计通过而破坏设计**——装饰性分隔线（`--line`）刻意保持低对比度，因为把它调亮会让界面又脏又吵。
