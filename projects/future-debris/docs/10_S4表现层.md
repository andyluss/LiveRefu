## 一、分层（与 02 一致，这里补充"谁碰什么"）

```
scenes/app/battle.tscn ──> app/battle_screen.gd     装配 + 输入（不知道规则细节）
                                  │
                    view/battle/battle_driver.gd      时序：什么时候 tick、什么时候刷新
                                  │
        ┌─────────────────────────┼─────────────────────────┐
   view/battle/battle_hud     view/battle/battle_board_view   view/battle/battle_hand_view
   （只读 battle，画读数）      （只读 battle，画塔位）          （只画，发 card_clicked 信号）
                                  │
                          core/（纯逻辑，无渲染依赖）
```

**三条铁律**：

1. **view 不改 battle 状态**——出牌必须走 app → driver → `CardPlayer`（否则"能出什么牌"会有两套判断）；
2. **几何只有一个来源** [`Geom`](../game/scripts/view/battle/geom.gd)——塔位矩形被棋盘、命中判定、覆盖层共用，写两遍必然错位；
3. **取色只从 token** [`BattlePalette`](../game/scripts/view/battle/battle_palette.gd)——不写字面量颜色，否则换纪元会出现"半新半旧"。

## 二、已实现（可直接跑）

| 件 | 内容 |
| --- | --- |
| **HUD** | 电力 / 残渣（含降级区规模）/ 波次进度（第 N 波 · 剩余 X/Y）/ 基地生命条（颜色分级）/ **生效规则**（规则卡是纪元差异的载体，必须可见） |
| **战场** | 8 个固定塔位；空格显示"空塔位 N"；已放置显示卡名、**有效战力**（已扣残渣惩罚）、每回合残渣；每格底部有**残渣热力条**（0 点不画） |
| **手牌** | 费用（走 `CardCost`，含规则减费）/ 战力 / 供电 / 残渣；**付不起的牌变暗**；选中态用 `--focus` |
| **交互** | 点手牌选中 → 点塔位放置；空格推进一回合 |
| **主题** | 全部文字与颜色来自编译后的 `Theme`（token 契约），字号用 5 级 type variation |

## 三、视图验收（第 8 道闸门）

`./run.sh scene` 断言两类事：

| 类型 | 断言 |
| --- | --- |
| **几何** | 塔位数量与 `BoardSystem.MAX_SLOTS` 一致；**每个塔位中心点都能解析回自身**（点 3 号位不会放到 4 号位）；棋盘外的点不命中任何塔位 |
| **取色** | 战场色取自 token；**残渣为 0 时热力色必须是背景色**（否则"干净格"看起来像"有污染"）；热力随数量变化 |
| **装配** | 战斗界面真的实例化成功，且**找得到 HUD / 战场 / 手牌三块视图**——只数子节点等于没验（一个空 Shell 也会通过，那正是白屏的形态） |
