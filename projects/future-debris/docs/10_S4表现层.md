## 一、分层（与 02 一致，这里补充"谁碰什么"）

```
scenes/app/battle.tscn ──> app/battle_screen.gd     装配 + 输入（不知道规则细节）
                                  │
                    view/battle/battle_driver.gd      时序：什么时候 tick、什么时候刷新
                                  │
        ┌─────────────────────────┼─────────────────────────┐
   view/battle/battle_hud     view/battle/battle_board_view   view/battle/battle_hand_view
   （只读 battle，画读数）      （只读 battle，画塔位）          （只画，发 card_clicked 信号）
                                  │
                          core/（纯逻辑，无渲染依赖）
```

**三条铁律**：

1. **view 不改 battle 状态**——出牌必须走 app → driver → `CardPlayer`（否则"能出什么牌"会有两套判断）；
2. **几何只有一个来源** [`Geom`](../game/scripts/view/battle/geom.gd)——塔位矩形被棋盘、命中判定、覆盖层共用，写两遍必然错位；
3. **取色只从 token** [`BattlePalette`](../game/scripts/view/battle/battle_palette.gd)——不写字面量颜色，否则换纪元会出现"半新半旧"。

## 五、动效与音效（S4 第二批）

### 5.1 音效：**程序生成，不放素材**

[`tools/gen_sfx.py`](../tools/gen_sfx.py) 生成 8 个 16-bit PCM 单声道音效（22050Hz）到 `game/assets/sfx/`，
并写一份 `manifest.json`（用途 + 时长 + **文件 sha256**）。理由有三：
**① 仓库不放二进制素材、不引授权问题**（与"字体不放二进制"同一立场）；
**② 复古未来的听感本就来自合成器与示波器音调**，程序生成正合题材；
**③ 参数化意味着"某次事件该多响、多长"可以被 diff 与评审**，而不是一段无法审阅的波形。

生成器带 4 个自检：幂等 / 时长正确 / **首尾样本接近 0（无爆音）** / 噪声层确为噪声。

| 事件 | 音效 | 设计意图 |
| --- | --- | --- |
| `place` | 上行短音 | "装上了" |
| `deny` | 低短下行 | **操作被拒也要有反馈**——"点了没反应"最让玩家困惑 |
| `clean` | 清亮双音 | 清理的爽感 |
| `residue` | 闷响 + 低频噪 | 不和谐，提示代价 |
| `zone` | 低沉扫频 | 威胁升级 |
| `wave_clear` | 三音上行 | 成就感的短句 |
| `leak` | 下行警示 | 损失 |
| `grade` | 明亮四音 | 收束 |

### 5.2 动效：参数只能来自 token

[`Motion`](../game/scripts/view/fx/motion.gd) 把 token 的时长与曲线转成 Godot 的 Tween 参数；
[`EventTicker`](../game/scripts/view/fx/event_ticker.gd) 把"刚刚发生了什么"排成**最多三行、各占一行、逐行上移淡出**。

**为什么不用自由摆放的浮字（实测教训）**：一回合里常常同时发生几件事（清波 + 降级区扩张 + 受伤），
自由摆放会让它们叠在一起互相压字，**比不显示更糟**。排成固定行位后，任何组合都不会重叠。

### 5.3 三条实测教训

1. **截图前必须等开局淡入结束**：否则截到的是半透明画面与背后默认灰的混色，
   底色读成 `#202429` 而契约是 `#10161c`——**差点被误判成主题 bug**。现在 `Shell.last_tween` 可供等待。
2. **Godot 会把"嵌套调用里的 nil 方法"报在调用方的下一行**：本次报错指向 `_popups.setup(...)`，
   而真正为 null 的是另一个变量 `_ticker`（我建的是 `ticker`、用的是 `_ticker`，两个名字）。
   定位办法：逐个加 `has_method` 守卫，而不是相信行号。
3. **两个"假通过"的检查**：哈希核对最初只查长度（等于没查）；后来又出现**Python 算 PCM、Godot 算整个 WAV 文件**
   的口径不一致（八条全不一致——这条反而是好事，说明核对真的在生效）。

## 六、卡面版式与插画位（S4 第三批）

### 6.1 六段版式有机器断言

卡面尺寸与六段高度是**契约**（[04 §七](04_视觉语言与设计token.md)）：`64 / 300 / 44 / 90 / 120 / 48`，
和 **666**，加余量 54（上 26 + 下 28）等于 **720**。这条现在由第 8 道闸门断言：

| 断言 | 为什么 |
| --- | --- |
| 六段之和 = 666 | 任何一段被改动而忘了调余量，卡面就会溢出或留白错位 |
| 六段 + 余量 = 卡高 | 同上，且保证"位置就是可读性"这条设计约束不被悄悄破坏 |
| 紧凑比例在 0..1 | 手牌是"缩小版卡面"，不是另一种卡 |

### 6.2 手牌与卡牌库**复用同一套版式**

手牌（`battle_hand_view`）现在**不再自己画一套卡面**，而是用 [`CardView`](../game/scripts/view/card/card_view.gd) 的紧凑模式。
理由：两处各画一套时，同一个字段会在两处显示不同，且改版式要改两遍（漏一处就长期不一致）。

新增**卡牌库**界面（`./run.sh shot card_gallery.png --scene=res://scenes/app/card_gallery.tscn`）：
一屏看全部卡面，顶部显示"插画就绪 N / M"。

### 6.3 插画位：**零登记**的资源约定

约定：`assets/cards/卡号.png`（例 `RC-ATOMIC-001.png`）。
- **为什么按卡号命名而不是登记清单**：清单会与卡表脱钩（加了卡忘了登记），按卡号命名是零登记的——放进去就生效。
- **缺图不是错误**：美术尚未启动时界面必须能带着占位正常运行；占位框里写着卡号，
  **它就是美术的出图任务单**。缺哪些图由 [CardArt](../game/scripts/view/card/card_art.gd) 的 `missing_ids` 可查。

### 6.4 又一次"截图才发现"

卡牌库第一版按 3 列排（520×3 = 1560 > 1280），**第三张被裁掉**；且 720 高的窗口装不下 720 高的卡。
→ 改为**按窗口宽度算列数** + 外层 `ScrollContainer`。
这条顺带说明：**卡面契约的 520×720 放不进 1280×720 的窗口**，
全尺寸卡面只适合卡牌库/详情，对局内必须用紧凑模式。
