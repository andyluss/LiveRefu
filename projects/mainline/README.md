# 主线纲领 · 决策与讨论空间

> **这是什么**：工作区里"下一款主线产品"的**纲领**——它不是某一款具体游戏，而是**容纳它（以及它的后继者）的决策空间**。
> 这里存两样东西：**建议**（提案、论证、数据）与**决定**（裁决、理由、代价）——建议面向讨论，决定面向执行。
> **为什么是"纲领"而不是"某个项目"**：具体产品可能更换，但**决策历史必须长期留存**——
> 否则每换一次方向，上一次"为什么这么决定"就得重新推一遍。因此本目录**不随任何单个项目的生命周期结束**。
> **当前承载的具体项目**：[`future-debris/`](future-debris/README.md)（《未来残片》，正式立项，代号 `future-debris`）。

## 一、怎么用这个空间

| 你想做的事 | 看哪 |
| --- | --- |
| 快速知道"要决定哪几件事、现状如何" | [00_决策总表](docs/00_决策总表.md) |
| 读某条建议的完整论证 | `docs/01`–`docs/09` 对应篇 |
| 直接回我的问题 | 各篇末「待裁决问题」；或一次回答 [决策总表](docs/00_决策总表.md) 的 Q1–Q12 |
| 记录一次讨论 | 在 `docs/discussions/` 下新建 `YYYYMMDD-HHMM-关键词.md`（模板见第五节；时间规则见 [R06](../../rules/R06-time.md)） |
| 查询某个词什么意思 | [08_共同语言与命名](docs/08_共同语言与命名.md) |

**约定**：**一条建议一个文件**；裁决后**不回删原文**，在原文上追加「裁决」小节（日期 + 选择 + 理由），并在 [00_决策总表](docs/00_决策总表.md) 与根 [`CHANGELOG.md`](../../CHANGELOG.md) 记账——保留"当时的判断"，将来才能看出哪里错了。

## 四、与工作区其它部分的关系

- 本目录受工作区根规则约束：[`rules/R01`](../../rules/R01-docs-convention.md)（文档体例与相对链接）、[`rules/R02`](../../rules/R02-git-convention.md)（提交信息）、[`rules/R03`](../../rules/R03-link-validation.md)（链接校验）、[`rules/R05`](../../rules/R05-changelog.md)（变更日志）。
- **题材权威**在 [`doc/retro-futurism/`](../../doc/retro-futurism/README.md) 与 [`doc/punks/`](../../doc/punks/README.md)：本目录引用它，**不复制、不改写**它的结论。
- **既有项目可复用、可并入，但不默认继承**：[`../refu-game-001/`](../refu-game-001/README.md)（卡片塔防垂直切片，含 36 张卡面与四道验收闸门）、[`../tomorrows-channel/`](../tomorrows-channel/README.md)（氛围陪伴应用）、[`../website/`](../website/README.md)（《未来档案》网站，已暂停）、[`../../indie/live-rpg/`](../../indie/README.md)（活世界工作台，独立仓库）。是否并入由 Q2/Q4 决定。
- **目录结构（2026-10-01 起）**：本目录是**纲领**；每个具体项目是它的一个子目录，**按代号命名**（符合 [08 §三](docs/08_共同语言与命名.md) 的"项目目录 = `projects/<代号>/`"——`mainline/` 本身不是项目、故不受此约束，其子目录才是项目）：

  ```
  projects/mainline/            ← 纲领：决策与讨论历史（长期留存，不随项目结束）
  ├── README.md  CHANGELOG.md   ← 纲领自己的说明与日志
  ├── docs/                     ← 提案、裁决、调研；discussions/ 存讨论记录
  └── future-debris/            ← 当前具体项目（代号即目录名）
      ├── README.md  CHANGELOG.md   ← 项目自己的说明与日志
      ├── docs/  game/  tools/  run.sh
  ```

- **如何容纳下一个具体项目**：在 `projects/mainline/<新代号>/` 建立新项目（自带 README / CHANGELOG / docs / 可运行实现），
  **本目录的 `docs/` 不动**——决策历史是纲领的资产，不属于任何单个项目。
  若下一个项目取代 `future-debris` 成为主线，`future-debris/` **保留在原处**（归档，不删除），并在 [00_决策总表](docs/00_决策总表.md) 记录这次更替的理由。
- **执行文档随项目走**：纲领只出"要做什么、为什么"，具体怎么实现（工程结构、数据契约、验收闸门）写在项目自己的 `docs/` 里。

## 五、讨论记录模板（新建文件时复制）

> **命名与时间**：文件名 `YYYYMMDD-HHMM-关键词.md`（例 `20261002-0915-玩法裁决.md`），正文首行用 `HH:MM`。
> **时间必须精确到分，且取自该记录的首次提交时间**（`git log --diff-filter=A`）——权威约定见
> [R06 时间与时间戳约定](../../rules/R06-time.md)，并由 [`tools/check_time_naming.ts`](../../tools/check_time_naming.ts) 机器校验。

```markdown
# 讨论记录 · YYYY-MM-DD HH:MM · <主题>

- 参与：<人 / 角色>
- 关联：<Q编号 或 文档链接>

## 结论
<一句话；若未收敛写"未收敛，下次继续">

## 论点与依据
- …

## 分歧与未决
- …

## 下一步
- [ ] …
```
