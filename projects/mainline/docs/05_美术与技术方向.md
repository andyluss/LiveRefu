# 05 · 美术与技术方向（主线项目）

> 回答：**长什么样**（Q6）、**用什么做**（Q7）、**AI 在哪里出力、在哪里不许它出力**。
> 日期：2026-09-30 ｜ 状态：**Q7 已裁决**（Godot 4.x + 表驱动）；Q6 待裁决（建议在 S3 动手做表现层前定）

## 一、起点：现有视觉的真实水平

诚实评估（基于 [02 §1](02_资产盘点与杠杆.md) 的存量）：

- **现有资产是"工程化的好看"，不是"能卖的美术"**：SVG 程序化出图能保证一致性、可 diff、可批量，但缺乏手绘的呼吸感与商业海报的冲击力。
- **它的真正价值是管线**：*SVG/模板为源 → 位图为产物 → 一键批量导出* 这条链条，在美术方向确定后价值极大（换风格卡即可重出全量）。
- **它已证明"批量一致性"可达**（36 张卡面 + 6 张地图 + 汇总图），但没有证明"单图能打"。

> 结论：**美术不是从零开始，而是从"管线已有、风格未定"开始**。所以 Q6 的重点不是"用什么工具"，而是**风格如何统一且可复制**。

## 二、Q6 · 复古未来的统一化策略

复古未来的根本困难：**它不是一个风格，是二十个互相冲突的风格**。任选其一则窄，混用则脏。三种解法：

### 候选 A：选一个时代，做纯正

- **是什么**：全程原子朋克（或磁带未来），视觉如出一辙。
- **优点**：辨识度最高、美术成本最低、营销一句话说完。
- **代价**：与 Q4-C（多纪元）冲突；纪元之间无法靠视觉区分，只能靠机制。
- **适配度**：中。

### 候选 B：拼贴（Collage）——所有时代同框

- **是什么**：画面里同时出现 1890 的飞艇与 1990 的 CRT，以"时代错置"为美。
- **优点**：最"复古未来"，最有艺术野心。
- **代价**：**极难保持可读性**（UI、单位、地形互相打架）；玩家会觉得"乱"；制作成本高（每个纪元都要画别的纪元的元素）。
- **适配度**：低（作为全局策略）；可作为**特定关卡/特定纪元**的例外。

### 候选 C：纪元风格卡 + 共享语法层（推荐）

- **是什么**：把视觉拆成两半——
  - **风格卡（每纪元一张，允许完全不同）**：色板、材质、光源逻辑、字体族、装饰母题、图像处理（噪点/扫描线/色偏/纸张纹理）。
  - **语法层（全局唯一，永不改变）**：UI 布局网格、信息层级、动效曲线与时长、图标语言、卡面结构（费用/数值/关键词位置固定）。
- **为什么推荐**：
  - **玩家学一次语法，享受多种风格**——这正是"综合性"的正确形态（像一套丛书的不同卷，而不是拼贴画）；
  - **成本可控**：新增纪元＝设计一张风格卡（半天到两天）+ 复用语法层；满足 [03](03_玩法与经济循环.md) 的 C3；
  - **保护可读性**：无论风格多花，信息位置不变；
  - **工程可落地**：语法层可写成设计 token（与《明日档案》的 `theme.css` 同源思路），风格卡＝一组 token + 一组素材生成参数。
- **代价**：需要**先做语法层**（前期一段"看不见成果"的投入）；风格卡设计需要真正的美术判断，AI 只能加速不能替代。
- **适配度**：高。

> **推荐 C**。并且建议：**语法层先行**（P1 就要有），因为它是"加法成本递减"的技术前提。

### 视觉差异化的三条具体建议

1. **给每个纪元一个"物质隐喻"**：原子纪元＝镀铬与塑料；磁带纪元＝磁带与静电；柴油纪元＝铆接钢与机油。材质是比颜色更强的记忆点。
2. **UI 就是世界观**：复古未来的界面本身是卖点（CRT 菜单、磁带播放器、软盘图标）。建议每个纪元有一套"界面外壳"，而内部控件语法不变。
3. **动效是低成本的辨识度**：扫描线、机械指针、磁带卷动的动效比高清插画便宜得多，且在短视频里更显眼（[06 §2](06_发行宣发与玩家互动.md)）。

## 三、Q7 · 技术栈与数据管线

### 引擎

| 候选 | 优点 | 代价 |
| --- | --- | --- |
| **A：Godot 4.x（推荐）** | **已有两条成熟工程线**（[`refu-game-001`](../../refu-game-001/README.md)、[`tomorrows-channel`](../../tomorrows-channel/README.md)）；无授权费与抽成；GDScript 便于 AI 大量读写；无头模式可做**自动化验收**（本工作区已跑通 19 项用例）；导出 PC/移动/Web 齐全 | 3D 与高端渲染弱于 Unreal；生态与插件少于 Unity |
| B：Unity | 生态最大、招聘容易、商用资源多 | 授权与政策风险；既有资产全部作废；AI 读写 C# 项目成本更高 |
| C：自研 / Web（Three.js / Godot Web） | 完全可控、便于 Web 分发与 UGC | 自研引擎会把项目变成引擎项目；Web 端性能与商店渠道受限 |
| D：GameMaker / RPG Maker 等 | 上手快 | 不适合卡牌+防线+多纪元的组合与长期扩展 |

> **推荐 A**。理由的核心不是"Godot 更好"，而是**你的验证管线已经建在 Godot 上**——"无头跑完整局 + 逐字段对账 + 截图比对"这套东西比引擎本身更值钱。

### 数据管线（建议固化，直接继承 `refu-game-001` 的做法）

```
设定（doc/ 知识库）→ 策划表（TSV/CSV，人可读可 diff）
        ↓ （AI 辅助生成 + 人工裁决）
游戏数据表（版本化）→ 校验脚本（表 ↔ 策划文档逐字段对账）
        ↓
核心逻辑（无渲染依赖）→ 无头用例（数值断言）→ 表现层（截图/帧比对）
        ↓
美术：模板/SVG 为源 → 风格卡参数 → 位图产物 → 一键批量导出
```

**三条硬要求**（把"可持续"落到技术上）：
1. **核心逻辑不依赖渲染**（否则无法自动验收，AI 也无法高效改玩法）。
2. **数据表是唯一真相**（策划文档与表由脚本对账，禁止口头流传的数值）。
3. **风格卡参数化**（换纪元不重画模板，只换 token 与材质参数）。

## 四、AI 产能的边界（重要，且必须写清）

| 环节 | AI 出力方式 | **不许**由 AI 单独决定 |
| --- | --- | --- |
| 设定与文案 | 从知识库派生纪元条目、卡牌风味文本、Devlog 初稿 | 世界观的核心判断（什么是对、什么是错的取舍） |
| 数值与平衡 | 批量填表、跑模拟、生成胜率矩阵、找异常 | 最终平衡裁决（涉及玩家体验意图） |
| 代码 | 写核心逻辑、写验证脚本、重构 | 架构决策与"可验证"门槛的放宽 |
| 美术 | 批量出图、风格迁移、导出与对齐、素材整理 | **首发关键视觉的最终定稿**（主视觉、商店页首图） |
| 测试 | 生成用例、跑无头验收、像素比对 | 验收标准的降低（红线：不让"永远通过"的检查器存在） |
| 运营 | 素材复用、社区回复草稿、多语言初翻 | 与玩家的承诺与道歉（必须人写） |

**一条经验**（来自本工作区既有教训）：*检查器本身也要被验证*——一个永远返回"通过"的检查器比没有检查器更糟。

## 六、裁决

**2026-09-30 · Q7 裁决结果：候选 A（Godot 4.x + 表驱动管线）**（用户选择，按推荐项）。

- **决议**：引擎＝Godot 4.x；数据管线按 §三 的五段流程固化（知识库 → 策划表 → 游戏数据表 → 无头用例 → 表现层；美术走模板/风格卡 → 位图产物）。
- **理由**：既有的验证管线（无头跑完整局 + 表与文档逐字段对账 + 字节级截图对照）比引擎本身更值钱，换引擎等于把它全部作废；且无授权费与抽成。
- **代价（接受）**：3D 与高端渲染弱于 Unreal、生态小于 Unity——本项目的形态（卡组 + 防线 + 多纪元 2D/2.5D）不依赖这些。
- **推翻条件**：若 S5 的垂直切片在目标平台上无法达到性能与表现要求（例如需要大量 3D 实时渲染），则重估引擎，并记账"迁移成本"。
- **仍未决**：**Q6（美术统一化策略）**——本文推荐候选 C（纪元风格卡 + 共享语法层），建议在 S3 做表现层之前裁决；美术产能来源（自画 / 外包 / AI / 素材包改造）也仍待你回答（§五 补充 1）。

**2026-09-30 · Q6 裁决结果：候选 C（纪元风格卡 + 共享语法层）—— 方案已裁决，产能来源待你提供**

- **决议**：视觉拆成两层——**语法层**（颜色语义、5 级字号、间距、圆角、描边、动效、图标语言、**卡面信息位置**，永不变）与**风格卡**（色板取值、材质、光源、装饰母题、图像处理、UI 外壳、音频语气，每纪元替换）。**语义 token 优先**：脚本与素材只引用 `--power` / `--residue` 这类语义名，不引用颜色名。
- **已完成的落地物**（不是口号）：
  - [`future-debris 04 视觉语言与设计token`](../../future-debris/docs/04_视觉语言与设计token.md)：13 个 token + 5 级字号 + 卡面版式规范 + 8 个风格卡槽位 + 7 条反模式；
  - [`future-debris 05 美术产能与预算`](../../future-debris/docs/05_美术产能与预算.md)：四条产能路线比较 + 分阶段采购单 + 成本口径（一次性投入 vs 边际成本）；
  - **对比度闸门** `./run.sh contrast`：27/27 组合达标，且**实测抓出并修掉两个真缺陷**（见下）；
  - 视觉样张：[`style-samples/`](../../future-debris/docs/style-samples/)（语法层 / 风格卡 / 卡面）——用于"10 秒辨识 + 30 秒氛围"人工评审。
- **理由**：玩家学一次语法即可跨纪元，**纪元改变外观、不改变理解方式**；这是"加法成本递减"在美术侧的技术前提；也让"纪元 2 = 换皮"的风险变成可检测项。
- **代价（接受）**：前期有一段"看不见成果"的语法层投入；风格卡的最终质量仍需真正美术判断（AI 只能加速）。
- **推翻条件**：若 S3 的"同版式换风格卡"像素级比对证明语法层过死（某纪元确实需要不同信息布局），则放宽为"位置可微调、层级不变"并记账。
- **顺带发现的两个真缺陷（值得单独记住）**：闸门第一次运行就抓出——`--text-faint` 对 `--bg-elev-1` 仅 **4.43:1**（需 ≥4.5）、`--line-strong` 对 `--bg-elev-2` 仅 **2.82:1**（需 ≥3）。**后者与既有项目《明日档案》当年栽的是同一个坑**：交互控件边框误用了装饰用色。修复值分别为 `#9E9889` 与 `#6F7B89`。
- **仍待你回答（Q6 的另一半）**：**美术产能来源**——自画 / 外包 / AI 出量 / 素材包改造，以及可用现金量级与每周工时。见 [05 §七](../../future-debris/docs/05_美术产能与预算.md)。

**2026-09-30 · Q6 产能来源裁决：AI 出量 + 自画语法层 + 小额外包；工时不可估**

- **用户的三个回答**：① 产能＝**AI 出量 + 人工定稿（卡面）＋ 自己/同伴动手画（至少语法层）＋ 外包精修关键件**；② 现金＝**万元级人民币以内**；③ 工时＝**波动很大，无法估**。
- **据此确立的三条**：
  1. **语法层 / 风格卡 / UI 外壳必须自有**（AI 与外包只加速，不决定）；卡面走 AI 出量、只把现金花在"玩家会盯着看的那 20%"上（主视觉、Demo 封面、徽记、关键卡 3–5 张）。
  2. **路线图不承诺日历时间**（以冲刺为单位）——工时不可估这一条使日历承诺失去意义。
  3. **卡量做"阶梯"，不做一次性门槛**：T1 机制验证 12 张 → T2 可试玩 Demo 40–60 张 → T3 可发售底 120–150 张 → T4 契约 v2 的 200–300 张。任何一阶停下都不产生半成品债务。
- **新识别风险 R10**：**工时不可估 × 卡量门槛 = 交付风险**。缓解方式不是加班堆量，而是排序（阶梯）+ 优先做四个**便宜的体量杠杆**：规则卡、难度阶梯、每日种子挑战、未来残片。
- **与 M3 反例呼应**：《杀戮尖塔 2》以最大声量换 Mixed，差评集中在平衡与数值堆砌——**堆卡量买不到好评，规则与平衡才买得到**。
- **落地文档**：[`future-debris 06 产能预算与卡量阶梯`](../../future-debris/docs/06_产能预算与卡量阶梯.md)（含卡量算术、四个杠杆、对六冲刺的具体修改、外包采购纪律）。
