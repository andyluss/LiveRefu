## 一、术语表（建议冻结；改动须走裁决并记账）

| 术语 | 定义 | 不是什么 |
| --- | --- | --- |
| **纪元（Era）** | 一个可独立成立的内容单元：一个时代的世界观 + 一套专属规则 + 一条叙事线 + 一套视觉风格卡 | 不是"关卡包"，也不是"皮肤" |
| **旗舰纪元** | 体量最大、建立标准、作为基础版售卖的纪元 | —— |
| **短篇纪元** | 体量较小、复用旗舰纪元语法层与引擎的纪元，可独立定价 | 不是"半成品" |
| **纪元包** | 对外售卖的形态：一个短篇纪元或一组内容 | 不等于"纪元" |
| **风格卡** | 一个纪元的视觉规范：色板、材质、字体、装饰母题、图像处理参数 | 不是"参考图" |
| **语法层** | 全局唯一的 UI/动效/信息层级规范，永不随纪元改变 | 不是"主题" |
| **时代提案卡组** | 玩家的出战卡组；"提案"指玩家扮演的是向某个未来提交改造方案的人 | —— |
| **规则卡** | 改变本局规则（而非提供单位）的卡；纪元差异的主要载体 | 不是"buff 卡" |
| **挑战卡** | 玩家自选难度修饰（沿用 [`doc/refu-game-001`](../../../doc/refu-game-001/README.md) 的既有定义） | 不是"每日任务" |
| **未来残片** | 跨纪元连接物：在后一纪元可获得的、来自前一纪元的遗物卡/条目，让"世界在长大"可被玩到 | 不是"彩蛋" |
| **纪元契约** | 一个纪元最少必须包含什么（见 [03 §3](03_玩法与经济循环.md)） | 不是"排期" |
| **台词/旁白** | 叙事文本；"纪元电台"形式的音频叙事 | —— |
| **内部可玩** | 团队内能跑、能评估的构建，**不对外** | 不是"可发布" |
| **公开里程碑** | 每季度对外发布一次的东西（Devlog / 试玩 / 素材） | 不是"发布" |
| **宣发契约** | 任何对外素材必须包含一个"只有这个游戏才有的机制瞬间"（见 [06 §1](06_发行宣发与玩家互动.md)） | 不是"素材清单" |

## 二、与既有术语的关系（避免冲突）

- [`doc/refu-game-001/10_术语表.md`](../../../doc/refu-game-001/10_术语表.md) 已有"卡/族/羁绊/挑战卡/远征"等定义；**若 Q3 沿用卡组循环，则直接继承其术语**，本表只增补上层（纪元/风格卡/语法层/未来残片）。
- "赛季"一词**暂不使用**：它与"纪元"混淆，且暗示限时删除。若将来确有赛季制，另行定义并明确"赛季内容是否永久保留"。
- "DLC" 作为**售卖形态**词汇保留，作为**设计单位**一律用"纪元包"。

## 三、命名规范（工程侧）

- **项目目录**：`projects/<代号>/`（ASCII、小写、连字符；不阻塞于正式中文名）。
- **数据表文件**：`<era>__<domain>.tsv`（例：`atomic__cards.tsv`），保证排序即分组、脚本可枚举。
- **规则卡 ID**：`RC-<ERA>-<NNN>`；条目 ID：`EN-<ERA>-<NNN>`；风格卡：`SC-<ERA>-v<N>`。
- **版本**：内容单元独立版本（`era.atomic v1.2.0`）；整体版本用于商店（`1.0`）。变更走根 [`CHANGELOG.md`](../../../CHANGELOG.md)。

## 四、Q12 · 项目代号候选

代号的用途是**内部指称 + 目录名 + 商店页占位**，正式中文名建议推迟到 P2 之后（那时才知道要卖什么）。命名要求：ASCII 可写、无重名冲突、与题材相关但不过度承诺。

| 候选（英文） | 中文直译 | 含义指向 | 备注 |
| --- | --- | --- | --- |
| `future-debris` | 未来残片 | 被取消的未来的遗物 | 与核心机制同名，辨识度高 |
| `the-unbuilt` | 未建成者 | 从未兑现的未来 | 语义漂亮，但偏文艺、不易搜索 |
| `era-cartridge` | 纪元卡带 | 卡带＝纪元载体；复古介质 | 与"卡组"结构呼应 |
| `tomorrow-archive` | 明日档案 | 与既有网站《明日档案》**同名，需避开或整合** | 若 Q2 选择并入则反而自然 |
| `proposal-86` | 提案 86 | "向未来提交提案"＋年份感 | 冷感、独特，但语义门槛高 |
| `signal-19xx` | 信号 19XX | 从过去发来的广播 | 适合"纪元电台"路线 |

**我对代号的建议**：用 **`future-debris`（未来残片）** 作为内部代号——它与核心机制同名（好的代号应当能让团队记住最重要的那件事），并且在商店与搜索中不易撞名。

**正式名建议的候选方向**（P2 再定，此处仅记录方向）：
- 走"档案馆/广播站"意象（与知识库和网站同族）；
- 走"提案/计划书"意象（与玩法框架同族）；
- 避免直接使用"复古未来"四字（不可商标化、不可搜索）。
