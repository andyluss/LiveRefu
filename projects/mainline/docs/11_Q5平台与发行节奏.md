# Q5 · 平台与发行节奏（提案 v2）

> 状态：**✅ 已裁决（2026-10-08）＝方案 A**（这是 S5 发 Demo 的前置，越早定越省返工）
> 日期：2026-09-30 ｜ 关联：[06 产能预算与卡量阶梯](../future-debris/docs/06_产能预算与卡量阶梯.md)、[10 推进计划与并入清单](10_推进计划与并入清单.md)
> 立场：**给出推荐 + 代价 + 推翻条件，由你决定**

## 一、先把一个前提说清楚：**Demo 不是第一次公开露面**

这一轮查证（见文末来源）里最值钱的一条是：**Steam 商店页（Coming Soon）越早上线越好**——
Valve 自己的数据显示，商店页上线至少 6 个月的游戏，发行表现显著更好。
而 Next Fest 是**放大器、不是起动机**：以接近零的愿望单进场，一周只能拿到约 358 个愿望单；
若进场前有稳定的日增速（11–100），同期能拿到约 1,470 个。**差 4 倍。**

所以"什么时候发 Demo"这个问题应该被替换成：**"什么时候上线商店页 / 什么时候开 Playtest / 什么时候发 Demo"**。

| 阶段 | 目的 | 关键事实 |
| --- | --- | --- |
| **Coming Soon 页** | 开始积累愿望单 | 越早越好；页面本身是**转化工具**，不是公告板 |
| **Playtest** | 打磨 + 换评测 | **不触发愿望单通知、不影响评价、可随时开关**——最适合换小 KOL 评测 |
| **Demo** | 引爆 + 为 Fest 备弹 | 会触发**一次性**的愿望单通知邮件，别浪费在前戏上 |
| **Next Fest** | 一次性放大 | 一个游戏只能参加一届；进场前要有基础盘 |

## 二、三个候选方案

### 方案 A（**推荐**）：Steam 为主 + itch.io 做低压渠道

| 做什么 | 什么时候 |
| --- | --- |
| Steam 商店页（Coming Soon） | **S5 之前就上**（需要胶囊图 + 预告片 + 截图，见下） |
| Steam Playtest | S5：用 T2（40–60 张）的版本开 Playtest，收集反馈 + 换小 KOL 评测 |
| Demo 上架 | Playtest 跑通核心循环后（"Demo 内容 30 分钟–1 小时、卡在最精彩处"） |
| Next Fest | Demo 上架后覆盖一次（**唯一一次**） |
| itch.io | 同步放一个**免费**的旧版本，作为社区/开发日志的落地页（不是主要收入来源） |

- **成本**：Steam Direct **每款 100 美元**（可回收：该产品累计收入达 1,000 美元后返还），另需一台 macOS/Windows 打包与上传时间。
- **代价**：商店页一旦上线就要维护（胶囊图、截图、公告）；Playtest 会带来**必须回应**的反馈量。
- **为什么推荐**：它把"公开露面"与"发 Demo"分开，而这恰好是本项目**最缺的东西**——
  我们的验证一直是**自证**（闸门 + 自动玩家），从未有过**外部**信号。

### 方案 B：只上 itch.io，暂不碰 Steam

- **好处**：零成本、零审核、当天能发；适合"先看有没有人喜欢"。
- **代价**：**触达极小**，几乎拿不到真正的市场信号；而 itch.io 的愿望单/关注**不能迁移**到 Steam。
- **适用**：只想先给朋友与社区试玩、完全不考虑商业规模时。

### 方案 C：Steam 商店页 + Demo 一次做完（跳过 Playtest）

- **好处**：省掉 Playtest 这一轮往返。
- **代价**：Demo 的一次性通知被用掉时，**页面转化率还没验证过**——
  等于在"不知道封面/截图/预告片能不能留住人"的情况下花掉最贵的资源。
- **什么时候可以这么干**：如果 S4 之后我们已经有一条能用的预告片与胶囊图，且自信转化率不差。

## 三、我的推荐：**A，且先把"上商店页"当成 S5 的第一个交付物**

理由按重要性排序：

1. **它是唯一能拿到外部信号的动作**。本项目至今所有结论都来自内部闸门；
   "玩家想不想玩"必须由外部回答，而商店页的**点击→愿望单转化率**就是那个答案。
2. **它不依赖卡量达标**。商店页/Playtest 不需要 200 张卡；T2（40–60 张）就够撑起 30–60 分钟的 Demo。
   这与我们已确认的卡量阶梯（T2 作公开 Demo）**正好对齐**。
3. **Playtest 是零风险的试错渠道**：不触发通知、不影响评价。用它换小 KOL 评测，
   也是目前**唯一**适合我们（预算 ≤ 万元级、无发行商）的推广手段。
4. **Demo 的时间点由"能做出来"决定，而不是由日历决定**——这与我们"sprint 制、不承诺日历"的既定做法一致。

## 四、这件事对 S5 范围的影响（需要你确认）

如果采纳 A，S5 的出口物会从"发一个 Demo"变成**两个**：

| 出口物 | 内容 | 依赖 |
| --- | --- | --- |
| **① 商店页** | 胶囊图（多尺寸）、30–60 秒预告片、6–8 张截图、简介文案（中英）、标签 | **美术**（胶囊图与截图需要能看） |
| **② Playtest 版本** | T2 卡量（40–60 张）、可玩完整一局、设置与退出、基础音效 | 我们已有：一局闭环、8 关、配额 |

**这里有一个我无法替你决定的取舍**：①需要**胶囊图与预告片**，
而美术产能目前是"AI 量产 + 自绘语法层 + 少量外包"、**预算 ≤ 万元级**。
胶囊图是**最容易做砸**的一环（它决定点击率），我建议**外包 1 张主胶囊图**而不是 AI 量产。

## 五、需要你回答的三个具体问题

1. **采纳方案 A / B / C 中的哪个？**（我推荐 A）
2. **Steam 上架主体**：个人开发者账号，还是注册公司/工作室？（影响税务与后续合作）
3. **是否愿意为"主胶囊图 + 1 张横幅"单独外包？**（预算的一小块，但对转化率影响最大）

## 七、裁决（2026-10-08）

**选择：方案 A**——**Steam 为主 + itch.io 做低压渠道**。核心是把**"公开露面"与"发 Demo"分开**：

| 做什么 | 什么时候 |
| --- | --- |
| Steam 商店页（Coming Soon） | **S5 之前就上** |
| Steam Playtest | **S5**：用 T2 版本开，收反馈 + 换小 KOL 评测 |
| Demo 上架 | Playtest 跑通核心循环后（内容 30 分钟–1 小时，**卡在最精彩处**） |
| Next Fest | Demo 上架后覆盖 **唯一一次** |
| itch.io | 同步放一个**免费**旧版本，作社区/开发日志落地页（不是收入来源） |

**理由**：商店页可以先积累愿望单而**不暴露完成度**；Playtest 能在小范围验证核心循环再决定要不要投入 Demo；
**Next Fest 只有一次机会**，留给 Demo 上线之后而不是之前。

**代价**：商店页一旦上线就要维护（胶囊图、截图、公告）；Playtest 会带来**必须回应**的反馈量。

### 7.1 三个附带默认值（**AI 设定 · 均可推翻**）

> 这三个是**我替你设的默认值**，不是你的明确选择；当时即声明可推翻。写在这里是为了让"默认"也是**明示**的，而不是悄悄生效。

| 项 | 默认值 | 为什么这样设 | 推翻成本 |
| --- | --- | --- | --- |
| **Steam 上架主体** | **个人开发者账号** | 最先可行、无额外设立成本；商店页不因此受限 | 低——后续要合作或做税务安排时再改 |
| **主胶囊图 + 库徽标** | **外包 1 张主胶囊图 + 库徽标**，**不 AI 量产** | 胶囊图决定点击率，且是**最容易做砸的一环**（[§四](11_Q5平台与发行节奏.md) 已述） | 中——外包需要提前排期与预算 |
| **预算** | **≤ 万元级 RMB** | 含 Steam Direct $100（该产品累计收入达 1,000 美元后可回收）与胶囊图外包 | 中——超预算则重新评估是否自画 |

### 7.2 推翻条件

1. 若 **S4 之后拿不出一条能用的预告片与胶囊图** → 推迟商店页（退回方案 C 的低压路线）；
2. 若**预算显著超过万元级** → 重新评估胶囊图是否自画；
3. 若 **Playtest 反馈显示核心循环不成立** → **不进 Demo 阶段**，回 S4 改玩法（这正是 Playtest 先行的意义）。
