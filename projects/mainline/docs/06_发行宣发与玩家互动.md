# 06 · 发行宣发与玩家互动（主线项目）

> 回答：**怎么让人知道、怎么让人留下、怎么让玩家参与**（Q8、Q9）。
> 日期：2026-09-30 ｜ 状态：待裁决

## 一、宣发的核心困难

复古未来题材的宣发是**双刃剑**：

- **优势**：视觉天生适合截图与短视频；审美受众明确且活跃（合成波/蒸汽波/复古游戏社群）；素材复用率高（同一批美术可用于商店页、动态图、壁纸、音乐封面）。
- **劣势**：**"好看"是所有同类作品的共同点**——只靠氛围的商店页会被淹没；玩家看完截图会问"所以玩什么？"，答不出来就划走。

> 因此宣发的核心命题是：**用 30 秒同时回答"这是什么氛围"与"我为什么该玩它"。**
> 建议这条写成一页**宣发契约**：*任何商店页/预告片素材，必须包含至少一个"只有这个游戏才有的机制瞬间"。*

## 二、可复用的钩子清单（按拍摄成本排序）

| 钩子 | 内容 | 成本 | 用途 |
| --- | --- | --- | --- |
| **时代错置瞬间** | 1950 年代的电视在播放 2000 年的内容 | 低 | 短视频/动图 |
| **纪元对比** | 同一关卡在原子纪元与磁带纪元下的两种画风与规则并排 | 低（复用） | 商店页第二屏、Devlog |
| **界面上演** | CRT 开机 → 磁带插入 → 载入卡组（全流程 8 秒） | 中 | 预告片开头、Steam 胶囊图动效 |
| **机制瞬间** | "倒带"把已经失败的一波倒回去重打 | 中 | 最能回答"玩什么" |
| **玩家决策后果** | 一个选择在 20 秒后导致防线崩溃 | 中 | 长视频/直播友好 |
| **音乐** | 纪元主题曲 + 电台旁白 | 中高 | 预告片、原声带变现 |
| **开发者复盘** | "我们为什么删掉了 XX 玩法" | 低 | 社群信任、Devlog 流量 |

**建议优先做前三个**（低成本、可复用、能在 P1 就产出，从而压缩 [01 §6](01_定位与目标.md) 的"最长无公开产出期"）。

## 三、Q8 · 发布节奏

| 候选 | 节奏 | 优点 | 代价 |
| --- | --- | --- | --- |
| A：闭门打磨，做完再公开 | 一次性大公布 | 首印象完整 | 风险全压在最后；没有早期反馈；社区从 0 开始建设 |
| B：全流程公开（每月直播开发） | 高频透明 | 社群黏性高 | 消耗极大；玩家对"未完成"的容忍度会被消耗；创意被提前锁定 |
| **C：双周内部可玩 → 季度公开里程碑（推荐）** | 内部每两周有可玩版本；每季度对外一次（Devlog + 素材 + Demo 或试玩周末） | 内部有节奏、外部有期待；与 [03 §4](03_玩法与经济循环.md) 的 P1–P4 天然对齐 | 需要稳定的"对外素材"产能（每季都要有东西可发） |
| D：抢先体验（Early Access） | 边卖边做 | 早期现金流 + 真实反馈 | 需要首发就有可玩体量；口碑风险（EA 疲劳）；对首次发行团队偏激进 |

> **推荐 C**。并建议：**Early Access 不作为首选**，但保留为"若 P2 数据好则提前发行"的可选项——判定条件写在 P2 出口（如愿望单与 Demo 数据双达标）。

**季度里程碑的具体形态建议**（每季一次，固定格式，形成期待）：

1. **Devlog**（视频/图文）：本季做了什么、砍了什么、下季做什么；
2. **可玩物**：一段录屏或一个试玩构建；
3. **一问**：向社区征求一个具体决策（例如"下一个纪元做哪个时代"）——**参与感来自被问，而不是被通知**。

## 四、Q9 · 玩家互动形态（分阶段，不要一次上齐）

| 阶段 | 互动形态 | 要解决的问题 | 代价 |
| --- | --- | --- | --- |
| P1 | 愿望单 + 社群群组（Discord/QQ）+ 邮件列表 | 找到前 500 个真心感兴趣的人 | 需要持续运营，冷启动慢 |
| P2 | 试玩 Demo + 反馈表单 + 每季"一问" | 拿到可用的改进方向 | 反馈噪声需要筛选机制 |
| P3 | 排行榜 / 每日种子挑战 / 挑战卡分享 | 让"重复玩"有理由 | 需要后端或可作弊的本地榜（权衡见下） |
| P4 | 异步对抗（对手快照/录像） | 让玩家彼此成为内容 | 后端成本、平衡压力 |
| P4+ | UGC（纪元编辑器 + 分享） | 内容自增殖（长期性的关键） | 审核责任、分发架构、质量参差 |

**两条具体建议**：

1. **排行榜先做"种子挑战"而不是全局榜**——同一种子的分数可比，无需反作弊后端；玩家分享的是"种子 + 卡组 + 分数"，天然是社区内容。
2. **UGC 优先复用 [`indie/live-rpg`](../../../indie/README.md) 的世界包契约**——它已经把"一个世界＝一份 JSON + 稿件集合"跑通了（158 用例），可省下数月工程量；但要注意它的形态是编辑器插件，需要改造成游戏内/发行版可分发的形态。

## 五、长期玩家互动的结构（"值得投入大量心力"的那部分）

长期关系不是靠更新频率，而是靠**玩家在这里有东西可积累**：

| 可积累物 | 说明 | 为什么有效 |
| --- | --- | --- |
| **纪元档案（收藏）** | 每纪元解锁的设定/美术/音乐，会随时间累积成一本"个人博物馆" | 与知识库同构，产能极高、成本极低 |
| **挑战卡战绩** | 自选难度的历史记录与分享 | 玩家自己制造难度与故事 |
| **家园/基地装饰（外观）** | 纯外观付费的落点 | 商业化与表达一致（不卖数值） |
| **赛季通行证（免费轨为主）** | 免费轨给内容，付费轨给外观 | 若做，必须保证免费轨完整 |

**反模式（明确避免）**：每日签到、限时逼氪活动、必须社交才能推进、把已发售内容回炉重卖。
