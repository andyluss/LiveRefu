# 03 · 数据契约

> 用途：**数据表是唯一真相**的落地说明 ｜ 建立于 S1 · 2026-09-30
> 机器契约：[`game/data/schema.json`](../game/data/schema.json)（校验器读它执行）｜ 执行者：[`tools/check_data.py`](../tools/check_data.py)

## 一、为什么把契约写成数据而不是注释

1. **可扩展**：加纪元＝加表 + 在契约里声明，不需要改校验器代码（[`mainline 03`](../../docs/03_玩法与经济循环.md) 的"加法成本递减"）。
2. **可审计**：契约本身是版本化文件，改动它会出现在 `git diff` 里，也会触发变更日志。
3. **可自检**：校验器带 `--self-test`，用故意坏掉的数据断言"能抓到"——**一个永远返回"通过"的检查器比没有检查器更糟**。

## 二、表结构（所有表统一）

```json
{
  "schemaVersion": 1,
  "name": "<纪元>__<域>",
  "note": "这张表是什么、当前是占位还是正式",
  "entries": [ { ...字段见契约... } ]
}
```

契约对每张表声明：`title` / `era` / `entryFields`（字段名 → 类型与约束）/ `minEntries`（条目数下限，防止"悄悄缩水"）。

支持的字段约束：`type`（string / int / array / object）、`pattern`（命名规范）、`enum`、`min` / `max`、`minLength`、`items`（数组元素类型）。
**注意**：`bool` 会被显式排除在 `int` 之外（Python 里 `True` 是 `int` 的子类，不排除会漏判）。

## 四、校验器做了什么（以及**不**做什么）

**做**（`./run.sh data`）：
- **跨表引用完整性**（S2 新增）：契约里可用 `references` 声明"某字段必须存在于另一张表"；
  例如卡表的 `faction` 必须存在于 `factions.json`。**这类错误不会让任何一张表自身违规**，
  只在运行期表现为"某阵营的卡永远不出现"，是最容易漏到最后才炸的一类缺陷。
- 表与契约**双向**对齐：契约声明但文件缺失 → 报错；磁盘有表但未写契约 → 报错；
- 顶层字段（`schemaVersion` / `name` / `note`）、`entries` 存在性；
- 逐条字段：缺失、类型、命名规范、枚举、数值范围、数组元素类型；
- **ID 唯一性**（重复时指出首次出现的位置）；
- 条目数低于契约下限 → 报错；出现契约外字段 → 警告（不拒绝，但要求确认是否该写进契约）。

**生成管线**（S2）：卡量进入量产阶段后，卡表由 [`tools/gen_cards.py`](../tools/gen_cards.py) 从
[`cardgen.seed.json`](../game/data/cardgen.seed.json) **幂等生成**（同种子同结果），并遵守两条硬约束：
① **不得覆盖手写卡**（id 数字 ≤ 12，手工设计的标志性卡是产品识别度）；② 生成物必须过本闸门。
生成器的自检断言"幂等 / 不覆盖手写卡 / id 无重复"三项。

**不做**（诚实边界）：
- **不判断数值平衡**——那属于 S2/S3 的模拟任务（[`../../tools/sim_refu_game_001.ts`](../../../../tools/sim_refu_game_001.ts) 的思路）；
- **不判断设计意图**——"这张卡是否有趣"不是机器能答的；
- **不校验跨表引用**（如 `card.faction` 是否存在于 `factions.json`）——**这是 S2 的待办**，届时会加"引用完整性"检查。

## 五、反向验证记录（S1 已做）

故意注入 3 处真实类缺陷，确认闸门会拦：

| 注入 | 结果 |
| --- | --- |
| `id = RC-ATOMIC-1`（应 3 位数字） | ❌ 被拦：`字段 id 不符命名规范 ^RC-[A-Z]{2,8}-[0-9]{3}$` |
| `cost = 42`（上限 9） | ❌ 被拦：`字段 cost 应 ≤ 9，实际 42` |
| `kind = mecha`（枚举外） | ❌ 被拦：`字段 kind 必须是 [...] 之一，实际 'mecha'` |

还原后复绿（5 张表 / 0 违规）。加上 `--self-test` 的 8 个负向用例，共 11 个"已知必须失败"的样本。

## 六、改契约的正确流程

1. 改 `game/data/schema.json`；
2. 同步改本文件的表格；
3. 跑 `./run.sh check`；
4. 在根 [`CHANGELOG.md`](../../../../CHANGELOG.md) 记账（契约属于"约定变更"，不可豁免）。
