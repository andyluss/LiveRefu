## [0.17.0] - 2026-10-01 11:26

### 新增

- **主线项目：采纳"按势力给不同胜利条件"（方案 A）——把机制差异变成玩法差异（八道闸门全绿，43 项断言）**：
  - **引擎保持通用**：它不认识"哪个势力"，只认势力表新增的 `winCondition` 字段（`clear` = 清空所有波次 / `survive` = **守住所有波次**）。判定入口收口在 `WinCondition.evaluate`，"守成"细节在 `WaveCondition`。`cleans`/`avoids` 守成，`moves`/`feeds` 清剿。
  - **两条实测抓到的关键规则**（各被抓一次，且都是"不会报错但结论错"的类型）：① **守住 = 基地还活着**——第一版只判"波次走完"，于是"守到 0 血"也算通关，**把防线失守记成胜利**；② **胜负必须在所有伤害结算之后判定**——原来在降级区伤害之前，于是"基地先被判为守住、随后被降级区打爆"。修法：`evaluate` 的第一条就是"基地被打爆即失败，与胜利条件无关"。**结算顺序就是规则，顺序错了规则就错了。**
  - **守成需要更宽的曲线**：守成比清剿更难（清剿清完最后一波就结束，守成要求**每一波**都达标），因此守成势力的配额在能力比之上再乘 `QuotaModel.SURVIVE_RELIEF = 0.78`（实测标定）。**这条设计知识收口在 `QuotaModel`，不在临时脚本里。**
  - **效果**：`cleans`/`avoids` 从"到 LV-06 就到顶"变成**到 LV-07**，与清剿势力形成"守成 vs 清剿"的区分；四个势力各有清晰路径，且差异现在是**玩法差异**而非同一尺子下的强弱排序。
  - **界面上要看得见**：战斗 HUD 新增"目标 / 势力"一行（文案由 `WinCondition.label` 统一提供，避免"守成/守住/存活"多种说法）；逐关扫描报告每行标出该势力是守成还是清剿——不标会被读成"同一把尺子下的强弱"，而那正是我们花了几轮才修掉的误读。
  - 新增 3 条断言（守成需基地还活着 / 清剿条件不受守成逻辑影响 / 未知胜利条件**显式回落** clear 而不是"读不到就当胜利"）；顺带把"报告行格式化"与"扫描不变量"拆开（`SweepReport`）。

## [0.15.0] - 2026-10-01 11:00

### 修复

- **主线项目：给势力机制加"正面收益"，并发现"收益机制要有人去用才测得到"**（八道闸门全绿，**38 项断言**）：
  - **背景**：`cleans`/`avoids` 的**自由输出**高于 `moves`，实战却更早崩——因为"清理要花电力，而它们的机制奖励清理"，等于**实力被自己的机制吃掉**；只奖励"少污染"而不补偿"清理成本"时，**越遵守机制的势力越吃亏**。
  - **三条改动**：① `cleans` 清理**返还 1/3** 消耗电力（在扣费之后**立刻**返还——收益与支出必须在同一处发生，否则"清理值不值"难以感知）；② `avoids` 每回合按**未污染的在用塔位**给电力利息（每格 1 点，放在交战前，本回合就能花掉）；③ `moves` 的回收返还 3/4 保留。新增 [`FactionPayoff`](game/scripts/core/systems/faction_payoff.gd)（**收益**与 `FactionMods` 的**代价**分开——两者变化的理由不同）。
  - **最值钱的一条教训**：第一次实现后逐关扫描的**数字完全没变**。原因不在机制，而在**测量工具**——自动玩家的清理判据是"残渣 > 2 且付得起"，于是它**几乎从不清理**，返还与利息**一次都没触发过**。**判据碰不到的地方就是没测到**（这与前面"判据把自己锁死"是同一类问题的另一面：那次是判据阻塞玩法，这次是判据让新机制无法被观测）。改法：电力有明显富余（≥ 3 × 该格残渣）时顺手清干净——**这本来就是玩家会做的事**。
  - **效果**：`moves` LV-07→**LV-08 通关**、`cleans` LV-05→06、`avoids` LV-05→06；**四势力现在都至少到达 LV-06，两个能通关末关**。
  - **仍未解决（如实记录）**：`cleans`/`avoids` 的机制本质是**缓解污染**，而 `moves`/`feeds` 是**直接换输出**；在"输出决定能否清波"的判定下，缓解类天然更弱——**这是设计取舍，不是数值 bug**。继续加收益边际效力递减（瓶颈是"打得不够快"）。下一步建议：给缓解类一条**能转化为输出**的路径（例：`avoids` 的干净格提供**战力**而非电力），或**按势力给不同通关条件**。已写入 [11 §5.4](docs/11_卡池均衡与难度标定.md)。
  - 新增 3 条断言（清理有返还 / 返还只对 `cleans` 生效 / `avoids` 利息随干净格数），其中一条当场抓到我**测试写错**（两张塔位都干净时利息应是 2，我写成了 1）。

  - **按势力独立配额**（消除"四势力能力相差 1.6 倍"的直接影响）：四势力实测输出相差 1.6 倍，单一曲线只能取一个基准——以最弱为基准时最强者过易，以最强为基准时最弱者永远打不过。三层各一小步：① 数据层关卡表可选 `quotas_by_faction`（没写的势力走通用曲线，向后兼容）；② 逻辑层 `LevelData.quotas_for(势力)` 决定用哪条，自洽校验要求"给了就必须给满 `waves` 条"；③ 导出层利用"通用配额本就是最弱势力能力 × 关卡比例"，因此**势力 f 的曲线 = 通用曲线 ×（f 能力 ÷ 最弱能力）**——形状不变、只按各自能力放大。实测倍率 `AEC 1.051 / HAU 1.000 / SUB 1.193 / ROA 1.606`。
  - **效果**：所有势力都比"单一曲线"时走得更远（`moves` LV-06→07、`avoids` LV-05→06、`AEC` LV-04→05），各关余血更均匀——说明是在消除能力差，而不是把难度整体调松。
  - **契约与校验器同步**：新字段先被数据闸门报成"契约外字段"（8 条警告）——**警告本身就是"契约与数据不一致"的信号**，因此补进 `schema.json`；而"**对象字段的键**"是校验器原来不支持的一类引用（只支持标量与数组），于是"对象里写了不存在的势力"完全不会被发现（后果是该势力静默用不到专属曲线）。已加 `keyOf` 支持并配两个负向自测。
  - **修掉一个计数 bug**：同一段自测里加了两个新用例，但报告的分母仍只数旧列表——数量是 5 个却打印"3/3"（失败时会打印"4/3 个用例不符预期"）。**计数是验收报告的可信度本身**，已改为显式统计实际跑过的用例。

- **Q6 产能来源裁决 + 由它推出的"卡量阶梯"**（用户答：AI 出量 + 自画语法层 + 外包精修关键件 / 现金**万元级以内** / 工时**波动很大、无法估**）：
  - **新识别风险 R10：工时不可估 × 卡量门槛 = 交付风险。** 现金不是瓶颈、**你的工时才是**；而把"200–300 张卡"压在 S5，会让任何一次工时下滑直接推倒交付。
  - **据此新增 [06 产能预算与卡量阶梯](docs/06_产能预算与卡量阶梯.md)**：把卡量做成**阶梯**而非一次性门槛——**T1 机制验证 12 张 → T2 可试玩 Demo 40–60 张 → T3 可发售底 120–150 张 → T4 契约 v2 的 200–300 张**；S5 的范围改为 **T2 的公开 Demo**（这也让 M3 的"Demo 前置"硬结论真正可执行）。每阶自己成立，任何一阶停下都不产生半成品债务。
  - **替代"堆卡量"的四个便宜杠杆（优先做）**：规则卡 / 难度阶梯 / 每日种子挑战 / 未来残片。依据是 M3 的结论"内容量决定差评下限、不决定销量上限"与《杀戮尖塔 2》反例——**堆卡量买不到好评，规则与平衡才买得到**。
  - 外包采购纪律：先冻结版式模板再下单；只买"玩家会盯着看的那 20%"（主视觉、Demo 封面、徽记、关键卡 3–5 张）；UI 外壳与图标不外包。
