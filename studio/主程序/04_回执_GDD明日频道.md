## 0. 一句话结论（回执）

> **引擎推荐 Godot 4.7.x 桌面导出作为首期与 M1 主线，系统级常驻（托盘/全局快捷键/勿扰）用薄原生桥（GDExtension/原生 helper）隔离实现；M1 只做「单频道（磁带暖未来）闭环」——氛围播放 + 番茄计时 + 混音台 1 版 + 收藏 1 卡，2D/UI 为主、后处理轻量化，系统级集成后置为独立验证切片。**
> 即：**"技术选型 = Godot 桌面 + 薄原生系统桥"；"原型范围 = 单磁带频道闭环"。**

## 1. 平台选型结论（桌面双端回执）

### 1.1 首期平台为桌面双端（macOS/Windows）——程序侧确认无误

GDD §2「桌面 PC（macOS/Windows）为首期目标：常驻后台、全局快捷键、勿扰集成是陪伴形态前提」成立，且平台优先于渲染细节：**陪伴应用的形态价值优先，渲染是放大器**。Web 版（次期降级）与移动端（远期）按 GDD 保持，首期不实现。

### 1.2 候选技术路线取舍

| 技术路线 | 对"桌面双端 + 后台常驻/托盘/迷你窗/全局快捷键" | 对"复古氛围渲染/UI/后处理" | 综合结论 |
| --- | --- | --- | --- |
| **Godot 4.7.x 桌面导出** | 原生导出 macOS/Windows 双端；MIT 免费；`OS.low_processor_usage_mode` 支持后台低功耗；**托盘/全局快捷键非核心原生**，需薄原生桥（见 1.3） | ★★★★★ 2D 独立引擎 + 深度可定制 UI + 自发光/面光源/HDR，复古后处理生态成熟 | **推荐主线** |
| **Electron** | ★★★★★ 原生 Tray/globalShortcut/powerSaveBlocker，双端成熟 | ★★☆ 渲染靠 WebView（Canvas/WebGL/CSS），后处理受限；体积与常驻内存偏大，与"低打扰陪伴"定位相悖 | 不取为主线；仅作 Godot 装不进时的兜底壳 |
| **Tauri** | ★★★★ 有托盘/全局快捷键插件，壳极轻 | ★★☆ 渲染仍靠系统 WebView；需团队具备 Rust 能力，成本转移 | 候选，但渲染层承受力不足 |
| **裸 Web 技术栈** | Web 天然缺系统级常驻/托盘/快捷键 | ★★★☆ Canvas/WebGL 可做 CRT shader，但整体性能与原生手感弱 | 不适配首期；作为次期降级演示 |

**取舍理由**：本项目（方向 D 氛围陪伴）的核心价值是"频道即世界观"的**视觉+音景氛围**（§1 卖点 1/2/4），它是渲染/UI/后处理重的应用，而非表单重的工具。Godot 在渲染/UI/复古后处理上最优且 MIT 免费、无授权成本；Electron/Tauri 的优势恰在"系统集成"而非"渲染"，而系统集成在本项目只是**窄而界面可控**的一小块（托盘图标、全局快捷键、后台低功耗、一个小迷你窗），用一个薄原生桥即可补齐，不值得为此把整个渲染层搬进 WebView。

> **结论**：**不采用 Electron/Tauri 作为 M1 与首期主线**；只用它们做"极致系统集成"的兜底评估（登记不实现）。首期主线锁定 **Godot 4.7.x 桌面导出**。Web 版（次期）复用地一内容池 + Godot Web 导出，缺失系统级常驻能力，作为演示降级（GDD §2 已明示取舍）。

### 1.3 Godot 做"常驻后台/托盘/迷你窗/全局快捷键"的可行性（关键）

Godot 4 对系统集成是**部分原生、部分需桥**，如实拆解如下（此项是 GDD §10 风险 1 的落点，须在立项早期验证）：

| 需求 | Godot 原生能力 | 可行性/方式 |
| --- | --- | --- |
| **后台常驻低功耗** | `OS.set_low_processor_usage_mode(true)`、`DisplayServer` 窗口管理、`OS` 生命周期 | ✅ 原生即可满足"最小化后仍在后台跑计时+氛围"；配合动态降低刷新 |
| **迷你窗/独立小窗** | Godot 4 多 `Window` 节点 + `DisplayServer.window_*`（borderless、always-on-top、透明） | ✅ 原生可做"计时迷你悬浮窗" |
| **系统托盘图标** | 核心**无原生 TrayIcon**；需 GDExtension/插件封装 macOS `NSStatusItem` / Windows Shell_NotifyIcon，或独立原生 helper 常驻进程 | ⚠️ 需薄原生桥（见下） |
| **全局快捷键（跨应用）** | Godot `Input` 仅应用内；系统级热键需 macOS `CGEventTap` / Windows `RegisterHotKey`，经原生桥或插件 | ⚠️ 需薄原生桥 |
| **系统勿扰集成** | 无原生；macOS Focus / Windows 专注助手需系统 API | ❌ 后置（GDD §10 风险 1 缓解已如此安排） |

**薄原生桥落地方案**（把平台差异收敛到一处，降低双端维护成本）：

- **优先**：寻找/vetted Godot 4.x 社区插件（托盘、全局快捷键，接 `addons/`），过许可与维护性评审后引入；
- **缺口**：由**图形程序员 A / 主程序**用 **GDExtension（C++ 或 Rust）** 写一个小的 `system_integration` 模块，只封装"托盘、全局快捷键、勿扰状态查询"三个小能力，对外暴露 GDScript 可调接口；渲染与逻辑层不感知平台差异；
- **兜底**：若插件+自研成本不可控，退化为"Godot 渲染核心 + Electron/Tauri 宿主壳"——仅在 M1 之后的系统集成切片（spike）评估出成本超预期时启用，属**预案非当前计划**。

### 1.4 打包与分发（桌面双端）

| 平台 | Godot 导出 | 分发要点 |
| --- | --- | --- |
| Windows | 导出 `.exe` + 资源（PCK 或嵌入） | 签名；可用 Inno Setup/NSIS 做安装器；分发经官网直下或 Steam |
| macOS | 导出 `.app`（含资源） | **必须代码签名 + 公证（notarization）** 才能绕过 Gatekeeper；Apple Silicon 用 universal binary 或双版本；分发经 DMG/notarized 或 Steam |

> 商业化形态（买断/订阅/免费）GDD §12 第 5 项【待定】，**不影响**程序侧打包方案；Steam 与官网直下均支持 Godot 导出。分发与签名配置在 M2 末期（临近垂直切片）再启动，M1 不投入。

## 2. M1 原型范围回执（单频道·磁带暖未来闭环）

### 2.1 范围对齐

GDD §10 建议 M1「单频道（磁带暖未来）完整闭环：氛围播放 + 番茄计时 + 混音台 1 版 + 收藏 1 张卡」，与主程序 `02_` 里程碑"M1 玩法原型：核心循环可玩"完全对齐。**接受该范围，并按"最小可行实现"切分、按"可玩且可见"验收**。

> 磁带暖未来锚点引 doc 卷：[`14_磁带篇`](../../doc/retro-futurism/14_磁带篇_磁带未来主义_模拟接口的暖未来.md)（界面即世界观、绿/琥珀单色 CRT、模拟接口暖未来）——M1 只取其"1 台终端"的最小气质，不铺 Channel 全部道具。

### 2.2 程序侧范围与最小可行实现

| 子项 | 需求来源 | 最小可行实现（M1 入口标准） | 主程序工作量（人日） |
| --- | --- | --- | --- |
| **项目脚手架/工程规范** | 主程序 `01_` | Godot 4.7.x 建项目；目录结构（scenes/scripts/assets/data/addons）；数据驱动配置表加载器；lint/自测跑通 | 1.5 |
| **内容池数据 schema + 加载器** | GDD §4/§6 | 图文卡/引言卡 JSON schema；每卡**强制版权字段**（见 §4）；1 频道（磁带）数据落地 | 1.0 |
| **氛围播放器** | GDD §4/§3.1 | 1 音景循环 + 1 占位视觉皮肤 + 2–3 张内容卡低打扰轮播；可切换"降噪态" | 1.5 |
| **番茄计时器** | GDD §4/§7 | 默认 25+5、可调 5–120；专注/休息状态机；完成触发"轻提示音 + 1 次信号碎片"；时段小结最小版 | 1.5 |
| **混音台 v1** | GDD §4/§6 | 2–3 轨（嗡鸣/磁带底噪/雨）音量滑杆混音；数据驱动音轨列表；不做预置保存 | 1.0 |
| **收藏 1 卡 + 图鉴最小** | GDD §4/§3.1 | 内容卡点"收藏"→ 写入本地图鉴列表（1 条目）；不做进度/归档/稀有度 | 0.75 |
| **系统集成最小** | GDD §4 系统集成(P1) | "最小化后仍在后台跑计时+氛围"（`low_processor_usage_mode`）+ 恢复；**托盘/全局快捷键勿扰不在 M1**（见 §4） | 0.75 |
| **联调/自测/验收** | 主程序 `02_` | 25min 专注可跑通、混音可用、可收藏 1 卡（GDD §11 M1 出口标准） | 0.75 |

**工作量粗估：主程序约 7.5–8.5 人日；图形程序员 A 约 0.5–1 人日**（占位后处理：扫描线/暗角/微噪轻量版，见 §5）。综合 ±30% 偏差。以 AI 工作室并行工作计，**约 1.5–2 周日历**，与主程序 `02_`"M1 2–3 周"排期相符（2 周可交付、留 1 周余量）。

> **M1 使用占位资源**：灰盒/色块 + 占位音（底噪/提示音），不投入正式美术/音频（主程序 `02_` 原则 3）。占位资源由主美术/UI 美术 A 提供最小可用版本，无需风格定稿。

### 2.3 M1 出口标准（同 GDD §11）

- 专注 **25min 不被打断**（计时器在后台/最小化仍准确）；坏点：后台计时漂移判为失败。
- 混音台**至少 2 轨**可调音量并生效；
- **至少可收藏 1 卡**并入本地图鉴；
- 氛围"静默可用"：关闭动态效果后频道静态仍成立（GDD §9）。

## 3. 风险回执（GDD §10 程序侧判断与对策）

| GDD §10 风险 | 程序侧判断 | 程序侧对策 |
| --- | --- | --- |
| **后台常驻/勿扰/快捷键的平台差异**（高/高） | **成立，且是首期第 1 大风险**。差异集中在"系统级集成"，而非渲染。 | M1 只做跨平台单一的"最小化后后台跑"（原生能力）；**托盘/全局快捷键/勿扰全部后置**，单独抽成一个"系统集成切片（spike）"在 M1 之后验证；用薄原生桥把双端差异收敛到一个适配层。若 spike 发现成本失控，降级交付"无托盘、有迷你小窗、无系统勿扰"版本，系统勿扰明确标为非首期。 |
| **内容版权**（高/高） | **转为工程合规闸门**（法律判定责任在主策划，程序侧只做"防漏放"闸门）。 | 内容卡数据模型加**强制版权字段**（source/license/license_url/status）；schema 校验阻止"无授权状态"卡进入发布内容池；CI 跑版权校验脚本；影音卡优先"程序化生成 + 公版影像"。**请主策划在 M0 前定版权口径复核责任人**（GDD §12 第 3 项【待定】），程序侧据此落地闸门规则。 |
| **音视频播放与耗电**（中/中） | **成立**；陪伴应用长期后台，耗电是真实体验短板。 | 播放器统一（单一 AudioBus，可统一静音/暂停）；音频用可控的流优先级；后台用 `low_processor_usage_mode` + 动态降刷新；动态氛围（扫描线/星雾）提供"静默可用"关闭态（与 GDD §9 同构，天然兼顾耗电）；macOS 注意 App Nap、Windows 注意省电计划。 |
| **频道滤镜性能**（中/中） | 成立，归**图形程序员 A**。 | M1 单频道**轻量后处理**（scanline/暗角/微噪）即可验证，不追求全后处理栈；每个 effect **可开关**、有单测性能数据（接图形程序员 A `02_` 成本表，目标 60 FPS 桌面不闪）；M1 若某 effect 超预算直接砍该 effect；三频道滤镜性能 A/B 留到 M2（图形程序员 A 任务清单）。 |
| **内容量铺不开**（中/中） | **程序侧不做内容，但为"内容廉价扩容"提供底座**。 | 内容全部走配置表 JSON，新增卡=加一条数据、零代码改动；提供内容校验脚本（字段完整性/版权必填/图鉴引用完整）；首期 3 频道内容量与单人周产匹配（GDD §6 ±30%），数据驱动保证扩容不引入代码返工。 |

## 5. 把关提示：首期不该进的东西（范围控制）

> 主程序 `02_` 原则 5：范围外一律登记【待定】，防止蔓延。下列系统**明确不进首期/M1**，防止 M1 范围失控：

| 系统/功能 | 归属进度 | 理由 |
| --- | --- | --- |
| **系统级勿扰集成**（macOS Focus / Windows 专注助手） | M1 后置（非首期） | GDD §10 风险 1 缓解项；平台差异大，先交付"无勿扰"版本 |
| **全局快捷键** | M1 后置 | M1 无快捷键也能验证陪伴手感；spike 后再做 |
| **3 频道全量**（太空时代/蒸汽波黄昏） | M1 只做磁带 1 频道；M2 各 1 场景 | 遵循"先验证舒适手感，再铺频道" |
| **完整收藏图鉴**（进度/归档/稀有度/卷） | M1 只做"收藏 1 卡 + 最小列表" | 图鉴进度/归档是长线目标（§3.3），M1 不落地 |
| **解锁与成长**（信号碎片经济/频道音景解锁/成就） | M1 仅"完成一段专注给 1 次正反馈"占位 | 避免在未验证手感前投入成长/经济（数值策划 A 完整曲线 M3 前） |
