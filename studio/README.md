# LiveRefu Studio · AI 开发工作室

> 本工作区专注 **复古未来（Retro-futurism）相关项目** 的开发。
> 本目录 `studio/` 是把参与这些项目开发的 AI 角色组织起来、按角色存放其职责文档与工作资料的 **模拟工作场所**——每个角色一个子目录，角色 README 是其"身份卡 + 入口"。

---

## 一、这是什么

`studio/` 是一间虚拟游戏工作室的文档空间。工作区里参与「复古未来相关项目」的 AI 开发角色（主策划、主程序、主美术、数值策划 A、图形程序员 A、UI 设计美术 A）在此各有独立的"工位"（子目录），存放：

- **角色 README**：岗位定位、职责边界、与其他角色的协作关系、工作守则；
- **该角色的工作文档**：草案、规范、模板、清单——初期为种子文档，随项目推进在各自目录内维护。

角色模拟约定：当以某角色身份工作时，先读取该角色目录的 `README.md`，把其中的职责与规范当作该角色的"记忆"，产出物一律写回对应角色目录。

## 二、工作区专注方向

- 本工作区的长期主题是 **复古未来（Retro-futurism）** 题材的项目开发。
- 题材/美学知识库沉淀在 [`doc/retro-futurism/`](../doc/retro-futurism/README.md)（21 篇总卷）及各专题卷：`doc/atompunk`、`doc/biopunk`、`doc/cyberpunk`、`doc/dieselpunk`、`doc/steampunk` 等。
- 各角色草案里的美学关键词（磁带未来主义、原子朋克、太空时代、蒸汽波、Y2K/Frutiger Aero 等）均可在知识库中查阅原始论述。

## 四、文档约定

1. **语言与格式**：简体中文，Markdown（UTF-8），与 `doc/` 现有体例保持一致。
2. **命名**：角色目录内统一 `README.md` 为入口；工作文档用 `两位序号_主题.md`，如 `01_美术风格方向草案.md`。
3. **草案状态**：未定稿文档在标题注明 `（草案 v0.x）`；未决问题用 `【待定】` 标出；确定结论写入文档末尾「决策记录」。
4. **引用**：跨角色引用用相对路径链到对方目录；引用知识库时链到 `doc/` 对应卷。
5. **变更**：每个角色目录内的文档只由该角色维护；需要其他角色意见时在文档「协作请求」小节登记。
