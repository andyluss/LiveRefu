## 一、一句话结论

**《明日频道》三频道滤镜（磁带扫描线+微噪 / 太空星雾缓移 / 蒸汽波慢速色偏）在既定平台（macOS + Windows 桌面双端）与主程序倾向的 Godot 4.7.x 路线上完全可行**——三者均为 2D 屏幕级/背景级后处理，不需要 Forward+ 独占特性（HDR 输出、AreaLight3D），单 pass 全屏即可承载，成本低、可各自独立开关、可无损降级为静态回退，满足 M2 风格切片与 GDD §9 的「静默可用」要求。真正的【待定】不在「能不能做」，而在**执行壳的渲染目标（Godot Shader 还是 WebGL/GLSL）** 与**三频道渲染后端的分工（Compatibility/2D vs Forward+/3D）**，详见 §五、§六。

## 二、三频道滤镜可行性切片表

> 对应 GDD §9「动态氛围」：磁带=扫描线与微噪、太空=星雾缓移、蒸汽波=慢速色偏。每行一个「效果 feature」，均遵循我 01 草案「后处理栈复用 + 效果可开关」与 02 草案「逐 effect 单测」原则。

| 频道 | 效果 | 技术路线 | 性能预估（1080p 桌面） | 计入 M2 风格切片 | 动效关闭的静态回退 |
| --- | --- | --- | --- | --- | --- |
| **磁带暖未来** | CRT 扫描线 + 微噪 | 屏幕后处理：全屏 shader 采样屏幕纹理，叠加重复扫描线掩码 + 细粒噪点。低成本变体：用 tileable 扫描线/噪点纹理的 `ColorRect` 叠加（`CanvasLayer` + `ShaderMaterial`），**不做**屏幕纹理重采样，成本最低。Godot 侧：Compatibility/2D renderer 原生支持。 | **低**：单 pass 全屏 ≈ 0.2–0.4 ms；纹理叠加法可 < 0.1 ms。 | **是**（M2 磁带场景定稿） | 扫描线/噪点转成**静态**半透明纹理（不滚动、不闪烁），或整层隐藏；基底＝暖色 LUT + 终端边框 + 自发光屏静态纹理，频道仍成立。 |
| **太空时代** | 星雾缓移（星云 + 星点缓动） | 2D/3D：低机率 tileable 星云/星点纹理做 UV 随时间慢速滚动（shader 驱动或 `Sprite` 滚动），叠加少量 `GPUParticles` 星点做纵深视差闪动。Forward+ 下可置于 3D 远景面片。**不依赖 HDR/AreaLight**，HDR 只对辉光有益、与「星雾」本体无关。 | **低-中**：背景滚动 shader ≈ 0.3–0.6 ms，粒子另计（数百点）；无 HDR 依赖 → 风险低。 | **是**（M2 太空场景定稿） | 冻结 UV 滚动与粒子时间常数，星雾定格为静态星云 + 星点图；基底＝深空紫蓝渐变 + 星云静态纹理，频道仍成立。 |
| **蒸汽波黄昏** | 慢速色偏（Hue/色带缓变） | 屏幕后处理：时间驱动 hue 偏移 / 分段色带映射（shader 内 `time` uniform 循环调色板），或动画 LUT 插值。2D 下可仅对背景层做缓变色带以进一步降本。 | **低**：≈ 0.2–0.5 ms（纯颜色数学或 LUT 采样，无纹理重采样）。 | **是**（M2 蒸汽波场景定稿） | 把 hue 冻结在既定调色板关键帧（静态渐变 + 静态色带）；基底＝蒸汽波渐变底图 + 低频色带，频道仍成立。 |

> 补充：三频道滤镜均为**可独立开关的 feature**（对应 01 草案 §三「每个效果一个可开关 feature」）。M1 只做磁带频道闭环，故**M1 仅需扫描线+微噪**；星雾与慢速色偏在 **M2** 定稿（对应 M1/M2 里程碑：M1 磁带闭环、M2 三频道三套氛围成立）。

## 三、「静默可用」在图形侧如何保证

GDD §9 要求「任何动态效果在关闭后频道仍成立（静态图 + 音景）」。图形侧把它当作**一等公民特性**，而非「把效果删掉后的残次状态」：

1. **feature 化与持久化**：每个动效是一个独立、可全局开关的 feature（01 草案「效果可开关」），开关状态持久化、默认值可由用户覆盖；全局「减少动态/关闭动效」开关（对齐 GDD §8.7 可及性）同时关闭粒子、UV 滚动、Hue 循环与呼吸动画，必要时保留**淡入淡出转场**（可再降级）。
2. **基底与动效层解耦**：每个频道渲染成两层结构——
   - **静态基底（必须渲染）**：色调 LUT + 材质语言 + tileable 静态纹理底图 + 界面皮肤（对应 GDD §6 每频道一套「视觉皮肤」）；
   - **动态叠加层（可关闭）**：扫描线/微噪、星雾滚动、慢色偏等，做成独立 `CanvasLayer` / 独立材质槽 / 独立粒子子场景。
   - 关闭动效 = 隐藏叠加层（节点可见性 off），**不改变基底场景树与调色**，从结构上保证「剥离动态层不破坏基底」。
3. **静态快照验收**：M2 切片交付时，每频道提交**「动效开 / 关」两态截图**（同一套 LUT/材质），作为主美术与 UI 美术的验收基准，实证「关动效频道仍成立」。
4. **与音景的静态闭合**：静态基底 + 音景本身就是一套完整氛围，符合 GDD §9「静态图 + 音景」；动效只是锦上添花，不承担「频道是否成立」的职责。

## 四、性能预算初估

> 依据我 02 草案预算表：原型 60 FPS、风格切片 M2 至少稳定 30 FPS、后处理全开 ≤ 3 ms/frame、DrawCall ≤ 2000(3D) / ≤ 500(2D)、显存 ≤ 2 GB（原型）。判读基础：**氛围陪伴是单频道场景，一次只渲染一个频道**；「三频道同时上屏」理解为最坏情况压测 / 性能 A/B 对照。

| 场景 | 说明 | 后处理耗时（估） | 其他（DrawCall / 显存） |
| --- | --- | --- | --- |
| **单频道上屏（真实用例）** | 只显示当前频道，滤镜栈 + 基底 | **≈ 0.5–1.0 ms** | 全屏采样 1 次（建议合并成单 pass）；2D DrawCall 增量 ≤ 5；远超 30 FPS 上限，60 FPS 无压力。 |
| **三滤镜同时上屏（最坏/压测）** | 三个 feature 同时启用（仅用于性能 A/B 对照） | **≈ 1.0–2.0 ms** | 仍在 ≤ 3 ms 预算内，但**不建议**生产启用；只作对照。关键优化＝合并成**单次全屏 pass**（共享调色/矩阵运算，按频道 feature 分支），避免多次屏幕纹理拷贝。 |
| **常驻后台 / 托盘 / 迷你窗态** | 降分辨率 + 降帧 + 暂停粒子与动效 | **< 0.3 ms（暂停时）**；迷你窗保活动画时每帧 ≈ 0.5 ms | 建议 15–30 FPS、0.25–0.5× 分辨率 upscale；CPU 侧数个百分点。全局快捷键唤回时全量恢复。 |
| **显存增量** | 星雾/扫描线/噪点 tileable 纹理 + LUT | 增量 **< 64 MB** | 纹理压缩（ASTC/BC），符合 ≤ 2 GB 原型预算。 |
| **Shader 编译与加载** | 首次切频道 | 每频道 1–2 个材质 | 建议切频道前预编译/预热，避免切换时掉帧（对接主程序加载管线 ≤ 5 s）。 |

**性能结论**：三滤镜是**低负载**后处理，主要瓶颈不在 shader 计算，而在**全屏 pass 数量**（一次屏幕纹理拷贝的成本）与**纹理内存**。图形侧的关键工程杠杆是：
- **合并成单次全屏 pass**，按频道 feature 分支，杜绝多 pass 重复拷贝；
- 磁带用**纹理叠加法**（tileable ColorRect）取代屏幕纹理重采样，把成本压到最低；
- 后台常驻态**主动降分辨率/降帧/暂停粒子**，把常驻负担压到可忽略。

## 八、追加回应：母意象「容器暖光 × 频道色」双层光合成（承接主美术回执）

> 2026-09-07 追加 · 回应主美术 [04_回执_GDD明日频道.md](../主美术/04_回执_GDD明日频道.md) §4 #1/#2——把母意象从"氛围锚"升级为"世界容器/装帧"层：**接收机本体=跨频道稳定框架（拧盘换频道）、频道=收进来的不同频率信号**，并由我图形侧承接**「容器暖光 × 频道色」双层光**合成。
> 本节**不重建**上文已定稿内容，只追加双层光的实现与性能响应。

### 8.1 可行性结论

**可行，且与主程序 Godot 4.7.x + 桌面双端路线、与我上文 §二/§三的"后处理栈复用 + 基底-动效层解耦"结构高度契合。** 关键判断：**「容器暖光」不是第三个滤镜，而是"容器(框架)层"自身的恒定光**；它与我上文的"三频道滤镜（扫描线/星雾/慢色偏）"是**不同层**的东西——暖光挂在容器层，滤镜挂在信号层，二者可平行存在、互不污染。

### 8.2 推荐实现：双层光的分层合成（复用"基底-动效层解耦"）

采纳主美术 §1.4 建议的 **2D 仿 3D"设备皮肤"**（不做真实 3D，控制成本），按"容器 / 信号 / 动效"三层解耦（直接复用我对"静默可用"的 §三结构）：

| 层 | 职责 | 是否恒常 | 承载的双层光 | 对应渲染层 |
| --- | --- | --- | --- | --- |
| **信号层（频道内容）** | 频道内容渲染 + **频道 LUT 颜色分级** → 只铺在接收机"中央窗口"区域 | 恒常（基底） | **频道色**（当前频道色调 LUT） | 基底内容层，位于窗口遮罩内 |
| **容器层（接收机框架）** | 接收机体（刻度盘/旋钮/网罩/电源灯/天线）+ **容器暖光**（刻度盘背光/真空管暖辉 + 外部"灯下"台灯局部光） | 恒常（基底） | **容器暖光**（琥珀暖光，跨频道恒定） | 独立 2D 皮肤层（`CanvasLayer`，叠加在信号层上方、UI 层下方） |
| **动效层（可关）** | 扫描线滚动 / 星雾缓移 / 慢色偏的"偏"，及暖光的**呼吸/辉光动态** | 可关 | ——（动态叠加） | 独立动效子场景/材质槽，可见性可关 |

**合成规则（保证"不互相污染"）：**
- **暖光与频道色用"区域/分层"隔离**，而非同一像素上直接相乘：容器暖光只作用于**容器层的皮肤材质**（作为其乘法光场 + 小范围辉光 bloom），**不接触信号层像素**；频道 LUT 只作用于**信号层窗口区**，**不接触容器皮肤**。
- 窗口区与框架区用**遮罩（mask）**界定：信号层内容被限制在"中央窗口"矩形/圆角区域内渲染，容器层在窗口周围框住它。暖光因此**不会"染"成频道色**，频道色也**不会"糊"到框架**上——这正是主美术要的"二者不互相污染"。
- 容器暖光的**"灯下"局部照明**用径向渐变/`PointLight2D`/薄雾状淡入实现（2D 假辉光，Compatibility 兼容）；刻度盘背光用小范围加法 bloom。**不依赖 HDR/真 bloom**，避免被 Forward+ 绑定（见 8.5 与主程序确认项）。

**实现顺序建议**：M1 磁带原型用**分层合成（Way A）**——容器层 2D 皮肤 + 信号层窗口 + 暖光径向辉光，成本可控、隔离清晰；M2 若需省一次全屏采样，再升为 **单全屏 pass + 双 LUT 遮罩（Way B）**（把"频道 LUT（窗口区）+ 容器暖光 grade（框架区）"编码进同一 pass，按区域遮罩分支），Engine 需要一帧预烘焙容器轮廓遮罩纹理。

### 8.3 性能增量预估（回应主美术 §4 #2 数值）

**结论：双层光是"既有单频道预算内的低增量"，不新增全屏 pass。**（主美术担心的"暖光/辉光、面板材质高光的后处理开销"我用下表收敛。）

| 方案 | 运行成本增量 | 说明 |
| --- | --- | --- |
| **Way A 分层合成（M1 推荐）** | **≈ 0.1–0.3 ms**（增量） | 容器层是 2D 静态皮肤 + 小范围径向辉光/加法 bloom，集中在**层内小区域**，非屏幕重采样。单频道总成本从 ≈0.5–1.0 ms 升到**≈0.6–1.3 ms**，仍在 ≤3 ms 预算内、30/60 FPS 无压力。 |
| **Way B 单 pass 双 LUT（M2 升窗）** | **≈ 0 ms（运行增量）** | 复用既有单全屏 pass，仅多一帧预烘焙容器轮廓遮罩 + shader 分支→**结构性工作量**而非运行成本；显存增量 < 8 MB（一张遮罩纹理）。 |
| **容器层纹理/显存** | **< 8 MB** | 接收机皮肤（含刻度盘/旋钮/网罩高光）+ 暖光径向渐变；纹理压缩（ASTC/BC）。 |

> 判读：**不突破**我 02 草案"后处理全开 ≤3 ms/frame"预算；双层光大头在"容器层的小范围辉光 bloom"与"窗口遮罩的一次切割"，均非屏幕全量运算。若主美术要**真 HDR bloom**（高亮霓虹），那才要 Forward+ 独占、成本跃升——见 8.5【待定】。

### 8.4 与「静默可用」的关系

**容器暖光属于"基底"，动效关闭后仍保留；它不是可关闭的动效项。**（与主美术 §1.3"静态也成立：一盏亮着的灯 + 一块静止的刻度盘"一致。）

- 承接主美术界定的**"存在 vs 动态"二分**：
  - **暖光的"存在"（常亮台灯 + 静止刻度盘 + 暖色面）= 基底** → 动效全关后仍保留，频道与母意象依旧完整成立；
  - **暖光的"动态"（灯光缓慢呼吸、辉光振幅、淡入淡出）= 动效** → 可关（对齐主美术 §2 表中磁带/蒸汽波的"指示灯慢呼吸≈0.5–2Hz、灯光长呼吸"）。
- 工程落地：容器层拆成"**暖光基本常亮**（恒常、属基底，默认不可关）" + "**暖光呼吸/辉光动态**（独立子场景，可关）"。全局"减少动态/关闭动效"开关（GDD §8.7）只关后者，**不关（也不应关）前者**——否则"一盏亮着的灯"这条母意象就不成立了。
- 建议给用户最终两档：**「灯下气氛」开启**＝暖光+辉光+呼吸全保持；**「灯下气氛-减轻」**＝仅保留暖光常亮（关辉光/呼吸），仍满足"静默可用"。是否提供"完全无暖光"一档由主美术定（我判断不建议，因为那是频道而非母意象的灭灯）。

### 8.5 需主美术 / 主程序确认的点（【待定】）

**向主美术：**
- 【待定】**容器暖光量化色值/色温**：琥珀背光准确色温、"设备自身暖光"与"外部台灯照明"两来源的强度比例与辉光范围——以便收敛进 `data/fx_preset.json`。
- 【待定】**容器层与频道窗口的区域界定**：接收机"中央屏幕/窗口"的尺寸、位置、圆角/遮罩形状——决定信号层裁剪区与容器遮罩边界，影响 `02_` 资源规格与分层资源命名。
- 【待定】**"静默可用"的暖光边界**：何谓"暖光基本常亮（属基底、不可关）" vs "暖光动态（呼吸/辉光，属可关动效）"——需主美术给出验收基准（对齐其 §1.5/§4 #1）。
- 【待定】**sRGB vs 广色域（Display P3）**（主美术 §4 #3 联动）：容器暖光高亮辉光在广色域下的色值域，需主美术定色、主程序定渲染/窗口色彩管理。

**向主程序：**
- 【待定】**容器暖光用真 bloom 还是 2D 假辉光**：真 bloom 需 Forward+（HDR，独占），与"磁带走 2D/Compatibility"冲突；我**建议 2D 假辉光**（径向渐变/`PointLight2D`/小范围加法），Compatibility 兼容、成本低——但需主程序确认渲染后端（联动我 §五「是否允许每频道切渲染后端」）。
- 【待定】**"拧盘换频道"切换时"容器光不闪、信号平滑过渡"**（主美术 §1.5 已列）：确认由**图形侧**承担暖光保持恒定的过渡（信号淡入淡出、刻度盘转动时容器光不抖动），还是由逻辑/动画层负责——影响我是否要做"暖光恒定 + 信号交叉淡入"的切换 shader。
