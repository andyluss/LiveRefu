## 一、一句话结论

**《明日频道》三频道滤镜（磁带扫描线+微噪 / 太空星雾缓移 / 蒸汽波慢速色偏）在既定平台（macOS + Windows 桌面双端）与主程序倾向的 Godot 4.7.x 路线上完全可行**——三者均为 2D 屏幕级/背景级后处理，不需要 Forward+ 独占特性（HDR 输出、AreaLight3D），单 pass 全屏即可承载，成本低、可各自独立开关、可无损降级为静态回退，满足 M2 风格切片与 GDD §9 的「静默可用」要求。真正的【待定】不在「能不能做」，而在**执行壳的渲染目标（Godot Shader 还是 WebGL/GLSL）** 与**三频道渲染后端的分工（Compatibility/2D vs Forward+/3D）**，详见 §五、§六。

## 二、三频道滤镜可行性切片表

> 对应 GDD §9「动态氛围」：磁带=扫描线与微噪、太空=星雾缓移、蒸汽波=慢速色偏。每行一个「效果 feature」，均遵循我 01 草案「后处理栈复用 + 效果可开关」与 02 草案「逐 effect 单测」原则。

| 频道 | 效果 | 技术路线 | 性能预估（1080p 桌面） | 计入 M2 风格切片 | 动效关闭的静态回退 |
| --- | --- | --- | --- | --- | --- |
| **磁带暖未来** | CRT 扫描线 + 微噪 | 屏幕后处理：全屏 shader 采样屏幕纹理，叠加重复扫描线掩码 + 细粒噪点。低成本变体：用 tileable 扫描线/噪点纹理的 `ColorRect` 叠加（`CanvasLayer` + `ShaderMaterial`），**不做**屏幕纹理重采样，成本最低。Godot 侧：Compatibility/2D renderer 原生支持。 | **低**：单 pass 全屏 ≈ 0.2–0.4 ms；纹理叠加法可 < 0.1 ms。 | **是**（M2 磁带场景定稿） | 扫描线/噪点转成**静态**半透明纹理（不滚动、不闪烁），或整层隐藏；基底＝暖色 LUT + 终端边框 + 自发光屏静态纹理，频道仍成立。 |
| **太空时代** | 星雾缓移（星云 + 星点缓动） | 2D/3D：低机率 tileable 星云/星点纹理做 UV 随时间慢速滚动（shader 驱动或 `Sprite` 滚动），叠加少量 `GPUParticles` 星点做纵深视差闪动。Forward+ 下可置于 3D 远景面片。**不依赖 HDR/AreaLight**，HDR 只对辉光有益、与「星雾」本体无关。 | **低-中**：背景滚动 shader ≈ 0.3–0.6 ms，粒子另计（数百点）；无 HDR 依赖 → 风险低。 | **是**（M2 太空场景定稿） | 冻结 UV 滚动与粒子时间常数，星雾定格为静态星云 + 星点图；基底＝深空紫蓝渐变 + 星云静态纹理，频道仍成立。 |
| **蒸汽波黄昏** | 慢速色偏（Hue/色带缓变） | 屏幕后处理：时间驱动 hue 偏移 / 分段色带映射（shader 内 `time` uniform 循环调色板），或动画 LUT 插值。2D 下可仅对背景层做缓变色带以进一步降本。 | **低**：≈ 0.2–0.5 ms（纯颜色数学或 LUT 采样，无纹理重采样）。 | **是**（M2 蒸汽波场景定稿） | 把 hue 冻结在既定调色板关键帧（静态渐变 + 静态色带）；基底＝蒸汽波渐变底图 + 低频色带，频道仍成立。 |

> 补充：三频道滤镜均为**可独立开关的 feature**（对应 01 草案 §三「每个效果一个可开关 feature」）。M1 只做磁带频道闭环，故**M1 仅需扫描线+微噪**；星雾与慢速色偏在 **M2** 定稿（对应 M1/M2 里程碑：M1 磁带闭环、M2 三频道三套氛围成立）。

## 三、「静默可用」在图形侧如何保证

GDD §9 要求「任何动态效果在关闭后频道仍成立（静态图 + 音景）」。图形侧把它当作**一等公民特性**，而非「把效果删掉后的残次状态」：

1. **feature 化与持久化**：每个动效是一个独立、可全局开关的 feature（01 草案「效果可开关」），开关状态持久化、默认值可由用户覆盖；全局「减少动态/关闭动效」开关（对齐 GDD §8.7 可及性）同时关闭粒子、UV 滚动、Hue 循环与呼吸动画，必要时保留**淡入淡出转场**（可再降级）。
2. **基底与动效层解耦**：每个频道渲染成两层结构——
   - **静态基底（必须渲染）**：色调 LUT + 材质语言 + tileable 静态纹理底图 + 界面皮肤（对应 GDD §6 每频道一套「视觉皮肤」）；
   - **动态叠加层（可关闭）**：扫描线/微噪、星雾滚动、慢色偏等，做成独立 `CanvasLayer` / 独立材质槽 / 独立粒子子场景。
   - 关闭动效 = 隐藏叠加层（节点可见性 off），**不改变基底场景树与调色**，从结构上保证「剥离动态层不破坏基底」。
3. **静态快照验收**：M2 切片交付时，每频道提交**「动效开 / 关」两态截图**（同一套 LUT/材质），作为主美术与 UI 美术的验收基准，实证「关动效频道仍成立」。
4. **与音景的静态闭合**：静态基底 + 音景本身就是一套完整氛围，符合 GDD §9「静态图 + 音景」；动效只是锦上添花，不承担「频道是否成立」的职责。

## 四、性能预算初估

> 依据我 02 草案预算表：原型 60 FPS、风格切片 M2 至少稳定 30 FPS、后处理全开 ≤ 3 ms/frame、DrawCall ≤ 2000(3D) / ≤ 500(2D)、显存 ≤ 2 GB（原型）。判读基础：**氛围陪伴是单频道场景，一次只渲染一个频道**；「三频道同时上屏」理解为最坏情况压测 / 性能 A/B 对照。

| 场景 | 说明 | 后处理耗时（估） | 其他（DrawCall / 显存） |
| --- | --- | --- | --- |
| **单频道上屏（真实用例）** | 只显示当前频道，滤镜栈 + 基底 | **≈ 0.5–1.0 ms** | 全屏采样 1 次（建议合并成单 pass）；2D DrawCall 增量 ≤ 5；远超 30 FPS 上限，60 FPS 无压力。 |
| **三滤镜同时上屏（最坏/压测）** | 三个 feature 同时启用（仅用于性能 A/B 对照） | **≈ 1.0–2.0 ms** | 仍在 ≤ 3 ms 预算内，但**不建议**生产启用；只作对照。关键优化＝合并成**单次全屏 pass**（共享调色/矩阵运算，按频道 feature 分支），避免多次屏幕纹理拷贝。 |
| **常驻后台 / 托盘 / 迷你窗态** | 降分辨率 + 降帧 + 暂停粒子与动效 | **< 0.3 ms（暂停时）**；迷你窗保活动画时每帧 ≈ 0.5 ms | 建议 15–30 FPS、0.25–0.5× 分辨率 upscale；CPU 侧数个百分点。全局快捷键唤回时全量恢复。 |
| **显存增量** | 星雾/扫描线/噪点 tileable 纹理 + LUT | 增量 **< 64 MB** | 纹理压缩（ASTC/BC），符合 ≤ 2 GB 原型预算。 |
| **Shader 编译与加载** | 首次切频道 | 每频道 1–2 个材质 | 建议切频道前预编译/预热，避免切换时掉帧（对接主程序加载管线 ≤ 5 s）。 |

**性能结论**：三滤镜是**低负载**后处理，主要瓶颈不在 shader 计算，而在**全屏 pass 数量**（一次屏幕纹理拷贝的成本）与**纹理内存**。图形侧的关键工程杠杆是：
- **合并成单次全屏 pass**，按频道 feature 分支，杜绝多 pass 重复拷贝；
- 磁带用**纹理叠加法**（tileable ColorRect）取代屏幕纹理重采样，把成本压到最低；
- 后台常驻态**主动降分辨率/降帧/暂停粒子**，把常驻负担压到可忽略。

## 五、与主程序技术路线（Godot/Web/跨平台壳）的适配评价——是否有冲突

**结论：无原则性冲突，基本利好；但有两个必须先对齐的边界。**

基于主程序 [03_Godot引擎调研](../主程序/03_Godot引擎调研.md)：

| 议题 | 主程序路线 | 图形侧适配评价 | 冲突？ |
| --- | --- | --- | --- |
| 执行壳 / 渲染目标 | 倾向 Godot 4.7.x 原生导出（macOS/Windows 原生，03 报告 §8）；Web 推导为次期降级 | **关键分支点**：若走 Godot 原生导出 → 材质写 **Godot ShaderLanguage**；若最终壳走 Electron/Tauri + Web 渲染 → 需写 **GLSL/WebGL2**。两者不通用。 | **需主程序拍板**（见 §六）。 |
| 渲染器分工 | 2D/UI（方向 A）走 Compatibility，3D 走 Forward+（03 报告 §4.1） | 磁带（2D/UI 重）用 Compatibility、太空/蒸汽波（含 3D）用 Forward+ 是**理想配对**；我 01 草案的「后处理栈复用」在两个后端都能落。 | 无原则冲突，但 2D/3D 混排是否允许**每频道切后端**需主程序确认。 |
| HDR / AreaLight3D / 最近邻缩放 | 4.7 新增（03 报告 §4.2），有利复古视觉 | 对本任务**非必需**：三滤镜是 2D 屏幕级、不依赖 HDR（星雾≠辉光）。HDR/AreaLight 是**扩展剧情**，不进 M2 低保真约束。 | 无冲突（HDR 属 Forward+ 独占，若空间频道加辉光再启用）。 |
| 社区 CRT 后处理方案 | 03 报告 §4.3 倾向由图形程序员 A 评估引入 vs 自研 | **M2 倾向自研轻量后处理栈**（控制权、许可清晰、无第三方依赖）；可参考社区 CRT 方案但需过许可与维护性评审。仅当扫描线细节远超自研成本时再引入。 | 无冲突；自研为主。 |
| 跨平台壳 / Web 降级 | 03 报告 §8，Web 导出 4.6+ 改进 | 三滤镜在 WebGL2/Compatibility 下均可运行（均为基础采样/数学，无需 Web 不支持的 HDR/面光源），**降级友好**。 | 无冲突。 |
| 后台常驻 / 迷你窗 / 全局快捷键 | GDD §10 风险：平台差异 | 与渲染解耦；图形侧只负责「后台态降分辨率/降帧/暂停动效」的渲染策略，系统级常驻由主程序承接。 | 无冲突。 |

> 一句话：**主程序 Godot 4.7.x 的路线在渲染上与我的后处理栈完全兼容**，且三滤镜特殊适配 2D/UI（Compatibility）与 3D（Forward+）的双路线；唯一门槛是**执行壳决定材质写哪种 shader 语言**，以及**是否允许每频道切渲染后端**。

## 六、需主程序 / 主美术 / UI 美术确认的点（【待定】）

> 语义：以下项目不动，我不保证 M2 切片能按期定稿；均已在对应文档用【待定】登记（本回执为中心登记，不回改他人文档）。

**向主程序：**
- 【待定】**最终执行壳**：Godot 原生导出（macOS/Windows 原生）还是 Electron/Tauri + Web？→ 决定我写 Godot Shader 还是 GLSL/WebGL2，直接影响 M2 切片开工时间。
- 【待定】**渲染后端分工**：是否允许「每频道切渲染后端」（磁带＝Compatibility/2D、太空/蒸汽波含 3D＝Forward+），还是整包统一一个后端？（统一则 2D/3D 混排成本上升。）
- 【待定】**性能档位确认**：M2 是否以 60/30 FPS 为验收、后处理总预算 ≤ 3 ms 是否认可？
- 【待定】**后台常驻渲染策略**：是否允许降分辨率 + 降帧 + 暂停粒子？全局快捷键唤回是否触发全量恢复？
- 【待定】**Shader 预编译/预热**：切频道前预热材质，避免切换掉帧（对接加载管线 ≤ 5 s）。

**向主美术：**
- 【待定】**三频道动效的视觉样本**：太空星雾的目标星云色调/密度、蒸汽波慢色偏的目标色带、磁带扫描线密度与微噪强度——以便我把参数收敛进 `data/fx_preset.json`（01 草案 §4）。
- 【待定】**跨频道同源复用**：星雾纹理是否允许在太空（星雾）与蒸汽波（慢色偏底图）间共用 tileable 资源？→ 影响资产数量与显存。
- 【待定】**静态回退的验收样式**：「静默可用」关闭动效后各频道的静态基准图（呼应 GDD §9 的「静态图 + 音景」）——需主美术给出静态验收标准。

**向 UI 设计美术 A：**
- 【待定】**扫描线/微噪是否覆盖 UI**（GDD §9 与我 01 草案 §5、02 草案接口均标记）→ 影响 UI 字号与对比度（CRT 覆盖文字磨损可读性）。
- 【待定】**蒸汽波慢色偏是否影响 UI 皮肤可读性与语义色**（按钮态/警示色）→ 需 UI 美术 A 出一版「动效关闭 vs 开启」的 UI 层叠约定（对齐 GDD §8.8 一句话帮助、§8.3 计时呈现）。

> 另：M2 切片需要主美术提供**各频道场景参考（哪怕 placeholder 拼贴）**，否则 M2「三套氛围成立」无法验收——此为协作依赖，登记如下。
