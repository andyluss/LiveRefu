# ideas/AI · AI 参考文档区

> **这里放 AI 生成的参考，不放人的设计意图，也不放项目决定。**
> 本目录是 [`../README.md`](../README.md) 的唯一例外：根目录 `ideas/` 是人的手写源，AI 默认只读；`ideas/AI/` 允许 AI 主动或按需生成参考文档。

## 一、这里放什么

适合：

- 一个模糊想法的多种可能方向；
- 两三个方案的对比、代价与反方论证；
- 题材/市场/机制的参考资料摘要；
- 对现有想法的红队评审：最可能失败在哪里；
- 原型验证计划、试玩问题、观察清单；
- “如果继续这个方向，下一步可以怎么验证”。

不适合：

- 替人做设计决定；
- 改写 `ideas/` 根目录的人类原文；
- 把参考直接写成项目规格、排期或验收标准；
- AI 生成的世界观/卡牌/剧情被当成既定设定；
- 未经来源核验的事实。

> **参考不是决定。** 人可以把这里的文档升级为项目方向，但升级动作必须由人明确做出。

## 二、AI 的写入权限

| 位置 | AI 权限 |
| --- | --- |
| `ideas/` 根目录（含本文件的上级） | **默认只读**；修改需要人明确要求 |
| `ideas/AI/` | 可以新建、补充、修订 AI 参考文档 |
| 项目 `docs/` | 按项目任务与人类指示写入；不得把 AI 参考自动搬进去 |

在 `ideas/AI/` 里生成内容时，仍然要：

- 先读 [`../README.md`](../README.md) 与相关人类想法；
- 不把 AI 的假设写成人的意图；
- 对事实、推断、猜测做区分；
- 标明这份参考基于哪些假设；
- 给出“什么情况下这个建议会失效”。

## 三、文件格式

命名：

```text
YYYYMMDD-主题.md
```

开头固定标注：

```markdown
> **AI 参考 · 非决定** ｜ 日期：YYYY-MM-DD
> 对应的人类想法：<链接或“暂无”>
> 用途：<这份参考帮人判断什么>
> 可信度：<事实 / 推断 / 假设的比例与来源>
```

推荐结构：

```markdown
## 我理解的人类意图
## 可选方向（2–3 个）
## 每个方向的代价与风险
## 反方论证：最可能失败在哪
## 建议的验证方式
## 不确定项 / 需要人回答
```

## 四、写作原则

1. **先复述人的意图**，再给 AI 的补充；
2. **给选项，不给命令**：用“可以 / 代价是 / 如果……则……”而不是“应该”；
3. **保留反方**：至少写一个“这个方向可能不成立”的理由；
4. **区分事实与假设**：外部资料给来源，推断标明推断；
5. **可被推翻**：写清楚什么证据会让你改变建议；
6. **不膨胀**：一份参考只回答一个判断问题，不堆无关内容；
7. **不抢方向盘**：不替人决定主题、目标体验、美术方向与范围。

## 五、从参考到项目

```text
人写想法 → AI 在 ideas/AI/ 做参考 → 人判断 → 人决定是否立项/改项目
```

- AI 参考只进入 `ideas/AI/`；
- 人明确采纳后，才进入项目 `docs/`；
- 项目里的实现裁决仍写在项目文档，不反向覆盖人的原始想法；
- 参考过期不删除也可以，用新日期文档替代，并在开头注明“替代了哪份”。
