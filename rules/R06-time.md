# R06 · 时间与时间戳约定（已定 · 现行）

**一句话**：所有**时间**一律用**东八区**、**精确到分**，且**不得脑内手写**——已提交产物取 **git 提交时间**，新建文件取**系统时钟**。

> **本文是"时间"这件事的总规则**：时区、精度、来源、格式、校验都在这里。
> 后续凡与"时间"有关的新约定（相对时间表示、跨时区协作、时间线对账、时间戳命名的新场景……）**都追加进本文**，
> **不另立新规则**——时间是一件事，拆成多条会让人不知道"该看哪条"。这也是本文取名 `R06-time.md`（而不是 `R06-time-precision.md`）的原因。

## 一、目标

让工作区里**任何一处时间**都满足四条：① 可追溯到**真实来源**（不是回忆）；② 精度**够用**（至少到分）；③ **格式一致**（同一种东西同一个写法）；④ **可被机器校验**。

**为什么必须成文**：时间是最容易被"随手写"的东西——写错**不会报错**，只会在几个月后让人无法判断"这条记录早于还是晚于那条"。本工作区已经吃过一次亏：变更日志的版本时间曾是"事后脑补"，与标签指向的提交对不上，于是那条校验形同虚设。另一次是讨论记录只用日期，同一天九次讨论**无法排序**。

## 二、规则条款（主选）

1. **时区**：一律**东八区**（与 [R01](R01-docs-convention.md)、[M2](meta/M2-naming-vocabulary.md) 一致）。
2. **精度**：**精确到分**（`HH:MM`）。新产物只写日期（`YYYY-MM-DD`）视为**不合规**；**历史产物不追改**（保留当时形态，需要时另加一行补记，而不是覆盖原值）。
3. **来源（禁止脑内手写）**，按产物状态二选一：
   - **已提交的产物** → 取该产物的 **git 提交时间**（权威、可复算）：
     ```
     git log --diff-filter=A --date=format-local:'%Y-%m-%d %H:%M' --format=%ad -- <路径>
     ```
   - **正在新建的文件** → 取**系统时钟**：`date '+%Y-%m-%d %H:%M'`。
   - 两者通常同分钟（工作区约定"非琐碎变更立即提交"）。**不一致时以提交时间为准**：**改文件名，不改提交**（提交历史是事实，命名是可修正的表述）。
4. **格式（三处，各自固定）**：

   | 出现位置 | 格式 | 例 |
   | --- | --- | --- |
   | 正文 / 文档内 | `YYYY-MM-DD HH:MM` | `2026-10-08 13:46` |
   | 文件名（**时事件**：会议 / 日志 / 决策 / 里程碑） | `YYYYMMDD-HHMM-关键词` | `20261008-1346-时间规则裁决.md` |
   | 同一分钟内多件同类文件 | 关键词前加 `-NNN-` 序号 | `20261008-1346-001-…`、`…-002-…` |

   > 文件名用 `HHMM`（**无冒号**：Windows 非法字符、URL 需转义，且可直接字典序排序）；正文用 `HH:MM`（给人读）。
   > **两处不同是有意的**——约束不同，不应强行统一。
   > 第 3 行是对 [M2 §二.2](meta/M2-naming-vocabulary.md) 的**细化**（M2 未规定同分钟冲突），不是替代。

5. **已知例外（机器解析所需，非疏漏）**：**规则演进的「演进历史」表、变更日志的表格中，日期列保持 `YYYY-MM-DD`**——
   该列由 [M3 演进检查器](meta/evolution/rule_evolution_check.ts) 按固定正则解析，加了时分反而会让该行**被静默跳过**。
   变更日志的**版本头**则必须带时分（`## [x.y.z] - YYYY-MM-DD HH:MM`，见 [R05](R05-changelog.md)）。
6. **版本头与标签**：[R05](R05-changelog.md) 的配套纪律——版本头时间 = 该版本 tag 指向提交的**作者时间**；打 tag 后由检查器核对。
7. **机器校验**：由 [`tools/check_time_naming.ts`](../tools/check_time_naming.ts) 校验带时间戳的文件名格式（覆盖 `projects/mainline/docs/discussions/` 与 `**/plans/**`），接入 pre-commit 与 CI。**约定靠人记必然退化**。

## 三、备选（被放弃的选项）

| 备选 | 为何不为主选 | 代价 |
| --- | --- | --- |
| 只写日期 | 同一天多次变更**无法排序**（本工作区一天内最多 9 次讨论） | 时间线混淆 |
| 精确到秒 | 无实际用途，文件名变长、更易写错 | 噪声，且不解决任何已知问题 |
| 一律用系统时钟（不看 git） | 事后补记**必然失真**，且无法机器核对 | "当时写了什么"不再可信 |
| 一律用 git 时间 | 新建文件时提交**尚不存在**，无法命名 | 流程死锁 |
| 各关注点自选格式 | 与 [M2](meta/M2-naming-vocabulary.md)"进任何目录都长一样"冲突 | 每次都要重新辨认 |

## 四、判定标准（写下一个时间前，依次问）

1. 这个时间**来自哪里**？能在 git 或系统时钟里**指出来**吗？→ 指不出 → **不许写**。
2. 精度**到分**了吗？→ 没有 → 补到分（历史产物、以及 §二.5 的例外列除外）。
3. 它出现在**哪个位置**（正文 / 文件名 / 版本头 / 表格列）？→ 用该位置固定的格式。
4. 有没有**同分钟冲突**？→ 有 → 加 `-NNN-`。
