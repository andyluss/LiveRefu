# R01 · 文档约定（已定 · 现行）

**一句话**：工作区 Markdown 一律**简体中文 + UTF-8**；`docs/`、`studio001/` 按各自体例；**相对链接**按“目标相对当前文档的正确深度”书写；**日期**取东八区系统时间。

> 状态：`accepted.active` ｜ 版本：v3 ｜ 最后更新：2026-10-27
> 本文是文档体例与相对链接的**唯一规则与格式规格**；原 [`tech/docs-convention.md`](../tech/docs-convention.md) 已整合进本文，仅保留指针。

## 一、目标与适用范围

让全工作区文档“体例一致、链接可跳转、日期可信”，使人与 AI 依据同一条约定书写。

适用于工作区根、`docs/`、`projects/`、`design/`、`tech/`、`studio001/` 等所有被跟踪 Markdown；`indie/` 独立仓库按各自约定执行。

## 二、规则条款（主选）

1. **语言与编码**：简体中文，Markdown（UTF-8）。
2. **`docs/` 编号体例**：`00_总论_…`、`01_理论篇_…`；专题卷 `00_对读篇_…` 起。
3. **`studio001/` 体例**：角色目录内 `README.md` 为身份入口，工作文档为 `两位序号_主题.md`；草案标 `v0.x`，未决问题标 `【待定】`，结论记入各文档「决策记录」。
4. **跨目录引用**优先使用**相对路径**链接；不用站内绝对路径（`/docs/...`）或本机绝对路径。
5. **相对链接深度**：以文件自身所在目录为基准，**朝向工作区根每深一级多一个 `../`**；详见 §三。
6. **日期**：一律**东八区（Asia/Shanghai，`+0800`）**、**取自系统实际时间**，写前先跑 `date '+%Y-%m-%d'`；**禁止“脑内手写”或相对推算**。

## 三、相对链接深度（细则）

链接必须以“目标文件相对当前文档的正确深度”书写，保证本地 IDE / 预览器 / 网页版都能跳转。

- 以文件自身所在目录为基准逐级向上（`../` 表示上一级目录）；**朝工作区根每深一层多一个 `../`**。
- **反例（写错深度）**：`studio001/主策划/01_立项概念草案.md` 指向 `docs/`，因它在 `studio001/主策划/`（比根深两级），须写 `../../docs/...`；写成 `../docs/...` 会落在 `studio001/docs/` 而失效。
- **优先用“工作区相对入口”**：在目录 README 集中建索引，减少深层 `../../`；文档被移动时只需改索引，不必逐篇手算。
- 链接目标必须存在；不得依赖本机文件或生成物。
- 图片、HTML、附件同样按相对路径处理。

## 四、校验机制

“相对链接写错”靠两道闸门拦截：

1. **pre-commit 钩子（本地）**：每次 `git commit` 校验本次暂存的 Markdown 内部链接，失效即阻断并打印明细。启用见 [`tools/install_hooks.sh`](../tools/install_hooks.sh)，说明见 [`tech/hooks-readme.md`](../tech/hooks-readme.md)。
2. **CI 链接检查（提交后兜底）**：push / PR 时由 CI 跑链接校验；即使本地未启用钩子，也会在托管平台暴露。

手动全量检查：

```bash
node tools/check_links.ts
node tools/check_links.ts --files <md文件>   # 只看指定文件
```

规则依据：[R03](R03-link-validation.md)。变更日志、规则、项目文档都是普通 Markdown，**不享受链接校验豁免**。

## 五、日期写法

```bash
TZ=Asia/Shanghai date '+%Y-%m-%d %H:%M'
```

- 文档/决策记录/变更记录中的日期取该命令返回值；
- 不要根据“印象中的今天”或相对日期推算；
- 需要精确到分时，按 [R06](R06-time.md) 执行；提交时间与文档时间的一致性由 R06/变更日志闸门把关。

## 六、备选（被放弃）

| 备选 | 为何不为主选 | 代价 |
| --- | --- | --- |
| 中英混排 / 英文文档 | 工作区读者与既有文档以中文为主 | 阅读成本、术语不一 |
| 站内绝对路径链接 | 本地 IDE / 预览器 / 网页版不通用 | 链接大量失效 |
| 手写日期 / 相对日期推算 | 易与实际（提交时间）不一致（曾发生写错案例） | 记录不可信 |

## 七、判定标准

- 新文档：简体中文 + UTF-8；体例属 `docs/` 或 `studio001/` 之一并符合其编号/命名。
- 含链接：按当前文件深度书写；经 R03 的 pre-commit / CI 校验通过。
- 含日期：其值等于运行 `date`（东八区）所得。

## 八、自检

> “这条链接换台机器、换个人打开还能跳转吗？这个日期是我 `date` 跑出来的吗？”
