# M1 · 文件组织方式（已定 · 已落地）

**一句话**：**关注点优先，类型其次，且递归**（concern-first, type-secondary, recursive）——顶层按
"关注点/领域/项目"切；关注点内部用类型词表组织，**并可继续用"子关注点"递归分解**。

## 一、目标

让人**更容易、更快**地理解工作区/项目文件结构，能在 1 次目录点击内定位到"这是关于什么的、属于哪类"。

## 二、主选（决策）

> 顶层按关注点/领域/项目切（第一刀=是什么），关注点内按固定类型词表（README/docs/data/code/test/plans/tool）。

**主轴选关注点**（对"快速理解"）：
- 人找东西的第一问是"**这是什么**"（知识库？项目？实验？），而非"这是什么类型"。
- 关注点是**语义边界**，天然聚合归属：`明日频道` 的文档/数据/代码都在其目录下，不会被拆散到全局 `docs/code/data` 桶。
- 顶层关注点**少而稳定**（约 5–8 个），一眼扫完、可记忆。

**从轴仍要类型**（避免"纯模块化"的另一极端）：进入某个关注点仍要区分"规范/数据/代码/测试/计划"，
统一类型词表让"进了任何目录都长一样"，认知负担最低；少数跨关注点类型（根 README、`tools/`、`tech/`）各归其位。

**权衡**：需先定义"哪些算关注点"（顶层保持小）；放弃"无类型轴"的最大自由，换取一致性。

### 2.1 递归：关注点之中可以有"子关注点"

一个关注点内部，除了**类型目录**（直接归属它的产物），还可以有**子关注点**——它本身是一个"是什么"
的语义单元，有自己的 README（出入口）与结构，并**递归**套用本规则。

- **子关注点**：其下是"属于它自己"的类型 / 更深的子关注点，**独立成篇、可单独演进**
  （如 `rules/` 下的 `meta/`；`lab/formal-system` 下的"数据验证器""可视化兜底""元规则"）。
- **类型目录**：直接把某类产物交给该关注点（如 `tools/`、`viz/`、`notes/`、`specs/`）。

**区分（子关注点 vs 类型）**：
1. 它是不是一个**可单独命名的"什么"**（一个实验 / 一个子系统 / 一个能独立说清的事）？→ **子关注点**。
2. 它是否是同一关注点下**的一类产物**（文档 / 数据 / 代码 / 输出 / 教训）？→ **类型目录**。
3. 反向检验：把子关注点的文件拆到多个类型/目录，是否**难以一眼看出"这是一个整体"**？→ 是，则**应做成子关注点**。

> 这正是 lab/formal-system 曾遇到的问题：`data-validator`（Rust 校验器）、`visual-fallback`（可视兜底）、
> `meta-rules`（元规则）本是三个**子关注点**，其文件却散在 `prototypes/`、`tools/`、`viz/`、`notes/`、
> `meta-rules/` 之间，时间久了易乱。按本规则的**推荐解法**：为每个子关注点建一个**自包含目录**
> （含 README + 各自的产物/子目录）；本目录 [`meta/`](README.md)（元规则）即是一例——含 README + 规则 + 配置 + `tools/` + `evolution/`。

## 三、备选（被放弃的选项）

| 备选 | 描述 | 为何不为主选 | 代价 |
| --- | --- | --- | --- |
| A1.1 类型优先（全局 docs/code/data） | 顶层全按产物类 | 切断"属于谁"的归属、跨项目无法一眼分清 | 随项目数线性膨胀、难排序 |
| A1.2 纯关注点（无类型轴） | 每关注点自定内部结构 | 结构不一致、不可预期 | 每次都要重新熟悉 |
| A1.3 按层级/角色切（studio 角色、docs/角色） | 顶层按角色/层级 | 角色/层级是"子关注点"，应是关注点内部再切 | 顶层会泛滥成"一人一层" |

## 四、判定标准（放一个新文件/一组文件时依次问）

0. 它/它们是不是一个**可自成一体**的子关注点（独立实验/子系统/能单独说清的事），且不宜被拆散？ → **建子关注点目录**
   （含 README + 自身类型；再递归应用本规则）；否则 → 进入所属关注点。
1. 它服务**哪个关注点/领域/项目**？ → 顶层目录（第一刀）。
2. 它是**哪种产物**（README/规范/数据/代码/测试/计划/工具/研究）？ → 关注点内类型子目录。
3. 它**跨关注点**吗（全局约定→[`../../tech/`](../../tech/README.md)；通用工具→`tools/`；通用说明→根 [`README.md`](../../README.md)）？

## 五、自检问题

> "新接手的人想知道 X，能否只靠 **1 次目录点击 + 一眼看清固定子结构** 就定位到 X？"
