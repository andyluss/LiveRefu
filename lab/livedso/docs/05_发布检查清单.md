# LiveDSO · 发布检查清单

> 状态：生效 ｜ 日期：2026-10-27 ｜ 适用：每次版本发布
> 规则依据：[`tech/changelog-convention.md` §十一](../../../tech/changelog-convention.md#十一版本段-append-only硬规则)

## 1. 发布前

- [ ] `node --test test/core.test.ts` 全过；
- [ ] `node src/cli.ts check` 无 error；
- [ ] `node src/cli.ts check vault-lrds` 无 error；
- [ ] Workbench 启动并走查至少：总览、Tokens、Contracts、Preview、Adoption、Checks、Report；
- [ ] `node tools/check_links.ts` 0 失效；
- [ ] 版本号/README/架构/路线图同步。

## 2. 写版本段

- [ ] 在 `CHANGELOG.md` 顶部新增 `## [x.y.z] - YYYY-MM-DD HH:MM`；
- [ ] **不删除、不改名、不折叠任何旧版本段**；
- [ ] `[未发布]` 只保留未发布内容；
- [ ] 时间取本次发布提交的**作者时间**；
- [ ] 条目不写“baseline”替代旧版本；baseline 只能作为新增摘要。

## 3. 提交与 tag

```bash
GIT_AUTHOR_DATE='YYYY-MM-DD HH:MM' git commit -m "release(livedso): vX.Y.Z"
git tag livedso-vX.Y.Z
node tools/check_changelog.ts --file lab/livedso/CHANGELOG.md --tag-prefix livedso-v
```

- [ ] tag 指向发布提交；
- [ ] tag 时间与版本头一致；
- [ ] 旧版本都有 `livedso-v*` tag（缺则补到该版本最后提交，不折叠）。

## 4. 推送

```bash
git push origin main
git push origin livedso-vX.Y.Z
```

> 发布不是“提交完就算”；**没有 tag 的版本不算发布**。如果暂时不能打 tag，就不要把它写成版本段，留在 `[未发布]`。
