# LiveAtelier · 灵动构坊（代号 LiveDSO）· 产品定义（v1.2.1）

> 状态：stable ｜ 日期：2026-10-28 ｜ 代号 LiveDSO；正式名 LiveAtelier / 灵动构坊。

## 1. 问题

设计系统团队知道“应该有一个源”，但日常现实是：

- token 在 Figma、代码、文档三处漂移；
- 组件只有样子，没有状态/键盘/错误处理；
- 对比度/裸值/弃用在发布前才发现；
- 不知道哪个产品用了旧组件；
- 每次变更都像拆弹。

## 2. 用户

| 用户 | 任务 | 付费理由 |
| --- | --- | --- |
| **独立开发者（首批）** | 一个人维护自己的 token/组件/风格卡 | 省时间、能直接导出/报告 |
| 设计系统负责人 | 证明系统在被采用、降低变更风险 | 审计/采用/迁移 |
| 设计工程师 | 从源生成多端、过 CI | 自动投影/闸门 |
| 产品设计师 | 看见代码里真正有什么 | 可信目录/状态 |
| 代理机构 | 复用一套方法交付客户 | 模板/白标/审计 |
| 小团队 | 不想自建脚本 | 一体化/托管 |

## 3. 价值主张

> 不是“展示设计系统”，而是“运行设计系统”：让变更从源到所有产品可见、可检查、可回滚。

## 4. v1.0 范围

**做**：token 解析/别名、3 类闸门、契约检查/编辑、风格卡与并排对比、健康报告、CSS 投影、Web 查看/改值、契约编辑、真实 token 组件预览、采用扫描（CLI/API/UI）、多 vault 切换、token 生命周期/弃用、本地快照与差异、跨 vault 本地 CI 门禁、本地检查插件、跨快照趋势、跨 vault 趋势（UI/CLI）、CI 模板、插件示例、`plugin-test`（单 vault/跨 vault 矩阵）、本地报告模板（含嵌套条件/循环/报告包）、Vaults 健康总览、CLI、从 `design/tokens` 导入 LRDS 真实 case。

**不做**：Figma 同步、云协作、账号、计费、完整 token 树编辑、真实产品组件渲染、团队权限/私有 registry/托管（按用户裁决搁置）、自动回滚、自动改目标代码。

## 5. 成功指标（v0.17）

- 能在 10 分钟内接入一个真实 vault；
- 能发现至少 1 个真实漂移/对比度问题；
- 能改完一个契约并在预览里看到变化；
- 采用扫描能在一个真实前端项目里找到旧 token/裸色；
- 能在两个 vault/两张风格卡之间切换并保持判断一致；
- 能标记一个弃用 token，并在契约/采用扫描里看到引用；
- 能创建快照并在改值后看到明确 diff，不依赖云；
- 能在本地 CI 用一条命令聚合所有 vault 并按阈值阻断；
- 能写一个本地插件把品牌规则接进 check/CI，而不改核心；
- 能在一屏看到多次快照的 token/弃用趋势，不依赖云；
- 能直接复制 CI 模板与插件示例，不必从零写；
- 能在 Workbench 的 Trends 页看到多 vault 趋势；能本地自检插件；
- 能一次看到同一插件在多个 vault 上的 issue 矩阵；
- 能用自己的 Markdown 模板生成报告，不依赖云；
- 能在一个页面比较所有 vault 的健康状态并切换；
- 能用模板循环列出 token/issue 明细，不依赖云；
- 能一条命令生成本地报告包，作为 CI artifact。
- 报告能被贴进 PR/评审；
- 自己每天愿意打开。

## 6. 非目标

- 不做通用设计工具；
- 不做文档站；
- 不做“AI 自动生成设计系统”；
- 不把维护/代价藏起来。
