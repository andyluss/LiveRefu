## 一、九项校验 + 一次刷新

每项都是一条子命令，退出码非 0 即 FAIL。命令统一前缀：`node --experimental-strip-types tools/sim_refu_game_001.ts`。

| 序 | 子命令 | 测什么 | 判据 / 阈值 | FAIL 时怎么办 |
| --- | --- | --- | --- | --- |
| 1 | `--selftest` | 模型自检：复现、单调、解析一致 | 同参数两次模拟结果相等；基准关（D=1）解析胜率 82%–87%；D=1.0 > 1.2 > 1.4 单调下降；n=20000 时模拟与解析偏差 ≤1.5pp | 查 λ0/γ/cap 是否被误改，断言不动 |
| 2 | `--verify-bands --n 20000` | 主线五章均值带位 | 第 1 章 80–100%、第 2 章 65–80%、第 3 章 55–70%、第 4 章 45–60%、第 5 章 40–55% | 改该章 B 或 α，不改带 |
| 3 | `--verify-rogue --n 20000` | 远征 8 节点带位（P=1.08） | 1–2 节点 70–90%、3–4 节点 40–65%、5–6 节点 12–30%、7–8 节点 3–12% | 改节点 B 或 ROGUE_P |
| 4 | `--verify-faction` | 族专属挑战卡双口径 | 基准 B=205、P=1.08；2 分卡平均跌幅 5–12pp、3 分卡 12–25pp；纯流派跌幅须大于平均且 ≤35pp | 调该卡 playerMul 系列 |
| 5 | `--verify-seed` | 种子与排行榜用例 | 同种子相同、不同种子不同；前 6 节点不重复；节点 1 限单入口图；1000 个种子内每张图都被抽中；三条比较器用例 | 查 MAP_POOL 与 drawRun |
| 6 | `--verify-anti-air` | 三族对空覆盖 | 每族可对空卡 ≥2 张，其中塔卡 ≥1 张 | 补卡或登记 AIR_CARDS |
| 7 | `--verify-air-matrix` | 空袭 × 三族 9 宫格公平性 | 空袭 B=120/180/240 三档，每档三族极差 ≤15pp | 调 FACTION_AA 或对空卡质量 |
| 8 | `--verify-air-mix` | 纯空军 / 混编 / 纯地面 | B=180；三族极差上限：纯空军 15pp、混编 12pp、纯地面 5pp | 先修纯空军档 |
| 9 | `--verify-pmod` | 永久修饰卡双口径 | 基准 B=205、P=1.08；平均增益 6–12pp；契合流派增益须大于平均且 ≤20pp | 调该卡 playerMul 系列 |

九项全 PASS 后刷新报告：`--report --out doc/refu-game-001/数值/体检报告.md`。报告头写明本次 `n / seed / λ0 / γ / cap / B_ref`，必须与九项校验同一次跑出，不能拼两次结论。

## 二、"设计意图 → 断言"：三个真实例子

一条断言 = 一个可测量的量 + 一个区间 + 越界处置。三原则：用带不用点；上限与下限分开写；先写带再调首值（[论文第五节](../00_塔防游戏研究_内涵与外延.md)：把设计意图写成断言）。

| 设计意图（人话） | 脚本里的断言 | 子命令 | 实测 | 越界处置 |
| --- | --- | --- | --- | --- |
| 换哪一族打同一档空袭，胜率差不超过 15 个百分点 | 极差 = max(胜率) − min(胜率) ≤ AIR_FAIRNESS_PP = 0.15 | `--verify-air-matrix` | 三档 1.0 / 9.7 / 8.4pp | 调 FACTION_AA 系数或补对空卡，不抬上限 |
| 挑战卡可以压垮纯流派，但不能一张卡杀死一套牌 | 纯流派跌幅 > 平均跌幅 **且** ≤ FACTION_PURE_CEILING = 35pp | `--verify-faction` | 最高 31.8pp（弹药禁令、腐蚀逆流），最低 16.3pp（护盾过载） | 调 playerMulPure，上限是红线 |
| 远征 BOSS 要被设计成难，而不是不可通关 | 节点 7–8 同带 [3%, 12%]（5–6 为 12–30%，构成断崖） | `--verify-rogue --n 20000` | 节点 8 实测 3.8%（设计表记 3.6%，口径说明见 01 号文件第四节） | 调 ROGUE_NODES 的 B 或 ROGUE_P |

## 三、接入 CI 与 pre-commit

| 事项 | pre-commit（[tools/hooks/pre-commit](../../../tools/hooks/pre-commit)） | CI（[.github/workflows/verify.yml](../../../.github/workflows/verify.yml)） |
| --- | --- | --- |
| 触发路径 | 暂存文件命中 `^(doc/refu-game-001/\|tools/sim_refu_game_001\.ts)`（改该卷或脚本即触发） | push / PR 到 main 即全量跑 |
| 跑哪些 | 第 1 项 + 第 2/3 项 + 第 4–9 项 | 第 1 项 + 第 2/3 项 + 第 4–9 项 |
| n 值 | 第 2/3 项用 n=5000（其余各项是解析式，不受 n 影响） | 第 2/3 项用 n=20000，作为结论依据 |
| 另外的兜底 | 只查与暂存相关的内容 | 另跑 `tools/check_links.ts -v`，本卷链接写错也会被拦 |

运行时长（本地实测，Node v24.20.0）：九项串行合计约 1.1 秒，单条 0.1–0.3 秒，最慢为 `--verify-bands --n 20000`（约 0.27 秒）。临时跳过用 `git commit --no-verify`，CI 兜底。

## 四、数值变更流程（五步，顺序不能换）

1. **改常量**：一次只动一个首值或常量，写下预期影响哪几项；
2. **重跑九项**：全 PASS 才算过；任一 FAIL 回到第 1 步，不先改断言；
3. **刷新报告**：`--report --out doc/refu-game-001/数值/体检报告.md`；
4. **更新受影响面**：[21_模拟验算表](../../refu-game-001/21_模拟验算表_章节胜率矩阵.md)、[20_难度曲线](../../refu-game-001/20_关卡难度曲线设计.md)、[11_数值框架表](../../refu-game-001/11_数值框架表.md)，以及 [可视化/01_难度与胜率曲线](../../refu-game-001/可视化/01_难度与胜率曲线.html)、[03_对空矩阵](../../refu-game-001/可视化/03_对空矩阵.html) 等生成面；
5. **CHANGELOG 记账**：卡表类改动版本号 +0.0.1（见数值 README 第二节），在 [CHANGELOG](../../../CHANGELOG.md) 写清"动了哪个常量、哪几项从什么变成什么"；暂存时过 [tools/check_changelog.ts](../../../tools/check_changelog.ts)。

## 五、参数冻结策略：哪些常量是红线

| 常量（脚本内名） | 当前值 | 为什么不能漂移 | 可否随版本动 |
| --- | --- | --- | --- |
| `B_ref`（B_REF_DEFAULT） | 158 | 难度比的分母，动它等于全局平移难度，历史 D 与胜率表全部不可比 | 红线 |
| `λ0` / `γ` | 1.35 / 3 | 漏怪强度与曲线陡度，动 γ 会改整条带位的形状 | 红线 |
| `cap`（CAP_DEFAULT） | 3 | 胜负判据本身（累计漏怪 < cap），改它等于改规则 | 红线 |
| `SIM_RATIO` | 0.667 | 双流挑战"同时段占比"的折算口径 | 版本内冻结 |
| 章节带与 α | 见第一节第 2 项；Ch2/Ch3 α=1.06 | 验收目标，改带就是改验收，不是改数值 | 红线，改则整册重跑并重写文档 |
| `ROGUE_P` 与节点 B | 1.08；`round(170.6 × (0.9 + 0.10i))` | 远征曲线的形状由公式而非手感决定 | 版本内冻结 |
| `FACTION_PURE_CEILING` / `PMOD_PURE_CEILING` | 0.35 / 0.20 | "单卡不能杀死一套牌"的上限 | 红线 |
| `AIR_FAIRNESS_PP` / 三形态 spreadMax | 0.15；0.15 / 0.12 / 0.05 | 三族公平性判据 | 红线 |
| B 序列、卡的 playerMul 系列、MAP_POOL 权重、AIR_CARDS 清单 | — | 这些是素材，不是尺子 | 可调，但调完必须重跑九项 |

判别口诀：改了只需**重跑**的是素材，改了必须**重写验收文档**的是红线。脚本把 λ0/γ/cap/B_ref/seed 开成命令行开关，那是给 [04_敏感性分析](04_敏感性分析.md) 做扰动实验的；验收基线一律用默认值。`D50` 与 `k` 无开关，要扰动须在脚本内调整后重跑。

## 六、常见 FAIL 的三类原因与排查顺序

| 类型 | 典型 FAIL 行 | 怎么分辨 | 排查顺序 |
| --- | --- | --- | --- |
| A 结构 / 清单类 | `--verify-anti-air` 某族"可对空 1/4"；`--verify-seed` 某图"从未被抽中" | 与 n 无关，输出里带着具体卡 id 或地图 id | 按输出的 id 回 AIR_CARDS / MAP_POOL 核对；确认新内容是否漏登记；再跑单项 |
| B 数值越界类 | `--verify-bands` 某章偏易 / 偏难；`--verify-air-matrix` 极差超 15pp | 胜率随 D 单调变化，通常只在被动过的那几关出现 | 先确认目标带没被顺手改；再查共享常量；再定位到具体卡的 mul；最后才动 B 序列 |
| C 可复现性类 | `--selftest` 报"种子不可复现"；同命令两次结果不同 | 同一输入两次跑不一致，或 n=5000 与 n=20000 结论相反 | 固定 seed；排查是否混入未固定种子的随机；抬 n 复核，带边界余量不足 1pp 时优先调 B 而非调 n |

总纲：先第 1 项（模型）→ 再受影响单项（内容）→ 最后第 2/3 项（曲线）；每步都读输出里的"实测值 vs 带"。
