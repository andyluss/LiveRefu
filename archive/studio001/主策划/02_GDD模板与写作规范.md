# GDD 模板与写作规范（草案 v0.1）

> 主策划 · 用途：立项通过后，玩法设计文档（Game Design Document）的统一样式与分章规范。供全工作室引用，尤其数值策划 A 与主程序按章拆解需求。

## 一、写作总则

1. 语言简体中文；每条规则写明「为什么」与「对应体验」。
2. 先结论后展开：每章开头用 3—5 行说清本章核心。
3. 描述"玩家行为"优先于描述"系统内部"，内部机制放附录。
4. 所有数值需求只写"目标与范围"，具体数值由数值策划 A 落表。
5. 【待定】问题不许静默搁置，必须登记到文档末尾「开放问题」。

## 二、GDD 固定章节模板

```
# 《项目代号》玩法设计文档

## 0. 一句话概念（logline）
## 1. 核心体验与卖点
## 2. 目标玩家与平台
## 3. 核心玩法循环（分钟级 / 小时级 / 天级）
## 4. 系统清单（列表 + 一句话职责，映射到负责人）
## 5. 世界观与叙事框架
## 6. 内容规模清单（场景/角色/道具/关卡）
## 7. 数值与成长目标（转数值策划 A 落表）
## 8. UI/UX 需求清单（转 UI 设计美术 A）
## 9. 美术风格要点（转主美术）
## 10. 技术风险与原型范围（转主程序）
## 11. 里程碑与验收标准
## 12. 开放问题（【待定】汇总）
## 附录 A. 术语表
```

## 三、章节写作规范要点

| 章节 | 规范 |
| --- | --- |
| 核心玩法循环 | 必须画出循环图（mermaid 或文本箭头），标注每个环的时长与反馈 |
| 系统清单 | 每条：系统名 / 一句话职责 / 依赖系统 / 负责人 / 优先级（P0-P2） |
| 内容规模 | 用表格，宁可低估并加"预估偏差 ±30%" |
| 数值目标 | 只写期望（如"30 分钟手感成型"），不写具体数值 |
| 里程碑 | 与主程序核对工期后再写，不许拍脑袋 |

## 四、评审流程（简）

1. 主策划出 v0.1 → 发各角色书面反馈（3 个工作日内）；
2. 汇总反馈修订为 v0.2 → 立项例会拍板 P0 范围；
3. 版本号规则：`v0.x` 草案 → `v1.0` 立项定稿；此后改动进「变更记录」。
