# 05 · 开源如何赚钱

> **一句话**：开源产品不缺“用户”，缺的是“可被采购的价值”；收入来自服务、托管、企业需求与信任。

## 一、七种常见收入

| 模式 | 卖什么 | 适合 | 风险 |
| --- | --- | --- | --- |
| **支持/ SLA** | 响应时间、修复、咨询 | 企业/关键系统 | 人力线性 |
| **托管** | 省运维、备份、可用性 | 小团队/个人 | 云成本/竞争 |
| **开放核心** | 团队/权限/审计/合规 | 成长型产品 | 边界争议 |
| **双许可** | 闭源集成/商业条款 | 库/基础设施 | 需版权/CLA |
| **市场** | 模板/插件/资产 | 创作/工具生态 | 冷启动 |
| **培训/认证** | 知识/课程 | 复杂工具 | 内容维护 |
| **定制/集成** | 项目交付 | 代理/企业 | 不可规模化 |

## 二、独立开发者的现实顺序

1. **服务先行**：审计/迁移/培训/定制，先验证“有人愿意付”；
2. **托管/团队版**：把重复服务产品化；
3. **企业版**：SSO/审计/SLA/私有部署；
4. **市场/生态**：最后做，不要一开始做平台。

## 三、定价原则

- 价格锚定“替代方案的成本”（自建/事故/审计/人力）；
- 个人价可低，团队/企业价按价值；
- 不搞“开源版残疾”；
- 提供年付/一次性迁移/培训组合；
- 公开透明，减少采购摩擦。

## 四、许可与收入的关系

- MIT/Apache：采用最快，护城河靠执行/服务/品牌；
- AGPL：保护托管，但降低企业采用；
- 源可用：保护商业，但社区信任成本高；
- 开放核心：平衡采用与收入，边界要诚实。

## 五、常见反模式

- 把“开源”当营销词，实际是 source-available；
- 企业版只是把基础功能锁起来；
- 只靠捐赠/赞助，没有服务；
- 免费无限托管，成本失控；
- 没有 CLA/DCO，后来无法改许可/双许可。

## 六、LiveDSO 的建议（未定）

首批用户是独立开发者：

- 个人版：免费/低价，核心开源；
- 团队版：托管/协作/审计；
- 企业版：SSO/合规/私有部署；
- 服务：迁移、审计、培训。
