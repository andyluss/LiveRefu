# 09 · 决策清单与模板

> **不是法律意见**；发布前请律师审阅。这里给的是工程/产品可执行的检查表。

## 一、发布前 20 项

- [ ] 选定 SPDX 许可，写入 `LICENSE`；
- [ ] 每个源码文件头/包元数据写 SPDX；
- [ ] 保留版权声明与 NOTICE（Apache）；
- [ ] 第三方依赖清单（名称/版本/许可/修改/链接方式）；
- [ ] 生成 SBOM（SPDX/CycloneDX）；
- [ ] 明确贡献者政策（DCO 或 CLA）；
- [ ] 商标/Logo/项目名使用政策；
- [ ] 安全政策（漏洞报告渠道）；
- [ ] 隐私/数据处理说明（如处理个人数据）；
- [ ] 出口/制裁声明（如需要）；
- [ ] 免责声明/担保范围；
- [ ] 商业版/开源版边界（如开放核心）；
- [ ] 文档写清“开源/源可用/免费试用”；
- [ ] 版本/弃用/迁移政策；
- [ ] 依赖许可兼容性检查；
- [ ] AI 生成代码/资产来源记录（如适用）；
- [ ] 贡献者名单/版权归属；
- [ ] 发布包不包含密钥/个人数据；
- [ ] 法务审阅；
- [ ] 发布后保留变更记录。

## 二、SPDX 文件头模板

```ts
// SPDX-License-Identifier: Apache-2.0
// Copyright 2026 <your name / entity>
```

```md
<!-- SPDX-License-Identifier: MIT -->
```

> 具体格式按项目语言/工具调整；不要只写“MIT”而不放 LICENSE 全文。

## 三、NOTICE 模板（Apache-2.0）

```text
LiveDSO
Copyright 2026 <name>

This product includes software developed by third parties.
See THIRD_PARTY_NOTICES.md for details.
```

## 四、CONTRIBUTING 最小段

```md
## License

By contributing, you agree that your contributions are licensed under the
project's LICENSE (Apache-2.0). You confirm you have the right to submit them.

## Developer Certificate of Origin

Sign off commits with `git commit -s` (DCO 1.1).
```

> 如果要做双许可/企业版，需 CLA；CLA 要写清授权范围、回授、专利、终止。

## 五、LiveDSO 特定

- 不把用户 vault 上传；文档写清本地优先；
- 如果未来加托管，先更新隐私/数据处理；
- 如果未来加 AI，先区分代码/模型/数据/输出；
- 已选 Apache-2.0 + DCO；`package.json` 的 `license` 字段已写入；
- 发布 npm 包前仍应让律师审阅 NOTICE/商标/贡献者政策。
