# 软件生态与产品机会（索引）

> **这是 `docs/` 的第五卷**：从“软件生态如何运转”到“青橙设计适合做什么产品”。
> 建立：2026-10-27 ｜ 状态：v0.1 ｜ 面向：产品设计开发者、独立开发者、小团队、想理解软件全局的人。

## 一、这一卷回答什么

1. **青橙设计/work区主题适合做哪些非游戏产品？**
   —— 不只列工具，也分析“为什么适合、第一版做什么、怎么开源、怎么收费、风险在哪”。
2. **整个软件生态长什么样？**
   —— 从芯片、操作系统、数据库、协议，到工具、知识、协作、交易、生活、公共、AI 与美学，给出可读的分层地图。

| 部分 | 内容 | 入口 |

## 三、阅读路径

- **只想选产品**：先读产品长文的「结论」「评分矩阵」「三档推荐」，再回看对应方向。
- **想理解全局**：按 [`ecology/README.md`](ecology/README.md) 的“12 层地图”顺序读；时间少读 00、03、04、09、10、11。
- **想做设计/品牌**：读 10 美学层，再回产品长文的“创作工具 / 世界创作 / 设计系统操作台”。
- **想找商业模式**：产品长文 §6 + 生态 06 交易层、08 公共层、11 结语。

## 四、写作约定

- **不把“复古未来”当皮肤**：美学必须落到材料、时间、维护、代价与可退出性。
- **不把“生态”写成公司清单**：每一层都回答“谁付钱、谁维护、什么被锁定、设计在哪里创造价值”。
- **不假装预测**：对不确定的市场用“可能/更适合/风险”降档；不编造数据。
- **产品建议必须可被小团队验证**：给出第一版、首批用户、收费方式与停止条件。
