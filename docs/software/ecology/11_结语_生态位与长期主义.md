# 11 · 结语：生态位与长期主义

> **一句话**：不要问“哪个赛道最大”，问“哪个生态位能让我持续维护、持续收费、持续变好”。

## 一、生态位的七个问题

1. **谁付钱？** 个人、团队、企业、公共机构；预算从哪来？
2. **为什么现在付？** 什么痛点/事件/合规/迁移触发购买？
3. **平台会不会顺手做？** 如果会，你的独立理由是什么？
4. **数据/工作流/关系能否累积？** 还是每年重新获客？
5. **维护成本随用户增长吗？** 如果线性增长，必须有服务收入。
6. **能否开源而不自毁？** 核心/服务边界在哪？
7. **能否退出？** 用户带走数据后还会回来吗？

## 二、三种长期策略

### 1. 垂直深度

在一个行业/工作流里做到“没有它不行”：设计系统、维修、能源、资产、教育。护城河是领域知识 + 集成 + 信任，不是功能数量。

### 2. 本地优先的信任

在云/订阅/锁定之外提供“可拥有”：本地文件、离线、端到端加密、可自托管、完整导出。护城河是信任 + 迁移成本（但用户不怕被锁）。

### 3. 美学与仪式

把“使用”变成“照料”：档案、维护、版本、交接、材料、声音。护城河是品牌/社区/习惯，但必须建立在可用性之上。

## 三、三种反模式

- **平台幻觉**：一开始就做全家桶，结果每块都不够好。
- **开源幻觉**：以为开源就有社区，忽略文档/治理/支持。
- **AI 幻觉**：以为模型能力就是产品，忽略工作流/评估/责任。

## 四、给产品设计开发者的路线

1. **先做自己的工具**：你每天用，才有资格判断。
2. **先卖服务**：迁移/审计/培训/定制，比订阅更早验证价值。
3. **再做产品**：把重复服务产品化，而不是先做平台。
4. **最后做生态**：插件/模板/市场，是结果，不是起点。

## 五、回到青橙

青橙设计的机会，不是“把软件做成复古”，而是：

> **把被云、订阅、黑箱与一次性消费占据的基础系统，重新做成人能理解、能维护、能带走的东西。**

这与 [产品机会长文](../product/01_青橙设计适合做的非游戏产品.md) 的结论一致：

- 设计系统操作台：专业最深、最近现金流；
- 世界/时代创作工具：差异化最强、最需要耐心；
- 个人档案 OS / 家庭服务器：最适合自用与长期信任；
- 代码编辑器：平台级，慎作第一产品；
- 社区能源/维护台账：最深、最慢、最有公共价值。

## 六、最后一句话

**软件生态不是一张公司地图，而是一组承诺：谁提供稳定、谁承担失败、谁有权修改、谁可以离开。**

选择你能长期兑现的那一组承诺。
