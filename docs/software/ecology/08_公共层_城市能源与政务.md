# 08 · 公共层：城市、能源与政务

> **一句话**：公共软件是**带政治的基础设施**；它卖的不是“效率”，而是**可问责的秩序**。

## 一、这一层有什么

- **政务**：身份、许可、税务、社保、档案、公开数据；
- **城市**：交通、规划、住房、应急、公共空间；
- **能源**：发电、电网、计量、需求响应、社区能源；
- **公共服务**：医疗、教育、图书馆、博物馆、邮政；
- **国防/安全**：指挥、后勤、情报、关键基础设施；
- **公民科技**：参与、监督、社区治理、开放数据。

公共层的客户是政府/公共机构/社区组织；采购周期长、预算慢、合规重，但一旦进入，收入稳定、社会影响大。

## 二、经济结构：采购、标准与责任

- **政府采购**：招标、框架合同、合规、数据驻留；
- **标准**：开放标准/互操作往往比专有功能更重要；
- **责任**：出错可能影响很多人；审计、可解释、可回滚是硬要求；
- **开源**：公共资金资助的软件越来越倾向开源；但维护/支持需要预算；
- **政治**：谁定义“效率”、谁被排除、谁承担代价。

## 三、设计在哪里创造价值

1. **可理解**：政策/流程/资格/申诉路径；不是把表格搬上网。
2. **可问责**：谁审批、依据什么、如何复核。
3. **可访问**：多语言、低带宽、旧设备、无障碍。
4. **可参与**：公众评论、社区维护、开放数据。
5. **可退出/可纠错**：更正、申诉、删除、数据携带。

> 公共软件的 UX 不是“转化率”，而是**一个人在最脆弱时能否被系统正确对待**。

## 四、复古未来的角度

公共层的旧媒介——公告栏、档案、地图、仪表、排队票号、市政大厅——有数字政务常丢失的**公共可见性**：

- 同一信息对所有人可见；
- 有编号/盖章/责任人；
- 有物理窗口与开放时间；
- 有申诉/复核的路径。

青橙的机会不是“复古政务皮肤”，而是把**公共性、可问责、可参与**带回系统。

## 五、机会与反模式

**机会**：

- 社区能源/维修/共享资产的台账；
- 小型博物馆/档案馆的离线 kiosk；
- 公民参与/预算透明/公开数据；
- 公共设施的维护/巡检/工单；
- 开源 + 培训/支持/迁移服务。

**反模式**：

- 用“智慧城市”做监控扩张；
- 用“数字化”取消线下/人工通道；
- 用“AI 审批”掩盖责任；
- 把公共数据做成一次性展示。

## 六、给青橙的判断

公共层不适合追求快速增长，适合**深度、长期、服务型**业务。优先社区能源/维修/档案；先找一个真实社区/小机构陪跑，再产品化。它最能体现青橙的“维护被看见、代价可见、可退出”。

## 附：参照与可验证假设

**代表参照**：

- **GOV.UK**：以内容/可访问性/服务设计为核心；教训是“公共服务的语言与路径”比视觉更重要。
- **18F/USDS**：政府内部数字化能力；教训是“采购/能力建设”与软件同等重要。
- **OpenEnergyMonitor**：社区能源监测；教训是“开源硬件 + 社区维护”可以服务本地能源。
- **CiviCRM**：非营利组织 CRM；教训是“垂直/开源/服务”可以形成长期生态。
- **Code for America**：公民科技；教训是“志愿者/政府/社区”的协作需要长期治理。

**可验证假设**：

- 社区能源/维修组织是否愿意为“台账 + 维护 + 公开看板”付费/共建？
- 小型博物馆/档案馆是否愿意为“离线 kiosk + 内容更新 + 维护”付项目费？

**一个反例**：用“智慧城市”做监控/数据集中，却没有公共参与/申诉/退出机制。
