# 10 · 美学层：复古未来如何进入软件

> **一句话**：复古未来不是“旧滤镜”，而是**用过去的材料与承诺，审问现在的技术代价**。

## 一、三种时间

- **复古主义**：回到某个被理想化的过去；风险是怀旧与排除。
- **未来主义**：相信技术会带来新世界；风险是速度崇拜与代价外移。
- **复古未来主义**：站在现在，回看“过去曾想象的未来”；它同时包含记忆、诊断与提案。

软件里的复古未来，不是把 UI 做成 1980 年代，而是让这三个时间同时可见：

- 这个系统继承了哪些旧承诺？
- 哪些承诺没兑现？
- 今天的选择会把谁留在未来之外？

## 二、美学如何进入软件结构

### 1. 材料

不是贴纹理，而是决定“这是什么做的”：

- 纸/墨/盖章 → 档案、登记、可追溯；
- 金属/搪瓷/塑料 → 耐用、可维修、有磨损；
- CRT/扫描线/荧光 → 状态、余晖、可读性；
- 玻璃/亚克力/透明 → 层次、轻、但易碎。

材料要对应**行为**：可修复的东西应该有“打开/更换/校准”的路径。

### 2. 时间

- 启动/加载：是“瞬间”还是“过程”？
- 动效：是装饰，还是状态变化？
- 版本/历史：能否看见“之前”？
- 维护周期：什么时候该保养/归档？

### 3. 声音

声音是最容易被忽略的“可感”层：按键、提示、环境音。它必须可关闭，且不能成为唯一反馈。

### 4. 排版与信息密度

复古未来常借用仪表/终端/档案的高密度排版；但必须保留字号层级、对比度、键盘与屏幕阅读器。

### 5. 仪式

登记、盖章、开箱、校准、归档、交接——这些仪式让“维护”被看见，也让用户感到系统被认真对待。

## 三、反模式

- **皮肤化**：只换色/字体/纹理，结构仍是黑箱；
- **怀旧消费**：用旧物当装饰，不讨论它服务过谁；
- **技术崇拜**：用“未来感”掩盖不可用/不可退出；
- **单一未来**：把赛博朋克/太阳朋克/原子朋克之一当成唯一正确答案。

## 四、青橙的机会

1. **风格卡产品化**：让团队可以定义/交换/组合“世界皮肤”，但共享语法与无障碍。
2. **档案/资产/文档**：把来源、版本、维护、授权做成可见的美学。
3. **设计系统工具**：把 token/组件/对比度/风格卡变成可操作的“材料库”。
4. **创作工具**：不是生成更多图，而是让世界更自洽、更可 remix。
5. **公共/社区软件**：把“维护被看见”做成界面，而不是口号。

## 五、判断标准

一个“复古未来”软件是否成立，问：

- 去掉视觉皮肤，产品还剩下什么？
- 它的材料/时间/声音是否对应真实状态？
- 它展示了谁维护、谁承担代价吗？
- 它保留了另一种未来/退出的可能吗？
- 它在 200% 字号、键盘、减少动态下还能用吗？

> 美学不是产品的最后一步，而是**产品对世界的态度**。

## 附：参照与可验证假设

**代表参照**：

- **Teenage Engineering**：用材料/比例/仪式做硬件；教训是“产品即界面”，但价格/稀缺也会排斥人。
- **Braun/Dieter Rams**：少而准的工业语言；教训是“克制”需要结构支撑，不只是留白。
- **经典 Mac OS / Windows 95**：可识别的桌面隐喻；教训是“熟悉感”能降低学习成本，也会限制新交互。
- **CRT/终端美学**（Bloomberg Terminal、旧式航空仪表）：高密度/单色/告警；教训是“信息密度”必须服务专业任务。
- **青橙 OS 实验**：把 Archive/Solar/Cyber 三张世界皮肤放在同一壳上；教训是“多世界”必须共享语法，否则只是三个皮肤。

**可验证假设**：

- 用户是否愿意为“可感/可维护/可导出的美学”付费，而不是为滤镜付费？
- 风格卡能否成为团队可交换的资产，而不是设计师的个人偏好？

**一个反例**：把界面做成 1980 年代，却让对比度、键盘、移动端全部退化；这是怀旧消费，不是复古未来。

> **清澄**：透明不是“玻璃拟态”，也不是把来源/代价藏进漂亮界面。复古未来可以很厚，但材料、光源、维护与代价要可见；见 [`09 清澄`](../../../design/philosophy/09_清澄_透明作为方法.md)。
