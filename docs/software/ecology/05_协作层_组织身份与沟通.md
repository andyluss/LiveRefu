# 05 · 协作层：组织、身份与沟通

> **一句话**：协作软件卖的是**降低协调成本**；但它也可能制造更多协调。

## 一、这一层有什么

- **沟通**：邮件、IM、视频、电话、社区；
- **项目**：任务、看板、文档、目标、OKR；
- **组织**：HR、身份、权限、目录、入职/离职；
- **客户**：CRM、支持工单、成功管理；
- **知识协作**：Wiki、评审、决策记录；
- **身份**：SSO、SCIM、OAuth、设备管理。

协作层的经济特征是**网络效应**与**切换成本**：团队越大，迁移越难；一旦成为“组织默认”，收入稳定，但产品容易臃肿。

## 二、经济结构：席位、集成与治理

- **按席位收费**：简单，但会鼓励“更多人进来”，与“减少打扰”冲突；
- **集成护城河**：与日历、邮件、代码、CRM 的深度连接；
- **治理/合规**：审计、留存、数据驻留、权限；企业愿意付费；
- **开源替代**：Mattermost、Nextcloud、Plane 等证明可自托管，但企业支持是关键；
- **AI 冲击**：会议摘要/自动回复/搜索很容易商品化；价值转向“决策记录/责任/信任”。

## 三、设计在哪里创造价值

1. **减少噪音**：通知分级、摘要、静默、异步优先。
2. **保留上下文**：为什么做这个决定、谁批准、何时复盘。
3. **降低协调**：清晰的所有者、截止、依赖、升级路径。
4. **可退出**：导出、迁移、保留、离职交接。
5. **身份可信**：权限、审计、设备、访问复核。

> 协作产品最容易被忽略的指标是**“会议/消息减少了多少”**，而不是“发送了多少”。

## 四、复古未来的角度

旧组织的协作媒介——备忘录、公文、登记簿、电话交换台、布告栏——有当代协作工具缺少的东西：

- **编号与归档**；
- **签发/盖章/责任人**；
- **延迟与优先级**；
- **可被查阅的历史**。

青橙不是要做“复古 Slack”，而是把**责任与记录**带回协作：谁决定、谁维护、谁承担。

## 五、机会与反模式

**机会**：

- 小型团队的“平静协作”（异步、摘要、决策记录）；
- 社区/合作社的治理工具；
- 可自托管的身份/权限/审计；
- 垂直协作（维修、能源、教育、医疗）；
- 迁移/培训/合规服务。

**反模式**：

- 用更多功能解决沟通过载；
- 用“AI 自动回复”替代责任；
- 用“免费”换数据；
- 不提供导出/交接。

## 六、给青橙的判断

协作层适合做**小型组织/社区**的垂直系统，而不是通用 Slack/Jira。优先“维护台账 + 决策记录 + 权限审计”，可以与社区能源、维修站、家庭服务器组合。

## 附：参照与可验证假设

**代表参照**：

- **Slack**：用频道/集成/机器人重塑团队沟通；教训是“集成生态”能形成网络效应，也会制造噪音。
- **Microsoft Teams**：用 Office/企业协议捆绑；教训是“分发渠道”有时比产品体验更强。
- **Jira**：把工作流/权限/报表产品化；教训是“流程软件”卖的是管理可见性，不是易用性。
- **Salesforce**：用平台/生态/定制占据 CRM；教训是“可配置性”能锁定大客户，也提高实施成本。
- **Okta/Entra**：身份成为基础设施；教训是“安全/合规”是长期付费理由。

**可验证假设**：

- 小团队是否愿意为“更少消息/更清晰责任”付费，而不是更多频道？
- 社区/合作社是否需要一个“治理 + 维护 + 决策记录”的轻量系统？

**一个反例**：用 AI 自动回复/摘要减少消息，却不改变“谁负责/谁决定”，只是把噪音换成幻觉。
