# 06 · 交易层：支付、商业与财务

> **一句话**：交易软件卖的是**信任与可审计**；钱流到哪里，责任就到哪里。

## 一、这一层有什么

- **支付**：收单、网关、订阅、发票、退款、风控；
- **商业**：电商、市场、POS、库存、订单、物流；
- **财务**：记账、报表、税务、报销、审计；
- **企业**：ERP、采购、供应链、合同；
- **平台**：抽成、结算、争议、合规。

交易层对错误极度敏感：一次重复扣款/漏账/税务错误，可能失去客户。因此它的设计重点不是“酷”，而是**可核对、可撤销、可审计**。

## 二、经济结构：费率、信任与垂直

- **支付费率**：规模效应强，赢家通吃；
- **垂直 SaaS**：行业工作流 + 合规 + 集成，护城河深；
- **市场抽成**：需要双边规模与信任；
- **开源**：核心可开源，但支付/合规/支持是服务；
- **监管**：税务、反洗钱、数据保护；进入门槛高，但也是护城河。

## 三、设计在哪里创造价值

1. **可核对**：每笔钱都能追溯到订单/合同/发票/银行流水。
2. **可撤销**：退款、冲正、对账差异；不要把用户困在“联系客服”。
3. **可审计**：谁改、何时、为什么；导出给会计/审计。
4. **可理解**：费用、税、汇率、账期；不要用行话掩盖。
5. **可迁移**：账本/客户/库存能带走；这反而增加信任。

> 交易产品的 UI 不是“结账页”，而是**“对账页”**。

## 四、复古未来的角度

账本、收据、印章、票据、复写纸、柜台——这些旧交易媒介的核心是：

- 一式多份；
- 编号与签字；
- 可核对；
- 有保管期限。

数字交易常常只剩“成功/失败”两个状态，丢失了“凭证”。青橙的机会：把“凭证感/可核对/可保管”带回小商家软件。

## 五、机会与反模式

**机会**：

- 小商家/维修店/工作室的账本 + 库存 + 发票；
- 垂直行业计费/对账；
- 开源支付/订阅基础设施 + 托管；
- 税务/合规/迁移服务；
- 公共/合作社的透明账本。

**反模式**：

- 用“免费”换支付数据；
- 把费率战当唯一竞争；
- 不给出可导出的账本；
- 用 AI 自动记账但不给核对路径。

## 六、给青橙的判断

交易层适合做**小商家/工作室的垂直账本**，而不是通用支付网关。优先“可核对、可导出、可交接”，并与维护/资产/客户系统组合；服务收入（迁移/培训/税务适配）往往比软件订阅更早到来。

## 附：参照与可验证假设

**代表参照**：

- **Stripe**：API/文档/开发者体验成为支付产品；教训是“信任 + 可集成”比费率更重要。
- **Shopify**：把电商基础设施 + 应用生态结合；教训是“商家成功”与“平台抽成”需要平衡。
- **QuickBooks/Xero**：小企业账本 + 会计生态；教训是“合规/税务/会计网络”形成护城河。
- **SAP/Oracle**：复杂企业流程；教训是“实施/咨询/迁移”本身就是收入，但也会拖慢产品。
- **Square**：硬件 + 支付 + 小商家软件；教训是“线下入口”可以带来软件分发。

**可验证假设**：

- 小商家是否愿意为“可核对 + 可导出 + 可交接”付费，而不只是为费率？
- 垂直账本（维修/工作室）能否通过“迁移/培训/税务适配”先于订阅收费？

**一个反例**：用“免费 + 支付数据变现”获取商家，最后失去信任；交易层最不能透支信任。
