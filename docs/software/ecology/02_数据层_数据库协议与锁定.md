# 02 · 数据层：数据库、协议与锁定

> **一句话**：数据层卖的不是存储，是**记忆的可靠性**；而记忆一旦被锁定，就会变成权力。

## 一、这一层有什么

- **数据库**：关系型（Postgres/MySQL/SQLite）、文档（MongoDB）、键值（Redis）、图、时序、向量、分析型（Snowflake/BigQuery）；
- **对象存储**：S3 兼容、CDN、备份；
- **协议/API**：REST、GraphQL、gRPC、WebSocket、WebDAV、OAuth/OIDC；
- **同步/一致性**：主从、分片、事务、CRDT、离线队列；
- **身份/权限**：账号、租户、角色、审计；
- **数据工具**：ETL、CDC、数据目录、血缘、质量。

## 二、经济结构：数据重力与迁移成本

数据层的核心经济规律是**数据重力**：

- 数据越多，应用、报表、权限、备份、合规越围绕它生长；
- 迁移成本不只是“拷贝”，还有 schema、历史、权限、审计、下游依赖；
- 一旦成为“系统 of record”，替换周期以年计。

因此，数据层的竞争不是“功能更多”，而是：

- 能否成为标准（SQL、S3 API、OpenTelemetry）；
- 能否降低迁移成本（导出、兼容、开放格式）；
- 能否提供信任（一致性、备份、审计、合规）；
- 能否让数据“可被理解”（目录、血缘、质量）。

## 三、设计在哪里创造价值

1. **数据可读**：schema、字段含义、来源、更新时间、质量标记。
2. **数据可带走**：完整导出、开放格式、迁移工具；不是“联系销售”。
3. **数据可追溯**：谁改、何时、为什么、影响了什么。
4. **同步可解释**：冲突、延迟、离线、重试；用户需要知道“现在是不是最新”。
5. **隐私/权限可见**：谁能看、谁能改、谁审计。

> 数据产品的 UX，往往不是查询界面，而是**信任界面**。

## 四、复古未来的角度

档案、登记、卡片目录、磁带、微缩胶片——这些旧媒介的共同点是：

- 有**物理位置**与**索引**；
- 有**副本**与**版本**；
- 有**保管者**与**借阅记录**；
- 有**损耗**与**修复**。

这恰好是当代数据产品缺失的：我们有了无限存储，却常常没有“这是哪一版、谁改的、还能不能读”。

青橙的机会：把“档案的诚实”带入数据产品——来源、版本、保管、销毁、迁移。

## 五、机会与反模式

**机会**：

- 本地优先数据库/同步层（离线、端到端加密、冲突可解释）；
- 数据目录/血缘/质量的小型化产品；
- 可携带的垂直数据系统（医疗、教育、维修、资产）；
- 备份/恢复/归档服务；
- 数据迁移与合规服务。

**反模式**：

- 用“云原生”作为锁定借口；
- 把“实时”做成不可解释的推送；
- 把“数据湖”做成没人能找的沼泽；
- 用“AI 自动整理”掩盖 schema 缺失。

## 六、给青橙的判断

数据层最好的切口不是“又一个数据库”，而是**“让数据重新可被拥有”**：本地优先、开放格式、完整导出、来源与版本。它适合与个人档案、资产库、小商家账本、家用服务器组合，而不是单独卖。

## 附：参照与可验证假设

**代表参照**：

- **PostgreSQL**：开放、扩展性强，成为“默认关系库”；教训是“可扩展 + 社区信任”能长期复利。
- **SQLite**：单文件、零运维，嵌入无数应用；教训是“极致的部署简单”本身就是护城河。
- **MongoDB**：用文档模型降低早期开发摩擦；教训是“易用”与“一致性/迁移”需要平衡。
- **Snowflake/BigQuery**：把分析型数据仓库云化；教训是“弹性 + 分离存储计算”改变组织预算。
- **Stripe**：用 API/文档/开发者体验把支付基础设施产品化；教训是“信任界面”也是数据层的一部分。

**可验证假设**：

- 用户是否愿意为“完整导出 + 迁移工具 + 来源/版本”付费，而不只是为存储付费？
- 在垂直行业（维修/医疗/教育），“本地优先 + 可审计”能否胜过通用云数据库？

**一个反例**：把“数据湖”做成没有目录/血缘/质量的沼泽，最后没人知道哪份数据可信。
