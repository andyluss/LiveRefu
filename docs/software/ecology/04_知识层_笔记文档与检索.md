# 04 · 知识层：笔记、文档与检索

> **一句话**：知识产品卖的不是“存储”，而是**在需要时找得到、信得过、传得下去**。

## 一、这一层有什么

- **个人知识**：笔记、双链、卡片盒、阅读标注、剪藏；
- **团队文档**：Wiki、协作文档、知识库、规范、Runbook；
- **检索**：全文、语义、图谱、问答、企业搜索；
- **学习**：课程、LMS、间隔重复、证书；
- **出版**：博客、文档站、电子书、邮件通讯；
- **档案**：版本、来源、引用、长期保存。

知识层的用户跨越个人/团队/机构；付费理由从“方便”到“合规/留存/培训”不等。

## 二、经济结构：习惯、检索与信任

- **习惯壁垒**：知识工具一旦成为日常，迁移成本很高；
- **检索质量**：找得到比写得好更重要；
- **信任**：来源、版本、权限、审计；企业尤其在意；
- **网络效应**：团队共享/模板/社区会增强留存；
- **AI 冲击**：生成摘要/问答很容易，但“可信来源”与“组织记忆”更难。

知识产品的常见误区是“功能堆叠”：双链、白板、数据库、AI、协作……最后变成一个用户不知道从哪开始的工具箱。

## 三、设计在哪里创造价值

1. **入口**：今天该看什么？什么变了？什么需要处理？
2. **检索**：自然语言/过滤器/时间/来源；结果要能解释“为什么是它”。
3. **结构**：文件夹/标签/双链/数据库不是目的；让用户在需要时能重建结构。
4. **信任**：来源、版本、引用、权限、审计。
5. **输出**：从笔记到文档/发布/分享的路径要短。

> 知识产品的核心指标不是“笔记数”，而是**“一次需要被满足的回忆”**。

## 四、复古未来的角度

知识层与复古未来天然亲近：卡片目录、索引卡、剪报、档案盒、微缩胶片、图书馆。

这些旧媒介的可取之处：

- 有**物理索引**与**编号**；
- 有**来源**与**版本**；
- 有**保管者**与**借阅记录**；
- 有**淘汰/归档**的仪式。

当代知识工具往往只保留“输入”，丢失了“保管”。青橙的机会是把“档案的诚实”带回个人/团队知识。

## 五、机会与反模式

**机会**：

- 个人档案 OS（来源/时间/版本/公开页）；
- 团队 Runbook/决策记录/维护知识；
- 可自托管的企业搜索；
- 出版/课程/邮件通讯工具；
- 迁移/整理/数字化服务。

**反模式**：

- 又一个“什么都能放”的 All-in-one；
- 用 AI 问答替代可读原文；
- 用双链图制造“学到了”的错觉；
- 不解决导入/导出。

## 六、给青橙的判断

知识层适合做“**档案 + 检索 + 输出**”的垂直组合，而不是通用笔记。最优先：个人档案 OS、设计/研究知识库、团队维护知识。它们可以与创作工具、资产库、家庭服务器共享数据层。

## 附：参照与可验证假设

**代表参照**：

- **Obsidian**：本地 Markdown + 插件生态；教训是“数据可拥有”能形成强忠诚，但协作/发布是弱项。
- **Notion**：把文档/数据库/协作做成一块画布；教训是“低门槛组合”能扩张，但复杂性和锁定也随之增加。
- **Confluence**：企业知识库的默认值；教训是“组织采购/权限/集成”比编辑体验更重要。
- **Algolia/Elasticsearch**：搜索基础设施；教训是“检索质量”可以独立成为产品。
- **Anki**：开放、可扩展的间隔重复；教训是“算法/数据可带走”能形成长期社区。

**可验证假设**：

- 用户是否愿意为“来源/版本/可发布”付费，而不是为更多笔记功能付费？
- 团队是否愿意为“可自托管的检索/档案”付费，以满足数据主权？

**一个反例**：用 AI 问答替代原文阅读，最后用户既不知道答案从哪来，也无法核对。
