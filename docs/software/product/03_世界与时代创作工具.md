# 世界与时代创作工具：让多世界保持自洽

> **一句话**：AI 让“生成一张图”变得便宜，让“让一个世界持续自洽”变得昂贵。不要做生图器，做**世界的编译器**。
> 方向：产品机会 Top 2 ｜ 状态：v0.1 ｜ 面向：游戏/叙事团队、独立世界构建者、博物馆/品牌、设计团队。
> **用户层次**：爱好者/业余创作者是入口；prosumer、独立工作室、博物馆/品牌是付费扩展（见 [12 用户分析](../ecology/12_目标用户分析_专业人士爱好者与普通人.md)）。

> **清澄视角**：每条 canon 有来源、置信度、依赖与冲突；每个时代显示技术、维护者与代价。AI 生成的内容不能伪装成 canon。见 [09 清澄](../../../design/philosophy/09_清澄_透明作为方法.md)。

## 一、先看 ArtCraft 真正证明了什么

ArtCraft 类工具的爆发，容易被误读为“又一个 AI 生图产品成功了”。更准确的理解是：

- 它把“从想法到视觉”的路径压缩了；
- 它把创作从“专业软件”推向“表达工具”；
- 它用模板/社区/作品流形成传播；
- 它仍然没有解决“世界是否自洽”。

真正稀缺的不是“生成”，而是：

1. **规则**：这个世界的技术、材料、能源、社会结构是什么？
2. **一致性**：同一个世界里的建筑、服装、广告、工具是否互相解释？
3. **来源**：这张图是谁生成的、用了什么模型、什么许可、能否商用？
4. **版本**：改了一个设定，哪些资产/文本/关卡需要跟着改？
5. **协作**：作者、画师、编剧、关卡设计师如何共享同一套 canon？
6. **输出**：同一套世界如何变成游戏、网页、印刷、展览、实体？

所以正确的产品不是“ArtCraft 克隆”，而是：

> **World / Era Authoring：用规则、风格卡、资产与版本，编译一个可持续扩展的世界。**

## 二、谁需要它

| 用户 | 当前做法 | 痛点 | 付费点 |
| --- | --- | --- | --- |
| 独立游戏团队 | Notion + 文件夹 + Midjourney + 引擎 | 设定散落、资产找不到、风格漂移 | 团队协作、资产库、输出 |
| 叙事/小说作者 | Word/Scrivener + 灵感图 | 人物/地点/时间线不一致 | 世界圣经、时间线、导出 |
| TTRPG/桌游 | Wiki + Google Docs + 素材包 | 规则与视觉脱节、无法复用 | 模板、素材包、社区 |
| 博物馆/品牌 | 策展文档 + 外包设计 | 时代考据、授权、版本混乱 | 项目制、授权/来源、维护 |
| 设计团队/广告 | Figma + 品牌手册 | 多品牌/多世界复制 | 风格卡、资产溯源、协作 |
| 教育/研究 | 课件 + 阅读包 | 世界构建门槛高 | 课程、模板、机构授权 |

**最容易付费的**不是“想画图的人”，而是**要对一个世界/品牌/展览负责的团队**。

## 三、核心对象：世界不是文件夹

### 1. World（世界）

一个世界有：

- 名称、类型、受众、基调；
- 技术 level、能源、材料、通信、交通；
- 社会结构、权力、劳动、生态；
- 禁忌/边界/代价；
- 允许的风格卡范围。

### 2. Era（时代/纪元）

时代不是“换一套颜色”，而是**同一世界在不同时间/尺度下的状态**：

- 技术变迁；
- 物质稀缺/丰裕；
- 制度/权力；
- 视觉母题；
- 代价（谁承担）。

### 3. Canon Fact（设定事实）

一条可被引用/检查的设定：

```json
{
  "id": "canon.orange-harbor.energy",
  "world": "orange-harbor",
  "era": "solar",
  "statement": "社区电站依赖本地光伏与维修站，夜间降级非必要服务",
  "confidence": "canon",
  "owner": "worldbuilding",
  "sources": ["interview-03", "doc-12"],
  "dependsOn": ["canon.orange-harbor.grid"],
  "conflictsWith": []
}
```

关键字段：`confidence`（canon/draft/rumor）、`sources`、`dependsOn`、`conflictsWith`。这让“设定”可被检查，而不是一段散文。

### 4. Entity（实体）

人物、地点、组织、物品、事件、技术、生物；有类型、关系、时代、资产、引用。

### 5. Style Card（风格卡）

- 色板/材质/光源/装饰母题/字体/图像处理；
- 与世界/时代绑定；
- 有对比度/可读性/输出限制；
- 可预览、可比较、可版本化。

### 6. Asset（资产）

图片、模型、纹理、字体、音频、视频、文本；必须带：

- 来源（作者/工具/模型）；
- 许可/商用范围；
- 衍生关系；
- 风格卡/时代；
- 版本。

### 7. Output（输出）

游戏资源、网页、印刷、展览、社交媒体；每个输出有自己的约束（分辨率、色彩、性能、可读性）。

## 四、工作流：从“一个想法”到“可发布的世界”

```text
种子（一句话/一张图/一段历史）
  → 定义约束（技术/能源/材料/社会/代价）
  → 选风格卡（或新建）
  → 建立 canon（实体/事实/关系）
  → 生成/导入资产（带来源）
  → 世界 lint（矛盾/时代错置/授权/风格漂移）
  → 输出（游戏/网页/印刷/展览）
  → 版本/扩展/remix
```

### 世界 lint 的例子

- **时代错置**：一个 1970 年代设定的世界出现智能手机；
- **能源矛盾**：没有电网却到处是霓虹；
- **材料矛盾**：大规模塑料却设定为石油枯竭；
- **劳动消失**：全自动维护，但没有维护者/供应链；
- **风格漂移**：同一个城市出现三种互不兼容的光照；
- **授权风险**：资产来源不明/不可商用；
- **叙事矛盾**：角色知道不该知道的信息；
- **尺度矛盾**：地图距离与行程时间不一致。

这些检查不是“AI 判官”，而是**可解释的规则 + 人工确认**。产品价值在于把“世界设定”从散文变成**可查询、可验证、可协作的结构**。

## 五、MVP：先做一个世界，不要做平台

### v0（4–6 周）

- 一个 World + 3 个 Era；
- 风格卡编辑器（色板/材质/字体/关键词）；
- Entity/Canon 的 Markdown + 结构化字段；
- 资产库（本地文件 + 来源/许可字段）；
- 世界 lint（5 条规则）；
- 静态导出：世界圣经 + 风格指南 + 资产清单。

### v1（8–12 周）

- 多世界/多用户；
- 时间线/关系图；
- 资产版本/衍生；
- 输出预设（Web/Godot/印刷）；
- AI 辅助（可选，必须带来源/可撤销）。

### 暂不做

- 通用生图器；
- 通用 3D 引擎；
- 通用 Wiki；
- 全自动“生成整个世界”；
- 游戏运行时。

## 六、差异化：不要和三类产品硬碰

| 竞品 | 强项 | 你的楔子 |
| --- | --- | --- |
| ArtCraft/Midjourney | 生成快、风格多 | 规则/一致性/来源/版本/协作 |
| World Anvil/Notion | 自由文本/百科 | 结构化 canon + lint + 输出 |
| 游戏引擎/资产管理 | 生产管线 | 世界层/跨介质/早期一致性 |
| 品牌手册/Figma | 视觉规范 | 多世界/时代/资产溯源/服务 |

一句话：

> **他们生成“看起来像这个世界”的图；你保证“这个世界还能继续被写下去”。**

## 七、开源与许可

- **核心开源**：世界文件格式（JSON/Markdown）、本地编辑器、lint 引擎、导出器；
- **收费**：托管协作、资产库、审阅、版本历史、市场、企业/教育；
- **插件**：lint 规则、输出适配器、AI provider；
- **资产许可**：平台不声称拥有用户资产；提供来源/许可记录，不提供法律保证；
- **格式开放**：世界可以被带走，避免“内容锁定”。

## 八、商业模式

| 收入 | 内容 | 谁买 |
| --- | --- | --- |
| **创作者订阅** | 多世界、资产库、导出 | 个人/小团队 |
| **团队版** | 协作/审阅/权限/历史 | 游戏/叙事团队 |
| **市场抽成** | 风格卡/模板/资产包 | 创作者 |
| **授权/清算服务** | 资产来源/商用许可审查 | 品牌/博物馆/出版 |
| **定制世界构建** | 品牌世界/展览/游戏 | 企业/机构 |
| **教育/课程** | 世界构建课/模板 | 学校/工作坊 |

**定价思路**：个人 $10–20/月；团队 $20–50/seat/月；机构项目 $10k–100k；市场 10–20% 抽成。不要一开始做“免费无限”，否则资产/存储成本会失控。

## 九、获客：用“世界”本身传播

- 公开世界页（可被引用/ remix）；
- 模板：赛博/太阳/原子/磁带/档案；
- Game jam/写作马拉松/世界构建挑战；
- 与博物馆/品牌/游戏团队做案例；
- 开源 lint 规则，吸引技术用户；
- “世界健康报告”作为审计服务。

## 十、用你的工作区先 dogfood

你已有：

- `docs/retro-futurism` 的七纪/四元素/七机制；
- `design` 的风格卡、token、多介质；
- 青橙 OS 的 Archive/Solar/Cyber 三个未来层；
- “橙港”这个虚构城市（天气/电台/邮件/能源）。

第一版可以直接做 **“橙港世界编译器”**：

- 一个世界 + 三个时代；
- 每个时代有技术/能源/材料/社会/代价；
- 资产库记录来源/许可；
- 导出世界圣经 + 风格指南 + 青橙 OS 的天气/电台数据；
- 用 lint 找“能源/材料/劳动”矛盾。

这比“再做一个生图器”更能证明产品价值。

## 十一、90 天验证

| 周 | 目标 | 产出 |
| --- | --- | --- |
| 1–2 | 选一个真实世界/团队 | 现有资产、设定、痛点 |
| 3–4 | 世界/时代/风格卡数据模型 | 一个可编辑的世界 |
| 5–6 | 资产来源/许可 + 5 条 lint | 一份“世界健康报告” |
| 7–8 | 静态导出 + 一个真实使用者 | 可发布的世界页 |
| 9–10 | 收费实验 | 模板/服务/团队版报价 |
| 11–12 | 决定 | 继续/收窄/停止 |

## 十二、指标

- 每个世界创建的 canon/资产数量；
- 资产来源/许可完整率；
- lint 发现并修复的矛盾数；
- 从设定到输出的时间；
- 模板/世界页的复用/remix 次数；
- 付费转化/团队留存。

## 十三、风险与停止条件

**风险**：

- AI 平台把“生成+一致性”做成内置；
- 世界构建是小众爱好，付费意愿分散；
- 资产版权/许可复杂；
- 范围膨胀成游戏引擎/Wiki；
- 内容审核/安全。

**停止条件**：

- 3 个目标团队都不愿为“一致性/来源”付费；
- 用户只用生成，不用 canon/资产/输出；
- lint 误报率高到用户关闭；
- 每个客户都要定制，无法产品化。

## 十四、结论

世界/时代创作工具是三个方向里**差异化最强、最需要耐心**的：

- 它不是“更快的生成”，而是“更长的自洽”；
- 它能把青橙的多世界语法变成产品；
- 它能服务游戏、叙事、博物馆、品牌、教育；
- 它的护城河是**数据模型 + 资产来源 + 工作流**，不是模型。

如果你能让一个世界在三种时代里都自洽，并且每个资产都能回答“从哪来、谁能用、改了什么”，你就做出了一个 AI 时代真正稀缺的东西：

> **不是更多的未来图像，而是可以被继续写下去的未来。**

## 附：橙港世界编译示例

### 世界约束

```yaml
world: orange-harbor
premise: 一座靠海的老工业城，在能源转型后被重新居住
constraints:
  technology: 1970s 材料 + 2020s 网络 + 有限 AI
  energy: 社区光伏/潮汐/电池；夜间降级
  scarcity: 稀土与芯片受限；维修文化强
  society: 合作社 + 市政 + 外包维护并存
  forbidden: 无代价的无限能源、无维护者的全自动
```

### 三个时代

| 时代 | 技术 | 视觉 | 代价 |
| --- | --- | --- | --- |
| **Archive** | 纸张/登记/旧电网 | 米白、青绿、琥珀、印章 | 低密度、手工维护 |
| **Solar** | 社区光伏/维修站 | 暖绿、陶土、太阳能黄 | 需要参与、速度慢 |
| **Cyber** | 城市电网/远程外包 | 深蓝、青、洋红、扫描线 | 监控、依赖、退出成本高 |

### 世界 lint 输出示例

```text
[ERROR] energy: solar 时代出现“24h 霓虹广告”，但设定夜间降级
[HINT]  可改为“定时亮起的社区公告牌”，并登记维护者
[WARN]  asset: 3 张街景图来源不明，license 未填
[WARN]  canon: 角色 A 在 2031 年知道 2035 年事件（时间线冲突）
[INFO]  style: 2 个资产偏离 Solar 色板（ΔE > 阈值）
```

### 输出管线

- **Web**：静态世界页 + 时间线 + 资产画廊；
- **游戏**：导出 Godot/Unity 资源清单 + 风格卡 JSON；
- **印刷**：世界圣经/设定集 PDF；
- **展览**：离线 kiosk + 展签/来源。

同一份 canon，不同输出只改变“投影”，不改世界规则。这是“世界编译器”与“生图器”的根本区别。

### 授权/审核

- 每个资产有 `source/license/model`；平台不做法律担保，但提供**证据链**；
- 团队可设置“仅内部/可商用/需署名”策略；
- 对外发布前跑“来源完整率”检查；
- 对品牌/博物馆客户，提供人工授权审查服务。
