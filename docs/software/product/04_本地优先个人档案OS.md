# 本地优先个人档案 OS：把数字生活变成可继承的档案

> **一句话**：不是又一个笔记 App，而是**一个可检索、可备份、可发布、可继承的个人档案系统**；文件是你的，索引是你的，退出也是你的。
> 方向：产品机会 Top 3 ｜ 状态：v0.1 ｜ 面向：研究者/写作者/设计师、家庭、小工作室。

## 一、为什么“笔记”不是答案

笔记工具的默认假设是：**你会持续写**。

但大多数人的数字生活不是“写出来的”，而是**积累出来的**：

- 下载的 PDF、截图、照片、录音；
- 邮件、发票、合同、票据；
- 网页剪藏、阅读标注；
- 项目文件、设计稿、代码；
- 聊天记录、旅行票根、家庭影像。

这些东西的问题不是“没地方写”，而是：

1. **找不到**：知道存在，但搜不到；
2. **不可信**：不知道哪一版、从哪来、能不能用；
3. **不可带走**：散在 10 个 App/云盘/邮箱；
4. **不可继承**：人走了，账号和文件一起消失；
5. **不可读**：格式过时，软件停止维护。

所以正确的品类不是“笔记”，而是：

> **Personal Archive OS：以文件为底座，以来源/版本/保管为骨架，以检索/发布/继承为出口。**

## 二、谁需要它

| 用户 | 当前状态 | 痛点 | 付费点 |
| --- | --- | --- | --- |
| 研究者/写作者 | Zotero + 文件夹 + 云盘 | 引用、版本、阅读标注分散 | 检索、引用、发布 |
| 设计师/摄影师 | Eagle/Photos/Lightroom + 硬盘 | 资产找不到、授权不清 | 资产库、来源、客户交付 |
| 家庭 | 手机相册 + 云盘 + 聊天 | 照片/证件/票据/纪念物分散 | 家庭档案、备份、继承 |
| 小工作室 | Notion + Drive + 邮件 | 项目结束就失忆 | 项目档案、交接、审计 |
| 自由职业者 | 发票/合同/客户邮件 | 报税/纠纷时找不到 | 凭证、检索、导出 |
| 遗产/家庭 | 账号密码/文件 | 无法交接 | 继承模式、托管 |

**最容易付费的**是“有明确损失风险”的人：研究者（引用/发表）、设计师（客户资产）、家庭（照片/证件）、小工作室（交接/审计）。

## 三、核心对象：档案不是文件夹

### 1. Item（条目）

任何东西：文件、照片、邮件、网页、发票、笔记、录音、书、联系人。每个条目有：

```json
{
  "id": "item.2026.receipt.0412",
  "type": "receipt",
  "title": "社区电站维修费",
  "createdAt": "2026-04-12",
  "source": "mail:repair@citrus.local",
  "files": ["receipts/2026-04-12.pdf"],
  "hash": "sha256:…",
  "license": "private",
  "custodian": "me",
  "retention": "7y",
  "collections": ["home/maintenance"],
  "links": ["project.orange-harbor"]
}
```

关键字段：`source`、`hash`、`license`、`custodian`、`retention`、`links`。

### 2. Collection（集合）

不是文件夹，而是**可多重归属的视图**：项目、人物、地点、主题、时间、事件。一个条目可以同时属于“2026 家庭”“橙港项目”“维修记录”。

### 3. Provenance（来源）

- 从哪来（网页/邮件/扫描/相机/生成）；
- 谁创建/修改；
- 什么时间；
- 什么工具/模型；
- 原始文件是否保留；
- 许可/使用范围。

### 4. Revision（版本）

不是“自动保存”，而是**可比较的历史**：

- 每次导入/编辑产生版本；
- 可回滚；
- 可导出“当前/历史”；
- 删除是 tombstone（墓碑），不是消失。

### 5. Custody（保管）

谁负责这个档案：

- 个人/家庭/团队；
- 继承人/托管人；
- 访问权限；
- 备份责任；
- 到期/销毁。

### 6. View / Public Page（视图/公开页）

- 时间线、地图、人物、主题；
- 公开/私密/仅链接；
- 可导出的“档案页”；
- 引用格式。

## 四、工作流：从“一堆文件”到“可继承的档案”

```text
导入/监听文件夹
  → 识别类型/提取文本/生成预览
  → 计算 hash/去重/版本
  → 建立来源/许可/保管
  → 索引（全文/元数据/关系）
  → 视图（时间线/项目/人物/地图）
  → 检索/回顾
  → 发布/分享
  → 备份/恢复
  → 继承/交接
```

### 关键设计：先只读，后写入

第一版**不要**急着做“编辑一切”。先做：

- 索引现有文件；
- 只读预览；
- 搜索/时间线；
- 导出。

这能避免“迁移失败/格式破坏”的风险，也让你先验证“找得到”的价值。

## 五、MVP：4–6 周做一个“可用的档案索引”

### v0

- 选择一个文件夹（vault）；
- 文件监听 + 索引（SQLite FTS）；
- 支持 Markdown/PDF/图片/文本/网页存档；
- 时间线 + 标签 + 集合；
- 预览 + 全文搜索；
- 导出清单/JSON；
- 本地备份（复制/校验）。

### v1

- 版本/来源/许可字段；
- 公开页（静态导出）；
- 多 vault；
- 备份恢复演练；
- 端到端加密同步（可选）；
- 家庭共享/继承模式。

### 暂不做

- 通用笔记编辑器（先接 Obsidian/Markdown）；
- 云相册 AI 识别；
- 社交/协作；
- 全格式写入；
- 手机原生 App（先 Web/PWA）。

## 六、差异化：不要和 Obsidian/Notion 正面竞争

| 竞品 | 强项 | 你的楔子 |
| --- | --- | --- |
| Obsidian | 本地 Markdown/插件 | 跨格式档案/来源/版本/继承 |
| Notion | 协作/数据库/模板 | 本地优先/可导出/长期保存 |
| Eagle/Photos | 视觉资产管理 | 跨类型/文档/邮件/票据/来源 |
| Zotero | 学术引用 | 通用档案/项目/家庭/公开页 |
| 云盘 | 存储/同步 | 可检索/可理解/可继承/可退出 |

一句话：

> **他们管理“笔记/图片/文件”；你管理“我这一生的证据与记忆”。**

## 七、开源与商业模式

**开源核心**：

- vault 格式（文件夹 + JSON sidecar）；
- 索引器/搜索；
- 导出器；
- 备份/校验；
- 本地 Web UI。

**收费**：

| 收入 | 内容 | 谁买 |
| --- | --- | --- |
| **同步订阅** | 端到端加密、多设备、版本 | 个人/家庭 |
| **发布** | 公开档案页/自定义域名 | 研究者/创作者 |
| **家庭版** | 多成员/继承/共享 | 家庭 |
| **迁移/数字化** | 旧硬盘/相册/纸质扫描 | 个人/机构 |
| **备份验证** | 恢复演练/异地副本 | 小工作室/家庭 |
| **机构版** | 权限/审计/合规 | 研究机构/小团队 |

**定价**：个人 $5–10/月；家庭 $10–20/月；机构 $500–5k/年；迁移/数字化按项目。不要用“无限存储”打价格战。

## 八、获客：从“数字盘点”开始

最有效的钩子不是“又一个笔记”，而是：

> **“你的数字生活，有多少是十年后还能打开的？”**

可以做：

- 免费“数字档案健康检查”：文件类型、重复、无备份、无来源、无许可；
- 3-2-1 备份指南/模板；
- “家庭档案”工作坊；
- 研究者/设计师的资产整理服务；
- 开源索引器 + 公开案例。

## 九、用你的工作区先 dogfood

你已经有一个理想测试集：

- `docs/` 的知识库（900+ Markdown、PDF/HTML、图片）；
- `design/` 的 token/组件/风格卡/截图；
- `projects/` 的项目文档与资产；
- `docs/phosphorus-loop` 这类新收编内容；
- 大量链接、版本、来源、生成物。

第一版可以直接索引这个工作区：

- 全文搜索跨 `docs/design/projects`；
- 时间线看“哪一天改了什么”；
- 资产来源/许可；
- 生成“档案健康报告”；
- 导出公开页。

这比凭空做一个笔记 App 更有说服力。

## 十、90 天验证

| 周 | 目标 | 产出 |
| --- | --- | --- |
| 1–2 | 选 1 个真实 vault（自己的） | 文件类型/痛点/检索需求 |
| 3–4 | 索引 + 搜索 + 时间线 | 能找到 10 个“以前找不到”的东西 |
| 5–6 | 来源/版本/备份 | 一次恢复演练 |
| 7–8 | 公开页/导出 | 一个可分享的档案页 |
| 9–10 | 收费实验 | 家庭版/迁移服务报价 |
| 11–12 | 决定 | 继续/收窄/停止 |

## 十一、指标

- 索引条目数/类型覆盖；
- 搜索成功率（任务测试）；
- “找到以前找不到”的次数；
- 备份恢复成功率；
- 来源/许可完整率；
- 公开页/导出使用；
- 付费转化/家庭留存。

## 十二、风险与停止条件

**风险**：

- 范围无限（所有格式/所有设备）；
- 同步/加密/冲突复杂度；
- 搜索质量不如系统/云；
- 用户不愿为“整理”付费；
- 隐私/数据责任。

**停止条件**：

- 3 个目标用户都不愿为“找到/备份/继承”付费；
- 索引准确率低到不可用；
- 维护成本随格式数量爆炸；
- 12 个月后仍只是“个人脚本”。

## 十三、结论

个人档案 OS 是三个方向里**最适合你先自用、最长期**的：

- 它不依赖流行趋势；
- 它能把你的知识库/设计/项目变成真实测试集；
- 它天然支持开源/本地优先/可退出；
- 它可以从“索引器”长成“家庭/团队档案基础设施”。

它最难的地方不是技术，而是**克制**：

> 不要做“所有东西的 App”；先做“让一堆文件重新可被找到、可被信任、可被继承”的那一层。

如果你能做到这一点，你做的就不是笔记软件，而是**一个人数字生活的保管系统**。

## 附：档案结构与继承

### Vault 结构

```text
vault/
  files/                 # 原始文件（按内容 hash 或日期）
  sidecars/              # 每条目的 JSON：来源/许可/版本/保管
  collections/           # 视图定义（项目/人物/时间/主题）
  exports/               # 公开页/清单
  backups/               # 备份清单（不存副本）
  index.sqlite           # 可重建索引
```

**原则**：原始文件不动；sidecar 记录“关于文件的事”；索引可删除重建。这样即使软件停止维护，文件仍然可读。

### 备份与恢复

- 3-2-1：3 份副本、2 种介质、1 份异地；
- 备份清单记录 hash/时间/位置；
- 每季度做一次**恢复演练**（不是只备份）；
- 恢复报告：恢复条目数/失败项/校验结果；
- 加密：本地可选；同步端到端加密；密钥由用户保管。

### 继承模式

- **保管人**：指定家人/朋友/律师；
- **访问包**：哪些集合/文件、什么条件下可访问；
- **时间锁**：到期/事件触发；
- **只读副本**：继承人可读，不可改；
- **删除/封存**：按遗愿处理；
- **密钥交接**：不与账号密码绑死。

这不是“法律遗嘱”，而是**技术上的可交接性**：让档案在账号失效后仍然可读。

### 第一个真实用例

一个家庭：

- 20,000 张照片、800 份文档/票据、3 个云盘、2 台旧电脑；
- 目标：十年后还能打开、孩子能继承、能找到“2019 年那张房产照片”。

**3 周试点**：

1. 索引所有文件，先去重/找重复；
2. 建 5 个集合：家庭/房产/教育/旅行/工作；
3. 补来源/日期/人物（只补高价值项）；
4. 做一次恢复演练；
5. 生成家庭档案页（私密链接）；
6. 交付“备份 + 继承”说明。

这比“再装一个相册 App”更接近真实需求：**不是看更多，而是不丢失、找得到、交得出去。**
