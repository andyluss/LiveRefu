## 一、为什么把这三个放在同一卷

Bloons TD 与 Sanctum、Orcs Must Die! 表面毫无关系：一个是卡通猴子戳气球的浏览器小游戏，一个是第一人称射击，一个是第三人称动作。但三者共享同一种设计冲动——**改写"布防—观察—调整"（论文要件七）的时间结构**，只是改写方向相反。

- **Bloons TD 改写资源与塔的表达**：它不增加塔的种类，而是把每座塔做成数百个升级节点，再用难度模式与无尽波把长线数值推到前台；
- **Sanctum 与 Orcs Must Die! 改写介入权**：玩家不再只是"看着塔开火"，而是亲自端起枪、挥起武器下场。

所以本卷要回答的不是"它们还算不算塔防"，而是：**当五要件中的某一项被极端拉伸，其余四项如何补偿？**论文第三节把这类情况处理成"家族相似"而非族属变更——判定的关键始终是要件一（路径给定）与要件七（交战中介入权）是否还在。

## 三、② 机制拆解：五要件逐项对照论文第二节

下表用论文第二节的五个操作要件（路径、塔位、资源、波次、失败判据）横切三作。记号为：● 完整具备，◐ 变形或部分具备，○ 缺失。

| 要件（论文 §2） | Bloons TD | Sanctum | Orcs Must Die! |
| --- | --- | --- | --- |
| **路径** Path | ● 每张图固定一条或多条路线，玩家不可改 | ● 固定进攻路线，敌人循路冲向核心 | ● 固定入口到裂隙的路线 |
| **塔位** Slot | ● 沿路固定放置点，离散且可读 | ● 建造阶段在**格上**建 **8 种塔**，位置离散 | ◐ 陷阱位离散，但机制重心是玩家自身的走位 |
| **资源** Resource | ● "钱"：击杀返还 + 波间结算，**塔用钱升级** | ● 建造阶段分配资源买塔与升级 | ● 波间用资源买陷阱与武器升级，**拆除可退款** |
| **波次** Wave | ● 核心结构：固定波 + 无尽波，难度模式改写强度 | ◐ **建造阶段与第一人称歼灭阶段分离**，形成大节拍 | ● 波次明确，**波次间有布防间隙** |
| **失败判据** Leak | ● 生命值；难度越高**生命越少** | ● 核心生命被耗尽 | ● 裂隙点数；**玩家阵亡扣裂隙点数** |

### 3.1 Bloons TD：把"塔"做成一张升级图

Bloons TD 最值得研究的一点是：它**没有靠增加塔的种类来做深度，而是把深度放进升级树**。

- **升级树**：塔用局内货币"钱"升级。**BTD4 起升级项大增**，每座塔的分支开始分化出不同的战术定位；到 **BTD6，每塔最多 5 级**，且 **tier-5 变体可合成 Paragon**——这等于把局内的垂直成长推到极限，同一座塔在一条路径上可以被拉到远超其基础形态的强度。
- **难度模式**：**BTD2 起引入难度选项**，**BTD5 提供四种难度**，**Bloons Monkey City 提供六种**。难度的实现方式非常"工程化"：难度越高，**生命越少、塔与升级越贵**。这正是论文 5.5"把难度从感觉写成公式"的工业化版本——难度不是隐藏的曲线微调，而是玩家可见、可复现的参数改动。
- **BTD6**：**2018-06-14 移动端首发**，新增**英雄**与 **2.5D 视角**；每张地图提供**三种标准难度**，外加 **CHIMPS 等限制模式**（限制模式通过禁止某些机制来制造硬约束）。

对照论文要件：路径与塔位完全标准；资源与波次被"升级树 + 无尽波"拉伸成长期成长；失败判据通过难度模式直接参数化。它证明了**长线数值的合法性来自"选择树"而不是"塔的数量"**。

### 3.2 Sanctum：用阶段分离换来第一人称

Sanctum 的解法是**把两种玩法在时间上切开**：建造阶段在网格上建 8 种塔，随后进入第一人称射击阶段亲自歼敌。玩家参战，但参战不占用布防时间。

- 这种"阶段分离"直接回应了动作缝合的根本矛盾：**射击需要反应时间，布防需要思考时间，两者同时进行会互相抢注意力**。
- 代价是塔防的空间决策被压缩进一个独立环节，交战中不再能调整布局，因此它的塔防深度更接近"一次性预算分配"，乐趣重心落在射击手感上。
- 维基对它的定义是 **first-person shooter tower defense**，不是"带射击的塔防"——顺序说明了设计的重心归属。
- 谱系上，维基指出 Sanctum 及其 2013 年续作 **popularized the first person shooter hybrid**，而更早的 **Iron Grip: Warlord（2008）是首个失败尝试**。这说明缝合动作本身不是难点，**难的是让布防与开火互不抢时间**。

### 3.3 Orcs Must Die!：不分离，而是让布防贯穿全场

Orcs Must Die! 走的是相反路线：**不设独立的建造阶段，陷阱可随时布放与拆除退款**，波次间另有布防间隙作为缓冲。

- 维基称其为 **action-tower defense**，并明确它**放弃了传统俯视视角，改用第三人称动作视角**。
- 玩家本人是战斗单位，**阵亡会扣除裂隙点数**——这条规则很关键：它把"玩家参战"从免费增益变成了**有成本的风险**，从而保留了塔防"失败是累积的"这一情感结构。
- 与 Sanctum 相比，它用"随时可布放 + 全程可退款"补偿了第三人称视角带来的布局不便，代价是单次布防的思考时间被切碎。

## 四、③ 它证明了什么

1. **升级树是一种"塔的类型学替代方案"**。当美术与关卡成本有限时，把深度放进升级分叉，比新增单位更经济；Bloons TD 用一条升级树撑起了近二十年的系列演进。
2. **难度可以被产品化，而不只是被调参**。Bloons TD 把难度做成显式模式（生命更少、造价更贵），玩家能理解自己为什么输——这比隐藏的 DDA 更透明，也更适合攻略社群。
3. **动作缝合的两种正解**：要么在时间上分离（Sanctum 的阶段制），要么在成本上约束（Orcs Must Die! 的阵亡扣点数 + 可退款陷阱）。**没有成本的动作介入会直接抹掉塔防的策略性**。
4. **缝合失败的样本同样有教学价值**。Iron Grip: Warlord（2008）作为首个失败尝试，说明"能同时做两件事"不等于"两件事都成立"。
5. **垂直成长的极限会撞上数值膨胀**。Paragon 这类"把 5 级变体再合成"的设计，是论文 10.2"数值膨胀"的高风险区：它提升了上限，也让曲线更难被玩家读懂。

## 五、④ 可迁移的做法

1. **升级树要"分叉不并发"**：同一座塔的多个分支让玩家单选或少量兼得，避免"全都要"退化成纯资源堆叠；每个分支绑定一个明确的战术场景（对空、对群、控场）。
2. **难度模式至少改两个参数**：只改敌人血量是"调参"，同时改**玩家生命 + 造价/收益**才是"模式"。让玩家能在 UI 上看到这些差异。
3. **动作缝合必须设成本闸门**：若玩家能在交战中自由布防，就给布防加冷却或取消退款；若玩家下场参战，就让阵亡/受伤付出基地资源代价（照抄"扣裂隙点数"）。
4. **无尽波需要"停手的仪式感"**：给出一个明确的"到此为止"的结算点或记录榜，避免长线数值变成没有终点的消耗。
5. **局外解锁只解锁选项，不解锁数值**：把局外成长限定在"新塔、新分支、新模式、外观"，避免论文要件六红线所警告的"付费夷平难度设计"。
