## 二、机制拆解：五要件逐项对照

下表按论文第二节 2.1–2.5 的五个要件（路径、塔位、资源、波次、失败判据）逐项对照，末两列备注要件六（局内/局外分层）与要件七（布防—观察—调整）。

| 要件 | Plants vs. Zombies | Kingdom Rush |
| --- | --- | --- |
| 路径 | **五路直线**：僵尸从右侧单向前进，不换行 | 每关固定路径（多张地图，含岔路与合流） |
| 塔位 | 网格格子：草坪、泳池、屋顶等，按格种植 | 路径旁固定建造点 |
| 资源 | **阳光**：天降 + 向日葵产出，用于种植与升级 | 金币（击杀/波次获得）买塔与升级；**stars** 换永久强化 |
| 波次 | 分波推进；**旗手指挥的大波次**预告压力峰值 | 分波推进；关卡内挑战条件驱动重玩 |
| 失败判据 | 僵尸抵达房屋；每路一台**单向割草机**作为一次性保底，用尽后即败 | 漏怪扣生命，生命归零即败 |
| 局外分层（要件六） | 轻：关卡解锁与图鉴为主 | 有：英雄、stars 永久强化、塔型专精 |
| 布防—观察—调整（要件七） | 有：种植与收集阳光即交战中的微调 | 有：英雄可自由移动、两个手动全局技能 |

### 2.1 植物大战僵尸：把"塔不会挨打"这个不直观补上

George Fan 的灵感来源是**魔兽争霸 III 的塔防 mod**。他注意到一个大家习以为常却并不直观的设定：**敌人从不攻击塔**。于是 PvZ 反过来设计——把路径做成直线车道，让僵尸**能够吃掉植物**。这一改动的连锁后果是：

1. **塔有生命、会被消耗**，防守不再是"摆好就不动"，而变成持续的补种与取舍；
2. **割草机**因此成为必要的一次性保底：它把"漏怪"从即时失败改成**每路一次的容错**，正好是论文 2.5 所说的"失败被离散化、允许少量失误"；
3. **阳光经济**把资源从"击杀返还"改成"产线投资"，玩家要在"多种向日葵"与"多种攻击植物"之间做前置权衡——这是对论文 2.4 资源节奏的一次重新配平。

配套的还有**每关限选种子包**：把"能造什么"提前锁成有限集合，等价于塔防的"塔位离散化"在**选择集**上的推广——离散化带来可读、可平衡、可比较（论文 2.2）。

### 2.2 王国保卫战：把"英雄"写进塔防的时间结构

Kingdom Rush 的机制清单几乎每一项都在补要件六或要件七：

| 机制 | 归属要件 | 设计作用 |
| --- | --- | --- |
| 四塔型：弓 / 法 / 炮 / 兵营 | 塔位 + 资源 | 伤害类型（单体/魔法/溅射/阻挡）互补，兵营把"阻挡"变成可买的资源 |
| 每塔三次升级后**二选一专精** | 资源 + 局内分层 | 同一塔位在后期分化，缓解"最优解把选择变成搜索"（论文 10.1） |
| **可自由移动的英雄**（独立技能与升级） | 要件七 | 给"观察期"一个高频手动介入点，维持参与感 |
| 流星、增援两个**手动全局技能** | 要件七 | 提供跨全场的紧急救援，制造"何时按"的决策 |
| **stars 换永久强化** | 要件六 | 典型的局外成长：失败也留下进度，降低重试门槛 |
| 关卡挑战驱动重玩 | 要件三 | 用同一张图的不同胜利条件延长内容寿命 |

值得注意的是首发形态：**2011-07-28 以免费 Flash 浏览器游戏在 Kongregate 上线**。它与 2007 年的 Desktop Tower Defense 共享同一条分发逻辑（见[本卷 01](01_早期谱系_从Rampart到DesktopTowerDefense.md)）——先用零门槛网页拿到规模，再迁移到付费移动端。移动端的成败关键不在塔防规则本身，而在**触屏是否让"布防—观察—调整"更顺**（论文 2.7 的判断）。

## 三、它证明了什么

这两作共同证明了塔防的**大众化不是靠简化规则，而是靠改变"玩家与防守对象的关系"**。PvZ 让塔暴露在敌人面前，把静态布局变成有生命的阵地，于是"守住"第一次有了表演性与情感重量；Kingdom Rush 则把塔防的介入权从"建塔那一刻"延伸到"全程手动"（英雄移动 + 两个全局技能），并补上 stars 这一层局外成长，让失败也能积累进度。前者证明了塔防可以成为**大众娱乐产品**，后者证明了塔防可以成为**移动端的长期服务型模板**。二者也各自留下一条方法论：PvZ 的"敌人可以攻击塔"是**对默认假设的反向提问**，Kingdom Rush 的"英雄 + 专精 + 局外强化"是**在不动核心五要件的前提下增加介入层**。这正是论文第十一节所说的"塔防作为规则容器"——好的大众化作品并不删要件，而是往要件七与要件六上加接口。

## 四、可迁移的做法

1. **审自己的默认假设。** 像 PvZ 那样把"敌人从不攻击塔"写出来质疑一遍；凡是被继承而非被论证的规则，都是差异化的候选点。
2. **把容错做成一次性资源而非数值。** 割草机式的"每路一次保底"比单纯加生命更可读：玩家能明确数出还剩几次机会，对应论文 2.5 的离散失败。
3. **资源要有一条"产线"分支。** 借鉴向日葵：让玩家在"扩张产能"与"购买战力"之间二选一，把资源决策从"买哪座塔"扩展成"投资还是消费"。
4. **给观察期留一个高频手动接口。** 英雄移动或全局技能都可以；要件七不能被自动战斗抽空，否则塔防会退化为"配置即结果"（论文 2.8）。
5. **局外成长只加"选择"不加"碾压"。** stars 换强化要落在新塔型/新技能上，而非直接等价于局内数值，否则会夷平难度设计（论文 2.6 的红线，第十节的数值膨胀症状）。
