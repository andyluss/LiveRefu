## 三、统一模板（每篇六段）

1. **卡面行**（用途／依赖／状态）；
2. **作品档案表**：年份、平台、开发者、发行商、类型定位；
3. **机制拆解**：按论文第二节的七个要件逐项对照（重点前五个：路径／塔位／资源／波次／失败判据，另注局外分层与介入权）；
4. **它证明了什么**：这部作品对类型史的贡献；
5. **可迁移的做法**：4–5 条可执行建议；
6. **参考来源与互链**：URL 列表 + 论文／数值卷／策划卷的反向链接。

## 四、事实与口径纪律

- 年份、平台、开发者等**硬事实**均来自联网核查（英文/中文维基当前版本，2026-09 抓取）；凡维基条目自带"原创研究"模板的段落，正文写成"可考最早"而非"最早"；
- **两处冲突并列呈现，不择一**：① Missile Command 只有 tower defense 条目单向引述，其自身条目未提塔防；② Kingdom Rush 的规模数据在"下载超 1 亿"与"App Store + Play 约 1,700 万份"之间冲突（口径不同）；
- **二手数据一律标注**（如《明日方舟》的收入与下载、Sanctum 的销量、Orcs Must Die! 的销量），本卷不把它们当作已核实的一手数据；
- 术语按维基原文口径：mazing / juggling / hybrid / reverse tower defense（=tower attack=tower offense）/ tower wars。
