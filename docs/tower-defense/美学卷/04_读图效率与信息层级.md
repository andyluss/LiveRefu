## 一、四项关键信息与"1 秒可读"测试

论文 10.6 给"视觉噪声压倒信息"开的诊断只有一句：**在最小目标机型与最坏光照下截图，检查四项关键信息（能量、生命、漏怪、卡面数字）是否 1 秒内可读**。机型、光照、判读人三个变量必须全部锁死，测试才可复现。

| 变量 | 取值 | 依据 |
| --- | --- | --- |
| 最小机型 | 中低端安卓与旧款 iPhone；低端档 30 fps、卡面插画 512 长边 | 07 第四节、美术 001·05 |
| 最坏光照 | 户外直射，数字与底衬 ≥ 7∶1 | 07 第四节、美术 001·03 |
| 取样帧 | HUD 三条与手牌数字、战场特效同时出现的最拥挤帧 | 论文 10.6 |
| 判读人 | 未参与设计者，遮住上下文，1 秒内念出四个数 | 论文 10.6 |

步骤：① 最小机型开低端档，打到四项信息同时变动的时刻截图；② 缩到 4.7 英寸实机尺寸，做灰度化与红绿盲模拟；③ 判读人 1 秒内念出四个数，**错一个即不过**，转第五节修复；④ 记下错误项与帧号，改动后复测同一帧。

注意 HUD 常驻只有三条（左能量、中基地、右漏怪，高 28 dp），卡面数字在手牌区、属"要低头看"的第二读区——第 4 项必须在手牌一次可见的前提下测。

## 二、工程口径：字号、触控、对比度与色弱冗余

| 项 | 口径 | 来源 |
| --- | --- | --- |
| 字号 | 主数值 ≥ 24 dp、关键词 ≥ 14 dp、二级说明 ≥ 12 dp；对照 001 的 12／10／11 pt，取更严者 | 002·08、001·03 |
| 对比度 | 数值与底衬 ≥ 4.5∶1，户外 ≥ 7∶1；关键词 ≥ 3∶1；灰度化后仍成立 | 001·03、002·08 |
| 光晕 | 辉光 ≤ 40% 且在数值层之下；数字底片上方 8 dp 禁内发光与 Bloom | 001·03、002·08 |
| 触控 | ≥ 9 mm ≈ 57 dp；本体与命中盒差 ≤ 9 dp、间距 ≥ 8 dp；塔位 ≥ 48 dp、手牌 ≥ 72×96 dp | 07 第二节、001·05 |
| 色弱 | 禁红绿分敌我、禁单色分标签，状态色加形双编码；纯色相编码 0 处 | 001·03、001·06 |
| 色差 | 十标签在深空靛 `#0E1526` 底上两两 ≥ 20（CIEDE2000），同屏标签色 ≤ 6 种 | 002·08 |
| 降级 | 字号、对比度、命中盒、数字底片一律不降 | 002·08、001·05 |

字号换算基准：dp = 1／160 英寸、pt = 1／72 英寸，1 pt ≈ 2.22 dp。据此可算出**001 的 pt 口径整体更严**（12 pt 约合 26.7 dp），两案并行时以更严者落地。

## 三、信息优先级冲突时的裁决顺序

裁决顺序：**数值 > 状态 > 特效 > 装饰**。它不是偏好，而是论文 9.1 红线"数值与状态信息永远压在视觉特效之上"的展开。

| 优先级 | 内容 | 承载物 | 冲突时怎么让 |
| --- | --- | --- | --- |
| 1 数值 | 能量、基地生命、漏怪、卡面费用与主数值 | 不透明底片、HUD 压暗带 | 永不让位 |
| 2 状态 | 护盾层、腐蚀层、共鸣计数、蓄力、受伤、漏怪逆推 | L2 内芯亮度加 L3 刻度 | 可降亮度，不可消失 |
| 3 特效 | 羁绊九条、进化枝、破盾反噬、BOSS 阶段技 | 粒子与光路 | 同屏同色系 ≤ 3 层；永远在卡面与 HUD 之下 |
| 4 装饰 | bling 级 1、箔纹、环境粒子、天气 | 贴图与背景 | 最先被砍，砍到零也可以 |

同优先级内部还有第二判据：粒子超预算时**先减重复火花，再减环境粒子，最后才减机制信号特效**；羁绊、进化、破盾、漏怪四类信号特效优先保留；BOSS 阶段技可瞬时借 200 粒子，须在 800 ms 内归还（美术 001·06）。

## 四、信息密度预算

| 预算项 | 口径 | 来源 |
| --- | --- | --- |
| 001 粒子与特效档位 | 高端 120／800／12、中端 80／450／8、低端 40／200／4（单机制／同屏总量／同屏特效数） | 美术 001·06 |
| BOSS 阶段技 | 可瞬时借 200 粒子，800 ms 内归还 | 美术 001·06 |
| 002 场景粒子总量 | ≤ 200（低端机 0，只留级 1 贴图） | 美术 002·09 |
| 002 天气粒子 | 水痕 24、气泡 40、闪粉 120、全息尘 60、雨 180；同帧只允许一档 | 美术 002·09 |
| 透明层数 | 单帧 ≤ 8；同屏"全透"单位 ≤ 6 | 美术 002·01 |
| 同色系与标签色 | 同屏同色系特效 ≤ 3 层；同屏标签色 ≤ 6 种 | 001·06、002·08 |
| 背景与分区 | 一塔位宽内 ≤ 2 个可辨图案、远景 ≤ 3 层×5 元素；战场级 3、卡牌区级 1–2、HUD 级 1 | 002·09、002·08 |

信息块预算：硬底线是四项关键信息（论文 10.6）；卡面常驻只给 3 个数字加 1 个关键词（07 第一节）。相乘可得同屏连续可读数值块 ≈ HUD 3 条 + 手牌 3× 可见手牌数 + 每单位 1 条刻度——末项由 002 的 L3 职责推导，**原文未给上限，须作待验项**。

读法两条：粒子与特效数是**同屏并发**约束，不是单次播放总量；002 的 ≤ 200 统计场景与天气，001 的低端 ≤ 200 是全部机制的合计量——数值相同、对象不同，验收要分开测。

## 五、三种典型失败与修复流程

| 失败 | 症状 | 诊断 | 修复 |
| --- | --- | --- | --- |
| 特效遮数值 | 羁绊、进化、阶段技的亮斑压住 HUD 或卡面数字 | 关 UI 层检查数字底片上方 8 dp 有无亮斑；查特效层级是否在卡面与 HUD 之下 | 先降 bling 级，再收窄特效范围；数值层不动 |
| 色弱下敌我同色 | 灰度化后敌我剪影分不开 | 灰度化加红绿盲模拟逐一点名；核对主体明度口径 | 补形状或纹理冗余，纯色相编码归零 |
| 光影把路径吃掉 | 镜面反射让路径读不出，或折射把路径拉歪 | 量反射位移是否 ≤ 自身宽度 5%、折射 ≤ 2 px、背景峰值 ≤ 主光峰值 25% | 降反射精度与范围；路径槽色只留描边；虚空区零反射并压暗 25% |

主体明度口径为"三族 ≥ 50%、敌方 ≤ 45%"（[002·12](../../refu-game-001/美术/美术设定002/12_键色与光照配方.md)），路径与塔位的具体画法可对照 [视觉语法](01_塔防的视觉语法.md) 与 [案例卷](../案例卷/README.md)。

修复流程四步，与数值卷把设计意图钉成断言的做法同源（[数值卷·05](../数值卷/05_验收与CI.md)）：① **复现**——回到最小机型与最坏光照，截同一帧留档；② **定级**——数值层被遮 P0、状态层 P1、特效 P2、装饰 P3；③ **让位**——按"装饰→特效→状态"依次让位，数值层永不参与；④ **回归**——同帧复测，四项 1 秒可读才算关闭。

## 六、发布前读图验收表（10 条）

| # | 验收项 | 阈值 | 依据 |
| --- | --- | --- | --- |
| 1 | 四项关键信息 1 秒可读 | 最小机型加最坏光照，错一个即不过 | 论文 10.6 |
| 2 | 卡面主数值字号 | ≥ 24 dp（对照 001 的 12 pt，取更严者） | 002·08 |
| 3 | 关键词与二级说明 | ≥ 14 dp 与 ≥ 12 dp，低端档不降 | 002·08 |
| 4 | 数字对比度 | ≥ 4.5∶1，户外 ≥ 7∶1 | 001·03 |
| 5 | 光晕不遮数值 | 底片上方 8 dp 无内发光与 Bloom；辉光 ≤ 40% 且在数值层之下 | 002·08、001·03 |
| 6 | 触控目标 | ≥ 9 mm（≥ 57 dp），相邻间距 ≥ 8 dp | 07 第二节、001·05 |
| 7 | 色弱冗余 | 灰度化加红绿盲模拟可逐一点名；纯色相编码 0 处 | 002·08、001·06 |
| 8 | 闪烁与亮度 | 闪烁 ≤ 3 Hz、覆盖 ≤ 25% 屏幕；亮度跳变 ≤ 10% | 001·06、002·01 |
| 9 | 粒子与特效档位 | 低端 ≤ 200 粒子与 ≤ 4 特效；场景粒子总量 ≤ 200 | 001·06、002·09 |
| 10 | 反射折射不改读 | 反射位移 ≤ 自身宽度 5%、折射 ≤ 2 px、反射层不含数字 | 002·09 |

第 1 条是总闸：它不过，其余九条全对也不算过；反过来，九条全过而第 1 条不过，说明规范守住了、玩家丢掉了——这正是论文 10.6 把"读不清"单列为症状的原因。
