## 摘要

塔防（Tower Defense, TD）是 21 世纪初最容易被低估、也最容易被误读的一类策略游戏：它既不考验手速，也不直接提供对抗，玩家做的事看起来只是"在路边摆东西，然后看着怪物走过去死掉"。但正是这种"低操作、高结构"的形态，让塔防成为一个罕见的**可形式化的策略游戏标本**：它的空间（路径与塔位）、时间（波次）、资源（能量经济）、难度（预算与胜率）都可以写成公式，也可以被反解、被验算、被批量生成。

本文分三条线索展开。**第一条是内涵**：用七个构成要件（路径、塔位、波次、资源、基地生命、局内外分层、布防—观察—调整的时间结构）界定塔防的本质属性，并用一组反例与边界案例（迷宫化、可移动塔、英雄单位、塔攻／reverse TD、自动战斗）检验判据的松紧。**第二条是外延**：清理塔防与 MOBA 兵线、生存防守、放置、自走棋、RTS 基建、卡牌塔防之间的家族相似关系，给出一张"要素 × 类型"的判定矩阵。**第三条是设计空间与文化位置**：把难度从"感觉"改写成可验算的量（预算 B、难度比 D、泊松漏怪与胜率函数），再讨论塔防的心理机制（计划—学习的循环、Flow、损失厌恶、可见系统的代理感）、产业结构（Flash 页游 → 独立 → 服务型手游与抽卡耦合）、美学语法（俯视/剖面、路径作为"被阅读的空间"，以及它与复古未来、千禧美学的天然亲和），最后给出"坏塔防的六种症状"与融合玩法的接口条件。

论文同时以本工作区的《Refu Game 001》为**可验算样本**：它的五章主线与八节点远征分别给出 94.9%→43.6% 与 84.4%→3.6% 的可复现胜率曲线，九项自动校验（模拟器）把"平衡"从编辑的口味变成了工程的判据。这使本文不只是文献综述，也是一份可以拿去跑的设计方法。

**关键词**：塔防；策略游戏；难度设计；类型学；游戏经济；形式分析；游戏美学；可验算设计

## 一、引论：为什么塔防值得一篇论文

### 1.1 一个体量与关注度不匹配的类型

塔防的产业体量无需辩护：从《魔兽争霸 III》的自定义地图到 Flash 页游时代的《Desktop Tower Defense》，再到移动端的《保卫萝卜》《明日方舟》与全球范围内的《Kingdom Rush》《Bloons TD》系列，塔防是少数**跨越四个平台世代而没有消失**的策略子类型。它也是"玩法模因"传播最成功的样本之一：几乎每一款带编辑器或关卡系统的游戏，都会在某处长出一张塔防图。

但与它的体量相比，塔防在游戏研究中的位置很尴尬。它既不像 MOBA 那样有清晰的竞技叙事，也不像叙事游戏那样便于文本分析；它缺少"玩家故事"，却拥有异常清晰的**系统结构**。学界对它的正式研究，往往集中在两个极端：一端是复杂度证明这类纯理论结果，另一端是关卡数值与 AI 求解的工程实践，中间那条"设计学"的线索几乎空缺。

### 1.2 三条线索与研究问题

本文的问题意识可以压缩成三问：

1. **什么是塔防**（内涵）：哪些属性是本质的，哪些只是常见配置？把某条属性抽掉，它还叫塔防吗？
2. **塔防的边界在哪**（外延）：它如何与 MOBA、生存防守、放置、自走棋、RTS 基建、卡牌游戏互相渗透？渗透到什么程度就不再是塔防？
3. **塔防为什么好玩，又为什么容易变坏**（设计空间与批评）：它的乐趣来自哪一层结构？什么情况下它会退化成"摆完就挂机"，或者被数值与变现合谋毁掉？

### 1.3 方法与材料

- **形式分析**：把塔防的空间与难度写成可计算的对象。本文采用本工作区的难度模型作为样本（预算 `B`、我方战力 `P`、难度比 `D = (B ÷ B_ref) × (P_ref ÷ P)`、泊松漏怪与 `cap`），并用模拟器实测曲线检验。
- **类型学**：用一组正交维度描述设计空间，把代表性作品放进坐标系，避免"像不像塔防"这种不可判定的争论。
- **案例比较**：选取横跨三十余年的节点作品（见第四节），每个案例只取它能证明的那个要素。
- **理论参照**：Flow、MDA、Rules of Play、"不确定性"与"游戏感"等既有框架（见参考文献），用来解释机制如何变成体验。
- **可验算样本**：本工作区的 [Refu Game 001](../../projects/refu-game-001/docs/design/README.md) 提供了完整的决策记录、卡表、数值表与九项自动校验脚本（[`projects/refu-game-001/tools/sim_refu_game_001.ts`](../../projects/refu-game-001/tools/sim_refu_game_001.ts)），本文用它来演示"设计可被反解"这件事。

**方法上的自我限制**：本文不做玩家行为实证（没有问卷、没有日志），因此关于心理机制的论述是**解释性**而非**验证性**的；凡涉及历史年份与作品史实，尽量以公开资料为准，无法确认者标为"通常说法"。

### 1.4 一个术语的分层：内涵与外延

- **内涵**（intension）：使某物成为塔防的那些**必要属性**。本文主张七个要件（第二节）。
- **外延**（extension）：由这些属性圈定的**实际范围**，包括各类变体与邻接类型（第三节）。
- **家族相似**：本文不追求"唯一判据"，而采用维特根斯坦式的宽松标准——满足多数要件即可入族，缺少关键要件则出族；争议案例用矩阵标注，而不是判决。

## 二、内涵：塔防的七个构成要件

塔防可以定义为：**在一条（或多条）被敌人固定的进攻路径上，玩家用有限资源在预设位置布置防守单位，通过多轮次的自动交战守住基地的游戏**。这个定义里藏着七个要件，每一个都可以被单独抽掉做实验。

### 2.1 要件一：路径（Path）——敌人的运动是给定的

路径是塔防的空间骨架。它决定了"敌人从哪里来、往哪里去、走多久"，也决定了玩家不能直接控制敌人的位置。塔防的空间感来自**"路径不可改，但路径周围的火力可布"**这一组约束。

- 变体：单入口单线、多入口合流、环形路径、可破坏障碍（桥、闸门）、地形减速（沼泽、腐蚀地）。
- 反例实验：如果玩家可以随意改变敌人路径（自由迷宫），游戏会立刻从"塔防"滑向"迷宫建造"（mazing），见 3.3。

### 2.2 要件二：塔位（Slot）——布置是离散的

塔位把连续的建造自由切成了有限的选项。离散化带来三件后果：**可读**（玩家一眼知道有哪些位置）、**可平衡**（位置本身就是数值）、**可比较**（同一张图上高下立判）。

- 变体：标准/支援/修饰三类槽位、高台加成、禁放区（虚空）、随地图开放的新位。
- 反例实验：若布置完全自由且无成本（任意坐标建造），决策会从"选哪个位"退化为"堆多少资源"。

### 2.3 要件三：波次（Wave）——时间被切成可预告的段落

波次是塔防的时间单位。它把一场防守切成若干"小局"，每一小局都有**预告—交战—结算**的节拍。波次让塔防可以在极短的单局时长内承载完整的"准备—应对"体验。

- 变体：固定波次、随机波次、呼吸波（低强度缓冲）、精英波、BOSS 波、无限波（无尽模式）。
- 关键设计点：预告的**信息量**。预告越精确，塔防越像解谜；预告越模糊，越像应变。

### 2.4 要件四：资源（Resource）——局内的现金流

资源是塔防的"经济"。它的经典形态是能量（Energy）：按时间自然增长，击杀敌人返还，波间结算奖励，用于买塔、升级与放技能。

- 资源结构决定节奏：起始值决定开局容错，增长速率决定中期强度，返还系数决定"清怪"的正反馈。
- 反例实验：把资源换成"无限但受塔位限制"，塔防就变成了纯粹的**空间拼图**（这也是许多变体的做法）。

### 2.5 要件五：基地生命与漏怪（Leak）——失败是累积的

塔防的失败通常不是"被打死"，而是**"漏过去的太多"**。基地生命（或漏怪上限）把失败离散化：允许少量失误，累计到阈值即输。这条规则塑造了塔防特有的情感曲线——紧张来自"还差几只"，而不是"血条还有多少"。

- 变体：固定生命、漏怪计数、惩罚性资源扣减、护盾门。

### 2.6 要件六：局内／局外分层（Run vs Meta）——成长放在哪一层

几乎每一款现代塔防都有两层：局内（一局之内的塔与资源）与局外（卡组、解锁、皮肤、赛季）。这个分层不是细节，而是**商业与耐玩的接口**：局内负责"这一局的乐趣"，局外负责"明天的理由"。

- 关键红线：局外成长若直接等价于局内数值，塔防的难度设计就会被付费夷平（见第八节与第十节）。

### 2.7 要件七：布防—观察—调整（Prep–Observe–Adjust）——决策的时间结构

塔防的操作节奏是"快决策 + 慢观察"：布防期集中做选择，交战中观察结果并微调。这个不对称结构是塔防与即时战略、动作游戏的根本分野，也解释了为什么塔防天然适合触屏与碎片时间。

## 三、外延：家族相似与邻接类型

### 3.1 一张"要素 × 类型"矩阵

下表用七个要件做行、用邻接类型做列，标记该类型与塔防的共享程度（● 共享，◐ 部分，○ 不共享）。

| 要件 | 塔防 | 塔攻(reverse TD) | MOBA 兵线 | 生存防守 | 自动战斗 | 放置(idle) | RTS 基建 | 卡牌塔防 |

| 路径给定 | ● | ● | ● | ◐ | ● | ● | ○ | ● |
| 离散塔位 | ● | ○ | ◐ | ◐ | ● | ○ | ◐ | ● |
| 波次 | ● | ● | ● | ● | ● | ◐ | ○ | ● |
| 局内资源 | ● | ● | ● | ● | ◐ | ● | ● | ● |
| 漏怪/基地 | ● | ● | ● | ● | ● | ● | ● | ● |
| 局外分层 | ◐ | ◐ | ● | ◐ | ● | ● | ○ | ● |
| 交战中介入 | ● | ● | ● | ● | ○ | ○ | ● | ◐ |

这张矩阵的价值在于：它把"某某游戏是不是塔防"变成"它在哪些格子上是、哪些格子上不是"。例如以抽卡养成著称的《明日方舟》，在七个要件里几乎全占，但它介入方式从"即时微操"变成"暂停布防"，因此它是**塔防的高介入变体**，而不是"塔防 + 养成"的简单叠加。

### 3.2 邻接类型逐个说

- **塔攻 / reverse TD**：把玩家的角色从"守方"翻到"攻方"，路径与波次仍存在，但"塔位"变成敌人的布防。它证明了塔防的核心不是"守"，而是**"读一条既定路线上的资源分配"**。
- **MOBA 兵线**：共享"固定路径 + 周期性小兵"，但把"塔"从玩家的免费选择变成对抗目标，并加入实时对抗。它是塔防的**对抗化**分支。
- **生存防守（survival defense）**：重心从"空间布局"移向"资源管理与压力承受"，塔位常常是动态的（可搬、可修、可拆）。
- **自动战斗**：保留塔防的全部结构，唯独抽掉交战中的介入权。它是塔防的**观赏化**分支：玩家在局外准备，在局内当观众。
- **放置（idle）**：把波次与资源增长抽象为可离线累积的进度，与塔防共享"配置—观察"的骨架，但删掉了失败风险。
- **RTS 基建**：共享"资源—建造—防守"，但敌人路径不固定、玩家可以操作单位，因此与塔防是**同源异流**。
- **卡牌塔防**：把塔、技能、增益全部卡化，用抽卡与卡组构成代替"自选建造"。本工作区的 Refu Game 001 属于这一支，并进一步把地图与事件也卡化（见 [02_卡片规则系统](../../projects/refu-game-001/docs/design/02_卡片规则系统.md)）。

### 3.3 三个长期争议的边界问题

1. **迷宫化（mazing）算不算塔防？** 按维基 tower defense 条目的定义，mazing 是"用塔本身筑成一条长而曲折的迷宫以延长敌人必须穿越的距离"；与之相邻的还有 **juggling**（在两侧出口之间轮流封堵，使敌人来回折返直至被消灭）与 **hybrid**（预设路径可被塔位部分修改）。Desktop Tower Defense 允许用塔把路径拖长，许多玩家视其为"正统"；另有 **tower wars** 指双方互相进攻对方棋盘的多人体。本文的处理是：迷宫化把要件一（路径给定）从"地图给定"改成"玩家构造"，它仍在族内，但属于**空间构造变体**——判据放宽的依据是"敌人的运动仍然是被决定的，只是决定者从地图作者变成玩家"。
2. **可移动/可升级塔算不算？** 只要塔位仍是离散的、布置仍有成本，就只是**塔的表达方式**变化，不影响族属。
3. **英雄单位算不算？** 若英雄是"一张会动的塔"（受塔位、资源与冷却约束），族属不变；若英雄可以自由移动、无限输出并直接改变路径，塔防就向动作游戏迁移了。

## 四、历史谱系：从街机到服务型手游

### 4.1 前史（1980–1990 年代）

- **更早的"守点"原型**：Space Invaders（1978）把关卡压到屏幕底部，并用可被摧毁的护盾提供"防线"概念；Defender（1981）与 Choplifter（1982）则把"保护对象"从玩家自身换成非玩家目标（据 [Wikipedia: Tower defense](https://en.wikipedia.org/wiki/Tower_defense) 的谱系段落）。
- **Missile Command（1980-06，Atari Inc.，设计 Dave Theurer）**：轨迹球操作，用 3 个反导基地守住 6 座城市，把"保卫城市"的失败做成不可逆的丧失（[Wikipedia: Missile Command](https://en.wikipedia.org/wiki/Missile_Command)）。**需要标注的引用细节**：把它与塔防相连的说法只出现在维基的 tower defense 条目里，"Missile Command"条目本身从未提及 tower defense——这是单向归类，而非互证。
- **Rampart（1990-10 街机，Atari Games，设计 John Salwitz，美术 Dave Ralston）**：交替进行"建造阶段"（用旋转方块补墙、把城堡围起来以扩大领地）与"战斗阶段"（炮击敌舰或对手城墙），战斗后未被墙完整包围的区域连同其中的炮台会归敌方。维基 tower defense 条目称它"generally considered to have established the prototypical tower defense"（[Wikipedia: Rampart](https://en.wikipedia.org/wiki/Rampart_(video_game))）。

这一阶段的关键遗产是**"布防与交战的时间分离"**——塔防的节拍从此确定。

### 4.2 自定义地图期（2002–2006）

自定义地图期是"塔防"从机制变成**名称**的时期，可考的命名轨迹如下：

- 最早用"Turret Defense"命名的是星际争霸自定义图（常见说法为 **2000-05**），随后是 Sunken Defense（**2001-11**）；
- 《魔兽争霸 III》（2002）的自定义地图把塔防要素**固化为模板**：固定路径、若干塔位、按波刷怪、共享金币、漏怪计数；该条目把 Element TD、Gem Tower Defense 记为 2006-02（引注为地图站，属弱一手证据）；
- **术语在此后被商业化收编**：COM2uS 于 **2007-06-13** 申请、**2008-06-03** 获得美国 "Tower Defense" 商标（serial 3442002），并在 2010 年初开始向 App Store 开发者发函。这与后来 Bloons 系列 2009 年因商标冲突改名（见 4.4）互相印证：**一个类型名在几年内从社区术语变成了法律资产**。

需要诚实标注的是：维基的 tower defense 条目**没有词源段落**，"tower defense"这一确切短语的最早使用**目前无法确证**；该条目本身还挂着"原创研究"（2020-11）与"过于细节"（2022-01）模板。因此凡涉及"最早"的说法，本文一律写成"可考最早"。

自定义地图的意义还在于**生态学**：它证明了塔防是一个可以被非专业作者批量再生产的玩法模因。

### 4.3 Flash 与页游期（2007–2010）

- **Flash Element TD（2007-01-12，David Scott）**：仿魔兽 III 的 Element TD 而作，到 2009-03 累计游玩超过 **1.4 亿次**，是"元素/合成"路线的开端（[Wikipedia: Flash Element TD](https://en.wikipedia.org/wiki/Flash_Element_TD)）。
- **Desktop Tower Defense（2007-03-03，Paul Preece）**：把塔防压缩成浏览器里的一屏网格。它最关键的改动是**取消预设路径**：塔位决定敌人的行进路线，敌人永远走最短路，且出口不能被完全封死——这正是"mazing"（迷宫化）的机制前提（[Wikipedia: Desktop Tower Defense](https://en.wikipedia.org/wiki/Desktop_Tower_Defense)）。其影响可量化：2007-07 已被游玩 1,570 万次，入选 Webware 100（2007 娱乐类前十），获 2008 年 IGF Gleemie 奖，2012 年入选 Time 的 All-Time 100 游戏，2009-05 推出 NDS 商业版；Preece 与 Scott（Flash Element TD 作者）后来共同创办了 Casual Collective。
- 同期还有 **Vector TD**（2007，David Scott 开发、PCH Games 发行，后在 2010 年移植 PSP/PS3/iPhone）等作品，逐步系统化"塔的类型学"（元素、合成、升级路径）。
- 这一时期的贡献是**数值自觉**：作者们第一次开始用表格与公式调难度，而不是凭感觉。

### 4.4 独立与主机期（2009–2013）

- **Plants vs. Zombies（2009-05-05，PopCap Seattle 开发、PopCap Games 发行）**：五路（后院六路）直线车道 + 阳光经济 + 极高的表演性。它的设计起点很值得记住：**主创 George Fan 受《魔兽争霸 III》塔防 mod 启发，但他认为"敌人从不攻击塔"这件事不直观**，于是让僵尸真的能吃掉植物——塔防的"塔"从此有了被摧毁的戏剧性（[Wikipedia: Plants vs. Zombies](https://en.wikipedia.org/wiki/Plants_vs._Zombies_(video_game))）。商业上它拿下 2010 Golden Joystick 的"Download Game of the Year"与"Strategy Game of the Year"，iOS 版首 9 天售出 30 万份、收入超 100 万美元；PopCap 也因此在 2011 年被 EA 以 7.5 亿美元收购（背景信息）。
- **Sanctum（2011-04-15，Coffee Stain Studios）**：维基把它定义为 **first-person shooter tower defense**——建造阶段在格子上搭 8 种塔，歼灭阶段切到第一人称亲自射击；Metacritic 70/100（混合），2011-08 前售出 18 万份以上（[Wikipedia: Sanctum](https://en.wikipedia.org/wiki/Sanctum_(2011_video_game))）。
- **Orcs Must Die!（2011-10，Robot Entertainment）**：**action-tower-defense**，放弃俯视改第三人称动作视角；陷阱可随时布放与拆除退款、波次间有布防间隙、玩家本人参战且阵亡会扣裂隙点数；获第 15 届 AIAS 的"Strategy/Simulation Game of the Year"（[Wikipedia: Orcs Must Die!](https://en.wikipedia.org/wiki/Orcs_Must_Die!)）。
- **更早的失败尝试**：Iron Grip: Warlord（2008）是第一个把 FPS 与塔防缝合的作品，但没有成功；维基认为是 Sanctum 及其 2013 续作"popularized the first person shooter hybrid"。这条记录说明**缝合的时机与完成度比创意本身更重要**。
- **Kingdom Rush（2011-07-28，Ironhide Game Studio，乌拉圭，2010 年创立；Armor Games 发行）**：以免费 Flash 游戏在 Kongregate 首发，随后移植 iOS（2011-12）、Android（2013-05-17）、桌面（2014-01-06）、Switch（2020）与 Xbox One（2023）。机制上提供了三样后来被广泛抄走的东西：**可自由移动的英雄单位**（用 stars 换永久强化）、**四塔型三次升级后二选一专精**、以及**流星与增援两个手动全局技能**；另有更难的"关卡挑战"驱动重玩（[Wikipedia: Kingdom Rush](https://en.wikipedia.org/wiki/Kingdom_Rush)）。
- **Bloons TD 系列（起点 Bloons Tower Defense，2007-08-16，Ninja Kiwi，免费 Flash）**：以"升级树 + 无尽波"著称；**2009 年因与 Com2uS《Tower Defense: Lost Earth》商标冲突而改名 Bloons TD**（与 4.2 的商标事件同源）；难度模式从 BTD2 起出现，BTD5 有四种、BTD6 每图三种标准难度并加入 CHIMPS 等限制模式；BTD6 于 2018-06-14 移动端首发，每塔最多 5 级、tier-5 变体可合成 Paragon，并引入英雄与 2.5D 视角（[Wikipedia: Bloons TD](https://en.wikipedia.org/wiki/Bloons_TD)、[Bloons TD 6](https://en.wikipedia.org/wiki/Bloons_TD_6)）。

**一处需要保留的口径冲突**：Kingdom Rush 的规模数据在不同维基条目里不一致——其自身条目称下载量超 1 亿，而 tower defense 条目称 App Store 与 Google Play 合计售出约 1,700 万份。两者统计口径不同（下载含免费获取），本文因此**并列呈现而不择一**。

### 4.5 反塔防（2011–2012）

**Anomaly: Warzone Earth（2011-04-08，11 bit studios，Windows/macOS 首发；iOS 2011-08-11、Android 2011-11-29、XBLA 2012-04）** 把镜头翻过来：玩家不摆塔，而是为车队设定街道路线、投掷诱饵与烟雾，攻破由大量防御工事保护的敌方基地（[Wikipedia: Anomaly: Warzone Earth](https://en.wikipedia.org/wiki/Anomaly:_Warzone_Earth)）。媒体给它起的名字有三个：**reverse tower defense / tower attack / tower offense**。它的成绩也不差：iOS 版 Metacritic 94，2011-06 获 Apple Design Award，并成为 Apple 当年"年度游戏"亚军。

它不只是"反过来玩"，而是完成了一次**类型自证**：当一条既定路径上的资源分配被反过来读，玩家立刻理解了塔防的本质。**术语状态需要标注**：reverse tower defense / tower offense 在维基百科上没有独立条目，也没有专门章节，只有 tower defense 条目里一句话级别的定义；因此本文把它们当作**描述性说法**而非严格分类。

### 4.6 移动与服务化（2012–今）

- **保卫萝卜（2012-07 iOS 发行；2013-02-04 经 360 手机助手 Android 发行；凯罗天下，后并入飞鱼科技）**：把塔防做成轻量、可爱、强反馈的移动产品；截至 2015-01 下载量 **2.5 亿**，验证了碎片时间与塔防的适配（[中文维基：保卫萝卜](https://zh.wikipedia.org/wiki/保卫萝卜)）。
- **明日方舟（2019-05-01 中国大陆首发，Hypergryph 开发并自主发行；2020-01-16 由 Yostar 在日韩及全球上线）**：以"地面格/高台格"双位型（近战可阻挡）、**随时间回复的部署点数**、手动开技能、可撤退再部署、以及**暂停与减速下指令**的操作范式，把塔防推向内容驱动型服务游戏（[English Wikipedia: Arknights](https://en.wikipedia.org/wiki/Arknights)、[中文维基：明日方舟](https://zh.wikipedia.org/wiki/明日方舟)）。其关卡设计被中文社区大量拆解（本工作区亦有一份 [参考拆解](../../projects/refu-game-001/docs/design/12_参考_明日方舟设计拆解.md)）。
  **商业数据须标注为二手转述**（均为维基引用第三方，本文未核原始报告）：2021-05 时为全球收入最高的塔防手游；首月流水约 6 亿元人民币；两年全球总收入约 7 亿美元；Sensor Tower 口径称截至 2023-11 全球总收入约 11 亿美元、2024-08 日本累计约 5 亿美元；上线两周下载量 500 万。
- **当代融合**：塔防作为"规则容器"被不断装入新玩法——Roguelike（随机关卡链 + 永久修饰）、自走棋（回合与羁绊）、异步 PvP（对手波次快照）、合作（共享基地）、UGC（编辑器与关卡分发）。

### 4.7 学术线：一个被证明为困难的问题

塔防不只是设计对象，也是**计算对象**。Suttichaya 在 PRICAI 2016  workshops 上给出结果：把"在 n × n 网格上放置 k 座塔以使起点到终点的最短路径最长"这一决策问题证明为 NP-hard（[Desktop tower defense is NP-hard, 2017](https://murex.mahidol.ac.th/en/publications/desktop-tower-defense-is-np-hard/)，DOI: [10.1007/978-3-319-60675-0_2](https://doi.org/10.1007/978-3-319-60675-0_2)）。

这条结果对设计有三点直接含义：

1. **"最优布局"通常不可求**：玩家与 AI 都只能在启发式层面玩，这天然保护了塔防的策略深度；
2. **关卡设计要提供"足够好的解"**：既然最优解不可达，设计者的责任就从"唯一正确答案"转向"多种可行答案"；
3. **难度必须被外部化**：当最优解不可计算时，只能用**可验算的近似指标**（预算、覆盖率、胜率曲线）来度量关卡，而不是靠直觉——这正是第五节的动机。

**近期工作（联网核实）**：

| 方向 | 文献 | 一句话 |
| --- | --- | --- |
| 优化建模 | *Modeling Bloons Tower Defense as a temporal two-dimensional knapsack problem with irregular shapes and side constraints*, ITOR, [DOI](https://doi.org/10.1111/itor.70238) | 把 Bloons TD 建成"时序二维背包"并用整数规划求解（是优化，不是硬度结论） |
| LLM 智能体基准 | Wang 等, *TowerMind: A Tower Defence Game Learning Environment and Benchmark for LLM as Agents*, AAAI-26, [DOI](https://doi.org/10.1609/aaai.v40i31.39818) | 用塔防做智能体基准：像素（512×512×3）／JSON／结构化三种观测，**含战争迷雾**；动作为混合型 `(x, y, c)`；以"合法动作率"作为幻觉指标，并以人类专家为基线（第 5 关所有模型至少低于专家 84%）；源码公开 |
| 强化学习 | Bergdahl, Sestini & Gisslén, *Reinforcement Learning for High-Level Strategic Control in Tower Defense Games*, IEEE CoG 2024, [DOI](https://doi.org/10.1109/CoG60054.2024.10645621) | 对象是**《植物大战僵尸》**（不是通用塔防）：用 PPO 做高层策略选择、脚本启发式 AI 负责执行，**目的是关卡自动化测试与验证**；报告成功率（HRL 57% / 启发式 48% / 随机 39%）、累计奖励与平均步数 |

**一条引文警告**：Ronald de Haan 与 Petra Wolf 的 *Restricted Power – Computational Complexity Results for Strategic Defense Games*（FUN 2018，[DOI](https://doi.org/10.4230/LIPIcs.FUN.2018.17)）常被误引为"塔防的复杂度结果"。它研究的其实是双人策略防御游戏 **Greedy Spiders**：在平面图上判定某方是否有必胜策略为 **PSPACE-完全**，并用元定理推广到一大类 strategic defense games（把任一方策略限制为"开局提交的多项式时间算法"时，限制 Player 1 得 Σ₂ᵖ-硬度、限制 Player 2 得 Π₂ᵖ-硬度）。它与塔防是**同族但不是同一对象**，引用时必须区分。

### 4.8 学术线的其余分支

除复杂度证明外，塔防还出现在三类研究里，值得在此登记（本文不做文献穷举）：

- **AI 与规划**：塔防的"长时程资源分配 + 空间布局"结构，使它成为强化学习与规划算法的小型测试床；相比实时策略，它的动作空间离散、单局时长短，更适合做可复现实验。
- **组合优化**：塔位选择与覆盖最大化可以形式化为集合覆盖/最大覆盖问题的变体，因此近似算法与启发式（贪心、局部搜索）的对照实验在塔防上非常自然。
- **人机交互与难度建模**：动态难度调节（DDA）在塔防里有一个罕见的优势——难度参数（波次预算、敌人组合）是**离散且可解释**的，因此适合研究"玩家是否能感知到被调节"这一经典问题。

## 五、形式分析：把塔防写成可验算的系统

塔防的特殊之处在于，它的核心体验可以被一组公式近似描述。下面以本工作区的《Refu Game 001》为样本（数值与脚本见 [数值/README](../../projects/refu-game-001/docs/design/数值/README.md) 与 [`projects/refu-game-001/tools/sim_refu_game_001.ts`](../../projects/refu-game-001/tools/sim_refu_game_001.ts)），给出一套完整的"可验算"框架。

### 5.1 空间：路径拓扑与"最优格"问题

塔防的空间是**有向图 + 覆盖问题**：

- 路径 `L` 是一条从入口到基地的有向折线（或环）；敌人的通行时间 `T = L ÷ v`（`v` 为移速）决定了每座塔能输出多少次。
- 塔位集合 `S` 是离散候选点；每座塔的有效覆盖是路径的一段弧长，`DPS_effective = f(伤害, 攻速, 穿透/溅射, 覆盖弧长)`。
- 于是"布置"变成：在预算约束下，选择 `k` 个位置与塔型，使**沿路径的累积伤害曲线**尽量均匀地超过敌方的累积生命曲线——注意这不是"单点最强"，而是**沿程分布的最优**。

这正是复杂度结果的来源：若允许玩家用塔改变路径（mazing），"最大化最短路径"的决策问题在广义模型下是 NP-hard（[Suttichaya 2017](https://murex.mahidol.ac.th/en/publications/desktop-tower-defense-is-np-hard/)）。它其实站在三条经典结果的交汇处：

| 经典结果 | 与塔防的关系 |
| --- | --- |
| 集合覆盖/最大覆盖的 NP-hard 性（Karp 1972, [DOI](https://doi.org/10.1007/978-1-4684-2001-2_9)） | "用有限塔位覆盖尽量多路径"就是最大覆盖 |
| 贪心近似及其界（Nemhauser, Wolsey & Fisher 1978, [DOI](https://doi.org/10.1007/BF01588971)） | 给了"启发式布防"一个可证明的近似保证 |
| 网格图中的哈密顿路径（Itai, Papadimitriou & Szwarcfiter 1982, [DOI](https://doi.org/10.1137/0211056)） | mazing 的本质是"用塔改变网格上的通路结构" |

设计含义是：**不要指望玩家求解最优，设计者要提供多个"足够好"的解**。

本作在空间上做的三个离散化决定，都是为了可控性：

| 决定 | 内容 | 效果 |
| --- | --- | --- |
| 固定路径 + 固定塔位 | 不做自由迷宫，塔位由地图卡给定（如峡谷哨站 标准 8 / 支援 3 / 修饰 1） | 空间问题从"连续优化"降为"离散选择"，可读、可平衡 |
| 槽位分型 | 标准/支援/修饰三类槽位，卡只能落在声明过的槽位 | 把"位置"变成接口（[02_卡片规则系统](../../projects/refu-game-001/docs/design/02_卡片规则系统.md)） |
| 地形加成 | 高台射程 +15%、沼泽移速 −20%、合流点受伤 +10%、腐蚀地每秒伤害 | 让"选位"仍保留空间策略，而不是纯数值堆叠 |

### 5.2 时间：波次与节奏函数

一个波次可以写成四元组：`W = (构成, 数量, 间隔, 威胁值)`，波次预算 `B = Σ(数量 × 威胁值)`。于是整局的敌方压力是一条序列 `B_1 … B_n`。

- **节奏**：`B` 的序列形状决定曲线。单调递增会疲劳，因此需要**呼吸波**（低强度缓冲）与**峰谷交替**。
- **预告**：预告把不确定性从"未知"变成"可规划"，预告精度是难度的隐性旋钮。
- **BOSS 的阶段技**：把"一条曲线"变成"两段曲线"。本作第八节点 BOSS 在 50% 血量变招（两路同时加速），这一设计的作用不是加数值，而是**打破玩家前 50% 形成的稳定解**。

### 5.3 资源：能量经济的正反馈与雪球

能量是塔防的现金流。本作的口径是：起始 10，自然增长 +1/s，击杀返还按原型分级（小兵/快速/空中 +1，装甲 +2，精英 +3，BOSS +10），波间奖励 +5，上限 99。

经济设计有三条经验规律：

1. **返还系数决定"清怪"是否划算**：清得越干净，收入越高，形成正向循环；把控不好会雪球（越强越富）。
2. **波间结算是唯一的"存钱窗口"**：它把"何时爆发"变成可规划的决策。
3. **上限（99）是给规则卡留的接口**：挑战卡「断供」（自然增长 −20%）与「封锁」（禁用技能卡）都作用在这条线上。

### 5.4 随机与信息：可复现的不确定性

塔防最适合的随机性不是"战斗随机"，而是**结构随机**：随机的关卡链、随机的敌人组合、随机的增益三选一。原因是战斗随机（暴击、闪避）会污染"计划—验证"的闭环，而结构随机只改变题目、不改变判卷方式。

本作在远征里的做法值得抄录：每日一枚**种子**，同种子同结果，玩家的操作不影响抽取序列。这样既保留了"今天的局不一样"的新鲜感，又让排行榜与复盘有意义（[26_远征_种子与排行榜验收](../../projects/refu-game-001/docs/design/26_远征_种子与排行榜验收.md)）。

### 5.5 难度：从"感觉"到公式

这是本文最想强调的一节。难度在多数团队里是形容词（"这关有点难"），但塔防可以把它写成名词：

```
B   = Σ(敌人数量 × 威胁值)              敌方压力
P   = 塔位数 × 卡组平均有效 DPS × 覆盖系数   我方战力（相对值，基准 P_ref = 1.0）
D   = (B ÷ B_ref) × (P_ref ÷ P)         难度比（B_ref = 158）
λ   = λ0 · D^γ                          漏怪强度（λ0 = 1.35，γ = 3）
P(胜) ≈ 1 ÷ (1 + e^{k(D − D50)})        胜率函数（D50 = 1.25，k = 7）
胜   ⇔  整局漏怪总数 < cap               胜负判据（cap = 3）
```

这套模型的工程价值在于**可反解**：给定目标胜率，可以算出需要的 `B`；给定 `B` 与 `P`，可以算出 `D`；给定 `D`，可以预测漏怪分布。于是"平衡"从口味问题变成约束满足问题。

本作据此得到两条被实测验证的曲线：

| 主线五章 | 平均 D | 实测胜率 | 目标带 |
| --- | --- | --- | --- |
| 第 1 章 | 0.81 | 94.9% | 80–100% |
| 第 2 章 | 1.07 | 76.0% | 65–80% |
| 第 3 章 | 1.16 | 64.4% | 55–70% |
| 第 4 章 | 1.20 | 58.8% | 45–60% |
| 第 5 章 | 1.30 | 43.6% | 40–55% |

| 远征八节点 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 预算 B | 171 | 188 | 205 | 222 | 239 | 256 | 273 | 290 |
| 难度比 D | 1.00 | 1.10 | 1.20 | 1.30 | 1.40 | 1.50 | 1.60 | 1.70 |
| 胜率（设计表，[23 号文档](../../projects/refu-game-001/docs/design/23_规则卡组_Roguelike远征.md)） | 84.4% | 72.1% | 59.2% | 43.5% | 28.0% | 16.9% | 8.6% | 3.6% |
| 胜率（当前脚本 `--verify-rogue --n 20000`） | 84.5% | 72.7% | 58.6% | 42.8% | 28.0% | 17.2% | 8.8% | 3.8% |

> **两行差异说明**：两套数字均 PASS 目标带，逐点相差 ≤0.6pp，来源是随机种子与样本量（文档表为设计记录，脚本行为当前复现结果）。本卷与 [数值卷](数值卷/README.md) 统一采用"并列呈现"：引用设计目标时用上表，引用复现结果时用下表，并在方法文档里注明口径。

两条曲线的形状说明了一件事：**塔防的难度可以像音乐一样被谱写**——主线是"教学式渐强"，远征是"断崖式收缩"（第 8 节点 3.6% 的通关率是被设计出来的，不是失手）。

### 5.6 平衡的四种口径与验收

单一指标必然被钻空子。可工程化的平衡至少需要四种口径：

| 口径 | 问题 | 本作判据（示例） |
| --- | --- | --- |
| **平均** | 对普通卡组是否公平 | 永久修饰平均增益 7.0–10.1pp，允许带 6–12pp |
| **流派** | 对专属卡组是否过强 | 契合流派增益 11.6–16.9pp，上限 20pp |
| **极差** | 三族之间是否均衡 | 对空矩阵三档极差 1.0 / 9.7 / 8.4pp（判据 ≤15pp） |
| **上限** | 单卡能否杀死一套牌 | 族专属挑战卡对纯流派跌幅 ≤35pp（实测最高 31.8pp） |

四种口径被写进自动校验（`--verify-bands / --verify-rogue / --verify-faction / --verify-air-matrix / --verify-air-mix / --verify-pmod` 等九项），并在每次提交时运行。这是本文主张的"可验算设计"的落地形态：**把设计意图写成断言，让 CI 替你记住它**。

### 6.3 组合原则：为什么"少即是多"

塔防的自由度很容易过度供给，导致两个后果：**认知过载**与**唯一解**。四条组合原则可以当作刹车：

1. **单一职责**：一张卡/一座塔只做一件事，强度靠组合而非单卡全能；
2. **显式接口**：一切交互经过槽位、标签、事件钩子，杜绝隐形依赖；
3. **可无痛移除（remove-safe）**：删掉任意卡或玩法包，其余内容仍能自洽运行；
4. **可读性优先**：任何在 4.7 英寸屏幕上读不清的设计都是负债。

这四条来自软件工程的内聚/耦合语言，本作把它写成了卡片契约（[02_卡片规则系统](../../projects/refu-game-001/docs/design/02_卡片规则系统.md)）。塔防之所以适合这套语言，是因为它本来就是"接口游戏"：路径是接口、塔位是接口、波次也是接口。

### 6.4 五种塔防亚型及其代价

把设计空间里的极端取值固定下来，就得到五种稳定亚型。每种亚型都有明确的收益与代价，选择亚型等于选择要付哪一笔账。

| 亚型 | 核心改动 | 收益 | 代价 |
| --- | --- | --- | --- |
| **迷宫型** | 允许改造路径（mazing） | 空间深度最大，"最优解不可求"带来的重复可玩性 | 新手门槛高、路径可读性差、易出现单一迷宫范式 |
| **英雄型** | 加入可移动/可养成单位 | 情感投射强、演出资源集中、便于做角色经济 | 容易压过塔的作用，把类型推向动作游戏 |
| **卡牌型** | 塔与增益卡化、抽卡与卡组构成 | 收集与构筑驱动力强、内容复用率高 | 数值与商业化最易越界（见 10.4），局内可读性下降 |
| **塔攻型** | 玩家为攻方，反向读同一条路径 | 类型自证式的创新、节奏更快 | 与动作/潜行类型竞争，塔防爱好者未必买账 |
| **无尽型** | 波次无限、难度渐进 | 深度数值玩家的乐园、天然长线 | 数值膨胀几乎不可避免（见 10.2），新手无从下手 |

一个务实的判断是：**亚型不是身份，而是权重**。成熟作品往往以某一种为主，辅以其他亚型的局部机制——例如本作用"卡牌型"作骨架（全要素卡化），但明确保留"英雄型"的禁入（不引入可自由移动单位）与"迷宫型"的禁入（固定路径 + 固定塔位，D2），以确保可读性与可验算性。

## 七、心理与体验：为什么"守着看"会上瘾

### 7.1 计划—学习循环

塔防的乐趣核心不是"操作爽"，而是**预演—落子—观察—修正**的学习循环：

1. 玩家根据预告在脑内模拟（"这一波空袭，我的对空够不够"）；
2. 落子（有限资源下的取舍）；
3. 观察结果（漏了几只、哪段火力不足）；
4. 修正（换装、补位、改节奏）。

这个循环与 Csikszentmihalyi 的 [Flow 理论](https://en.wikipedia.org/wiki/Flow_(psychology))（1990）高度契合：难度略高于技能时进入心流区，而塔防恰好能用 `D` 这个旋钮把难度精确地压在"略高"上。它也解释了为什么"漏 1 只"比"被击败"更有教育意义——**失败的信息量被控制了**。

### 7.2 从机制到体验：MDA 视角

用 Hunicke、LeBlanc 与 Zubek 的 [MDA 框架](https://en.wikipedia.org/wiki/MDA_framework)（2004）看塔防：

- **机制（Mechanics）**：路径、塔位、波次、资源、漏怪；
- **动态（Dynamics）**：火力覆盖的边际递减、"补位"的时机权衡、经济的雪球与断供；
- **美学（Aesthetics）**：挑战、发现（"原来这个位能覆盖两段路"）、表达（卡组即风格）、掌控感。

塔防的美学层有个常被忽略的成分：**"秩序感"**。把一条混乱的进攻线变成一条被管理的通道，本质上是**工程审美的满足**——这与模拟经营、解谜共享心理学根基。

### 7.3 损失厌恶与"漏怪"的情感设计

行为经济学中的**损失厌恶**（Kahneman & Tversky, 1979）在塔防里被制度化了：基地生命与漏怪计数把"未阻止"变成可计数的损失。相比"血条缓慢下降"，"漏 1 只"提供的是一次**离散的、可归因的失败**——玩家清楚地知道是哪一段、哪一波、哪张卡没到位。这种可归因性，是塔防最被低估的情感设计。

### 7.4 不确定性与"可读的随机"

Costikyan 在《不确定性的游戏》（2013）里指出，不确定性是游戏趣味的核心来源之一。塔防的最优解不是战斗随机，而是**结构随机**：随机的关卡链、随机的增益三选一、随机的敌人组合。原因在于塔防玩家的核心快感是"我算对了"，战斗随机会让这个判断无法成立，而结构随机只更换题目。

### 7.5 重复、仪式与"看塔开火"

塔防有一段"什么都不用做"的时间——敌人走在路上，塔在自动交战。许多设计者想删掉它，但它其实是塔防的**仪式性享受**：看着自己搭的系统运转（"engineering porn"）。Sanctum、Orcs Must Die! 用参战替代了这段等待，而纯塔防把它保留为奖励。这一段的存在也解释了塔防与放置/自动战斗的天然亲缘：它们共享"看系统工作"的满足。

### 7.6 从心理到伦理：难度鄙视链与付费降压

当难度被设计成可售卖的"降压阀"（花钱变简单），损失厌恶就会从乐趣变成压力来源。塔防尤其危险，因为它的难度感来自系统性累积，玩家很容易把失败归因为"卡不够"。这也是本文在第八、十节反复回到的话题：**塔防的商业化必须绕开难度本身**。

### 7.7 失败学：塔防如何把失败设计成教材

塔防的失败几乎总是"可归因"的，这是它最值得学习的地方。一次好的失败应当同时满足三件事：

1. **可归因**：玩家能指出是哪一段路径、哪一波、哪张卡出的问题（本作把这一点做成"漏怪计数 + 波次预告 + 结算三项指标"）；
2. **可学习**：失败暗示一个具体的改法（补位、换装、改节奏），而不是"再刷点资源"；
3. **可复现**：同样条件下重打，玩家的改进应当带来可见的差异（因此战斗随机被压到最低）。

与之相对的是**三种坏失败**：不可归因（"不知道怎么就没守住"）、不可改进（数值墙）、不可复现（随机性吞噬复盘）。凡是让玩家感到"这一局本来就不可能赢"的设计，都在消耗塔防最珍贵的资产——**玩家对自己判断力的信任**。

## 八、经济与产业：从 Flash 页游到服务型手游

### 8.1 平台迁移与操作简化

塔防的每一次平台迁移都伴随一次操作简化：鼠标（Flash 页游）→ 手柄（主机 TD）→ 触屏（移动）→ 长按/拖拽（手机卡牌塔防）。这与它的"低操作、高结构"属性天然契合：**塔防是少数在触屏上不需要妥协的策略类型**。本作把这一点写进了界面契约：竖屏、战场 60% / 卡牌 40%、触控目标 ≥9mm、手势只用拖拽/长按/双击/上滑（[07_移动端与界面](../../projects/refu-game-001/docs/design/07_移动端与界面.md)）。

### 8.2 变现结构：四种模式与其红线

| 模式 | 代表 | 对设计的影响 | 风险 |
| --- | --- | --- | --- |
| 买断/一次性 | 独立塔防（Sanctum、Kingdom Rush 早期） | 难度可保持纯粹 | 内容消耗快，续作压力大 |
| 内购去广告/便利 | 休闲塔防 | 轻度干扰 | 便利与作弊的界线模糊 |
| 抽卡/养成 | 服务型塔防（明日方舟式） | 元进程成为主要内容 | **数值与难度合谋**：付费即降压 |
| 通行证/赛季外观 | 现代服务化的折中 | 保留难度纯粹性 | 需要稳定的内容产能 |

本作的决策是"外观 + 便利付费，不卖数值"（D6），并把难度修饰做成**挑战卡**（自选难度与额外奖励，D9），把终身成长放到**远征点**上（只能换外观与机制变体）。这是一条"心理上允许、数值上无害"的中间路线。

### 8.3 内容生产：编辑器、UGC 与赛季

塔防的内容成本主要在**关卡**。三条降本路径：

1. **关卡即卡组装**：地图卡 + 波次卡 + 事件卡 + 规则卡 四件套拼关（本作 [18_样例_关卡组装示例](../../projects/refu-game-001/docs/design/18_样例_关卡组装示例.md)）；
2. **编辑器与 UGC**：先内测服务内部产能，验证审核成本后再开放玩家分发（D10）；
3. **赛季与难度卡带**：用"每赛季轮换的挑战卡池 + 排行榜"复用既有地图（本作以族专属挑战卡池与每日种子实现）。

### 8.4 留存节奏：碎片关 + 周常长局

塔防的会话结构极其适合"双轨"：日常 3–5 分钟碎片关（本作 6–8 波），周常长局（12–14 波 + 特殊规则卡）。前者给每日习惯，后者给深度与社群话题。远征模式（每日一枚种子的 8 节点链）则是第三种：**把"重复"包装成"每天的新题目"**。

### 8.5 关卡经济：塔防内容的成本结构

塔防的内容消耗速度主要取决于**关卡复用率**。把一关拆成四件套（地图卡 + 波次卡组 + 事件卡组 + 规则卡），复用的可能性就变成乘法：6 张地图 × 3 套波次 × N 组事件 × M 张规则卡。

本作的复用矩阵给出了一个具体量级：六张地图各配三套波次卡组（普通/精英/周常），即 18 套基础关卡组合；再叠加事件卡组与规则卡（含远征规则卡组），可以低成本产出大量"看起来新的"关卡（[19_地图卡表](../../projects/refu-game-001/docs/design/19_地图卡表.md)）。

对应的三条成本纪律：

- **地图尽量少而深**：新地图的生产成本远高于新波次，因此地图要有明确的"性格"（单线/双线/环形）以承载不同玩法；
- **难度用参数而非新内容解决**：目标胜率带由 `B/D` 调节，不需要每次都做新敌人；
- **编辑器优先服务内部产能**：先让关卡设计者用同一套卡片拼关，再考虑开放 UGC（D10 的顺序）。

## 九、美学与文化：塔防的看与被看

### 9.1 视觉语法：路径作为"被阅读的空间"

塔防是少见的**以"看"为主要动作**的策略游戏。它的画面必须在同一屏内同时说清四件事：

1. **敌人往哪走**（路径与入口）；
2. **我能放哪**（塔位与地形）；
3. **我放了什么**（塔的类型与状态）；
4. **现在几比几**（生命、漏怪、能量、波次）。

因此塔防形成了独特的视觉语法：**俯视或等距视角**（保证路径可读）、**色带分层**（我方高明度 / 敌方低明度）、**信息压在不透明底片上**（数字永远比特效亮）。本作把这条写成红线："数值与状态信息永远压在视觉特效之上"，并在两套美术方案里都用它约束了特效强度（[美术设定001](../../projects/refu-game-001/docs/design/美术/美术设定001/README.md)、[美术设定002](../../projects/refu-game-001/docs/design/美术/美术设定002/README.md)）。

### 9.2 复古未来与千禧美学：一种天然的亲和

塔防的界面本身就是"过去想象的未来"：雷达屏、CRT 绿字、沙盘推演、剖面图。它与本工作区收集的两条美学线索高度契合：

- **复古未来**（[主卷](../retro-futurism/README.md)）：沙尘、纸图、黄铜、磁带——把高技术塞进旧机器。塔防的"指挥台"视角天然属于这一类。
- **千禧美学 / Y2K**（[附录卷](../retro-futurism/附录_千禧美学卷/README.md)）：透明塑料、水光、镭射箔、bling——未来刚刚拆封。把它用在塔防上，会得到"能看穿内部结构的透明工事"（[美术设定002](../../projects/refu-game-001/docs/design/美术/美术设定002/README.md)）。

这解释了为什么塔防的"美术换皮"极其有效：它的核心是抽象系统，**美学是它的可换外壳**，而系统不变。这一点也带来风险——见第十节"视觉噪声压倒信息"。关于两套美学取向在塔防里的具体落点、读图效率与代表作视觉谱系，见[美学卷](美学卷/README.md)。

### 9.3 军事—工程想象与"防御"的政治

塔防的题材几乎天生带着军事与工程色彩：防空（Missile Command）、要塞（Rampart）、阵地（大量二战/科幻塔防）。它的政治性藏在**"我们在保卫什么"的空白**里：多数塔防不告诉你基地是什么，只告诉你它不能被攻破。

这个空白是双面的：一方面它让塔防成为最容易被不同文化填充的类型（可爱化、科幻化、神话化）；另一方面它也可能滑向"纯技术中立"的自我麻醉。作为批评，值得追问的是：**防御的叙事是否只能是被动挨打？** 反塔防（Anomaly）与"进攻型塔防"（玩家推塔）正是对这个问题的回答。

### 9.4 在地化：三种塔防气质

| 线路 | 特征 | 代表 |
| --- | --- | --- |
| 中式 | 系统化与内容化：强养成、强演出、关卡即内容包，审美上常与科幻/都市结合 | 保卫萝卜、明日方舟 |
| 日式 | 机制精致与角色化：塔即角色，演出与语音密集 | 大量手游塔防、主机 TD |
| 欧美独立 | 机制优先：迷宫化、元素合成、无尽数值、编辑器生态 | Desktop Tower Defense、Element TD、Bloons TD |

三者并非互斥，而是**同一条设计空间里的不同权重**：中式押"内容与元进程"，日式押"角色与表演"，欧美押"系统与工具"。

### 9.6 一个区域案例：中文塔防的四级跳

中文市场的塔防演化可以粗略分成四级，每一级都对应一次"塔防 + 什么"的回答（年份为公开资料的常见说法，此处为概述而非考据）：

1. **页游与 Flash 期**：塔防作为休闲页游的一种，玩法基本沿袭海外模板，靠关卡数量与轻量社交留住玩家；
2. **移动休闲期（2010 年代前期）**：以《保卫萝卜》为代表的可爱化、强反馈、单机式关卡推进，把塔防推向大众；
3. **内容驱动期（2019 前后起）**：以《明日方舟》为代表，把塔防与角色养成、剧情演出、关卡机制复合，形成"高台/地面"双位型与暂停布防的操作范式；塔防第一次成为长线服务型产品的骨架；
4. **平台下沉期（近年）**：微信小游戏与短视频平台上的轻量塔防，把单局压到 1–3 分钟，靠广告与内购变现，设计重心回到"前 30 秒的爽感"。

这四级跳揭示了一条规律：**塔防的可塑性来自它的抽象骨架，而每次成功的地方化，都是在骨架上绑定了一种新的"外附价值"**——可爱、角色、叙事、社交或时间碎片。

### 9.5 可观赏性：塔防是一种"看得懂的算法"

塔防的另一个文化属性是**可观赏**：它的过程可以被旁观者理解（"他在补空袭的洞"），因此天然适配直播与短视频。这既是机会（传播成本低），也是设计约束（画面必须一眼懂）；如果一局塔防的精彩时刻无法被 15 秒讲清，传播就会失效。

## 十、批评：坏塔防的六种症状

批评比赞美更有用。以下六种"症状"都能在真实作品里找到实例，本文给每种症状附上**诊断指标**与**处方**。

### 10.1 伪选择：最优解把选择变成搜索

**症状**：关卡存在唯一（或少数）最优布局，玩家的实际行为是"抄作业"。

**诊断**：如果一关的可通关卡组方差极小（例如 90% 的玩家用同一套），说明选择空间是假的。可用指标：**卡组多样性**（前 3 套卡组的通关占比）。

**处方**：引入多条可行路径（不同标签的羁绊都能过）、在地图上制造"局部最优互相冲突"（覆盖长路径 vs 覆盖合流点）、用随机性（结构随机）阻止单一最优解被记忆。

### 10.2 数值膨胀

**症状**：为了让老内容继续有挑战，敌人的生命与数量不断上涨；新塔的数值必须更高。

**诊断**：看**威胁值是否通胀**。本作对此的立场是明确的：威胁值不随章节通胀，只调数量与组合（[数值/04](../../projects/refu-game-001/docs/design/数值/04_敌人数值与波次威胁值.md)）；难度靠预算 `B`、我方战力 `P` 与机制，而不是靠新塔吊打旧塔。

**处方**：把成长放到"机制变体"（进化枝、模块换装、羁绊）而不是纯数值；用 `D` 而非等级来控制难度。

### 10.3 挂机化：介入权被抽走

**症状**：布防结束后玩家无事可做，胜负在开局 30 秒就已决定。

**诊断**：统计"本局的有效决策数"（玩家在交战中的操作改变了结果的数量）。若接近 0，就是挂机化。

**处方**：保留要件七（介入权）——技能卡、局内换装、暂停布防、阶段技应对；或干脆诚实地把它做成放置游戏，别假装是策略游戏。

### 10.4 难度与抽卡的合谋

**症状**：关卡的难度曲线与卡池强度绑定，"打不过就抽卡"成为主要解法。

**诊断**：计算**付费强度与通关率的相关性**。若强相关，难度设计就已经被商业目标接管。

**处方**：把付费限制在外观与便利（D6）；让难度修饰由玩家**自选**（挑战卡 D9）；让成长资源只能换外观与机制变体（远征点）。

### 10.5 内容的劳动化

**症状**：日常任务、体力惩罚、重复刷本把游戏变成日程表。

**诊断**：看"无趣操作占比"——玩家为了奖励而做、但无法从中学到新东西的时间比例。

**处方**：把重复包装成"每日新题目"（种子、轮换词缀）；用周常长局承载深度；不做体力惩罚（本作 D5 的会话节奏设计）。

### 10.6 视觉噪声压倒信息

**症状**：特效、粒子、光晕遮住了数值与状态，玩家读不清战场。

**诊断**：在最小目标机型与最坏光照下截图，检查四项关键信息（能量、生命、漏怪、卡面数字）是否 1 秒内可读。

**处方**：写进美术红线（本作两套美术方案都写了）；透明与发光必须"让机制更清楚"，否则砍掉。

## 十一、融合与未来：塔防作为"规则容器"

### 11.1 接口条件：什么样的塔防能被反复装入新玩法

塔防要成为"容器"，必须满足三条（本作把它写成扩展性验收）：

1. **不改动既有卡的规则层字段**：新玩法只能用新增规则卡与内容卡表达；
2. **新玩法可由 1–3 张规则卡 + N 张内容卡完整表达**；
3. **移除该玩法包后，其余模式与存档不受影响**（remove-safe）。

这三条的实质是：**把玩法做成插件，而不是把引擎改成"什么都做一点"**。塔防之所以特别适合，是因为它的要素本来就是接口（路径、槽位、波次、资源）。

### 11.2 五类已成熟的融合接口

| 融合包 | 规则卡要点 | 复用的既有卡 | 对塔防的改变 |
| --- | --- | --- | --- |
| Roguelike 远征 | 关卡链、每关三选一永久修饰、失败即结束 | 塔卡、修饰卡、地图卡 | 把"选关"变成"被关选"，难度靠 `D` 抬升 |
| 自走棋式回合 | 回合购买、羁绊凑数、自动交战 | 单位卡、羁绊系统 | 把"布置"变成"构筑" |
| 异步 PvP | 对手波次卡组快照、公平模式 | 波次卡、规则卡 | 塔防的"题目"变成另一个人写的 |
| 双人合作 | 共享基地、分工卡池 | 支援卡、事件卡 | 从族的"支援位"扩展到两名玩家 |
| 潜行/护送 | 目标卡、视野与警戒、限时 | 事件卡、地图卡 | 塔防的"守"变成"带" |

### 11.3 AI 与生成：三个真实可用的方向

1. **关卡生成**：用 `B/D` 与覆盖率作为适应度函数，自动生成"落在目标胜率带内"的关卡草稿，再由人做手感打磨；
2. **难度自适应**：以目标胜率带（例如 45–60%）为控制目标，动态调整波次预算 `B`；但要谨慎——玩家会感知到"被放水"，因此更适合做"补丁式"微调而非实时控制；
3. **AI 对手／伙伴**：由于最优布局不可求（NP-hard），AI 的合理目标是"人类风格的可行解"而不是最优解；这类 AI 反而更容易做出可读的博弈。
4. **AI 做关卡测试**：这是目前最有落地价值的一条。Bergdahl 等在 2024 年的工作就是用它给《植物大战僵尸》做**自动化关卡验证**（强化学习选策略、脚本 AI 执行），把"这关能不能过、大概多难"从人工试玩变成可批量跑的实验。对本作这类"关卡即卡组装"的塔防来说，这条路径几乎是把[数值卷](数值卷/README.md)的验收再往前推一步：**先跑机器，再叫人试**。展开见 [AI 卷](AI卷/README.md)。

### 11.4 学术机会

塔防留给研究的空间至少有三块（展开见[AI 卷](AI卷/README.md)：为什么适合做基准、复杂度边界、LLM/RL 进展、可解释难度与实验协议）：**组合优化**（布局与覆盖的近似算法）、**学习基准**（作为长时程规划与资源管理的小型测试床）、**难度模型的可解释性**（把"胜率"分解成"预算—战力—机制"三项可解释因子）。本文第五节的模型可以视为一个可被复现的起点。

### 11.5 风险清单

融合不是免费的：动态难度会稀释"我变强了"的成就感；UGC 会带来质量与审核成本；异步 PvP 会让"难度"从设计者手里转到玩家手里（本作因此在 v0.1 禁用挑战卡于远征，避免两套难度系统互相污染）。**每一次融合，都要回到七个要件上问一句：我们还在做塔防，还是已经换了一个类型？**

### 11.6 塔防的另一条外延：作为教学与建模工具

塔防的低操作门槛与高结构透明，使它在游戏之外也有用途：

- **编程与算法教学**：路径搜索、覆盖优化、状态机与波次生成，都可以在塔防的语境里讲；学生能立刻看到代码变化对"能不能守住"的影响；
- **运筹与系统思维**：资源分配、瓶颈识别、边际收益递减——塔防把这些概念压缩进 5 分钟；
- **AI 课程实验**：由于动作空间离散、单局短、结果可复现，塔防适合做搜索与强化学习的入门实验；
- **难度建模研究**：第五节的模型是一个可复现的起点，适合用来讨论"可解释的难度"。

这条外延反过来也解释了塔防为什么长寿：**它是一个可以承载别的东西的形状**。

## 十二、结论

如果把本文压缩成四句话：

1. **塔防是一种"低操作、高结构"的策略类型**，它的内涵由七个要件构成，其中"路径给定"与"交战中介入权"最关键；它的外延比通常以为的更宽，但边界可以用矩阵而不是争论来标记。
2. **塔防是少数可以被形式化的娱乐产品之一**：预算 `B`、战力 `P`、难度比 `D`、泊松漏怪与胜率函数把"难度"从形容词变成名词，本工作区的样本给出了 94.9%→43.6% 与 84.4%→3.6% 两条可复现曲线。
3. **它的乐趣来自学习的闭环与秩序的满足**：计划—观察—修正、损失厌恶与可归因的失败、结构随机而非战斗随机；它的危险来自伪选择、数值膨胀、挂机化、难度与抽卡的合谋、内容的劳动化，以及把信息埋进特效。
4. **它的未来在"容器化"**：当玩法被写成规则卡，塔防就成了可以反复装入新模式的骨架——但每次装入都要重新回答"我们还在做塔防吗"。

塔防的朴素外观掩盖了它的理论丰度：它同时是一个复杂度问题、一个经济学问题、一个心理学问题，也是一个美学问题。它值得的不只是关卡表，而是一份像本文这样的说明书。

| 术语 | 定义 |
| --- | --- |
| 塔防（Tower Defense） | 在既定路径上用有限资源布置防守单位、以波次为单位承受进攻的类型 |
| 塔攻／反塔防（reverse TD） | 玩家扮演进攻方穿过敌方塔阵的变体 |
| 路径（Path） | 敌人从入口到基地的既定路线 |
| 塔位（Slot） | 允许放置塔卡/支援卡/修饰卡的离散位置 |
| 波次（Wave） | 一次成组的敌人进攻，含构成、数量与间隔 |
| 威胁值（Threat） | 敌人相对压力的权重（本作以小兵 = 2 为基准） |
| 波次预算（B） | `Σ(数量 × 威胁值)`，衡量单波敌方压力 |
| 我方战力（P） | `塔位数 × 卡组平均有效 DPS × 覆盖系数` 的相对值（基准 1.0） |
| 难度比（D） | `(B ÷ B_ref) × (P_ref ÷ P)`，1.0 为基准，1.3 以上为挑战 |
| 漏怪（Leak） | 敌人抵达基地；累计超过上限即失败（本作 cap = 3） |
| 呼吸波 | 高强度波之间插入的低强度缓冲波 |
| 迷宫化（mazing） | 玩家用塔改变敌人路径以延长通行时间 |
| 羁绊 | 同标签卡达到阈值触发的套装效果 |
| 进化枝 | 涌潮虫系机制：单位卡满足条件后替换为高阶变体 |
| 模块换装 | 铁砧机制：局内替换修饰卡以改变同一座塔的职能 |
| 共鸣 | 星辉机制：相邻塔位形成共鸣区并共享增益 |
| 挑战卡 | 局前自选的难度修饰卡，附带额外奖励 |
| 永久修饰（PMOD） | 远征中每节点三选一、本局有效的强化卡 |
| 种子（Seed） | 远征每日抽取序列的编号，同种子同结果 |

## 附录 D · 塔防设计检查清单（20 条）

**定义与骨架**

1. 七个要件里，明确写清哪些是硬约束（本作：路径固定、塔位离散、波次、介入权），哪些允许变体；
2. 地图不超过 6–8 张，每张有明确性格（单线/双线/环形/可破坏）；
3. 塔位分型不超过 4 类，且每类有排他用途（否则玩家会问"为什么不能都放标准位"）。

**难度**

4. 敌方压力写成 `B`，我方写成 `P`，难度写成 `D`，不要用"等级"；
5. 定义目标胜率带，并让每一章/节点都落在带内（本作五章 94.9%→43.6%）；
6. 威胁值不通胀：新章节只调数量与组合；
7. 失败判据离散化（漏怪计数），并允许少量失误；
8. 至少两条难度曲线：教学式渐强（主线）与断崖式收缩（终局内容）。

**空间与经济**

9. 每张地图的"关键格"（覆盖两段路、合流点、高台）不超过 3 个，保证决策聚焦；
10. 能量曲线写清来源（自然增长/击杀返还/波间）与去向（塔/技能/修饰）；
11. 至少一条"回流"设计（拆除返还、护盾击破返还），避免一锤子买卖；
12. 上限类参数（能量上限、卡组上限、难度分上限）用于给规则卡留接口。

**可读性与美术**

13. 四项关键信息 1 秒可读：能量、基地生命、漏怪、卡面数字；
14. 我方高明度、敌方低明度分带，色弱下靠形状冗余；
15. 透明/发光必须"让机制更清楚"，否则砍掉；
16. 最小可点击目标 ≥ 9mm，手势不超过四类。

**平衡与验收**

17. 平衡至少四口径：平均、流派、极差、上限；
18. 把设计意图写成断言，纳入 CI（本作九项校验）；
19. 每一种玩法融合都满足：不改旧卡字段、1–3 张规则卡可表达、移除后 remove-safe；
20. 商业化绕开难度：付费只买外观与便利，成长资源只换变体不换数值。
