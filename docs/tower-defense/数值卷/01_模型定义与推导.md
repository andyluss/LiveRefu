# 01 · 模型定义与推导

> 卡面：用途＝塔防难度模型的形式定义、推导与验证｜ 依赖：[论文第五节](../00_塔防游戏研究_内涵与外延.md) ｜ 实现：[`tools/sim_refu_game_001.ts`](../../../tools/sim_refu_game_001.ts) ｜ 状态：v0.2 · 2026-09-15

## 一、五个符号

| 符号 | 名称 | 定义 | 本作取值 |
| --- | --- | --- | --- |
| `B` | 波次预算 | `Σ(敌人数量 × 威胁值)` | 逐波计算 |
| `B_ref` | 基准预算 | 一关的"标准压力" | **158** |
| `P` | 我方战力 | `塔位数 × 卡组平均有效 DPS × 覆盖系数`（相对值） | 基准卡组 **1.0** |
| `D` | 难度比 | `(B ÷ B_ref) × (P_ref ÷ P)` | 主线 0.81–1.30；远征 1.00–1.70 |
| `λ` | 漏怪强度 | `λ0 · D^γ`（整局漏怪数的期望） | `λ0 = 1.35`，`γ = 3` |

**威胁值**是整条链的起点：它是"敌人相对压力"的权重，本作以小兵 = 2 为基准（[数值/04](../../refu-game-001/数值/04_敌人数值与波次威胁值.md)）。有了威胁值，`B` 才能把"六只装甲 + 四只空中"折算成一个可比较的数。

## 二、为什么 `D` 要写成乘积

`D = (B ÷ B_ref) × (P_ref ÷ P)` 的形式有两个好处：

1. **可比**：任何关卡只要给出 `B` 与卡组 `P`，就能与基准关比较，不需要知道关卡长什么样；
2. **可反解**：给定目标 `D`，可以反推需要的 `B` 或允许的 `P`。

注意 `P` 在分母：**同一关，卡组越强，难度越低**。这一点看似显然，但很多团队的"难度"定义里没有 `P`，于是"关卡难度"与"玩家强度"永远纠缠不清。

## 三、为什么会漏怪服从泊松

把每一波看作一次"压力事件"，漏怪数量取决于两件事的差值：敌方瞬时强度与我方瞬时输出。由于：

- 敌人的进入时刻在波内近似均匀（本作波次卡给的是数量与间隔，不指定精确相位）；
- 每次"漏"是小概率独立事件（某只怪在某个窗口没被打死）；
- 窗口数量足够多（一局 6–8 波、每波数十次判定机会）；

于是整局漏怪数 `X` 近似服从泊松分布，`P(X = k) = e^{−λ} λ^k / k!`。

**λ 为什么是 `D^γ` 而不是线性**：难度对漏怪的影响是超线性的。`D` 从 1.0 升到 1.7（+70%），漏怪期望从 1.35 升到 `1.35 × 1.7³ ≈ 6.6`（约 5 倍）。这条幂律解释了塔防的一个普遍现象——**难度"最后一段"最难设计**：在 `γ = 3` 下，最后 0.1 的 `D` 增量造成的漏怪增加，比前面 0.3 还多。

## 四、胜率函数与胜负判据

胜负判据：**整局漏怪总数 `< cap`** 即胜（本作 `cap = 3`）。于是

```
P(胜) = P(X < cap) = Σ_{k=0}^{cap−1} e^{−λ} λ^k ÷ k!
```

这条精确式（泊松累积）与工程上常用的 logistic 近似

```
P(胜) ≈ 1 ÷ (1 + e^{k(D − D50)})，  D50 = 1.25，k = 7
```

在参数区间内高度一致，logistic 的好处是可以直接反解 `D50`（五五开难度）。

**两种口径的对照**（本作实测，主线与远征）：

| 关卡 | D | 泊松/logistic 模型 | 蒙特卡洛实测 | 偏差 |
| --- | --- | --- | --- | --- |
| 主线第 1 章 | 0.81 | 95.6% | 94.9% | −0.7pp |
| 主线第 2 章 | 1.07 | 77.9% | 76.0% | −1.9pp |
| 主线第 3 章 | 1.16 | 65.3% | 64.4% | −0.9pp |
| 主线第 4 章 | 1.20 | 58.7% | 58.8% | +0.1pp |
| 主线第 5 章 | 1.30 | 41.3% | 43.6% | +2.3pp |
| 远征节点 4 | 1.30 | 41.3% | 43.5% | +2.2pp |
| 远征节点 6 | 1.50 | 14.8% | 16.9% | +2.1pp |
| 远征节点 8 | 1.70 | 4.1% | 3.6% | −0.5pp |

**口径说明**：远征八节点的设计表（[23 号文档](../../refu-game-001/23_规则卡组_Roguelike远征.md)）记 84.4 / 72.1 / 59.2 / 43.5 / 28.0 / 16.9 / 8.6 / 3.6%，而当前脚本 `--verify-rogue --n 20000` 复现为 84.5 / 72.7 / 58.6 / 42.8 / 28.0 / 17.2 / 8.8 / 3.8%；两者均 PASS 目标带，逐点差 ≤0.6pp，差异来自随机种子与样本量。论文与数值卷统一按"设计表 / 脚本实测"并列引用。

**读法**：模型在中段偏高（模拟比模型更宽容），两端贴合。原因是模拟器还包含塔位覆盖、精英免疫减速、BOSS 阶段技等结构性因素，而解析式只用了聚合量。工程结论：**用解析式做设计（快），用模拟做验收（准）**。

## 五、模型的边界与失效条件

模型是近似，必须写明它什么时候不管用：

| 失效情形 | 原因 | 应对 |
| --- | --- | --- |
| 战斗随机（暴击/闪避）比例高 | 泊松假设的"独立小概率"被武器化 | 把随机移到结构层（关卡链、增益三选一） |
| 单点爆发型解法（一发秒杀 BOSS） | `P` 的"平均 DPS"掩盖了峰值 | 引入 `P_peak` 第二口径，或给 BOSS 加阶段技 |
| 玩家操作强介入（暂停微操、手动技能） | `P` 不再是一个常数 | 把操作折算成 `P` 的区间（如 0.85–1.15）分别验收 |
| 关卡过短（≤3 波） | 泊松的大数近似不成立 | 直接用枚举/模拟，不用解析式 |
| 多路并行且耦合（共享基地） | 各路漏怪不再独立 | 用"有效预算"折算（本作双流 ×1.24 即此法，见 [06 号文件](06_远征与挑战卡的数学校验.md)） |
