# 08 · 扩展包架构

> 版本：v2.0 ｜ 六款节律 app 的 core + packs 统一模型。

## 一、模型

```text
AppConfig
  core        一个必选 Collection（entries）
  packs[]     可选 Pack
    modules[] 一个或多个 Collection
```

- core 永远可用；
- pack 关闭后：导航隐藏、API 403、数据保留；
- pack 打开后：模块出现在同一套 shell 中；
- 慢慢记沿用自定义 server，但也遵守同一套“核心 + pack”产品规则。

## 二、Store

```json
{
  "version": 2,
  "settings": { "packs": { "sleep-environment": true } },
  "entries": [],
  "modules": { "environment": [] }
}
```

- core 在 `entries`；
- 模块在 `modules.<moduleId>`；
- `settings.packs` 控制可见/可用；
- 旧 v1 store 读取时自动迁移。

## 三、API

```text
GET  /api/state              config + settings + entries + modules + summaries
POST /api/entries            core
POST /api/modules/:moduleId  模块
PATCH/DELETE 同上
PATCH /api/settings          packs 开关
```

## 四、工程约束

- 模块字段/摘要与 core 使用同一套 Field/Summary 契约；
- 不复制第二套表单/列表/图表；
- 每个 app 只写 config 与文档；
- 新增模块不改 core server。
