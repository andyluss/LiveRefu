# 09 · 统一决策记录

> 版本：v2.0.1 ｜ 日期：2026-10-29 ｜ 覆盖：Life 套件 + 慢慢记
> 这是 Life 相关决策的**单一事实来源**；不在这里之外维护第二份决策表。

## 一、ID 规则

| 前缀 | 范围 |
| --- | --- |
| `L` | Life 套件级：工程、架构、设计系统、分发 |
| `A` | 七款节律 app 的扩展包取舍 |
| `M` | 慢慢记（ledger）产品决策 |

历史 ID 不重编号；迁移不改变 M1–M14 的含义。

## 二、Life 套件级

| # | 决策 | 结论 | 理由 / 影响 |
| --- | --- | --- | --- |
| L1 | 产品形态 | 本地优先、零运行时依赖、Node 24 | 可审计、离线、数据可带走 |
| L2 | 工程骨架 | 七款节律 app 共用 `AppConfig` + `createLifeApp` | 领域不同，服务端/前端骨架相同 |
| L3 | 慢慢记的位置 | `apps/ledger`，保留自定义财务 server | 财务流程与节律 app 差异大，不强行套通用表单 |
| L4 | Store | `{version:2, settings, entries, modules}` | core 与 pack 数据同文件、可整体备份 |
| L5 | 扩展包 | 真实 API/导航开关，默认关闭，关闭不删数据 | 不做营销式“假开关” |
| L6 | 设计系统 | 八款共享 `--life-*` / `--mm-*` 与组件骨架 | 产品差异只换 accent/风格 |
| L7 | 主题 | 7 个风格族 × light/dark；`data-theme` 外观、`data-style` 风格 | 对齐 R-001；风格与外观分离 |
| L8 | 主题来源 | 从 LiveDSO 风格卡生成，不手写 hex | 狗粮闭环；改卡后重新生成 |
| L9 | 独立分发 | 每个 app 可单独启动；`bundle` 生成 `dist/<app>` | 统合开发不等于必须统合运行 |
| L10 | 数据边界 | app 之间不共享数据；未来聚合需用户明确选择 | 生活数据敏感，不做默认联动 |
| L11 | 未来统合 | 先保持 API/Config 契约，再换 SQLite/gateway/壳 | 避免过早微服务化 |
| L12 | 文档 | 先写产品/功能/数据/验收，再写代码 | 防止功能堆叠失去边界 |
| L14 | 十款新增 | 逐款开发，每款 core + ≥2 packs | 不铺半成品；「好好穿」先行 |
| L13 | 决策记录 | 本文件为唯一决策源；原各 app 决策表迁移或保留指针 | 避免多份决策漂移 |

## 四、慢慢记（M1–M15）

> 原 [`apps/ledger/docs/07_决策记录.md`](../apps/ledger/docs/07_决策记录.md) 已迁移到这里；原文保留指针。

| # | 决策 | 结论 | 理由 / 影响 |
| --- | --- | --- | --- |
| M1 | 形态 | 本地 Node 服务 + 无构建单页 | 零依赖、可审计、离线 |
| M2 | 存储 | 单个 JSON + `.bak` | 易备份、可读、够个人用 |
| M3 | 金额 | integer cents | 避免浮点误差 |
| M4 | 账户 | 期初 + 流水派生余额 | 不改写历史余额 |
| M5 | 转账 | 一条 transfer，两个账户 | 不产生虚假收入/支出 |
| M6 | 扩展包 | 真实 API/导航开关 | 不做营销式“假开关” |
| M7 | 发票收款 | 生成收入流水 | 开票与记账闭环 |
| M8 | 删除 | 直接删除流水，派生重算 | v1.x 不做软删除/审计 |
| M9 | 多币种 | 不做 | 汇率与税务会让 v1 失焦 |
| M10 | UI 设计 | 产品自有 `--mm-*`，映射 LRDS 语义 | 验证后再迁入设计系统 |
| M11 | 分类新增 | 只预置，API 可扩展 | 避免空产品先堆设置 |
| M12 | 账号/云 | 不做 | 本地优先是产品承诺 |
| M13 | 主题来源 | 来自 LiveDSO 风格卡，生成不手写 | 狗粮闭环；LiveDSO 改卡后重新生成 |
| M14 | 风格/外观 | `data-style` 风格；`data-theme` system/light/dark | 对齐 R-001；固定双变体 |
| M15 | Life 整合 | 迁入 `apps/ledger`，复用共享主题/工程规范 | 保留财务 server 独立性 |
