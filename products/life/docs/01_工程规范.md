# 01 · 工程规范

> 版本：v2.0

## 目录

```text
products/life/
  packages/core/   共享 app 契约、store、HTTP、校验
  packages/web/    共享 token、组件、表单、列表、图表
  apps/<id>/       领域配置 + 静态入口 + 测试
  tools/           启动全部、打包、检查
  test/            跨 app 测试
  docs/            统合文档
```

## App 契约

五款节律 app 的 `apps/<id>/config.ts` 导出：

```ts
export const config: AppConfig = {
  id, name, tagline, accent, port,
  fields: Field[],
  columns: string[],
  summary(entries) { return { metrics, chart, streak } }
  packs?: PackConfig[]
}
```

五款节律 app 的 `server.ts` 只做：

```ts
import { createLifeApp } from '../../packages/core/server.ts'
import { config } from './config.ts'
createLifeApp(config).start()
```

五款节律 app 的 `web/index.html` 只做：

```html
<link rel="stylesheet" href="/shared/tokens.css">
<link rel="stylesheet" href="/shared/life.css">
<script type="module" src="/shared/app.js"></script>
```

## 字段类型

`date` / `time` / `text` / `textarea` / `number` / `select` / `rating`。

- `required` 只影响表单与 API；
- `min/max/step` 用于 number；
- `options` 用于 select；
- `default` 只用于新建表单，不写进服务端默认。

## 版本

- suite：`life-v2.0.0`；
- 每个 app 跟随 suite 版本，不单独漂移；
- 破坏 `AppConfig` 或 store 形状 → suite major；
- 新增 app → suite minor；
- 修 bug/文案 → patch。

## 测试

```bash
npm test          # 共享 core + 五份 config 契约
npm run check     # test + 每个 app 的 config/静态入口检查
```

每个 app 至少验证：

- config 必填字段/端口/accent；
- summary 能处理空数据与样例数据；
- 服务端 CRUD 冒烟（共享 core 已覆盖）；
- 静态入口能返回。

## 独立分发

```bash
npm run bundle
# dist/sleep/、dist/meal/ ...
```

每个 `dist/<app>/` 包含（慢慢记也遵循同一布局）：

```text
apps/<app>/
packages/core/
packages/web/
```

启动：

```bash
cd dist/sleep/apps/sleep
node server.ts
```

## 提交

- Conventional Commits：`feat(life): ...` / `fix(life-sleep): ...`；
- 每个 app 有 README；suite 有 CHANGELOG/TODO；
- 不提交 `data/store.json`。
