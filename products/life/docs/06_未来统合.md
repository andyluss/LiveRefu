# 06 · 未来统合

> 版本：v1.0 ｜ 当前已统合工程、设计、架构；数据库/后端/前端保留升级路径。

## 一、已经统合

- 同一套 `AppConfig`；
- 同一套 store 形状；
- 同一套 HTTP/API；
- 同一套字段校验；
- 同一套 Web 组件/token；
- 同一套测试/打包。

## 二、未来可以统合

### 数据库

```text
现在：每 app 一个 data/store.json
未来：SQLite 单库，表 entries(app_id, id, date, data_json)
```

API 不变；store 实现替换。

### 后端

```text
现在：每个 app 一个 Node 进程
未来：一个 life gateway，按 app_id 路由
```

`createLifeApp` 的 handler 可以挂到同一个 server。

### 前端

```text
现在：共享无框架 app.js
未来：一个 Life Shell / 或继续独立静态页
```

字段/summary 契约不变，UI 可替换。

### 设计系统

```text
现在：--life-* 共享 token
未来：LRDS product.life.* + 每 app accent
```

### 账号/同步

只在用户明确需要时做；本地优先不变。同步必须解决冲突/加密/退出，否则不做。

## 三、迁移顺序

1. 抽出 `@life/core` npm 包（或 vendored）；
2. 把五份 JSON 迁到 SQLite，保留导出；
3. 统一 gateway；
4. 统一 Life Shell（可选）；
5. 把 `--life-*` 提升为 LRDS product token；
6. 再谈账号/同步。

## 四、不做

- 不为“统合”把六款 app 做成一个巨型表单；
- 不共享用户数据给其它 app；
- 不引入云依赖作为 v1 前提。
