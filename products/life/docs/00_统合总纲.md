# 00 · 统合总纲

> 版本：v3.2 ｜ 日期：2026-10-29

## 一、目标

做十六款**各自能独立用**的个人生活应用，同时让它们在以下三个层面已经是同一套东西：

1. **软件工程**：同一套 app 契约、目录、测试、版本与打包方式；
2. **设计系统**：同一套 token、组件、排版、空态、表单与无障碍规则；
3. **系统架构**：同一套本地服务、JSON store、校验、静态资源与 API。

未来可以在不改 app 领域逻辑的前提下，统合数据库、后端服务、前端壳与设计系统。

## 三、统合原则

### 1. 领域不同，骨架相同

```text
AppConfig（字段 + 摘要）
  → createLifeApp
  → 共享 HTTP / store / 校验
  → 共享 Web shell
```

五款节律 app 只写：

- `config.ts`：名称、字段、示例数据、summary、packs；
- `web/index.html`：静态引用；
- `README.md` / `docs/`：领域说明。

慢慢记保留自定义财务 server 与前端，但复用共享主题、设计 token 与打包规范。
通用 app 不写自己的服务端路由、表单渲染、列表、图表、CSS。

### 2. 数据本地，边界清晰

- 每个 app 一个 `data/store.json`；
- 不共享数据库、不共享账号；
- 数据模型为 `{version, settings, entries, modules}`；core 在 `entries`，扩展包在 `modules`；
- 未来统合时，先迁移数据，再换存储。

### 3. 独立分发是硬约束

- 每个 app 可单独 `npm start`；
- `tools/bundle.ts` 生成 `dist/<app>/`，包含 app 与共享包；
- 不要求用户安装 workspace 其它 app；
- 共享代码是**同一份源**，不是运行时云依赖。

### 4. 设计系统是产品的一部分

- 共享 `--life-*` / `--mm-*` token；
- 每个 app 只换 accent，不换组件语法；
- 暗色/浅色/系统由产品层负责；
- 不在 app 里写裸色、裸间距。

## 四、非目标

- 不做云同步/账号/团队；
- 不做跨 app 的实时联动；
- 不强制统一数据库；
- 不为了统合而把所有 app 塞进一个巨型服务。

## 五、完成定义

十六款 app 同时满足：

```text
能单独启动 + 能记录/编辑/删除 + 有摘要 + 有测试 + 有文档 + 可打包
```

且共享层只有一份。
