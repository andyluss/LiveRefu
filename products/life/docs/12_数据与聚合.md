# 12 · 统一数据、导入导出与跨应用聚合

> 版本：v1.0 ｜ 统一存储：`products/life/data/apps/<id>/store.json`

## 一、数据在 apps 外

```text
products/life/data/
  apps/
    sleep/store.json
    ledger/store.json
    wear/store.json
    ...
  legacy/            旧 data/store.json 的一次性快照
```

- `data/` 已被 [`products/life/.gitignore`](../.gitignore) 忽略；
- 每款 app 的 server 默认读取 `data/apps/<id>/store.json`；
- 旧的 `apps/<id>/data/store.json` 由 `tools/migrate-data.ts` 迁移；
- 独立 bundle 中，数据落在 bundle 根目录的 `data/apps/<id>/`，仍不进入源码。

## 二、独立导入导出

每个 app：

```text
GET  /api/export   下载该 app 的完整 JSON
POST /api/import   用 JSON 覆盖该 app 数据（写前 .bak）
```

慢慢记同样支持；另有 CSV 导出。导入后只替换该 app，不影响其它 app。

## 三、统合导入导出

统合主页：

```text
GET  /api/export   下载 { version, app:"life", exportedAt, apps:{...} }
POST /api/import   按 app id 恢复；每款写前 .bak
```

- 统合导出是**数据快照**，不是云备份；
- 导入会覆盖对应 app 的 store；
- 不做账号、同步、冲突合并。

## 四、跨应用节律

跨应用节律是独立页面 `/rhythm`：

- 应用过滤：任意多选；
- 周期：近七天 / 近十天 / 近三十天 / 本周 / 本旬 / 本月 / 本朋 / 本季 / 本年；
- 默认本月；本旬按 1–10、11–20、21–月末；本朋两月一期、一年六期；本季从 3 月立春起算；
- 年按 12 个月聚合，朋/季按周聚合，月/旬/周/近 N 天按日聚合；
- 同时显示总记录、有记录天数、有记录应用数。

可视化只读 `/api/state`，不向各 app 写数据；主页不承载图表。

## 五、命令

```bash
cd products/life
node tools/migrate-data.ts   # 一次性迁移旧数据
npm run home                 # 统合主页
```
