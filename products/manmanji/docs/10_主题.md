# 10 · 主题与 LiveDSO 狗粮

> 版本：v1.1 ｜ 主题不是手写色板，而是 LiveDSO 风格卡的投影。

## 一、主题来源

| 产品主题 | LiveDSO vault / card |
| --- | --- |
| `paper` | 产品默认（本地 tokens） |
| `night` | 产品默认（本地 tokens） |
| `retro-paper` | `retro-futurism / retro-paper` |
| `retro-crt` | `retro-futurism / retro-crt` |
| `cassette-amber` | `cassette-futurism / cassette-amber` |
| `atompunk` | `atompunk / atompunk` |
| `material-dark` | `material-3 / material-3-dark` |
| `tailwind-paper` | `tailwind / tailwind-paper` |
| `carbon-night` | `carbon / carbon-night` |

## 二、生成

```bash
cd products/manmanji
npm run themes          # 生成 CSS + 主题列表
npm run themes:check    # CI 校验
npm run themes:list     # 查看 id/名称/来源
```

工具：

```text
server/themes.ts         主题白名单（id/name/mode/vault/card）
tools/build-themes.ts    读取 LiveDSO 风格卡 → 解析角色 → 生成
web/themes.generated.css 每个主题的 --mm-* 覆盖
web/themes.generated.js  THEMES 列表
```

## 三、映射

LiveDSO 角色 → 产品变量：

```text
bg/surface/surfaceRaised/text/textMuted/border/borderStrong
action/onAction/actionHover/focus
danger/warning/success
```

生成时只读取风格卡声明的角色，不在产品里复制 LRDS 的 50 角色。

## 四、规则

- 不手改 `themes.generated.*`；
- 不把 hex 直接写进产品 UI；
- 新增主题必须同时登记 `server/themes.ts`；
- LiveDSO 风格卡变更后必须 `npm run themes`；
- `npm run check` 会跑主题生成物校验。

## 五、边界

- 主题是**视觉皮肤**，不改变记账/发票数据；
- 暗色主题独立设计，不是反色；
- 产品未把 `manmanji` 提升为 LRDS `product` 前，主题只消费现有风格卡；
- 若产品脱离本工作区单独分发，需要把生成物一起带上，或把生成器改为读取导出数据。
