# 01 · 计算核心

> 纯函数 `reduce(state, action) => state`；无 DOM、无存储、无网络。

## 为什么纯

计算器最危险的问题是“屏幕显示的值”和“实际参与运算的值”不一致。纯状态机让二者只有一个来源。

参考独立项目的缺陷回归：

- `±` 在运算符后必须开启负数输入，而不是只取反屏幕；
- `200 + 10% =` 必须得到 `220`；
- 错误必须带原因，且数字 / AC / 退格能明确恢复；
- 连按 `=` 重复运算；
- 纸带独立于当前计算。

## 状态

```text
phase: input | operator | result
value, entry, pending, repeat, error, expression, history
```

## 关键语义

| 输入 | 结果 |
| --- | --- |
| `2 + 3 =` | `5` |
| `2 + 3 = =` | `8` |
| `5 + =` | `10` |
| `5 + ± 3 =` | `2` |
| `200 + 10% =` | `220` |
| `200 × 10% =` | `20` |
| `9 √` | `3` |
| `2 + 9 √ =` | `5` |
| `5 ÷ 0 =` | `Error / 除数不能为 0` |

## 边界

- 最多 15 位输入；
- 定点显示优先，极端数量级才用科学计数法；
- 纸带最多 50 条，损坏数据整条丢弃；
- `load` 动作用于内存取回，不写纸带。
