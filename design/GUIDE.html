01 / Principles

八条原则（已冻结）

01

先语义，后色值

业务只引用角色，不写 #57d8c8。

02

一套语法，多种介质

Web / Godot / App / 打印 / 实体共享理解方式。

03

产品可变，理解不变

换风格卡，不换信息位置与交互语法。

04

无障碍是闸门

对比度、焦点、缩放、减少动态由机器守。

05

单一事实来源

JSON 只写一次；生成物可复算、可对账。

06

设计是闸门

先规格后实现，发布前有验收；设计债按 P1。

07

先收编，再统一

保留合理差异，先对齐语义再替换取值。

08

两个试点

没有真实消费者，不算交付。

03 / Tokens

三层 token：ref → sys → product

REF

原始值

色相、尺度、字体族；低频变动。例：ref.color.ink.950。

SYS

通用语义

背景、文字、行动、反馈、焦点；跨产品共用。例：sys.color.action.primary。

PRODUCT

产品语义

产品/纪元专属角色；例：product.future-debris.color.power。

06 / Theme

三态主题：系统 / 深色 / 浅色

默认跟随系统；用户可显式选择深色或浅色；选择持久化，系统切换实时响应。主题不是信息载体，两种外观都必须过对比度与焦点闸门。

规则：[R-001](rules/R-001-theme-modes.md)（proposed，待批准）；存储键统一 `lrds-theme`。

硬要求

  • 默认 `system`，不得强制单一外观。
  • 三态控件，不得只做二态开关。
  • CSS 加载前设置 `data-theme`，避免闪烁。
  • 两种外观都测对比度、焦点、禁用态。
  • 打印强制浅色/白底。

08 / Use

怎么接入

WEB

CSS 变量 + 组件类

加载 `tokens/dist/web/.css`，再加载 `components.css`；不写裸值。

GODOT

JSON → Theme

消费 `tokens/dist/godot/tokens.json`；产品风格卡投影到 `.tres` 并过对账。

APP

平台无关 JSON

`tokens/dist/app/tokens.json`；首个真实 App 后再决定 Swift/Kotlin 常量。

修改前：读 rules/ 与相关契约；跑 bash design/tools/check.sh；改 token 源后重跑生成器。项目状态与阶段见 HUB.html。
