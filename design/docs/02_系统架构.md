# 02 · 系统架构：一套语法，多种介质

> 本文是**技术架构提案**，对应 [D1 / D3 / D4 / D6](00_决策总表.md)。
> 目标：让网站、游戏、应用、打印与实体产品**共用一套语义**，同时允许每个产品/纪元拥有自己的风格卡。
> 日期：2026-10-21 ｜ 状态：**v0.1 已按本架构实现**（见 [05 实现记录](05_实现记录_v0.1.md)）｜ 前置阅读：[01 现状盘点](01_现状盘点.md)

## 一、架构命题

> **不要统一“长什么样”，要统一“怎么理解”。**

复古未来主义不是一个风格，而是二十种互相冲突的风格（这是 [主线 Q6](../../projects/mainline/docs/05_美术与技术方向.md) 已经裁决过的判断）。因此本系统**不追求全产品同一套配色**，而是：

1. **语义层统一**：什么是“背景 / 主文字 / 行动 / 危险 / 焦点 / 标题 / 正文”，全产品一致。
2. **取值层可变**：原子纪元是青+橙，磁带纪元是棕+琥珀，档案纸是墨+奶油——都合法。
3. **理解方式不变**：字号层级、信息位置、交互反馈、焦点行为、无障碍下限不变。

这条命题的代价是：**前期必须先做一层“看不见的语法”**；收益是：新增一个产品/纪元 = 写一张风格卡 + 接生成器，而不是重做一套 UI。

## 二、五层模型

```
┌──────────────────────────────────────────────────────────────┐
│ L0 品牌核心 Brand Core                                       │
│ 定位 / 承诺 / 语气 / 标志 / 署名 / 版权 / 法务                 │
│ —— 极少变，单向门                                             │
├──────────────────────────────────────────────────────────────┤
│ L1 语法层 Grammar                                            │
│ 语义角色 / 字阶 / 间距 / 形状 / 动效 / 图标 / 网格 / 无障碍下限 │
│ —— 版本化，稳定                                              │
├──────────────────────────────────────────────────────────────┤
│ L2 组件与模式 Components & Patterns                           │
│ 组件解剖 / 状态 / 交互契约 / 页面模式 / 空状态 / 错误          │
│ —— 按需增长，不做全家桶                                       │
├──────────────────────────────────────────────────────────────┤
│ L3 介质适配 Medium Kits                                       │
│ Web / Godot / App / Print / Physical                          │
│ —— 每介质独立演进，共享 L0–L2                                  │
├──────────────────────────────────────────────────────────────┤
│ L4 资产库 Assets                                              │
│ 标志 / 图标 / 插画 / 摄影 / 3D / 纹理 / 模板 / 登记表          │
│ —— 持续积累                                                   │
└──────────────────────────────────────────────────────────────┘
```

**跨层约束**：版本、变更日志、评审、无障碍、法务、本地化。它们不属于某一层，但每一层都要过。

### L0 品牌核心（最少的不可变项）

| 项 | 内容 | 变更门槛 |
| --- | --- | --- |
| 品牌定位 | 一句话“我们做什么、为谁、凭什么” | 你 + 书面提案 |
| 语气 | 档案员 + 广播员：精确、克制、略带冷幽默；不堆“复古未来”四字 | 你 |
| 标志系统 | 字标、徽记、最小尺寸、留白、单色/反白、禁用示例 | 你 |
| 署名 | “LiveRefu 出品 / A LiveRefu project”的固定格式 | 你 |
| 法务 | 商标、版权行、字体/素材许可、AI 资产声明 | 你 |

> **v0.1 不要求完成 L0**：母品牌正式名、标志、语气手册可以后做；但**署名格式与版权行**要先有，否则实体包装无法落稿。

### L1 语法层（本系统的核心）

L1 只定义**角色与尺度**，不定义某个产品的具体值。完整 token 类别：

| 类别 | 作用 | 例子 |
| --- | --- | --- |
| `color` | 背景、表面、文字、线、行动、反馈、焦点、数据 | `sys.color.bg.base` |
| `type` | 字族、字重、字号、行高、字距、行宽 | `sys.type.body.md` |
| `space` | 4 基数间距 | `sys.space.4` |
| `size` | 控件高度、图标、触控目标、卡宽 | `sys.size.control.md` |
| `radius` | 控件/面板圆角 | `sys.radius.panel` |
| `border` | 描边宽度、焦点环宽度/偏移 | `sys.border.focus` |
| `shadow` | 浮起层级 | `sys.shadow.elevated` |
| `motion` | 时长、曲线 | `sys.motion.duration.fast` |
| `z` | 层级 | `sys.z.modal` |
| `opacity` | 禁用、遮罩、装饰 | `sys.opacity.disabled` |
| `breakpoint` | 响应式断点 | `sys.breakpoint.md` |
| `grid` | 栏数、槽宽、最大宽度、安全区 | `sys.grid.web.maxWidth` |
| `icon` | 画布、描边、光学对齐 | `sys.icon.stroke` |

**不放进 L1 的东西**：`power`（电力）、`residue`（残渣）、`phosphor`（荧光）这类产品/玩法语义。它们属于 `product.*`。

### L2 组件与模式（克制）

**不建组件库**。只定义**契约**，按“跨产品重复率 × 出错代价”排序。v0.2 已写 3 个（draft）：

1. ✅ **按钮**（primary / secondary / ghost / danger；default / hover / active / focus / disabled / loading）；
2. ✅ **表单字段**（标签、输入、帮助、错误、必填；8 种状态）；
3. ✅ **面板/卡片**（头/身/脚、静态/可交互/浮起）；
4. ⏳ **导航**（站点头部、侧栏、面包屑、分页）；
5. ⏳ **反馈**（toast、banner、空状态、加载、错误）。

每个契约包含：**解剖图、状态表、尺寸/间距、键盘行为、ARIA/无障碍要求、do/don't、跨端差异**。**不包含**具体像素皮肤——皮肤由介质包与风格卡提供。契约闸门见 [`check_component_contracts.ts`](../tools/check_component_contracts.ts)；共享 Web 组件层在 [`kits/web/components.css`](../kits/web/components.css)，网站/LiveFab 已渐进接入（见 [08](08_组件落地_v0.2.md)）。

### L3 介质适配（Medium Kits）

| Kit | 消费方式 | 特有内容 | 何时做 |
| --- | --- | --- | --- |
| `web` | CSS 自定义属性 + Tailwind preset + 组件样式 | 响应式、焦点、暗/亮、打印样式、减少动态、字体子集 | `v0.1` |
| `godot` | `tokens.json` + 主题生成器 + GDScript 常量 | Theme 资源、SystemFont、手柄焦点、安全区、像素对齐 | `v0.1` |
| `app` | `dist/app/tokens.json`（平台无关 JSON） | Dynamic Type、触控目标、安全区、平台导航、深色模式、无障碍 | `v0.3` 起步 |
| `print` | CSV/JSON 规格 + 版式模板 | CMYK/专色、纸张、出血、裁切、字阶 pt、条码/QR、法务位 | `v0.3` |
| `physical` | CMF 规格 + 刀版/包装模板 + 供应商清单 | 颜色/材料/表面、工艺、公差、包装结构、安全与可持续 | `v0.4` |

> **介质包不是“再写一套 token”**：它只做“**如何把 L1 的值落地**”。Web 输出 CSS，Godot 输出 Theme，Print 输出规格表。任何介质包都不得新增核心语义；缺语义时先回 L1 提案。

## 三、三层 token

### 3.1 定义

```
ref.*       原始值，无语义。只回答“有哪些值”。
  ref.color.ink.950 = #0B0F14
  ref.space.4 = 4px

sys.*       通用语义角色。只回答“用在哪”。
  sys.color.bg.base        = {ref.color.ink.950}
  sys.color.text.primary   = {ref.color.paper.50}
  sys.color.action.primary = {ref.color.teal.400}
  sys.color.focus          = {ref.color.focus.400}

product.*   产品/纪元语义。只回答“这个产品里叫什么”。
  product.future-debris.color.power   = {sys.color.action.primary}
  product.future-debris.color.residue = {sys.color.feedback.danger}
  product.tomorrows-channel.color.phosphor = {ref.color.amber.400}
```

**规则**：
- 业务代码**只允许**引用 `sys.*` 或 `product.*`，不允许 `ref.*`，更不允许裸值。
- `product.*` 只能映射到 `sys.*` 或 `ref.*`，不能定义新的通用角色。
- 一个 `product.*` token 只能属于一个产品；跨产品共享的语义必须上移到 `sys.*`。
- 别名必须可解析、无环、无孤儿；生成器负责检测。

### 3.2 命名

| 层 | 命名 | 例子 |
| --- | --- | --- |
| JSON | 点分小写 | `sys.color.bg.base` |
| CSS | `--lr-` + 短横线 | `--lr-color-bg-base` |
| Godot | `LR_` + 大写下划线 | `LR_COLOR_BG_BASE` |
| 文件 | `kebab-case` / `snake_case` | `future-debris.atomic.tokens.json` |
| 风格卡 | `SC-<PRODUCT>-<ERA>-vN` | `SC-FUTURE-DEBRIS-ATOMIC-v1` |

**语义命名禁用颜色名**：`sys.color.action.primary` 可以，`sys.color.teal` 不行；颜色名只允许出现在 `ref.*`。

### 3.3 双字阶

| 字阶 | 级数 | 用途 | 约束 |
| --- | --- | --- | --- |
| **UI** | 5 级 | 游戏、应用、仪表、控件 | 沿用《未来残片》已验证的 28/20/16/14/32；**不得新增第 6 级** |
| **Editorial** | 7 级 | 网站长文、印刷、品牌书 | display / h1 / h2 / h3 / body / caption / footnote；共享基准与行高规则 |

> 为什么不是一套 7 级通吃：游戏 UI 需要“级数少、决策快”，长文需要“层级细、阅读稳”。两套字阶共享 `type.family`、`type.weight`、行高与对比度规则，避免变成两套排版。

### 3.4 颜色角色

| 角色 | 语义 | 禁止 |
| --- | --- | --- |
| `bg.base` | 页面底 | 不得用于控件底 |
| `bg.surface` / `bg.raised` | 面板/浮起面 | 必须与背景有层级差 |
| `text.primary` / `secondary` / `muted` | 三级文字 | `muted` 是文字可访问性下限，不得更暗 |
| `line.subtle` | **装饰**分隔线 | 不得用于交互控件边框 |
| `line.strong` | **交互控件**边框 | 对背景 ≥3:1 |
| `action.primary` | 主行动/选中 | 同时只允许一个主焦点 |
| `feedback.success` / `warning` / `danger` | 状态 | 不得仅靠颜色传达 |
| `focus` | 键盘/手柄焦点 | **不得复用 action / feedback**；2px 环 + 偏移 |
| `data.*` | 图表/数据系列 | 必须色盲友好，配图案/标签 |

> `focus` 单列是《未来残片》已经用真实缺陷换来的规则；本系统把它上升为**全局硬约束**。

## 四、单一事实来源与生成管线

### 4.1 目录

```
design/tokens/
├── core/
│   ├── ref.tokens.json          # 原始值
│   └── sys.tokens.json          # 通用语义
├── products/
│   ├── future-debris.atomic.tokens.json
│   ├── future-archive.tokens.json
│   ├── livefab.tokens.json
│   └── tomorrows-channel.tape.tokens.json   # SC-TOMORROWS-CHANNEL-TAPE-v1
├── schema/
│   └── tokens.schema.json       # 自描述 schema
└── dist/                        # 生成物（提交；CI 校验可复算）
    ├── web/future-archive.css
    ├── web/livefab.css
    ├── godot/tokens.json
    ├── app/tokens.json
    └── docs/tokens.md
```

### 4.2 JSON 形状（DTCG 风格）

```json
{
  "$schema": "../schema/tokens.schema.json",
  "sys": {
    "color": {
      "bg": {
        "base": { "$value": "{ref.color.neutral.0}", "$type": "color" }
      },
      "focus": {
        "ring": { "$value": "{ref.color.blue.300}", "$type": "color" }
      }
    }
  }
}
```

- `$type` 至少支持 `color` / `dimension` / `fontFamily` / `fontWeight` / `duration` / `cubicBezier` / `number` / `shadow`。
- 别名用 `{...}`；生成器解析为最终值，同时保留变量输出（CSS 用 `var()`，Godot 用常量）。
- 不接受“仅靠注释说明”的约束；能机器校验的都写进 schema。

### 4.3 生成器

`design/tools/build_tokens.ts`（零第三方依赖，Node/Deno/Bun 兼容，遵循工作区 TS 脚本惯例）：

```
读 core + product JSON
  → 解析别名、检测环/孤儿/类型错误
  → 校验：对比度、层级顺序、字号阶梯、间距阶梯
  → 输出 dist/web/{future-archive,livefab}.css、dist/godot/tokens.json、dist/docs/tokens.md
  → --check：重新生成到临时目录，与 dist/ 比较；有 diff 即失败
```

**Godot 的 `.tres` 不在核心生成器里生成**：由 `design/kits/godot/build_theme.gd` 读取 `dist/godot/tokens.json` 生成，保持核心与引擎解耦。这样换引擎不用改核心。

### 4.4 为什么生成物要提交

- 产品可直接消费，不要求 Godot CI 装 Node；
- 生成物可审计（diff 里能看到值的变化）；
- CI 用 `--check` 防“改了源、忘了生成”。

**代价**：仓库里有一份“可复算的重复”。用 `--check` 把风险关进闸门，比让产品各自复制 token 更可控。

## 五、介质如何取值（示例）

### Web

```css
:root {
  --lr-color-bg-base: #0b0f14;
  --lr-color-text-primary: #f2ede3;
  --lr-color-action-primary: #57d8c8;
  --lr-color-focus: #8ab4f8;
  --lr-space-4: 16px;
  --lr-radius-panel: 8px;
  --lr-border-control: 1.5px;
}
```

- 组件只引用 `var(--lr-*)`；ESLint/stylelint 规则禁止裸 `#hex` / `rgb()`（允许 `transparent` / `currentColor`）。
- 焦点：`outline: 2px solid var(--lr-color-focus); outline-offset: 1px;`，用 `:focus-visible`。
- 装饰层（CRT/扫描线）必须可关闭；`prefers-reduced-motion` 下动效降为 0。

### Godot

- 主题资源由 token 生成，场景根用 `RootBackground` 显式套 `bg.base`（这是《未来残片》踩过的坑：`theme_type_variation` 会静默回落）。
- 字体用 `SystemFont` 按族名查找；不得在仓库塞未授权字体。
- 手柄/键盘焦点用 `focus`，2px 环 + 1px 偏移；不得复用强调色。
- 控件常态底色用 `bg.raised`（不是 `bg.surface`，否则在根背景上看不出边界）。

### Print / Physical

- **颜色**：sRGB 仅供参考；实际以 `print/spot-colors.json` 的 CMYK/专色/纸张组合为准，打样后用 Delta E 验收。
- **字阶**：Editorial 字阶换算为 pt；正文不小于 9pt（以纸张与阅读距离为准）。
- **版式**：出血 3mm、裁切线、安全边距、条码/QR 留位、法务位。
- **实体**：CMF 规格（颜色/材料/表面/工艺）+ 刀版 + 公差 + 供应商；颜色以实物样为准，不以屏幕为准。

## 六、闸门（机器守，不靠肉眼）

| # | 闸门 | 拦住什么 | 何时 |
| --- | --- | --- | --- |
| 1 | **Schema** | 类型错、别名环、孤儿 token、重复 ID | `v0.1` |
| 2 | **对比度 / 层级** | 文字 <4.5:1、控件边框 <3:1、层级亮度被压平、focus 与 action 同色 | `v0.1` |
| 3 | **无裸值** | 产品代码里出现 `#hex` / `rgb()` / 魔数间距 | `v0.1` |
| 4 | **生成物无 diff** | 改了源没重新生成，或手改生成物 | `v0.1` |
| 5 | **文档对账** | 文档写的值与 token 不一致 | `v0.2` |
| 6 | **无障碍静态检查** | 焦点、ARIA、减少动态、文字缩放、触控目标 | `v0.2` |
| 7 | **视觉回归** | 迁移前后截图差异未解释 | `v0.2` |
| 8 | **资产登记** | 资产缺源/许可/作者/版本 | `v0.3` |

> **另**：明日频道的 `.tres` 是手写引擎资源，暂不走上述八道通用闸门；由 [`check_tomorrows_channel_skin.ts`](../tools/check_tomorrows_channel_skin.ts) 单独做风格卡对账（9 色 + 6 光照/装饰），见 [07 风格卡登记](07_风格卡登记.md)。

**每条闸门都必须带 `--self-test` 负向用例**，且断言**错误类型**而非“有错”。这是工作区已经验证过的纪律：检查器本身也要被校验。

## 八、`v0.1` 的技术边界

**做**：
- `ref` / `sys` 两层 token + 一个产品风格卡；
- CSS 与 Godot 两个生成器；
- 四道闸门（schema / 对比度 / 无裸值 / 生成物无 diff）；
- 网站与游戏的迁移（只换取值，不重做布局）。

**不做**：
- 组件库、Figma 同步、App/Print/Physical 的完整实现；
- 设计系统文档站（先用 Markdown + 自动生成的 token 表）；
- 多主题运行时切换（先支持构建期选择）。

**为什么**：先用两个真实产品证明“同一套语义能同时服务阅读与游戏”，再扩介质。没有落地的规范不算交付。

> **v0.2 追加**：Web 生成按产品拆分（`future-archive.css` / `livefab.css`），网站 app 全量 token 化，LiveFab 接入；见 [06 实现记录](06_实现记录_v0.2.md)。
