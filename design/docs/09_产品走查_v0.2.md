# 09 · 产品走查：真实渲染与 Tab 焦点审计

> 目的：验证 `lr-*` 组件层渐进接入后，网站与 LiveFab 的**真实页面**没有回归；为“删除重复皮肤”提供依据。
> 方法：构建产物 + 本地 SSR 服务 + Headless Chrome（CDP），截图 + Tab 焦点序列。
> 日期：2026-10-21 ｜ 状态：**通过（0 缺失焦点）** ｜ 前置：[08 组件落地](08_组件落地_v0.2.md)

## 一、怎么跑

```bash
# 1) 网站（构建产物；Node 运行）
cd projects/website && PORT=3100 node .output/server/index.mjs

# 2) LiveFab（构建产物）
cd projects/livefab/portal && HOST=127.0.0.1 PORT=4321 node dist/server/entry.mjs

# 3) Headless Chrome + CDP
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless=new --disable-gpu --no-sandbox \
  --remote-debugging-port=9222 --user-data-dir="$PWD/.tmp/chrome" about:blank

# 4) 走查
node --experimental-strip-types design/tools/capture_products.ts \
  --website=http://127.0.0.1:3100 --livefab=http://127.0.0.1:4321 --cdp=http://127.0.0.1:9222
```

> **运行时的实测记录**：网站构建产物用 `bun .output/server/index.mjs` 在本机触发 Bun NAPI 崩溃（SIGABRT），改用 `node` 可正常服务；这不妨碍构建与页面验证，但部署时应按目标运行时重新确认。LiveFab 用 Node 正常。

## 四、发现与判断

### 没有发现的回归

- 卡片、按钮、搜索框的视觉与交互未出现错位/溢出；
- 搜索弹窗仍可用 `Meta+K` 打开，焦点陷阱正常；
- 网站与 LiveFab 的焦点色统一为独立蓝，未出现“焦点=强调色”。

### 保留的“重复皮肤”

本轮**不删除**产品侧 `.deco-btn` / `.card` / `.cta` / `ul.svc li`，因为：

- 它们是产品的**视觉决策**（6px 圆角、描边按钮、卡片内边距），不是组件层能直接替代的；
- 组件层当前提供的是**基线与行为**；删除产品样式会改变视觉，需要单独评审；
- 先走查、再决定，避免“为了统一而统一”。

### 一个既有信息架构观察（非回归）

网站头部同时有“搜索”导航链接与“搜索 ⌘K”按钮。两者都可达、焦点可见；是否合并是产品决策，不在本轮处理。
