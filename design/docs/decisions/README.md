## 一、范围

| 层级 | 是否建文件 | 位置 |
| --- | --- | --- |
| **D** 战略 / 单向门 | ✅ 一篇 | `decisions/D-XXX-关键词.md` |
| **E** 执行 / 双向门 | ❌ 只占一行 | [`../00_决策总表.md`](../00_决策总表.md) |
| **P** 未决定提案 | ✅ 一篇 | [`../proposals/`](../proposals/) |

> **一个决策只有一个 canonical 记录**：00 是索引，D 文件是全文，E 行链接实现记录；其他文件只链接，不复制。

## 二、文件命名

`D-XXX-关键词.md`，例如 [`D-003-five-layer-model.md`](D-003-five-layer-model.md)。

- `D-XXX` 用现有编号，不重编号；
- 关键词用 ASCII kebab-case，方便跨平台/URL；
- 新 D 决策顺延：`D-011`、`D-012`……；
- 文件名不写日期；日期在正文元信息里（R06）。

## 三、状态

**决策状态**：

| 状态 | 含义 |
| --- | --- |
| `draft` | 只有想法，尚未成文 |
| `proposed` | 已成文，待裁决 |
| `accepted` | 已采纳，作为依据 |
| `rejected` | 明确不采纳，保留理由 |
| `superseded` | 被新决策取代，保留历史 |
| `retired` | 不再相关，留档 |

**执行状态**（可选，用于 D/E 的落地）：`pending` / `in-progress` / `done` / `blocked`。

> 决定了吗（决策状态）和做了吗（执行状态）分开；不要把“已执行”写成“已裁决”，也不要把“已裁决”当成“已完成”。

## 四、D 级记录模板

```markdown
# D-XXX · 标题

> 状态：accepted ｜ 日期：YYYY-MM-DD HH:MM ｜ Owner：… ｜ 层级：D ｜ 关联：…
> 取代：D-00X ｜ 被取代：—

## 背景
（为什么必须决定）

## 选项
| 选项 | 优点 | 代价 |
| --- | --- | --- |

## 决定
（选了什么，一句话）

## 后果
（会带来什么，哪些是接受的代价）

## 推翻条件
（什么情况下重估）

## 链接
（实现记录、代码、CHANGELOG、TODO）
```

## 五、流程

1. **提案**：非琐碎事项先写 `proposals/YYYYMMDD-HHMM-关键词.md`；写清背景、选项、推荐、影响。
2. **讨论/评审**：记录分歧与证据；结论回到提案或 00。
3. **裁决**：
   - D：用户最终裁决；设计主控可提技术性反对；
   - E：设计主控批准。
4. **记录**：
   - D：00 表一行 + 本目录一篇记录；
   - E：00 表一行 + 详据链接。
5. **落地**：有发布影响 → CHANGELOG 链接决策 ID；还有工作 → TODO 链接决策 ID。
6. **取代**：新决策写 `supersedes`；旧记录标 `superseded`，不删除。

## 六、角色

| 角色 | 权力 |
| --- | --- |
| 用户 | D 级最终裁决；可推翻任何决定 |
| 设计主控 | E 级批准；D 级技术性反对；维护索引与状态 |
| 提案人 | 写清背景、选项、推荐、影响 |
| 实现者 | 按 accepted 记录执行；发现冲突回到提案，不静默偏离 |

## 八、链接规则

- `00_决策总表`：索引、状态、一句话选择、链接；
- `decisions/`：D 级完整理由、选项、后果、推翻条件；
- `proposals/`：未决定前的选项与推荐；
- `CHANGELOG`：发布级“改了什么”，链接决策 ID；
- `TODO`：还剩什么、谁做、优先级，链接决策 ID；
- 讨论记录：当时的判断、分歧、证据，不写最终状态。
