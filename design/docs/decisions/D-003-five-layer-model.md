# D-003 · 五层模型 + 三层 token

> 状态：`accepted · done` ｜ 日期：2026-10-21 12:43（裁决）/ 2026-10-26 12:10（补记）｜ Owner：设计主控 ｜ 层级：D
> 取代：无 ｜ 被取代：无 ｜ 关联：[00 决策总表](../00_决策总表.md) · [02 系统架构](../02_系统架构.md) · [05 v0.1](../05_实现记录_v0.1.md)

## 背景

工作区当时有四套各自演化的视觉定义：

- 网站 `theme.css`；
- 《未来残片》`game/data/tokens.json`；
- LiveFab 内联样式；
- 《明日频道》的磁带 `.tres` 皮肤。

它们的语义相同、取值不同，而且已经出现 **focus 色与强调色混用** 这类真实缺陷。如果继续每个产品一套，第二个、第三个产品会把成本复制一遍。

需要决定的是：**多产品、多介质共用什么样的系统模型，才能既统一语义，又不强迫所有产品长一样？**

## 选项

| 选项 | 优点 | 代价 |
| --- | --- | --- |
| A. 一套 CSS 变量走天下 | 实现最简单；Web 上手快 | 游戏、App、印刷读不了；产品差异无处安放 |
| B. Figma 当唯一来源 | 设计端直观；协作方便 | 多介质/CI/AI 读写弱；工具锁定；生成链复杂 |
| C. 五层模型 + 三层 token（选中） | 语义可跨介质；产品差异有明确位置；可生成 | 需要生成器、schema、文档与闸门 |
| D. 每个产品各自维护 | 产品自由；启动快 | 语义漂移；无障碍/品牌复利消失；长期最贵 |

## 决定

采用 **五层模型**：

1. **L0 品牌核心**：定位、承诺、语气、标志、署名、法务；
2. **L1 语法层**：语义角色、字阶、间距、形状、动效、图标、网格、无障碍下限；
3. **L2 组件与模式**：组件解剖、状态、交互契约、页面模式；
4. **L3 介质适配**：Web / Godot / App / Print / Physical；
5. **L4 资产库**：标志、图标、插画、摄影、3D、纹理、模板。

并采用 **三层 token**：

- `ref.*`：原始值（调色板、间距、字号刻度）；
- `sys.*`：通用语义（`bg.base`、`action.primary`、`focus.ring`）；
- `product.*`：产品/风格卡映射（`future-archive.bg`、`future-debris.power`）。

关键规则：

- 产品专属语义（如 `power` / `residue`）**不进核心层**；它们映射到 `sys.color.action.primary` / `sys.color.feedback.danger`；
- 业务代码只引用 `sys.*` 或 `product.*`，不写裸色值；
- JSON 是源，CSS / Godot / App / 文档是生成物；
- 焦点色独立于强调色（`focus.ring` 不复用 action）。

## 后果

**接受的代价**：

- 需要维护 `build_tokens.ts`、schema、别名解析与生成物对账；
- 需要文档解释“ref / sys / product”各改什么；
- 团队要学习语义命名，不能随手写 `#3FB8AB`；
- 需要处理产品差异，而不是“一套皮肤走天下”。

**换来的能力**：

- 同一语义可投影到 Web / Godot / App / 未来打印与实体；
- 产品可以换风格卡，但不换信息位置与交互语法；
- token 可检查、可版本化、可弃用；
- 第二个产品不必重新发明按钮、字号与对比度。

## 推翻条件

- 如果产品数长期不超过 3 个，可把 L2/L3 合并；**`ref/sys/product` 三层建议保留**；
- 如果生成器维护成本长期高于收益，可降级为“Web 用生成器、游戏/印刷人工同步”，但必须保留 schema 与对比度闸门；
- 如果 DTCG 标准发生破坏性变化，保留自有 schema 的兼容层，不追标准。
