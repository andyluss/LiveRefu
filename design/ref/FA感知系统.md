# FA 感知系统 · Frutiger Aero as Perceptual Interface

---

## 一、一句话定义

**FA 感知系统是一套把真实物理量与信息变化映射为可感知视觉现象的设计语法——每一个透明、光泽、水感、深度，都对应一个可测量、可追溯、可参与的真实过程，用户不需要读数字，只需要看、摸、听。**

它要解决的核心问题是：扁平极简界面把“系统状态”压缩成数字和图标，用户只能“读取”而不能“感知”。FA 感知系统把状态还原为**现象**——水变浑了、光泽变暗了、气泡变慢了、颜色变暖了——用户的身体先于认知做出反应。

---

## 二、感知映射法则：物理量 → FA 视觉参数

这是整个系统的核心。每一条映射都必须满足三个条件：**可测量、可追溯、可参与**。不可测量的映射是装饰，不可追溯的映射是幻觉，不可参与的映射是黑箱。

| 物理量 / 信息变化 | FA 视觉参数 | 感知含义 | 例子 |
|---|---|---|---|
| **透明度** | 浊度 / 清晰度 | 系统可观测性、水质纯净度 | 灰水过滤槽从浑浊到清澈，用户看到的是“净化在发生” |
| **光泽 / 高光强度** | 能量流 / 活跃度 | 有能量流动的地方才有光泽 | 太阳能储能在充电时表面泛起微光，放空时暗淡 |
| **水滴 / 湿润感** | 水循环 / 湿度 / 液体流动 | 水在系统中存在的状态 | 雨水收集箱外壁的凝结水珠密度反映蓄水量 |
| **折射 / 扭曲** | 压力 / 密度 / 梯度 | 系统内部的张力 | 堆肥区空气折射率随温度变化轻微扭曲背景 |
| **气泡 / 发酵活性** | 气体交换 / 微生物活性 | 代谢的活跃程度 | 堆肥液肥发酵时气泡频率反映微生物活性 |
| **流动纹理 / 流速** | 物质流 / 数据流速率 | 系统周转速度 | 灰水管道中的流动纹理速度反映用水量 |
| **色温 / 色调偏移** | 温度 / 化学状态 | 系统的热状态与化学平衡 | 土壤湿度指示植物从冷绿转为暖黄，反映干旱胁迫 |
| **深度 / 层次感** | 系统复杂度 / 嵌套关系 | 可见层与隐藏层的关系 | 多层过滤界面每一层的透明度不同，暗示不同处理阶段 |
| **表面张力 / 边缘锐度** | 系统稳定性 / 临界状态 | 接近阈值时的视觉紧张 | 磷储备接近下限时，界面边缘从柔和变为锐利 |
| **雾化 / 凝结** | 挥发 / 散失 | 不可见损失的可视化 | 堆肥氨挥发以轻微雾化效果呈现，提醒覆盖 |

**关键原则：映射不是比喻，是索引。** 透明度必须真的由浊度传感器驱动，光泽必须真的由能量流数据驱动。用户看到的每一个视觉现象，背后都有一条可查的数据链。这不是“让界面看起来像水”，是“让水的视觉语言成为水质数据的直接呈现”。

## 三、五层感知架构

从物理世界到用户感知，中间经过五层转化。每一层都必须可独立验证，否则整个系统就是黑箱。

### 第一层：物理传感层

部署在代谢节点上的传感器网络。不是“物联网”意义上的全面监控，而是**每个代谢节点至少有一个可感知的物理量**：

- 灰水过滤槽：浊度传感器 + 流量计
- 鸟粪石反应器：pH + 镁离子浓度 + 反应时间
- 堆肥区：温度 + 湿度 + 气体浓度（CO₂/氨）
- 土壤：湿度 + 有机质（间接通过颜色/质地）
- 雨水收集：液位 + 电导率
- 能源：电流 + 储能状态

**设计约束：传感器必须可被居民校准和更换。** 一个需要厂家上门校准的传感器，在代谢设计里是不合格的——它把“可参与”变成了“可外包”。

### 第二层：数据映射层

把物理量映射为视觉参数的规则引擎。每一条映射规则都是**公开的、可修改的、可审计的**：

```
浊度 0-100 NTU → 透明度 100%-20%
能量流 0-5 kW → 光泽强度 0-1
堆肥温度 20-70°C → 色温 6500K-2700K
液位 0-100% → 水滴密度 0-50 滴/单位面积
```

**关键设计：映射曲线不是线性的。** 在阈值附近，视觉变化应该更敏感——堆肥温度在 55-65°C（病原体灭活关键区间）时，色温变化应该加速，让用户对“是否达标”产生直觉。这是**感知的优先级设计**：重要的变化更显眼，不重要的变化更柔和。

### 第三层：视觉渲染层

FA 视觉语言的渲染引擎。核心不是“画得像 Aero”，而是**让视觉现象服从物理规律**：

- **透明度**不是简单的 alpha 值，而是模拟真实介质的散射和吸收——浊度高的水不仅更不透明，还会让背景产生轻微的模糊和色偏。
- **光泽**不是贴图高光，而是根据光源方向和表面法线实时计算——能量流强时高光更锐利，弱时更弥散。
- **水滴**不是静态图标，而是有表面张力、有蒸发速率、有汇聚行为的动态系统——湿度高时水滴更大更圆，干燥时更小更扁。
- **折射**不是滤镜，而是对背景的实时扭曲——温度梯度大的地方，背景产生热浪般的轻微波动。

**渲染的物理正确性是可验证的**：如果你把传感器数据录下来，回放时渲染结果应该和实时渲染一致。这不是“看起来像”，是“算出来就是”。

### 第四层：交互层

用户如何与这些感知界面互动。核心原则：**交互不是“操作”，是“照料”**。

- **触摸**：不同材质的表面有不同的触感反馈——玻璃是凉的、陶土是温的、木头是暖的。触摸过滤槽外壁，温度反映水温。
- **注视**：不需要点击，注视超过 2 秒会触发细节展开——透明度变化的历史曲线以水波纹的形式在表面扩散。
- **声音**：水流声、气泡声、堆肥翻动声——不是提示音，是系统运转的真实声音的放大。用户闭着眼睛也能判断系统是否正常。
- **气味**（可选）：堆肥区的气味采样，经过稀释后以微弱的、可控的方式释放——不是臭味，是“土壤在呼吸”的信号。

**关键设计：交互必须容忍“不操作”。** 用户不需要持续监控，系统在异常时通过视觉/听觉的变化主动引起注意。正常运转时，界面是安静的、有节律的、不打扰的。

### 第五层：意义层

用户从感知中建构理解。这一层不是界面能直接设计的，但可以被**引导**：

- **时间对比**：界面保留“昨天此时”的淡影，用户看到的是变化的方向和幅度，而不是一个静态值。
- **关联提示**：当灰水浊度上升时，界面边缘轻微泛黄，同时厨房水槽的界面也轻微泛黄——用户感知到的是系统关联，不是孤立数据。
- **阈值预兆**：在接近临界值之前，视觉语言开始“紧张”——边缘变锐、光泽变冷、流动变急。用户不需要读数字，身体先感知到“快到了”。

## 四、组件库：从图标到现象

不是“FA 风格的图标”，而是**把状态呈现为现象**的组件。每个组件都是一个小型的物理模拟器。

### 1. 透明度槽（Clarity Vessel）

一个容器，内部介质的透明度由真实浊度驱动。不是进度条，是**看得见的水**。用户看到的是“这水有多清”，而不是“水质 85%”。

- 正常状态：介质清澈，背景清晰可见，表面有柔和光泽。
- 浊度上升：介质逐渐浑浊，背景模糊，光泽变散。
- 临界状态：介质几乎不透明，表面张力增大，边缘锐利。
- 交互：触摸外壁，温度反映水温；注视 2 秒，历史浊度以波纹扩散显示。

### 2. 光泽面（Luster Surface）

一个表面，光泽强度由能量流驱动。不是电池图标，是**看得见的能量**。

- 充电中：表面泛起流动的高光，方向与能量流方向一致。
- 放电中：高光变弱、变散，表面趋于哑光。
- 满储：高光稳定、锐利，表面有轻微的“饱和感”。
- 空储：表面暗淡，边缘有轻微的“干涸”纹理。

### 3. 气泡柱（Bubble Column）

一个垂直柱体，气泡频率和大小由微生物活性驱动。不是“活性 72%”，是**看得见的代谢**。

- 高活性：气泡密集、上升快、大小均匀。
- 低活性：气泡稀疏、上升慢、大小不一。
- 停滞：无气泡，介质分层，表面有薄膜。
- 交互：倾听气泡声，频率反映活性；触摸柱体，温度反映堆肥核心温度。

### 4. 色温环（Thermal Ring）

一个环形界面，色温由温度驱动。不是温度计，是**看得见的热**。

- 低温：冷白到淡蓝，环体收缩。
- 适宜：暖白到淡黄，环体舒展。
- 高温：橙红到深红，环体扩张，边缘有热浪扭曲。
- 临界：深红，环体边缘锐利，有轻微的“沸腾”纹理。

### 5. 湿度植（Moisture Flora）

一株真实的或模拟的植物，状态由土壤湿度驱动。不是湿度百分比，是**看得见的生命**。

- 湿润：叶片舒展，颜色饱和，表面有微小水珠。
- 适宜：叶片挺立，颜色正常，生长稳定。
- 干旱：叶片下垂，颜色偏黄，边缘卷曲。
- 交互：触摸叶片，弹性反映含水量；观察叶尖，是否有露珠反映空气湿度。

### 6. 深度井（Depth Well）

一个多层界面，每一层的透明度和折射率不同，代表不同处理阶段。不是流程图，是**看得见的过程**。

- 顶层：原水，浑浊，折射强，背景扭曲。
- 中层：过滤中，半透明，有悬浮颗粒缓慢沉降。
- 底层：净化后，清澈，折射弱，背景清晰。
- 交互：注视某一层，该层展开细节；触摸层间边界，显示该层的处理参数。

## 五、交互模式：照料，而不是操作

### 模式一：日常巡视（Ambient Monitoring）

界面在正常情况下是**安静的、有节律的**。用户不需要“查看”，只需要在路过时瞥一眼——水的清澈度、光泽的强弱、气泡的节奏、植物的状态。这些现象构成一个**背景感知场**，用户不需要集中注意力，但异常会自动“跳出来”。

**设计约束：正常状态不能有“通知”。** 通知是扁平界面的产物——因为界面平时无感，所以只能靠弹窗来提醒。FA 感知系统的正常状态本身就是有信息的，不需要额外通知。

### 模式二：异常吸引（Anomaly Attraction）

当某个物理量偏离正常范围时，视觉现象发生变化——不是弹窗，是**现象本身变得“不对劲”**。水变浑了、光泽变冷了、气泡变慢了、植物下垂了。用户的身体先于认知注意到变化。

**设计约束：异常必须分级。** 轻微偏离是“柔和的变化”（光泽变散、颜色偏移）；严重偏离是“紧张的变化”（边缘锐利、流动变急、色温骤变）。用户不需要读数字，就能判断“需要现在处理”还是“可以等一等”。

### 模式三：深度参与（Deep Engagement）

当用户决定介入时，界面展开细节——但不是数字面板，是**可操作的物理模拟**。用户可以“拨动”一个虚拟阀门，看到水流变化；可以“翻动”堆肥，看到气泡频率变化；可以“调整”映射曲线，让某个物理量在视觉上更敏感。

**设计约束：参与必须改变系统。** 用户的介入不是“查看数据”，是**实际影响代谢过程**。拨动阀门真的改变流量，翻动堆肥真的改变温度，调整映射曲线真的改变感知优先级。这是“可参与”的最终含义：不是“能看到”，是“能改变”。

### 模式四：时间回看（Temporal Reflection）

界面保留历史痕迹——不是折线图，是**时间的沉积**。透明槽的内壁有水垢的痕迹，光泽面有能量流的历史纹理，堆肥区有不同阶段的颜色分层。用户看到的是“系统经历了什么”，而不是“当前值是多少”。

**设计约束：历史必须可追溯。** 每一条痕迹都对应一个时间段的数据，用户可以“触摸”痕迹来展开那段时间的细节。这是“可追溯”的最终含义：不是“有记录”，是“能感知到记录”。

## 六、技术实现路径

### 阶段一：单节点原型（3-6 个月）

选择一个代谢节点（建议灰水过滤槽），部署传感器 + 映射引擎 + 渲染界面。

- 传感器：浊度、流量、温度
- 映射：浊度→透明度，流量→流动纹理速度，温度→色温
- 渲染：基于物理的透明度模拟 + 实时折射
- 验证：盲测用户能否仅凭视觉判断水质

### 阶段二：多节点网络（6-12 个月）

扩展到 3-5 个节点，建立节点间的关联映射。

- 节点：灰水、堆肥、雨水、能源、土壤
- 关联：一个节点的异常在关联节点上产生“共振”现象
- 验证：用户能否感知到系统级的关联，而不仅是单节点状态

### 阶段三：社区部署（12-24 个月）

在真实社区部署，收集长期使用数据。

- 关键指标：用户主动巡视频率、异常响应时间、参与维护的意愿、对系统状态判断的准确率
- 验证：与扁平界面版本做对照实验，测量感知敏感度和参与度的差异

### 技术栈建议

- 传感器：开源硬件（ESP32 + 通用传感器），可校准、可更换
- 映射引擎：轻量级规则引擎，映射曲线可配置、可审计
- 渲染：WebGL / Three.js，物理基础的透明度、折射、光泽模拟
- 数据：本地优先，社区可访问，不上传云端

## 七、验证方法：怎么知道它真的让人更敏感

### 盲测一：状态判断

给用户看 FA 感知界面和扁平数据界面，让他们判断系统状态（正常/异常/临界）。测量判断准确率和反应时间。假设：FA 界面的判断更快、更准，尤其是对“临界”状态。

### 盲测二：异常发现

在用户不知情的情况下引入轻微异常（如浊度缓慢上升），测量用户主动注意到的時間。假设：FA 界面的异常发现时间显著短于扁平界面。

### 盲测三：关联感知

改变一个节点的状态，测量用户对关联节点变化的感知。假设：FA 界面的关联映射让用户更容易感知系统级的影响。

### 长期跟踪

- 用户主动巡视的频率和时长
- 用户对系统维护的参与度
- 用户对系统状态的“直觉”准确率（不看界面，凭记忆判断）
- 用户对界面的情感依恋（“我喜欢看它运转” vs “我只是需要查数据”）

## 八、风险与边界

**风险一：感知过载。** 如果每个节点都有丰富的视觉现象，用户可能被淹没。防御：**正常状态必须安静**，异常才“跳出来”。视觉丰富性不等于视觉噪音。

**风险二：映射的任意性。** 如果映射规则是设计者随意定的，用户无法建立稳定的感知习惯。防御：**映射必须基于物理相似性**——透明度对应浊度是直觉的，光泽对应能量流是有隐喻基础的，气泡对应活性是有经验支撑的。任意映射（如“红色代表磷储备”）是符号，不是感知。

**风险三：技术的黑箱化。** 如果传感器需要专业校准、渲染引擎不可审计，系统就变成了新的黑箱。防御：**传感器可更换、映射可配置、渲染可验证**。用户能理解“为什么水变浑了”，而不只是“界面变浑了”。

**风险四：FA 被消费主义收编。** 这套系统可能被简化为“好看的界面”，失去与真实过程的连接。防御：**可见化测试**——每一个视觉现象都必须指向一个可查的数据链。没有数据链的 FA 是装饰，有数据链的 FA 是感知。

---

## 九、一句话的收束

**FA 感知系统的目标不是“让界面更好看”，是“让用户的身体重新参与到代谢过程中”。** 扁平界面让用户对着数字发呆，FA 感知系统让用户看到水在变清、能量在流动、土壤在呼吸、系统在运转——**不是通过读数，是通过看、摸、听、闻。** 它的验证标准不是“用户觉得好看”，是“用户能不能在不读数字的情况下，判断系统是否正常、是否需要介入、是否在变好”。
