# 05 · 多端扩展

> 青橙全栈 · 技术框架提案 ｜ 状态：提案 / 未实现 ｜ 日期：2026-10-26 13:24
> 第一版只做 Web；这一篇说明未来移动端、游戏、CLI 怎么接，避免 Web 架构把未来堵死。

## 一、共享什么，不共享什么

| 层 | 是否共享 | 说明 |
| --- | --- | --- |
| 应用契约（页面/动作/数据/auth） | 部分共享 | 数据/权限/业务规则可共享；页面/UI 不共享 |
| 数据 schema/迁移 | 共享 | 同一套表/迁移；移动端可能用本地缓存 |
| auth/session | 部分共享 | Web cookie；移动端 token；服务端统一 |
| 设计 token | 共享 | LRDS 的语义 token |
| UI 组件 | 不共享 | Web HTML / 移动原生 / 游戏主题各一套 |
| 渲染 | 不共享 | Web SSR / 移动原生 / 游戏引擎 |
| CLI | 共享 | 同一套命令/代码生成 |

> **共享契约，不共享渲染。**

## 二、移动端

### 2.1 先 PWA/WebView，后原生

- 第一版：Web 应用响应式 + PWA；可安装、离线缓存（后续）；
- 第二版：WebView 壳（Capacitor/自研）复用 Web UI；
- 第三版：原生/React Native/Expo adapter，复用数据/auth/业务 API。

原因：

- 青橙全栈的 Web 第一版能覆盖大量“应用”需求；
- 移动端原生是另一个渲染世界，过早做会拖垮核心；
- 先验证 API/数据/auth 契约是否平台无关。

### 2.2 移动端需要的适配

- token 存储（不要复用 cookie）；
- 安全区/触控/Dynamic Type（见 `design/kits/app`）；
- 推送/深链/离线；
- 生物识别/钥匙串；
- 审核/隐私清单。

## 三、游戏

游戏（Godot）**不嵌入 JS 框架**；共享：

- HTTP/JSON API（账号、存档、商店、排行榜）；
- 数据 schema/迁移（服务端）；
- 设计 token/风格卡（客户端主题）；
- 内容/规则数据（可由服务端或打包）。

不共享：

- 渲染/场景/输入；
- Web 组件；
- 前端路由。

游戏接入方式：

```text
Godot 客户端 → HTTPS API → 青橙全栈服务端 → SQLite/Postgres
```

需要额外做的：

- 游戏专用 auth（设备/平台账号/匿名升级）；
- 幂等/重放保护；
- 低延迟/断线重连；
- 版本/内容签名。

## 四、CLI

CLI 是最容易共享的端：

- 用同一套 `qc` 核心；
- 命令：`qc db` / `qc auth` / `qc content` / `qc export`；
- 不依赖 Web 渲染；
- 可作为运维/内容/数据工具。

第一版先把 `qc` 做成 Web 工具链；CLI 应用（非框架命令）后置。

## 五、平台矩阵

| 能力 | Web | Mobile | Game | CLI |
| --- | --- | --- | --- | --- |
| 路由/页面 | ✅ | 原生导航 | 场景 | 命令 |
| 数据/迁移 | ✅ | API/本地缓存 | API | ✅ |
| auth | cookie | token | 平台/设备 | token |
| 设计 token | CSS | JSON/原生 | Godot theme | 终端色 |
| UI 组件 | HTML/LRDS | 原生/自绘 | Godot | 文本 |
| 构建 | esbuild | 平台工具 | Godot | 单文件 |

## 六、什么时候做下一端

触发条件，不是日期：

- Web 框架有 **≥2 个真实应用** 稳定运行；
- 数据/auth/API 契约经过真实使用；
- 有一个明确的移动/游戏需求，而不是“为了全栈”；
- 现有端没有因为抽象而变得难维护。

否则不做。

## 七、避免“一套代码跑所有端”

- 不承诺 100% 共享；
- 不把 Web DOM 抽象成“万能 UI”；
- 不让游戏/移动端为了复用而牺牲体验；
- 共享的是**语义/数据/权限/业务规则**，不是像素。

## 八、第一版预留的接口

- `runtime` adapter 接口；
- `data` adapter 接口；
- `auth` provider 接口；
- `ui` renderer 接口（HTML/island）；
- `qc` 命令注册表。

这些接口现在只为 Web 服务，但签名不要写死 Node/Bun/SQLite/HTML。
