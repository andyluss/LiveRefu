# 06 · 路线图与验收

> 青橙全栈 · 技术框架提案 ｜ 状态：提案 / 未实现 ｜ 日期：2026-10-26 13:24
> 原则：**先用一个真实应用证明，再扩平台。** 不做“先写框架、再找用户”。

## 一、阶段

### P0 · 决策与地基（当前）

- 决策清单 [08](08_决策清单.md) 拍板；
- 确定名称/命名空间/CLI；
- 确定运行时/UI/数据/auth/依赖策略；
- 不写框架代码。

**出口**：关键决策有结论；没有结论的不进入 P1。

### P1 · 最小骨架（Hello, CRUD）✅ 2026-10-26

- `qc new` / `qc dev` / `qc build` / `qc start`；
- 文件路由、页面、布局；
- SQLite 连接 + schema + 迁移；
- 一个页面 + 一个 action + 一张表；
- 错误页/日志/`qc doctor`；
- 测试：类型 + HTTP 集成。

**出口**：空目录 10 分钟出页面；1 小时出 CRUD；Node 生产启动成功。

> 已落地：见 [09 P1 实现记录](09_P1实现记录.md)。

### P2 · 完整应用（Auth + 表单 + 安全）← 下一步

- session/password/CSRF/安全头；
- 表单校验/错误回填；
- 权限/角色；
- 文件上传/邮件（可选）；
- 配方：列表/详情/创建/编辑/删除/登录；
- 可访问性/安全默认值；
- 一个真实应用（博客/后台/LiveFab 子集）dogfood。

**出口**：真实应用能登录、CRUD、迁移、部署；无 P0 安全债。

### P3 · 打包与部署

- `qc build` 产物/manifest；
- Docker 模板；
- 备份/健康检查/日志；
- `qc update` 迁移提示；
- 文档/示例/错误诊断。

**出口**：在目标机器单进程部署；升级不破坏数据。

### P4 · 第二端（按需）

- 移动 PWA/WebView 或 Godot API；
- 只做有真实需求的一端；
- 不为了“全栈”而扩。

## 二、第一版必须有的验收

| 类别 | 验收 |
| --- | --- |
| 启动 | `qc new` + `qc dev` 无配置可跑 |
| 路由 | 静态/参数/404/405/重定向 |
| 渲染 | HTML 转义/布局/表单 |
| 数据 | 迁移/事务/参数化/测试库 |
| Auth | session/密码/CSRF/权限 |
| 错误 | 开发堆栈/生产 request id |
| 安全 | 头/CSRF/上传限制/密钥 |
| 可访问性 | 键盘/焦点/对比度/标签 |
| 构建 | 产物可启动；无隐藏运行时 |
| 诊断 | `qc doctor` 能定位常见问题 |
| 依赖 | 核心运行时依赖 ≤5；锁文件 |
| 文档 | 新用户 1 小时能完成教程 |

## 三、Dogfood

优先选一个**真实、非关键**的应用：

- 一个小型内容站/笔记/后台；
- 或 LiveFab 的一个子模块；
- 不先迁移网站全站，不先重写 LiveFab。

Dogfood 的判据：

- 开发者不需要读框架源码；
- 遇到问题能靠错误/文档解决；
- 升级一次不破坏应用；
- 性能/安全可接受；
- 愿意把第二个应用也放上来。

## 四、估算（量级，不是承诺）

| 阶段 | 量级 |
| --- | --- |
| P1 骨架 | 1–2 周 |
| P2 完整应用 | 2–4 周 |
| P3 打包部署 | 1–2 周 |
| P4 第二端 | 另立提案 |

估算前提：一个人 + AI 协作；不包含美术/内容/业务。

## 五、停止条件

出现以下情况，停下来重估：

- 核心依赖超过预算且无法替换；
- 1 小时内做不出 CRUD（说明抽象错了）；
- dogfood 应用必须读源码才能用；
- 安全/可访问性无法默认保障；
- 维护成本高于现有 Nuxt/Astro；
- 没有真实应用愿意用。

## 六、第一版不做

- 移动端/游戏/CLI 全家桶；
- 多租户/SaaS 计费；
- 实时协作/WebSocket；
- 完整 CMS；
- serverless/edge；
- 可视化建站；
- 自动迁移所有旧项目。
