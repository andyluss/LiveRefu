# 02 · 架构总览

> 青橙全栈 · 技术框架提案 ｜ 状态：提案 / 未实现 ｜ 日期：2026-10-26 13:24

## 一、分层

```text
┌──────────────────────────────────────────────┐
│ L4 应用：pages / actions / data / auth / ui   │
├──────────────────────────────────────────────┤
│ L3 核心：router / lifecycle / config / errors │
├──────────────────────────────────────────────┤
│ L2 适配：runtime / data / ui / deploy         │
├──────────────────────────────────────────────┤
│ L1 原语：Web Request/Response / SQLite / TS   │
├──────────────────────────────────────────────┤
│ L0 平台：OS / Node / Bun / 浏览器 / 文件系统   │
└──────────────────────────────────────────────┘
```

**原则**：越往下越稳定，越往上越可替换；核心不感知具体数据库/运行时/UI 库。

## 二、核心模块

| 模块 | 职责 | 不做什么 |
| --- | --- | --- |
| **router** | 文件→路由、参数、方法、中间件、404/405 | 不解析 HTTP 原始字节 |
| **lifecycle** | 请求上下文、错误、重定向、cookie、headers | 不渲染 HTML |
| **config** | `qc.config.ts`、环境变量、默认值、诊断 | 不读取业务数据 |
| **app** | page/action/api 的注册与调用 | 不绑定具体 UI |
| **data** | schema、迁移、事务、查询 helper | 不做 ORM 魔法 |
| **auth** | session、密码、角色、OAuth 适配位 | 不做用户业务 |
| **ui** | HTML 模板、设计系统组件、islands 接口 | 不强制客户端框架 |
| **cli** | new/dev/build/start/db/auth/test/doctor | 不做运行时逻辑 |
| **adapters** | Node/Bun、SQLite/Postgres、HTML/其它 | 不反向依赖应用 |

## 三、请求生命周期

```text
请求
  → runtime adapter（Node/Bun）
  → 规范化 Request
  → router 匹配
  → middleware（安全头 / session / CSRF / 限流）
  → page / action / api
  → data / auth / files / email
  → 渲染 HTML 或返回 JSON/stream
  → 设置 cookie/headers
  → 响应
  → 结构化日志 / request id
```

关键约定：

1. **一个请求一个上下文**；不把请求状态放全局。
2. **错误统一收口**；`NotFound` / `Unauthorized` / `ValidationError` 有默认页。
3. **重定向/cookie/headers 只通过上下文**，不让页面直接写全局。
4. **动作和页面共享同一套 auth/data 上下文**。
5. **不隐藏响应**：`qc doctor` 能打印最终 headers/route。

## 四、项目结构（默认）

```text
my-app/
├── app/
│   ├── pages/
│   │   ├── index.page.ts
│   │   └── posts/
│   │       ├── index.page.ts
│   │       └── [slug].page.ts
│   ├── actions/
│   │   └── posts/
│   │       ├── create.action.ts
│   │       └── delete.action.ts
│   ├── api/
│   │   └── health.api.ts
│   ├── data/
│   │   ├── schema.ts
│   │   └── migrations/
│   ├── auth/
│   │   └── config.ts
│   ├── ui/
│   │   └── components/
│   └── lib/
├── public/
├── qc.config.ts
├── package.json
└── tsconfig.json
```

- **文件即路由**；页面/动作/接口各有后缀，避免“这个文件是前端还是后端”的歧义。
- **数据 schema 和迁移在一处**；不靠运行时自动同步。
- **UI 组件在 app/ui**；可直接用 LRDS 的 token/HTML 组件。
- **public 只放静态资源**；不放源码。

## 五、核心契约（API 形状）

```ts
// page
export default definePage({
  auth: 'optional',
  async load(ctx) {
    return { posts: await ctx.db.query('select * from posts order by id desc') }
  },
  render({ posts }) {
    return html`<h1>Posts</h1>${posts.map(p => html`<a href="/posts/${p.slug}">${p.title}</a>`)}`
  },
})

// action
export default defineAction({
  input: postInput,
  auth: 'required',
  async handle({ input, db, session }) {
    const id = await db.insert('posts', { ...input, authorId: session.userId })
    return redirect(`/posts/${id}`)
  },
})

// data
export const posts = defineTable('posts', {
  id: 'integer primary key',
  slug: 'text unique not null',
  title: 'text not null',
  body: 'text not null',
  createdAt: 'text not null',
})

// auth
export default defineAuth({
  session: { store: 'sqlite', cookie: 'qc_session' },
  password: { min: 10 },
  oauth: { github: { clientId: env('GITHUB_ID'), clientSecret: env('GITHUB_SECRET') } },
})
```

> 以上是**提案形状**，不是已实现 API。具体命名在 P1 前定。

## 六、数据层

- **SQLite 优先**：单文件、零运维、适合单机/小团队；先满足博客、后台、工具、LiveFab 子集。
- **SQL-first**：schema 与迁移是 SQL/DSL 的明确产物，不靠运行时扫描/自动改表。
- **typed helper**：`db.query` / `db.insert` / `db.transaction` 有类型；复杂查询允许 raw SQL。
- **连接/事务**：一个请求一个连接上下文；事务显式；长事务/异步不要跨请求。
- **Postgres adapter**：同契约，SQL 方言差异由 adapter 处理；不保证“零改动”，但页面/动作不改。

## 七、Auth

- 默认 **session cookie + SQLite session store**；
- 密码用成熟哈希（argon2/bcrypt），不自己写；
- 默认 CSRF（表单 token + SameSite）；
- 角色/权限是应用层 `requireRole()`，不塞进框架核心；
- OAuth/OIDC 走 adapter；不在第一版做复杂 SSO；
- 不把“登录”绑定到第三方服务。

## 八、UI / 渲染

- **HTML-first**：服务端输出 HTML；表单是真实表单；
- **islands 可选**：需要客户端交互时，按组件挂载；不强制全站 SPA；
- **LRDS**：token/组件/焦点/对比度直接用；框架只提供 `<html>` 模板、布局、表单 helper；
- **无虚拟 DOM 默认**：减少运行时；需要时由 island adapter 提供。

## 九、运行时与部署

- **Node 24 兼容为核心**（生产稳定；工作区已有 Bun NAPI 崩溃教训）；
- **Bun adapter 可选**（开发/单文件部署）；
- **单进程 + SQLite + 反向代理** 为默认部署；
- 后续再做 serverless/edge adapter，不放进第一版。

## 十、可观测与诊断

- 请求 id、方法、路径、状态、耗时、错误码；
- `qc doctor`：打印配置、路由、数据连接、session、构建产物；
- 错误页：开发显示堆栈/修复建议；生产只显示 request id；
- 健康检查 `/health` 由框架提供，不靠用户写。

## 十一、退出通道

| 想退出 | 出口 |
| --- | --- |
| 路由 | raw handler / 自定义 middleware |
| 渲染 | 直接返回 `Response`/HTML |
| 数据 | raw SQL / 换 adapter |
| auth | 自定义 provider |
| 构建 | 拿到 server entry，自己打包 |
| 部署 | 标准 Node 进程，不依赖专有平台 |

> 架构的成败不在“默认路多聪明”，而在“下车时会不会掉进坑里”。
