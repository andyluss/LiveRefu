# R-008 · 风格卡：换皮肤，不换语法

> **状态**：`active` ｜ **级别**：MUST ｜ **生效**：2026-10-21
> **范围**：产品/纪元风格卡、介质 kit ｜ **Owner**：设计主控 + 产品
> **关联**：D5、[07 风格卡登记](../docs/07_风格卡登记.md)、[02 §五](../docs/02_系统架构.md)

## 一、规则

**风格卡只换色板、材质、光源、装饰母题、图像处理、字体族；不换信息位置、字阶、间距、焦点、交互语法与无障碍下限。**

## 二、要求

1. **两层**：语法层（永不变）+ 风格卡（每产品/纪元一张）；不得把风格卡值写回 `sys.*`。
2. **登记**：每张卡有 ID、源 JSON、投影产物、对账方式；未登记不算存在。
3. **语义固定**：`sys.*` 名不变；产品差异用 `product.<product>.*`。
4. **对比度**：每张卡都要过 R-006；不得以“氛围”为由降低可读性。
5. **信息位置**：卡面/面板/表单的信息位置不随风格卡移动。
6. **反模式**：不得用风格卡掩盖结构问题（间距、层级、焦点）。

## 三、验收

```bash
node design/tools/check_contrast.ts
node design/tools/check_tomorrows_channel_skin.ts
bash design/tools/check.sh
```

## 四、例外

- 游戏内全屏叙事/过场可暂时改变信息位置，但必须可跳过、可恢复、可读。
- 打印/实体按介质规范另定，不共用屏幕风格卡。

## 五、反例 / 迁移

- **反例**：风格卡改动信息位置；为“氛围”降低对比度；把产品值写回 `sys.*`；未登记就上线。
- **迁移**：先把差异登记为 `product.*`，再投影为风格卡；对比度不达标的卡不得发布。
