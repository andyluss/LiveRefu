# 05 · 质量闸门

> 纲领第六篇 ｜ 关联：[R-006 无障碍](../rules/R-006-accessibility.md)、[R-013 评审闸门](../rules/R-013-review-gates.md)

## 一、闸门顺序

```text
1 结构/别名     token 能解析、无循环、类型合法
2 语义         角色齐全、成对、无裸值
3 对比度       正文/状态/焦点/边框
4 风格卡       稀疏覆盖、角色完整、皮肤 audit
5 生成物       CSS/JSON/报告可复算
6 视觉          截图基线/回归
```

前一层失败，不进入下一层。

## 二、对比度下限

| 对 | 最低 |
| --- | --- |
| 正文 text / bg、surface | 4.5 |
| 次要 textMuted / bg、surface | 4.5 |
| onAction / action | 4.5 |
| onDanger / danger | 4.5（或明示豁免） |
| focus / 相邻背景 | 3.0 |
| border / surface | 3.0 |

状态色不能以“品牌色”为由豁免；豁免必须登记，并在 UI 中保留文字/图标。

## 三、风格卡闸门

每张卡检查：

- 完整角色集是否有来源；
- 是否只做稀疏覆盖；
- `mode` 是否明确；
- 深浅模式下 `color-scheme` 是否跟随；
- 主题切换是否清除旧皮肤；
- 是否有截图基线。

## 四、项目工具

具体命令、路径与运行方式由**项目自己的文档**维护；纲领只规定闸门顺序与阈值，不绑定某个工具。

参考实现见 [`../projects/livedso/`](../projects/livedso/README.md) 的项目文档。

## 五、失败处理

- **不静默绕过**：失败必须修复，或在评审中登记例外；
- **不弱化阈值**：不改 4.5 来让坏卡拉绿；
- **不手改生成物**：改源，再生成；
- **不把截图当唯一证据**：对比度与角色完整性必须先过。

## 六、发布前最小证据

1. token 检查通过；
2. 对比度通过；
3. 风格卡 audit 通过；
4. 至少一张真实页面截图；
5. 变更日志与版本头一致；
6. 有回滚路径。
