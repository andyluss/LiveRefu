# 06 · 多品牌与多介质

> 纲领第七篇 ｜ 关联：[D2/D5](../docs/00_决策总表.md)、[02 系统架构](../docs/02_系统架构.md)、[R-008](../rules/R-008-style-cards.md)

## 一、统一的是语法，不是外观

```text
品牌 A / 网站 / 亮色 → 一套角色，不同 product 覆盖
品牌 B / 游戏 / 暗色 → 同一套角色，另一张 product 卡
品牌 C / App / 触控 → 同一套角色，另一套尺寸/介质规则
```

- 语义角色同名；
- 介质只改“怎么落地”；
- 产品/纪元只改 product 覆盖；
- 不复制一整套 token。

## 二、风格卡与产品

| 概念 | 层 | 例子 |
| --- | --- | --- |
| 品牌核心 | L0 | 标志、语气、署名 |
| 语义角色 | sys | `sys.color.action` |
| 产品差异 | product | `product.archive.role.bg` |
| 介质适配 | kit | Web CSS / Godot Theme / App JSON |

一张风格卡 = 一个 `product.<id>` 的稀疏覆盖 + 元数据 + QA。

## 三、介质差异

| 介质 | 共享 | 特有两 |
| --- | --- | --- |
| Web | 角色、字阶、间距、焦点 | 响应式、CSS 变量、打印样式、减少动态 |
| Godot | 角色、状态、焦点 | Theme、手柄焦点、像素对齐、安全区 |
| App | 角色、触控目标 | Dynamic Type、平台导航、安全区 |
| Print | 角色、字阶语义 | CMYK/专色、出血、纸张、字体嵌入 |

**不允许**每个介质自己发明一套角色名。

## 四、多品牌接入

1. 建 `product.<brand>` 覆盖，不改 `sys`；
2. 只覆盖差异角色；
3. 过对比度/风格卡闸门；
4. 登记 owner、维护代价、弃用条件；
5. 加视觉基线。

## 五、边界

- 品牌可以改变视觉语言，但不能改变信息架构与无障碍下限；
- 产品专属业务色留在产品层，不进 `sys`；
- 不同介质的实现可以不同，语义必须同名；
- 没有真实消费者的品牌/介质包不建。
