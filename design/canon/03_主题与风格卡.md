# 03 · 主题与风格卡

> 纲领第四篇 ｜ 关联：[R-001 主题模式](../rules/R-001-theme-modes.md)、[R-008 风格卡](../rules/R-008-style-cards.md)

## 一、语法不变，皮肤可变

```text
语法层：角色名 / 字阶 / 间距 / 焦点 / 无障碍
风格卡：同一角色下的取值、材质、字体族、装饰
```

风格卡可以很不同，但不能改变：

- 信息位置；
- 交互语法；
- 字阶与间距语义；
- 焦点可见性；
- 对比度下限。

## 二、主题是稀疏覆盖，不是第二套系统

推荐：

```text
sys.role.*                默认主题的 50 角色
product.<card>.role.*     仅与默认不同的角色
```

风格卡：

```json
{
  "id": "archive",
  "mode": "light",
  "roles": {
    "bg": "sys.role.bg",
    "text": "sys.role.text",
    "action": "product.archive.role.action"
  }
}
```

- `sys.role` 提供默认值；
- `product.<card>` 只写差异；
- 风格卡只做引用，不写 `#rrggbb`；
- 不允许每张卡复制完整 50 角色到 `theme.<card>`。

## 三、为什么删掉全量 `theme-roles`

全量副本会造成：

1. 风格卡 `roles` 与 theme token 双源；
2. token 数量虚增但没有新增表达；
3. 默认 `sys` 缺失被掩盖；
4. 迁移时不知道哪个才是“角色源”。

因此 `theme.*` 只保留为**迁移别名**：

- 当前版本继续兼容；
- 下一个 major 删除；
- 新卡不再生成 `theme-roles.tokens.json`。

## 四、风格卡的完整定义

每张卡必须具备：

| 字段 | 说明 |
| --- | --- |
| `id` | 稳定 id；不随展示名改 |
| `name` | 展示名 |
| `mode` | `light` / `dark` |
| `note` | 谁维护、代价是什么 |
| `colors` | 用于展示/对比的色板（可引用角色或 ref） |
| `roles` | 50 角色引用；缺口必须有 fallback |
| `qa` | 对比度、角色完整性、截图基线 |

## 五、主题评审

1. 这张卡解决什么场景？
2. 哪些角色是覆盖，哪些继承默认？
3. 文字/背景/边框/焦点是否过闸门？
4. 深浅模式下的原生控件是否跟随？
5. 改动后，哪些产品需要重新截图？
6. 这张卡谁维护、何时弃用？

## 六、边界

- 风格卡不是品牌手册；
- 不负责布局、信息架构；
- 不允许以“氛围”降低可读性；
- 不把产品专属组件塞进 50 角色。
