# 04 · 组件契约

> 纲领第五篇 ｜ 关联：[R-007](../rules/R-007-component-contracts.md)、[`../components/`](../components/)

## 一、先契约，后实现

组件进入核心前，先写清：

```text
anatomy     解剖：容器/标签/图标/帮助/错误
states      default / hover / active / focus-visible / disabled / loading
tokens      每部分引用哪些 sys/component token
keyboard    Tab / Enter / Space / Escape / Arrow
a11y        role / aria / 焦点顺序 / 错误关联 / 200% 字号
do / dont   正确与错误用法
```

没有契约的组件只能是产品局部实现，不能进核心库。

## 二、Token 只引用语义

```json
{
  "button": {
    "bg": "sys.color.action",
    "fg": "sys.color.onAction",
    "border": "sys.color.border",
    "focus": "sys.color.focus",
    "height": "component.button.height",
    "radius": "component.button.radius"
  }
}
```

- 不写 `#hex`；
- 不写 `12px`，除非是 component 层尺寸；
- 状态差异用 actionHover/Pressed/Disabled；
- 组件不能私自定义 `--primary` 第二套变量。

## 三、状态必须完整

只定义 default 的组件不算契约完成。至少：

- hover / active / focus-visible / disabled；
- 错误/只读/加载按组件类型补齐；
- 每个状态都有键盘与屏幕阅读器行为。

## 四、跨端一致

Web / App / 游戏共用：

- 角色名；
- 状态名；
- 尺寸语义；
- 无障碍下限。

介质只改变实现：CSS 变量、Godot Theme、Swift/Kotlin 常量。

## 五、评审问题

1. 这个组件是否跨两个产品重复？
2. 它的哪个部分用了哪个角色？
3. 焦点与错误是否只靠颜色？
4. 200% 字号/减少动态下是否可用？
5. 没有真实消费者时，为什么现在进核心？
