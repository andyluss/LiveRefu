# 09 · 落地检查表

> 纲领第十篇 ｜ 从当前资产迁移到本纲领的验收清单
> 目标不是“文档写完”，而是 **ref/sys/product 真正成为唯一事实来源**。

## 一、Token 层

- [x] scale token 归入 `ref.*`，不再有 `md.scale.*` / `cds.scale.*` 平行层；
- [x] 默认主题 50 角色落在 `sys.role.*`；
- [x] 风格卡差异只生成 `product.<card>.role.*` 稀疏覆盖；
- [x] `theme.<card>` 已删除（LiveDSO v2.0）；
- [x] `theme-roles.tokens.json` 已删除；
- [x] 组件尺寸/部件归 `component.*`；
- [x] 别名可追溯；`sys`/`product` 不再写裸色；
- [ ] 无裸 `#hex` / 裸尺寸进入 `sys` / `component` / `product`。

## 二、风格卡

- [ ] 每张卡有 `mode`；
- [ ] 每张卡 50 角色有来源（继承或覆盖）；
- [ ] 风格卡不写 hex，只引用 token；
- [ ] 对比度通过；
- [ ] 深/浅模式原生控件跟随；
- [ ] 截图基线存在；
- [ ] owner/代价/弃用条件已写。

- [ ] 所有交互状态完整；

- [ ] 有真实消费者。

## 四、工具与闸门

- [ ] token 结构/别名检查；
- [ ] 对比度检查；

## 五、文档

- [ ] 纲领与规则不冲突；
- [ ] 决策记录链接到纲领条目；
- [ ] 迁移步骤可执行；
- [ ] 旧路径有迁移映射；
- [ ] README 能让人 5 分钟找到入口。

## 六、完成定义

一个设计系统变更只有在以下同时成立时才算完成：

```text
源改完 + 生成物复算 + 闸门通过 + 文档/版本 + 可回滚
```

否则只是“改了几个值”。
