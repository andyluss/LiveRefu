# 08 · 治理与演进

> 纲领第九篇 ｜ 关联：[R-010 决策记录](../rules/R-010-decision-records.md)、[R-011 版本](../rules/R-011-versioning.md)

## 一、角色

| 角色 | 权限 |
| --- | --- |
| 用户 | 最终裁决、推翻 |
| 设计主控 | 技术性否决、规则维护 |
| 产品负责人 | 产品级采用与验收 |
| AI 代理 | 执行、检查、提案；不代替用户裁决 |

## 二、什么需要决策记录

- 新增/删除层级；
- 改变角色语义；
- 弃用 token/组件/风格卡；
- 改变对比度或无障碍下限；
- 破坏性迁移。

日常取色、微调不写决策记录，但要有 diff 与截图。

## 三、版本与弃用

- SemVer；
- 破坏性变更进 major；
- 弃用先标记、给窗口、给替换路径；
- 旧别名保留一个 minor；
- 产品钉版本，升级由产品负责人确认。

## 四、评审问题

1. 这个变更属于哪一层？
2. 谁消费、谁维护、谁承担代价？
3. 是否破坏既有角色/契约/风格卡？
4. 如何验证、如何回滚？
5. 是否需要迁移文档与截图？

## 五、纲领自身的演进

- 纲领变更同样需要决策记录；
- 不把纲领写成不可质疑的教义；
- 每次真实项目复盘后，允许修正一条原则；
- 修正必须说明“原来错在哪、代价是什么”。

## 六、最小治理闭环

```text
提案 → 决策 → 实现 → 闸门 → 文档 → 版本 → 复盘
```

没有闸门与版本的“规范”不算完成；没有复盘的“治理”会退化成流程表演。
