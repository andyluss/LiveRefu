# 07 · 实现与工具链

> 纲领第八篇 ｜ 关联：[`../projects/livedso/`](../projects/livedso/README.md)（参考实现）、[R-009](../rules/R-009-generated-artifacts.md)

## 一、源与生成物

```text
手写源： tokens/*.json + components/*.md + canonical docs
生成物： CSS / JSON / 报告 / 截图 / 索引
```

- 不手改生成物；
- 生成器必须可复算；
- 生成物进入版本控制，便于 diff；
- 生成失败即发布失败。

## 二、工具在系统里的位置

工具不是规范本身。它只做三件事：

- 读取源（ref/sys/component/product）；
- 把判断变成可重复检查；
- 把结果投影成可消费产物或报告。

具体实现、命令与项目状态由 `design/projects/` 下的项目文档维护。

## 三、一次变更的完整链路

```text
改 ref
  → 改 sys 角色（如需要）
  → product 覆盖（如风格卡）
  → 组件契约
  → 生成 CSS/JSON
  → token/对比度/风格卡/截图闸门
  → 文档与版本
```

## 四、纲领与项目

纲领不记录单个项目的版本、tag、迁移进度；这些在 [`../projects/livedso/docs/16_项目状态.md`](../projects/livedso/docs/16_项目状态.md) 维护。

## 五、工程约束

- 零运行时依赖优先；
- 本地可运行优先；
- 生成/检查可脚本化；
- 失败退出码明确；
- 不把审计变成“为了绿而弱化阈值”。

## 六、最低交付

一个设计变更至少要带：

1. token diff；
2. 受影响角色/组件；
3. 生成物；
4. 闸门结果；
5. 截图或可复现 URL；
6. 回滚方式。
