# 青橙 OS · Web 模拟操作系统

> **LAB / EXPERIMENTAL** ｜ 状态：`prototype` ｜ 第一个综合实验
> 目标：把青橙设计**当前已确定的语法**与**未来可能的多种世界**放进同一个可操作的桌面。

## 一、一句话

一个借 macOS 的**空间与操作逻辑**、但不复制 macOS 外观的 Web 桌面：
菜单栏、窗口、Dock、Spotlight、控制中心与 9 个应用；右上角的**未来转盘**可在
Archive（现在）、Solar（提案）、Cyber（诊断）之间切换，并始终保留“回到现在”。

## 二、怎么打开

直接双击 `index.html` 即可（无构建、无外部依赖、无网络请求）。

也可以本地起静态服务：

```bash
cd design/lab/os
python3 -m http.server 4173
# http://127.0.0.1:4173
```

## 三、9 个应用

| 应用 | 作用 | 与青橙理念的关系 |
| --- | --- | --- |
| **Finder** | 文件、位置、预览、搜索 | 可查、可追溯；文件带来源/状态 |
| **Notes** | 笔记、编辑、导出 | 可参与、可改写；本地保存 |
| **Settings** | 主题、未来层、减少动态、高对比、重置 | 可退出；三态主题与无障碍 |
| **Gallery** | 未来影像/明信片 | 可感；每张图有“它对应什么状态” |
| **Radio** | 模拟电台、节目单、波形 | 现象优先；明确标注“模拟信号” |
| **Terminal** | 命令、状态、打开应用、切换未来 | 可读退路；所有视觉状态可查 |
| **Calendar** | 月历、事件、维护日 | 维护被看见；可添加/删除 |
| **Mail** | 收件、阅读、写信、发件 | 谁在维护、谁承担代价的叙事 |
| **Weather** | 橙港天气、能源结构、预报 | 可感数据；显示数据来源与代价 |

## 四、未来转盘

右上角 `未来` 按钮：

- **Archive / 现在**：当前 LRDS 的纸感、青绿、琥珀与登记语气；
- **Solar / 提案**：适当的未来，本地能源、维修、社区、低密度；
- **Cyber / 诊断**：高科技低生活，高密度、监控、外包维护。

每次切换都会显示：

- **改了什么**：色板、材质、信息密度、措辞；
- **谁维护 / 谁承担**：这个未来的代价；
- **怎么退出**：一键回到 Archive，或“恢复当前设计”。

未来转盘不是三套桌面，而是**同一套语法上的三张世界皮肤**。

## 五、操作

| 操作 | 方式 |
| --- | --- |
| 打开应用 | 点 Dock 图标 / 双击桌面图标 |
| 移动窗口 | 拖标题栏 |
| 调整大小 | 拖右下角 |
| 最小化 / 最大化 / 关闭 | 标题栏左侧三个圆点 |
| 聚焦搜索 | `⌘K` / `Ctrl+K` 或点菜单栏放大镜 |
| 关闭浮层 | `Esc` |
| 关闭窗口 | `⌘W` / `Ctrl+W` |
| 终端 | 输入 `help`，或 `open notes`、`era solar`、`theme dark` |

## 六、实验假设

1. “未来”不必是三套产品；同一桌面可以承载多张世界皮肤，只要语法不换。
2. “可感”必须有退路：每个未来层都能在 Terminal 里读到当前状态与来源。
3. macOS 的空间逻辑（菜单栏/窗口/Dock/Spotlight）是低学习成本的壳，但视觉必须属于青橙。
4. 诚实展示代价比“未来感”更重要：Solar 有低密度代价，Cyber 有监控/外包代价。

## 七、已知边界

- 全部数据为本地模拟；无真实网络、账号、音频、天气 API。
- Radio 是视觉/时间模拟，不播放真实音频；若需要可后续接 WebAudio。
- 窗口位置/大小不持久化；应用数据（笔记/邮件/日历/设置）持久化到 `localStorage`。
- 只在现代 Chromium/Safari/Firefox 目标；未做旧浏览器兼容。
- 移动端为可用性降级，不是完整触控桌面。

## 八、可能沉淀

- “未来层”作为风格卡的一种承载方式；
- 状态来源/代价面板的组件模式；
- 可退出主题切换的系统级模式；
- 9 应用壳的窗口管理/Spotlight 模式；
- 一套“设计实验”的评审清单。
