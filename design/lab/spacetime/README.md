## 一、实验问题

1. 人能否**先读懂空间，再读懂标签**？
2. 时间除了变成一条从左到右的线，还能怎样被空间化？
3. 当“位置 / 距离 / 方向 / 折叠 / 房间 / 因果”成为主要界面语法，什么变清楚了，什么变危险了？
4. 这些空间隐喻中，哪些可以被回收成 LRDS 的组件、布局或评审问题？

## 三、实验假设

- **H1 位置先于标签**：当对象有稳定空间位置与邻居关系时，人更少依赖文字层级。
- **H2 时间可变成地形**：把时间映射到高度、天气、距离，比均匀刻度更能表达“确定性 / 记忆强度 / 情绪重量”。
- **H3 因果需要织物**：单条时间线无法表达“同一时刻的多股过程”；平行股 + 交叉节点更接近真实项目。
- **H4 尺度需要建筑**：不同时间尺度不是同一个视图的缩放，而是不同房间；换房间应换问题，而不只是换单位。
- **H5 折叠产生比较**：把远距离时间折近，能让人看到“同构/回声”，但必须显式提醒“距离没有真的消失”。

## 四、边界（虚构/模拟）

- 所有节点、事件、房间、年份均为**模拟内容**，不是真实项目数据。
- 没有后端、没有网络请求、没有真实日历/账号。
- 交互是设计探索，不是可用性结论；没有做真人实验。
- 移动端为可用性降级，键盘/触控只覆盖主要路径。
- 时间房间的“流速”是视觉模拟，不是物理时间。

## 七、可能沉淀

- “空间先于标签”的布局评审问题；
- 时间地形的“高度 = 确定性、天气 = 未知”编码；
- 因果织网的 upstream/downstream 高亮模式；
- 时间房间的“换尺度 = 换问题”导航；
- 折叠时间的“并置但不等价”提示模式；
- 一套面向空间/时间界面的可读性、方向感、退出路径检查表。

## 八、不做什么

- 不把这些案例当成已验证的交互模式；
- 不用 3D/动效制造“未来感”而牺牲可读性；
- 不隐藏时间刻度、来源、当前位置与返回路径；
- 不让“空间化”变成对真实因果/时间距离的误导。
