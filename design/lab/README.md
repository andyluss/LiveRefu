# 青橙设计 · 实验区（Lab）

> **这是青橙设计的未来试验场，不是生产规范。**
> 状态：`experimental` ｜ 建立：2026-10-26 ｜ 第一个实验：[青橙 OS](os/README.md)

## 一、这里做什么

`design/lab/` 用来试**尚未确定的设计**：

- 未来可能的界面、材质、动效与空间结构；
- 还不值得进 token/组件契约的交互；
- 多世界语法、风格卡、可感/可参与/可退出理念的极端版本；
- 对 macOS、旧式桌面、游戏 HUD、实体界面等体验的重新组合。

实验**可以使用**未定 token、临时组件、非常规布局、虚构数据、未来技术假设；
它**不必**先通过生产组件的完整闸门。生产规则仍然只管生产，不被实验区拖慢。

## 二、硬边界

1. **不伪装成生产**：实验页面必须标注 `LAB / EXPERIMENTAL`，不得在 README 中暗示已定稿。
2. **不伪造证据**：假数据必须标“模拟/虚构”；不生成假截图、假对比度、假测试。
3. **可退出**：涉及主题/模式/未来层的实验，必须有一条随时回到“当前设计”的路径。
4. **可回收**：每个实验要有“可能沉淀什么”的说明；不能只留下视觉垃圾。
5. **不碰生产源**：实验不得直接改 `design/tokens/`、`design/components/`、产品代码；要沉淀时另开提案。
6. **仍然尊重人**：实验可以奇怪，但不能用不可读、不可键盘操作、不可关闭来制造“未来感”。

## 三、每个实验必须写

- **假设**：这个实验想验证什么？
- **来源**：借了哪些理念/参考？哪些是青橙的，哪些是外部的？
- **边界**：哪些是虚构/模拟/未实现？
- **入口**：怎么打开、怎么操作、怎么退出？
- **回收**：如果成立，能沉淀成 token / 组件 / 规则 / 风格卡中的什么？
- **状态**：`sketch` / `prototype` / `candidate` / `archived`。

## 六、毕业路径

`sketch → prototype → candidate → 生产提案`

进入 `candidate` 前，至少要回答：

- 它解决的是哪个真实问题，而不是“看起来未来”？
- 它的可感现象能追溯到什么状态？
- 谁维护、谁承担代价、谁能退出？
- 它需要哪些 token/组件/规则变更？
- 它能在 200% 字号、键盘、减少动态下工作吗？

> 实验区的价值不是“更大胆”，而是**用较低成本把未来试到可以被判断**。
