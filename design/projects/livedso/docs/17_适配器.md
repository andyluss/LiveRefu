# 17 · 外部 Token 适配器（P2）

> 版本：v1.17 ｜ 日期：2026-10-28 ｜ 范围：DTCG / CSS / Tailwind JSON / Style Dictionary / Figma Tokens → LiveDSO vault

## 一、边界

适配器**不修改用户 token**，也不要求用户采用 LRDS 命名。它做的是：

```text
用户源（只读）
  → 显式 mapping profile
  → 校验（角色/别名/对比度）
  → 生成 LiveDSO vault（ref.source.external + sys + product + style cards）
```

生成物是派生物；源变化后必须重新 `adapt --check`。

## 二、P2 支持

- **DTCG**：`$value` / `$type` 文件或目录；
- **CSS variables**：`:root` / `.dark` 等块中的 `--name: value`；
- **Tailwind JSON**：`theme.extend.colors` / `theme.colors` 导出；
- **Style Dictionary / Figma Tokens JSON**：`value` / `type` 叶子；
- **多主题**：`themes[]` → 默认 `sys.color.*` + 差异 `product.<theme>.role.*`；
- **component 映射**：`component.button.bg` 指向 `sys.color.*` 或源 token；
- **B 档角色建议**：`--suggest` / `--suggest-out` 只输出建议，不自动写入；
- `--dry-run` / `--check` / `--json`；
- source hash、style cards、严格 schema 输出。

仍不支持：

- Figma Variables 原始 API / Figma 文件（需先导出 Tokens Studio JSON）；
- Tailwind JS config（不执行用户代码）；
- 自动语义猜测/自动写入 B 档。

## 三、Mapping profile

单主题：

```json
{
  "theme": { "id": "paper-brand", "name": "Paper Brand", "mode": "light" },
  "source": { "format": "dtcg" },
  "roles": {
    "bg": "color.background",
    "surface": "color.surface",
    "surfaceRaised": "color.surfaceRaised",
    "surfaceSunken": "color.surfaceSunken",
    "text": "color.text",
    "textMuted": "color.textMuted",
    "textInverse": "color.textInverse",
    "action": "color.action",
    "onAction": "color.onAction",
    "actionHover": "color.actionHover",
    "focus": "color.focus",
    "border": "color.border",
    "borderStrong": "color.borderStrong",
    "danger": "color.danger",
    "success": "color.success",
    "warning": "color.warning"
  }
}
```

多主题：

```json
{
  "source": { "format": "css" },
  "themes": [
    { "id": "brand-light", "mode": "light", "roles": { "bg": "css.default.bg", "...": "..." } },
    { "id": "brand-dark", "mode": "dark", "roles": { "bg": "css.dark.bg", "...": "..." } }
  ]
}
```

- 主题 id 只允许小写字母/数字/连字符；
- 每个主题 16 个 A 档角色必须映射；
- 源路径必须存在且为 color；
- 别名必须能解析；
- 对比度必须通过。

## 四、源格式

### DTCG

```text
light.color.bg
dark.color.bg
```

### CSS variables

```css
:root { --bg: #F7F3EA; }
.dark { --bg: #1B222B; }
```

适配器把变量读成：

```text
css.default.bg
css.dark.bg
```

只支持简单声明块；`@media` / 嵌套规则 / 复杂 `var()` 不保证。

### Tailwind

只接受 **JSON 导出**：

```json
{ "theme": { "extend": { "colors": { "bg": "#F7F3EA" } } } }
```

读取为 `tailwind.color.bg`，不执行 JS 配置。

### Style Dictionary / Figma Tokens

支持 `value` / `type` 叶子：

```json
{ "color": { "bg": { "value": "#F7F3EA", "type": "color" } } }
```

- Style Dictionary：`source.format = "style-dictionary"`；
- Figma Tokens Studio 导出：`source.format = "figma"`；
- 别名仍是 `{path}`；
- 不执行 JS / 不调用 Figma API。

## 五、component 映射

profile 可显式映射组件部件：

```json
{
  "component": {
    "button.bg": "sys.color.action",
    "button.border": "color.border",
    "button.height": "light.size.controlHeight"
  }
}
```

- `sys.color.*` → 生成 `{sys.color...}` 别名；
- 其他路径 → 必须在源 token 中存在；
- 生成 `component.button.*`，类型取源 token；
- 不自动推断组件结构。

## 六、命令

```bash
cd design/projects/livedso

# DTCG
node src/cli.ts adapt --source examples/adapt/source.tokens.json \
  --profile examples/adapt/profile.json --out /tmp/adapted-brand

# 多主题 DTCG
node src/cli.ts adapt --source examples/adapt/multi.tokens.json \
  --profile examples/adapt/multi-profile.json --out /tmp/adapted-multi

# CSS / Tailwind
node src/cli.ts adapt --source examples/adapt/theme.css \
  --profile examples/adapt/css-profile.json --out /tmp/adapted-css
node src/cli.ts adapt --source examples/adapt/tailwind.tokens.json \
  --profile examples/adapt/tailwind-profile.json --out /tmp/adapted-tw

# Style Dictionary / Figma Tokens
node src/cli.ts adapt --source examples/adapt/style-dictionary.tokens.json \
  --profile examples/adapt/style-dictionary-profile.json --out /tmp/adapted-sd
node src/cli.ts adapt --source examples/adapt/figma.tokens.json \
  --profile examples/adapt/figma-profile.json --out /tmp/adapted-figma

# 选项
--dry-run    只校验，不写
--check      生成物与源不一致时失败
--suggest    输出 B 档角色建议（不写入）
--suggest-out <file>  写建议草稿，人工确认后再合并
--json       机器可读结果
```

## 七、输出结构

```text
<tokens/tokens.json>
  meta（sourceHash / profile / format / themes）
  ref.source.external.*     用户源副本
  sys.color.*               默认主题 16 A 档角色
  product.<theme>.role.*    非默认主题的差异（若有）
  component.*               可选组件映射
<style-cards/<theme>.style.json>
  roles → sys.color.* / product.<theme>.*
README.md                   来源/hash/格式/主题
```

- 生成 vault 通过 `check-vault-schema.ts`；
- 每个主题一张风格卡，只含 A 档角色；
- B 档/预览 fallback 由 LiveDSO 处理；
- source hash 用于漂移检查。

## 八、失败语义

- 缺主题 / 缺 A 档角色 / 源不存在 → error；
- 别名断链 → error；
- 颜色无法解析 → error；
- 对比度不足 → error；
- `--check` 生成物不一致 / 源已变更 → error（且不覆盖现有生成物）。
- CI 中先 `adapt` 生成，再 `adapt --check`；source hash 已写入 `meta`，漂移不会静默通过。

P1 仍不放宽到 warning；有真实客户后再决定是否允许显式豁免。
