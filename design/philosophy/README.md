## 三、七个核心判断

0. **先清澄，后一切**：来源、代价、权限、退路可见；没有透明，其他原则都会退化成氛围。
1. **先真相，后风格**：视觉现象必须指向真实（或虚构世界内部自洽）的系统状态；没有数据链/设定链的“好看”只是装饰。
2. **先关系，后物件**：设计不是把东西做漂亮，而是安排技术、人、自然、劳动与权力之间的关系。
3. **现象优先，退路常在**：可感不等于不可读；数字、标签、屏幕阅读器、精确值必须保留。
4. **保留人的位置**：技术可以翻译，不可以替代判断；关键节点要有人判断、维护、拒绝与退出。
5. **多世界，不多教义**：赛博朋克、太阳朋克、原子朋克、磁带未来、Archive/Console 都可以并存；共享问题，不共享答案。
6. **诚实展示代价**：每个未来都要显示谁受益、谁承担、谁维护、什么会坏；不把乌托邦或反乌托邦当装饰。

## 七、阅读地图：按任务选一条路

> 16 篇不是线性教材。不要从 00 一路背到 15；先确定你**现在要做什么**，再选路径。

### 7.1 一页地图

```text
问题
  → 09 清澄：来源、代价、权限、退路是否可见？
  → 02 可感：系统状态如何变成可感知的现象？
  → 03 可参与：技术是否保留人的判断、维护、拒绝与退出？
  → 04/06 适当的未来 / 多世界：什么该采用，什么只是装饰？
  → 05 游戏：机制是否在让玩家体验一个未来问题？
  → 12 空间：人是否先读懂空间，再读懂界面？
  → 10/11 设计思维：如何把判断组织成可被体验的答案？
  → 08 十问：在评审里把以上问题问出来。
```

### 7.2 五条路径

| 你现在要做什么 | 路径 | 读完能回答 |
| --- | --- | --- |
| **10 分钟认识青橙** | 00 → 09 → 08 | 青橙是什么、最硬的一条原则是什么、评审时先问什么 |
| **做设计 / 做评审** | 00 → 09 → 08 → 13 → 14 → 15 → 10 → 11 → 12 | 如何从问题走到可被体验的答案，并在界面里保留空间与退路 |
| **做游戏 / 做世界** | 00 → 01 → 02 → 05 → 04 → 06 → 07 | 游戏如何成为未来实验室，世界语法如何不变成教义 |
| **做产品 / 做技术** | 00 → 03 → 04 → 07 → 12 → 08 | 技术如何保留人的位置，产品如何诚实展示代价 |
| **研究设计思维** | 10 → 11 → 09 → 12 | 设计思维与工程/产品/管理/商业/运营的区别，以及它的边界 |

### 7.3 三个检查点

1. **概念前**：用 [09 清澄七问](09_清澄_透明作为方法.md) 查来源、代价、权限、退路；
2. **方案前**：用 [08 青橙十问](08_青橙十问.md) 查谁受益、谁承担、谁维护、什么会坏；
3. **界面/空间前**：用 [12 空间直觉](12_空间直觉_让界面先被看见再被读懂.md) 查人是否先读懂空间，再读懂控件。

### 7.4 读完之后的动作

不要停在“有启发”。读完至少产出一件可被检查的东西：

- 一句项目意图；
- 三条非目标；
- 一张“谁受益 / 谁承担 / 谁维护 / 什么会坏”的表；
- 一次用十问做的评审记录；
- 一个能被人真实体验的最小原型。

> 如果读完没有改变任何一个设计决定，说明这次阅读还停留在气氛层。

## 八、不做什么

- 不把青橙做成“青橙渐变”的单一视觉风格；
- 不把“清澄”做成“全部曝光/极简白”的视觉标签；
- 不把赛博朋克当纯审美，也不把太阳朋克当唯一正确答案；
- 不把理念写成无法执行的口号；
- 不用理念替代 token、组件契约与无障碍闸门。

> 青橙不是答案，是提问方式。
